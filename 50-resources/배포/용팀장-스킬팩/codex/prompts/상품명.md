# 상품명 생성

썸네일·증거로 상품 정체를 확인하고 → 그 카테고리의 키워드 2~5개를 골라 →
네이버 상품명을 만들어 → 불사자에 반영한다.

## 최상위 원칙 — 카테고리가 먼저, 그 다음이 상품명

**네이버 노출 = 카테고리 매칭 + 키워드 매칭. 카테고리가 틀리면 키워드가 아무리 좋아도
그 카테고리 검색에 안 뜬다.** 그래서 순서가 있다:

1. **카테고리를 맞춘다** (`category-fix` 선행) — 이게 노출의 전제
2. **그 카테고리에 실재하는 키워드로 상품명을 짓는다**

**직결어가 하나도 없는 상품은 대부분 "상품명 문제"가 아니라 "카테고리 문제"다.**

## 사전 준비

| 필요한 것 | 설명 |
|---|---|
| **대상 상품의 카테고리가 교정돼 있을 것** | 미교정이면 `category-fix` 를 먼저 돌린다 |
| **카테고리별 키워드 목록** | 아이템스카우트·셀러라이프 등에서 받은 export 파일. 컬럼: `키워드 / 상품수 / 월검색량 / 쇼핑성` |
| 카테고리 교정 기록 CSV | `실물판정` 열을 재활용한다(있으면 썸네일 재판독 불필요) |

키워드 목록이 없으면 **작업을 시작하지 않는다.** 그게 이 작업의 원재료다.
사용자에게 어느 카테고리의 키워드 파일이 있는지 먼저 확인한다.

## Workflow

### Step 1. 대상 확인

- 마켓그룹(이름 또는 groupId) — `bulsaja_market_groups` 로 목록 조회
- 사용할 키워드 목록 파일 경로 — 사용자에게 확인
- **처음엔 3~5건.** 한 번에 20건을 넘기지 않는다

### Step 2. 상품 정보 수집

각 `productId` → `bulsaja_product_workdata(mode="full")`:
- 현재 카테고리 (`data.uploadCategory.ss_category.name`)
- 원본 상품명
- **중국어 원문명 · 옵션명** (실물 판정용)
- 썸네일 URL
- **옵션 가격이 전부 같은지** (= 추가금 0원 → 색상 예외 적용 가능)

**카테고리가 미설정인 상품은 분리한다** — 뷰가 없으므로 `스킵(카테고리미설정)`.
카테고리 교정을 먼저 하도록 사용자에게 알린다.

### Step 3. 키워드 목록 준비

그 상품의 카테고리에 해당하는 키워드 목록을 연다.
- 카테고리 교정 기록 CSV에 `실물판정` 이 있으면 **재활용한다. 썸네일을 다시 열지 않는다**
- 카테고리 목록에 직결어가 하나도 없으면 **상위 카테고리 목록**을 열어본다
  (다른 상품 키워드일 위험이 크므로 썸네일과 더 엄격히 대조)

### Step 4. 상품명 생성

**규칙 정본: [`../규칙/02-상품명-규칙.md`](../규칙/02-상품명-규칙.md)** — 그대로 따른다.

핵심만:
- 실물 확정 → 관련어 **전부** 뽑기 → 키워드 2~5개 선택 → `a 1 b 2 c` 배치 → 맨 끝 `기본형`
- **내용어 term 6 목표** (4~5 허용·경고, 3 이하·7 이상 실패)
- 키워드는 **연속 문자열 그대로** 넣는다. 쪼개면 적합도 0
- **반증 단계 생략 불가** — 채택보다 싼 관련어를 놔두고 비싼 걸 고르지 않았는지 되묻는다

**상품 1건씩 순차 처리한다.** 여러 건을 한꺼번에 판단하면 뒤 상품이 앞 상품에 끌려간다.

### Step 5. 검증 + 표 제시

`../규칙/02-상품명-규칙.md` 의 **검증 체크리스트 R1~R9** 를 자가 점검한다.
통과분만 표로 제시한다.

| 상품id | 원본 상품명 | 새 상품명 | 키워드(상품수) | term수 | 상태 | 속성제안 | 태그제안 |
|---|---|---|---|---|---|---|---|

**검증 실패 건은 반영 대상에서 빼고 사유를 적는다.** Step 4로 돌아가 다시 만든다.

### Step 6. 기록 (로컬 CSV)

`상품명_기록.csv` 에 append 한다. 헤더:
```
상품id,작업일,카테고리,원본상품명,새상품명,키워드1,키워드1_상품수,키워드2,키워드2_상품수,키워드3,키워드3_상품수,term분해,term수,반증,상태,메모,속성제안,태그제안
```

별도로 `관련어_기록.csv` — **"안 본 것"과 "보고 버린 것"을 구분하는 유일한 기록.**
재검수는 여기서 시작한다.
```
상품id,작업일,카테고리,관련어,상품수,검색량,채택여부,사유
```

- **원본 상품명은 반드시 남긴다.** 되돌리기의 유일한 경로다
- **재개**: `상품명_기록.csv` 에 이미 있는 상품id는 건너뛴다

### Step 7. 승인 → 불사자 반영

**사용자 승인 후에만** `bulsaja_product_rename` 으로 반영한다.

- **`상태=생성완료` 인 것만** 반영한다
- 여러 건이면 나눠서 호출한다. 배치가 거부되면 **더 작게 쪼개 재시도**한다
  (삭제된 상품이 1건 섞이면 배치 전체가 거부된다 — 1건 단위에서도 거부되는 것만 진짜 불량)
- 반영 성공분은 기록 CSV의 상태를 `반영완료` 로 바꾼다

## 상태 값

| 상태 | 의미 | 다음 |
|---|---|---|
| `생성완료` | 검증 통과. **반영 대상은 이것뿐** | Step 7 |
| `검증실패` | R1~R9 위반(사유 기재) | Step 4 재작업 |
| `보류(실물불명)` | 증거 4종으로도 실물 불명 | 이미지 더 보기 |
| `보류(카테고리의심)` | 목록에 직결어가 하나도 없음 = 카테고리가 틀렸다는 신호 | **카테고리 재교정** |
| `보류(키워드부족)` | 직결어는 있으나 2개를 못 채움 | 상품수 계단 확장 / 상위 카테고리 |
| `스킵(카테고리미설정)` | 카테고리가 없어 목록 자체가 없음 | 카테고리 교정 먼저 |
| `반영완료` | 불사자 반영까지 끝남 | — |
| `재작업(카테고리변경)` | 카테고리가 바뀌어 이 상품명이 무효 | 새 카테고리로 다시 |

## 보류 건 — 한 바퀴 다 돈 뒤 성격별로

**배치 중간에 멈추지 말고 한 바퀴를 다 돈 뒤** 보류를 모아 처리한다.
**원인이 다르니 처리 경로도 다르다. 셋을 한 큐로 뭉치지 않는다.**

**① `보류(실물불명)`** — 썸네일 2·3장 → 옵션 이미지 순으로 증거를 보강해 실물 확정 → Step 4부터 다시.
그래도 불명이면 사용자에게 보고한다. **추측 저장 금지.**

**② `보류(카테고리의심)`** — 카테고리부터 재교정한다. 직결어가 하나도 없는 건 상품명 문제가 아니다.
판단 기준 = **그 상품의 대표 검색어로 검색했을 때 1페이지에 뜨는 카테고리가 정답**
(카테고리는 의미가 아니라 업로드 분포다).
카테고리가 바뀌면 새 키워드 목록으로 Step 4부터 다시. 대개 직결어가 나온다.

> **카테고리가 바뀐 상품의 기존 상품명은 전부 무효다.**
> 키워드를 그 카테고리 목록에서 뽑았으므로 **모집단 자체가 틀렸다.**
> 부분 회수(키워드 하나만 갈아끼우기)는 금지 — 새 목록에서 다시 뽑는다.

**③ `보류(키워드부족)`** — 카테고리는 손대지 않고 상품수 계단 확장 또는 상위 카테고리로 후보를 보탠다.
그래도 안 되면 보류 유지.

## 표본 재검수 — 한 그룹이 끝난 뒤

형식 검증을 다 통과해도 **판단의 질**은 규칙으로 못 막는다.
반증 목록을 던져도 "없음"이라 답하면 그만이고, 적합성 오판은 산술 밖이다.
그래서 **수상한 것부터 표본을 뽑아 사람이 본다.**

**의심 신호(플래그) 우선으로 30~40건 뽑는다:**

| 플래그 | 점수 |
|---|---|
| 반증 후보가 많았는데 '없음' 이라고 답함 | +3 |
| 내용어 term이 4개 (6을 못 채움) | +1 |
| 상위 카테고리 목록으로 폴백함 | +2 |
| 관련어를 3개 이하만 기록함 | +2 |
| 채택 키워드 상품수가 10만 이상 | +1 |
| term이 원본 상품명에 하나도 없음 | +2 |

각 표본의 **썸네일과 키워드 목록을 열어** ①이 상품이 맞나 ②더 싸고 맞는 키워드를 놓쳤나를 본다.

- **틀린 게 3건 이상이면 규칙 적용을 재점검**한다
- **0~1건이면 나머지를 신뢰**한다
