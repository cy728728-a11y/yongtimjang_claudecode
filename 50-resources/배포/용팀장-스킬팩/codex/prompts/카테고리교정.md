# 카테고리 교정

불사자 상품의 잘못된/미설정 카테고리를 **네이버 정답 카테고리**로 교정한다.

**왜 이게 1번인가**: 네이버 노출 = 카테고리 매칭 + 키워드 매칭.
카테고리가 틀리면 키워드가 아무리 좋아도 그 카테고리 검색에 안 뜬다.
**카테고리 → 상품명 → 옵션** 순서를 지킨다.

## 진행 원칙

> **제안 우선(proposal-first).** 카테고리는 실판매 데이터다.
> 반드시 `이전 → 제안` 표를 사용자에게 보여주고 **승인 후에만** 저장한다.
> 사용자가 "확신도 높은 건 알아서 저장해도 된다"고 명시하면 그때부터 자동 저장한다.

> **소수 테스트 기본.** 처음엔 3~5건으로 검증하고, 결과가 납득되면 늘린다.
> 한 번에 30건을 넘기지 않는다(응답이 커서 대화가 무거워진다).

## Workflow

### Step 1. 대상 상품 확정

- 마켓그룹으로: `bulsaja_market_groups` 로 그룹 목록 → `bulsaja_product_list`
- 상품코드로: `bulsaja_product_find_by_code`
- 사용자가 상품 ID를 직접 주면 그대로 쓴다

각 상품에서 `productId` 와 `상품명` 을 추린다.

### Step 2. 현재(이전) 카테고리 읽기

각 `productId` → `bulsaja_product_workdata(mode="full")` →
`data.uploadCategory.ss_category` 의 `name` = 스마트스토어 현재 카테고리.
- `name` 이 빈 문자열이면 **"미설정"**.
- 같은 응답에서 **중국어 원문명 · 옵션명 · 썸네일 URL** 도 함께 확보한다(Step 3의 증거).

### Step 3. 실물 정체 판별 → 대표 검색어 도출

**규칙 정본: [`../규칙/01-실물판별-대표검색어.md`](../규칙/01-실물판별-대표검색어.md)** — 그대로 따른다.

요약:
1. 증거 4종(한국어 상품명 · 중국어 원문명 · 옵션명 · 썸네일)으로 **A 일치 / B 정정확정 / C 정체불명** 판정
2. A·B → 실물 기준 **대표 검색어**(분야 한정어 + 2단어 이상) 도출
3. C → `보류(정체불명)`. 카테고리 조회를 태우지 않는다. 조금이라도 애매하면 C

썸네일은 URL을 Read 로 열어 직접 본다.

### Step 4. 대표 검색어 → 네이버 카테고리 경로 확인

도출한 대표 검색어가 **네이버에서 어느 카테고리에 속하는지** 확인한다.

**방법 A — 셀하(sellha.kr) (권장)**
셀하에 로그인해 대표 검색어를 조회하면 `생활/건강 > 공구 > 원예공구 > 농기계` 형태의
카테고리 경로와 확신도(%)가 나온다. **이 경로를 그대로 쓴다.**
- 사용자가 셀하 계정이 있으면 직접 조회해서 경로를 알려달라고 요청한다
- 여러 건이면 검색어 목록을 표로 정리해 한 번에 조회하도록 넘긴다

**방법 B — 네이버 쇼핑 직접 확인 (셀하 없을 때)**
네이버 쇼핑에서 대표 검색어를 검색해 **1페이지 상위 상품들의 카테고리**를 본다.
가장 많이 나오는 카테고리가 정답이다. 확신도 수치는 없으므로 **전부 수동 승인 대상**이다.

> **핵심 원리**: 네이버 가격비교 카테고리는 "의미상 맞는 곳"이 아니라
> **실제 업로드 분포**다. 그래서 **대표 검색어로 검색했을 때 1페이지에 뜨는 카테고리가 정답**이다.

### Step 5. 최종 차수 → 불사자 매칭

카테고리 경로의 **최종 차수**(예 `농기계`)를 `bulsaja_product_category(keyword=최종차수)` 로 조회 →
`마켓별후보.스마트스토어` 후보 중 **전체 경로가 네이버 경로와 일치**하는 것을 고른다.

- 경로 정규화: 양쪽 모두 `>` 주변 공백을 제거하고 비교
- **정확 일치** → 확정
- 최종차수는 같은데 상위 경로가 다르면(동명 카테고리) → **부분일치** 플래그
- 후보가 없으면 → **매칭불가** 플래그

### Step 6. 제안표 → 승인 → 저장

아래 컬럼으로 제안표를 만들어 사용자에게 보여준다.

| 상품id | 상품명 | 이전 카테고리 | 변경 카테고리(제안) | 검색어(사용) | 확신도 | 상태 | 실물판정 |
|---|---|---|---|---|---|---|---|

- **검색어(사용)**: 실제로 조회에 넣은 대표 검색어. 실물 정정(B)이면 `(실물정정)` 표기
- **실물판정**: 증거 4종으로 판정한 실물 정체 (예 `자키+에어펌프+전동렌치 세트`)
  → **상품명 작업에서 이 값을 재활용한다. 반드시 기록에 남긴다**

**승인 후 저장**:
```
bulsaja_product_category(productId=<id>, keyword=<최종차수>)
```
- ⚠️ 이 저장은 **모든 마켓**(스마트스토어/쿠팡/11번가 등)을 같은 키워드로 한꺼번에 지정한다.
  스마트스토어는 정확히 맞지만 타 마켓은 자동매칭이라 부정확할 수 있다.
  네이버 셀러라면 **스마트스토어 기준으로 검증**한다.
- 저장은 서버 즉시 반영이다. PC를 꺼도 유지된다.

### Step 7. 기록 (로컬 CSV)

작업이 끝날 때마다 **로컬 CSV 파일**에 append 한다. 기본 경로:
`카테고리교정_기록.csv` (사용자가 지정하면 그 경로)

헤더:
```
상품id,상품명,이전카테고리,변경카테고리,검색어,확신도,상태,실물판정,썸네일URL,기록일
```

- **1건 처리가 끝날 때마다 즉시 쓴다.** 중간에 멈춰도 그때까지가 남는다
- **재개**: 다시 실행하면 CSV의 `상품id` 를 먼저 읽어 **이미 있는 건은 건너뛴다**
- CSV는 UTF-8 (BOM 포함) 로 쓴다 — 엑셀에서 한글이 깨지지 않게

## 상태 코드

| 상태 | 의미 | 저장? |
|---|---|---|
| `변경대상` | 정답 카테고리 확정. 승인 대기 | 승인 후 O |
| `저장완료` | 승인·저장 완료 | 완료 |
| `이미정확` | 이전 카테고리 == 조회 결과 | X |
| `조회실패` | 검색 결과 없음 | X |
| `매칭불가` | 불사자에 해당 최종차수 후보 없음 | X |
| `부분일치확인요` | 최종차수는 같은데 상위 경로 다름(동명) | 수동 판단 |
| `보류(정체불명)` | 증거 4종으로도 실물 판별 실패 | X (이미지 더 보고 재판정) |
| `승인보류` | 사용자가 보류·거부 | X |

## 보류 건 처리 — 한 바퀴 다 돈 뒤에

**중간에 멈추지 않는다.** A·B를 전부 돌린 뒤 `보류(정체불명)` 만 모아서 처리한다.
그래야 그 상품군이 어떤 물건들인지 파악된 상태에서 본다.

**이미지 사다리 (싼 것부터)**:
1. **남은 썸네일 2·3장** — `workdata` 응답에 이미 URL이 있다. 사실상 공짜. 여기서 상당수 풀린다
2. **옵션 이미지** (`uploadSkus[].urlRef`) — 옵션은 실물 변형이라 정체가 드러난다.
   상세페이지 원본에 가장 가까운 소스다
3. 그래도 불명 → **사용자에게 보고**. 혼자 추측해서 엉뚱한 카테고리에 넣지 않는다

## 카테고리를 바꾸면 그 상품의 상품명도 무효다

**카테고리를 교정한 상품의 기존 상품명·키워드는 전부 폐기한다. 부분 회수는 없다.**

상품명 키워드는 **그 카테고리의 키워드 목록에서** 뽑는다.
카테고리가 틀렸다면 그 목록도 틀렸고, 거기서 고른 키워드·상품명이
**전부 잘못된 모집단에서 나온 것**이다. "키워드 하나만 갈아끼우기"는 안 된다.

→ 교정한 상품은 **상품명 작업 대상으로 다시 올린다.**

## 리스크 — 확신에 찬 오답

카테고리 조회 확신도가 100%여도 **검색어가 상품을 잘못 대표하면 확신에 찬 오답**이 나온다.
확신도는 "검색어 ↔ 카테고리"의 신뢰도이지 "검색어 ↔ 상품"이 아니다.

**방어선**: 증거 4종 정체판별(최대 방어선) + 키워드 규율 + 매칭불가 자동 차단 +
낮은 확신도 수동 보류 + 정체불명 2바퀴.

**결과 검토 기준**: 네이버 카테고리는 의미가 아니라 **업로드 분포**다.
**카테고리가 의미상 이상해 보인다는 이유로 오답 판정하지 마라.**
(뷔페워머기 → 식기>접시, 수심측정기 → 낚시 어탐기 — 둘 다 정답으로 검증됨)
**진짜 오답은 대표 검색어가 상품을 잘못 대표한 것뿐이다.**
검토는 카테고리↔상품이 아니라 **검색어↔상품명(필요시 썸네일)** 을 대조한다.
