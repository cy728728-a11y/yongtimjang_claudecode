# 구매대행 상품 작업 규칙 (AGENTS.md)

이 프로젝트에서 상품 작업을 요청받으면 아래 규칙을 따른다.

## 작업 3종과 순서

**카테고리 교정 → 상품명 생성 → 옵션 정리.** 이 순서를 지킨다.
네이버 노출 = 카테고리 매칭 + 키워드 매칭이라, 카테고리가 틀리면 키워드가 아무리 좋아도
그 카테고리 검색에 안 뜬다. 카테고리를 바꾸면 그 상품의 기존 상품명은 전부 무효다.

| 요청 | 실행할 프롬프트 |
|---|---|
| "카테고리 교정", "카테고리 바꿔줘", "카테고리 정리" | `prompts/카테고리교정.md` |
| "상품명 만들어줘", "상품명 바꿔줘", "키워드로 상품명" | `prompts/상품명.md` |
| "옵션 정리", "옵션명 정리", "대표옵션", "판매범위" | `prompts/옵션정리.md` |

각 프롬프트는 `규칙/` 폴더의 판단 규칙 정본을 읽고 실행한다.

## 항상 지키는 것

1. **제안 우선(proposal-first).** 저장·반영 전에 반드시 표를 만들어 보여주고
   사용자 승인을 받는다. 승인 없이 상품 데이터를 바꾸지 않는다.
2. **소수 테스트 기본.** 처음엔 3~5건(옵션은 1~3건)으로 검증하고 늘린다.
   한 번에 30건을 넘기지 않는다.
3. **한국어 상품명은 정답지가 아니라 용의자다.** 실물 판별은 반드시
   중국어 원문명·옵션명(가공 전 원본)을 함께 본다.
4. **모르면 보류한다. 추측해서 저장하지 않는다.** 조금이라도 애매하면 보류다.
5. **기록은 로컬 CSV.** 작업 1건이 끝날 때마다 즉시 append 한다
   (중간에 멈춰도 그때까지가 남는다). UTF-8 BOM으로 써서 엑셀에서 한글이 안 깨지게 한다.
6. **재개**: 다시 실행하면 기록 CSV의 상품id를 먼저 읽어 **이미 있는 건은 건너뛴다.**

## 도구

상품 정보 조회·저장은 **불사자 MCP**로 한다.

| 용도 | 도구 |
|---|---|
| 마켓그룹 목록 | `bulsaja_market_groups` |
| 상품 목록 | `bulsaja_product_list` |
| 상품코드로 찾기 | `bulsaja_product_find_by_code` |
| 상품 상세(카테고리·원문명·옵션·썸네일) | `bulsaja_product_workdata` (mode="full") |
| 카테고리 조회·저장 | `bulsaja_product_category` |
| 상품명 변경 | `bulsaja_product_rename` |
| 옵션 변경 | `bulsaja_option_update` |

불사자 MCP가 연결돼 있지 않으면 **작업을 시작하지 말고 먼저 알린다.**
