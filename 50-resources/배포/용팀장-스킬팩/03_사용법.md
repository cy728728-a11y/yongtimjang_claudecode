# 사용법 (클로드 코드 · 코덱스 공통)

설치가 끝났다는 전제입니다. 아직이면 [01](01_설치_클로드코드.md) 또는 [02](02_설치_코덱스.md) 먼저.

---

## 큰 그림 — 순서가 있습니다

```
① 카테고리 교정  →  ② 상품명 생성  →  ③ 옵션 정리
```

**왜 이 순서인가**

네이버 노출 = **카테고리 매칭 + 키워드 매칭**입니다.
카테고리가 틀리면 그 카테고리 검색에 아예 안 뜹니다. 키워드가 아무리 좋아도 소용없습니다.

그리고 상품명 키워드는 **그 카테고리의 키워드 목록에서** 뽑습니다.
카테고리가 틀렸다면 그 목록도 틀렸고, 거기서 고른 키워드가 전부 잘못된 모집단에서 나온 겁니다.

> **카테고리를 나중에 바꾸면 그 상품의 상품명은 전부 다시 만들어야 합니다.**
> 키워드 하나만 갈아끼우는 건 안 됩니다. 그래서 카테고리가 먼저입니다.

## ① 카테고리 교정

### 준비물
- 불사자 MCP 연결
- 셀하(sellha.kr) 계정 — **없어도 됩니다.** 대신 네이버 쇼핑에서 직접 확인합니다

### 말하는 법

```
1번 마켓그룹에서 5개만 카테고리 교정해줘
```

### 무슨 일이 일어나나

1. **상품의 실물 정체부터 판별합니다** — 이게 이 작업의 핵심입니다
   - 한국어 상품명은 **믿지 않습니다**. 수집·번역 과정에서 왜곡되기 때문입니다
   - 대신 **중국어 원문명 + 옵션명 + 썸네일**을 같이 봅니다
2. 실물 기준으로 **대표 검색어**를 뽑습니다 (`농약 분무기` 처럼 분야를 못 박은 2단어 이상)
3. 그 검색어가 속한 **네이버 카테고리 경로**를 확인합니다
4. **표를 보여주고 멈춥니다** ← 여기서 여러분이 확인합니다
5. 승인하면 저장합니다

### 실제 사례 — 왜 원문을 봐야 하나

```
① 한국어 상품명 : 자동차 전동 자키 받침대 오렌지 작키 작기 유압 수리
② 중국어 원문명 : 沪工电动液压千斤顶12V多功能车载充气泵电动扳手汽车越野车SUV
③ 옵션명        : 3톤 세단 모델잭에어펌프 / 5톤 2기통 오프로드잭에어펌프전동렌치

→ 실물 = 자키 + 에어펌프 + 전동렌치 세트
→ '받침대'는 실물에 아예 없습니다. 상품명만 믿었으면 엉뚱한 카테고리로 갔습니다
```

### 표를 볼 때 확인할 것

| 상품id | 상품명 | 이전 카테고리 | 변경 카테고리(제안) | **검색어(사용)** | 확신도 | 상태 |
|---|---|---|---|---|---|---|

**보실 곳은 "검색어(사용)" 열입니다.**

- ⭕ 검색어가 그 상품을 제대로 대표하나? → **이것만 보세요**
- ❌ 카테고리가 의미상 이상해 보이나? → **이건 오답 신호가 아닙니다**

> **중요 — 카테고리가 이상해 보인다고 오답이라고 판단하지 마세요.**
> 네이버 카테고리는 "의미상 맞는 곳"이 아니라 **실제 업로드가 몰린 곳**입니다.
>
> | 상품 | 카테고리 | 이상해 보이지만 |
> |---|---|---|
> | 뷔페워머기 | 식기 > 접시 | **정답** |
> | 수심측정기 | 낚시 > 어탐기 | **정답** |
>
> **진짜 오답은 검색어가 상품을 잘못 대표한 것 하나뿐입니다.**

### 셀하가 없으면

네이버 쇼핑에서 대표 검색어를 검색 → **1페이지 상위 상품들의 카테고리**를 봅니다.
가장 많이 나오는 게 정답입니다. 확신도 수치가 없으니 **전부 눈으로 확인**하세요.

## ② 상품명 생성

### 준비물
- **카테고리가 먼저 교정돼 있을 것**
- **카테고리별 키워드 목록 파일** ← 이게 없으면 시작 자체가 안 됩니다
  (아이템스카우트·셀러라이프 등에서 받은 export. 컬럼: 키워드 / 상품수 / 월검색량)

### 말하는 법

```
1번 마켓그룹 상품 5개 상품명 만들어줘.
키워드 파일은 C:\작업\키워드\서랍장.xlsx 야
```

### 결과물이 어떻게 생겼나

```
가정용 무선 각얼음 빙수기 눈꽃 슬러시 기본형
└──┬──┘ └┬┘ └─┬─┘ └┬─┘ └┬┘ └─┬─┘ └─┬─┘
  원본   키워드  키워드  원본  원본  원본   마커
```

**핵심 규칙 3가지만 알면 됩니다:**

| | 규칙 | 왜 |
|---|---|---|
| 1 | **내용어 6개를 채운다** | 3개 이하는 검색 노출이 안 나오고, 7개 이상은 네이버 패널티 |
| 2 | **키워드는 통째로 붙인다** | 네이버는 검색어가 **연속으로 그대로** 있을 때만 적합도 만점. 쪼개면 0점 |
| 3 | **맨 끝에 `기본형`** | 네이버가 요구하는 "대표상품 지칭". 옵션 정리에서 대표옵션에도 같은 단어를 붙여 짝을 맞춤 |

### `기본형` 이 뭔가요

네이버는 **추가금 0원인 대표옵션**을 상품명으로 쓰라고 요구합니다.
그래서 **썸네일 = 대표옵션 = 상품명**이 같은 하나를 가리켜야 합니다.

```
옵션 (선택 1개)          상품명
  블랙 기본형  ← 대표     "…무선청소기 기본형"
  화이트                 ↑ 같은 단어로 짝이 맞습니다
  베이지
```

상품명 쪽은 **대표옵션이 뭔지 몰라도 됩니다. 무조건 맨 끝에 붙이면 됩니다.**

### 표를 볼 때 확인할 것

- **키워드 상품수** — 상품수가 낮은 게 1페이지에 뜹니다. 10만 넘는 게 있으면 의심
- **term수** — 6이 목표. 4~5는 통과지만 경고
- **`기본형` 이 끝에 딱 1번** 있는지

### 잘 안 나올 때

| 상태 | 뜻 | 여러분이 할 일 |
|---|---|---|
| `보류(카테고리의심)` | 그 카테고리 키워드 목록에 **직결어가 하나도 없음** | **카테고리부터 다시 보세요.** 상품명 문제가 아닙니다 |
| `보류(실물불명)` | 증거를 다 봐도 무슨 물건인지 모르겠음 | 상품 페이지를 직접 보고 알려주세요 |
| `보류(키워드부족)` | 직결어는 있는데 2개를 못 채움 | 상위 카테고리 키워드도 같이 주세요 |

> **`보류(카테고리의심)` 이 많이 나오면 카테고리 교정이 덜 된 겁니다.**
> 파일럿에서 보류 4건이 **전부** 이 케이스였습니다.

## ③ 옵션 정리

> ⚠️ **매출 직결입니다.** 무엇을 팔고, 무엇을 내리고, 대표가격이 얼마인지를 바꿉니다.
> **가장 마지막에, 1~3건으로 시작하세요.**

### 말하는 법

```
상품 U01xxx 옵션 정리해줘
```

### 무슨 일이 일어나나

1. **파는 물건이 아닌 행을 골라냅니다**
   - 구매금지 안내 / 사이즈표 / 보증금·배송비 / 부속품 단독 / 다른 모델 / 맞춤제작 문의
2. **옵션명을 중국어 원문 기준으로 다시 짓습니다** (25자 이내, 서로 안 겹치게)
   - 기존 한국어 이름은 기계번역이라 틀린 게 많습니다. **그걸 다듬으면 틀린 채로 다듬게 됩니다**
3. **최저가를 대표옵션으로 세우고, 그 1.5배까지만 팝니다**
4. **판매가 오름차순 = 업로드 순서**
5. **검수표 3개를 보여주고 멈춥니다** ← 여기서 확인
6. 승인하면 저장

### 1.5배 규칙

```
대표(최저가) 24,000원  →  판매 상한 36,000원
36,000원 넘는 옵션은 판매에서 제외
```

**왜**: 대표가격과 너무 차이나는 비싼 옵션이 섞이면 고객이 대표가만 보고 들어왔다가
이탈합니다. 그리고 네이버 가격 경쟁력도 왜곡됩니다.

> ⚠️ **부속품을 먼저 안 빼면 이게 망가집니다.**
> 부속품 500원이 섞인 채 계산하면 상한이 750원이 되어 **본품이 전멸합니다.**
> 그래서 "메인상품 선별"을 먼저 하는 겁니다.

### 검수표에서 볼 것

| 표 | 볼 곳 |
|---|---|
| ① 옵션명 교정표 | 중국어 원문과 교정 후가 실제로 맞나. 25자 넘는 건 없나 |
| ② 판매 계획표 | **대표에 ★가 하나만** 있나. 순서가 가격 오름차순인가 |
| ③ 제외 사유표 | **팔아야 할 걸 빼지 않았나** ← 여기가 제일 중요 |

### 저장했는데 마켓에 안 바뀝니다

**정상입니다.** 저장은 **불사자 서버의 상품 데이터**만 바꿉니다.
이미 마켓에 올라간 상품이면 **수정 업로드를 따로** 해야 반영됩니다.

> 그래서 **아직 마켓에 안 올린 상품을 정리하는 게 가장 안전한 타이밍**입니다.

### 되돌리려면

저장 직전에 `옵션백업_<상품id>.json` 이 만들어집니다. **이게 유일한 원본입니다.**
지우지 마세요.

## 자주 하는 질문

**Q. 한 번에 몇 개까지 되나요?**
카테고리·상품명은 **5건으로 시작 → 익숙해지면 20~30건**.
옵션은 **1~3건**부터. 한 번에 30건을 넘기면 대화가 무거워져서 오히려 느려집니다.

**Q. 중간에 멈췄는데 처음부터 다시 해야 하나요?**
아닙니다. 작업 1건이 끝날 때마다 CSV에 기록됩니다.
다시 시키면 **이미 처리된 상품은 건너뜁니다.**

**Q. AI가 마음대로 상품을 바꾸면 어쩌죠?**
승인 없이는 저장하지 않게 규칙에 박아놨습니다.
다만 **"응 알아서 해줘"를 습관적으로 누르지 마세요.** 표를 보는 게 여러분 일입니다.

**Q. 기록은 어디에 남나요?**
작업 폴더의 CSV 파일입니다. 엑셀로 열립니다.

| 파일 | 내용 |
|---|---|
| `카테고리교정_기록.csv` | 이전/변경 카테고리, 사용 검색어, 실물판정 |
| `상품명_기록.csv` | 원본/새 상품명, 채택 키워드와 상품수 |
| `관련어_기록.csv` | **보고 버린 키워드와 그 사유** — 재검수는 여기서 시작 |
| `옵션정리_기록.csv` | 유지/제외, 대표옵션, 기준가·상한 |

**Q. 결과가 마음에 안 들면?**
그냥 말하면 됩니다. `이 상품은 실물이 OO야, 다시 해줘` 처럼.
규칙을 아예 바꾸고 싶으면 규칙 파일(`references/` 또는 `규칙/`)을 직접 고치면 됩니다.

**Q. 상품수 수백 개를 자동으로 돌릴 수 있나요?**
이 팩으로는 안 됩니다. 대량 자동화는 별도 스크립트·서버 세팅이 필요합니다.
이 팩은 **판단 규칙**이 핵심이고, 그 규칙은 대량이든 소량이든 똑같습니다.
