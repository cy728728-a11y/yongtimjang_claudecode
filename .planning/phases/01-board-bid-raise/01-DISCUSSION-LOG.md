## 미리보기 산출물

**선행 실측:** dry-run stdout 은 10건만 찍고 `… 외 N건` 으로 접으며, `run_ads.py cmd_bids` 가 `run_bids` 리턴값을 버린다 → **stdout 파싱으로 미리보기 표 생성 불가**. CLI 가 파일을 쓰는 것이 유일한 경로로 확정(Q1 에서 플래그 추가 허용을 이미 받음).

### Q1. `run_bids(commit=True)` 가 plans 를 재계산해 미리보기와 어긋날 수 있다. 어떻게?

| Option | Description | Selected |
|--------|-------------|----------|
| 재계산 유지 + diff 보고 | CLI 는 그대로 재계산, 웹앱이 preview.json 과 결과를 대조해 "달라진 N건"을 사유와 함께 보고. 쿨다운·연속실패·상한 가드가 실행 시점 기준으로 살아있다 | ✓ |
| 미리보기 값을 강제 | 실행이 preview.json 의 `to` 를 그대로 씀. 화면·결과 100% 일치하지만 검증된 방어를 우회 — 제약 위반에 가깝다 | |
| 그냥 재계산, diff 없음 | 가장 싸다. 단 "본 거랑 다른 게 돌았다"를 눈치챌 수단이 없다 | |

**User's choice:** 재계산 유지 + diff 보고

### Q2. 미리보기 표를 어느 단위로? (보드는 상품 줄, CLI plans 는 소재 줄)

| Option | Description | Selected |
|--------|-------------|----------|
| 미리보기는 소재 줄 | 보드=상품 / 미리보기=소재. 가격이 바뀌는 단위가 소재라 화면·실행이 1:1. 상품 줄 선택 시 "N건에 적용됩니다" 선표시 | ✓ |
| 미리보기도 상품 줄 | 눈은 편하지만 소재 2~3개 상품(88개)에서 일부만 인상되는 경우를 한 줄로 표현하기 애매 | |
| 보드도 소재 줄로 통일 | 구현 최단. 단 Phase 3~5 의 상세·썸네일이 상품 단위라 그때 보드를 다시 짜야 한다 | |

**User's choice:** 미리보기는 소재 줄
**Notes:** 실측 근거 — 상품 2,637개 중 소재 2개 이상인 것 88개, 최대 3. 팬아웃이 작아 접기 비용이 낮다.

### 되돌리기 범위 (논의 미선택 → Claude 결정 → 사용자 승인)

**발견:** `run_revert` 는 `before_bids_<alias>.json` **전체**를 되돌린다. 이 백업은 회차 안에서 **누적 병합**된다(`bids.py` Important 1). 화면의 "되돌리기"를 `--revert` 에 직결하면 **방금 누른 작업이 아니라 그 회차 인상분 전부가 풀린다.**

**결정:** 웹앱이 작업 단위로 "인상 성공한 adId 목록"을 jobs DB 에 남기고, 되돌리기는 그 목록을 `--only-ads` 로 넘겨 그 작업분만 되돌린다. 백업 파일은 손대지 않는다(최초 원본 보존). 화면에 "이 작업분만 되돌리기"와 "이 회차 전체 되돌리기"를 따로 둔다.

**사용자 응답:** "1. 이대로 좋다" (2026-09-19)

### planner/executor 재량으로 넘긴 것

- 미리보기·타깃·결과 파일의 이름과 스키마, jobs DB 테이블 컬럼
