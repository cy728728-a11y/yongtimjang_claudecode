# 260930-c4 — 쿠팡 gate: 쿠팡 그룹 밖으로 옮겨진 사본도 잡는다

## 문제

gate 는 (1) 지금 쿠팡 그룹(1003308)에 있는 상품 (2) 그 run-dir 의 copied.jsonl 만 대조한다.
파일럿 사본 `oEEpBU9Ol7PCRzQGyww2J`(원본 `03lPOGjwQKt96y4uNt1Ik` 머그컵)은 상품그룹
`구매_가공완료` 로 옮겨져 쿠팡 그룹 목록에 안 나온다 → 원본이 다시 후보로 나온다
(evidence/07-07-commit.md). 승인하면 두 번째 사본이 생긴다.

## 서버 신호 (읽기 전용 실측, 2026-09-30)

- `find_by_code([불사자코드])` = 같은 계보(원본·사본·재수집분) 전부. 머그컵 10건, PLIG74 28건.
  → 계보만으론 "쿠팡 사본" 판별 불가(스마트스토어 사본·재수집분이 섞여 있다).
- `bulsaja_product_workdata` 의 `data.uploadSelectedMarketGroupId` = 그 상품의 **마켓그룹**.
  사본 oEEpBU = **1003308**(쿠팡) · 원본 03lPOG = 1001189. 쿠팡 그룹 목록 5건 표본 모두 1003308.
  상품그룹(`구매_가공완료`)으로 옮겨도 이 값은 쿠팡 그대로 남는다.
- 계보 필드(원본pid·복사원본)는 workdata 에 **없다** — 위 조합이 유일한 서버 신호다.

→ 로컬 대장 폴백(과거 run-dir copied.jsonl 합집합)은 쓰지 않는다(서버 신호 있음 · 대장 신설 금지).
