# Quick 260930-m3: 형제 미리보기 이중 반영 방지 (06-06 P1)

## 문제
미리보기마다 `web/market_<미리보기id>/` 가 새로 생기고, 반영 대상·미리보기 표는 **그 폴더의** `market_status.json` 만 본다.
옛 미리보기에서 이미 반영된 상품이 새 미리보기에서 다시 '이번 반영' → 스토어에 두 번 나갈 수 있다.
게이트 패널은 남은 0건이어도 "나머지를 진행해라" 를 띄운다.

## 판단
- 서버 쪽 신호: CLI `_상품판정` 의 workdata 는 채널상품번호·상세만 준다 — "이 상세가 이미 마켓에 반영됐다" 는 신호 없음.
  → 로컬 체크포인트 합집합이 근거.
- 대상 산정은 이미 웹앱 라우트(`post_market_commit` · `_마켓손댐`)가 한다. CLI 는 받은 대상에 `_새접수대상` 만 적용.
  → 같은 자리에서 합집합만 넓힌다(새 CLI 옵션 불필요, CLI 무변경).

## Task 1 (auto)
- `_마켓체크포인트_합침(폴더, 체크)`: 같은 `web/` 의 모든 `market_*/market_status.json` 손댄 항목 이월(자기 기록 우선, 성공 우선, `이월출처` 표시, 깨지면 `_체크포인트깨짐`).
- 미리보기 ctx · commit 대상 · 게이트 패널 남은 수가 합집합 기준. 게이트 닫힘 + 형제 손댐 이월 → 400.
- 템플릿: 남은 0건이면 0건 안내, '다음 회차' 는 실제 남을 때만.
- 테스트: 형제 성공 → 반영됨(성공) + 대상 제외 / 전부 반영 → 버튼 없음·400 / 스킵은 이월 안 함 / 게이트 전 형제 1건 → 400 / 형제 깨짐 → 400 / 게이트 패널 0건 문구.
