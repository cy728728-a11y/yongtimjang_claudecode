## 코드 — 이번에 고친 것

### 1. `axis` 명령을 새로 만들었다 (원장 replay)

**저장부만 고쳐서는 쌓인 게 안 나갔다.** `apply --commit` 이 축을 저장하는 건 *이번 run 에
든 상품*뿐인데, 원장에 쌓인 축은 전부 **옵션이 이미 `완료` 인 상품**의 것이라 현황판
`pending` 에 안 잡힌다. 200축이 그 상태였다. 옵션을 통째로 다시 돌릴 이유는 없다 —
바뀌는 건 축 표기 하나고 무엇을 파느냐는 이미 정해져 있다.

```bash
run_options.py axis --sheet <시트>            # 미리보기(원장 안 씀)
run_options.py axis --sheet <시트> --commit   # 저장 + 원장 갱신
```

원장이 현재와 어긋나면 안 보낸다: 이미 그 이름이면 호출 없이 `반영`, 축이 그새 바뀌었으면
`보류(축이 바뀌었다: …)`. 판정·검증은 `apply` 와 **같은 함수**(`axis_saveable`·`axis_verify`).

### 2. `/` → `·` 자동 교정 (`axis_repair`) — 이룸님 판단

저장 못 한 30축 중 **25축이 전부 같은 원인**이었다: 제안에 `/` 가 들어감
(`색상/마감`·`모델/용량`·`등급/무게`). 축 이름 금지문자다.
**그 제안들은 금지문자 규칙이 생기기 전(2026-08-06)에 지은 것**이라 워커 탓이 아니고,
사람이 25번 고쳐 앉을 일도 아니다.

`/` 는 금지문자 중 **유일하게 뜻이 확실하다** — `색상/마감` = "색상과 마감이 섞였다"이고
`색상·마감` 이 그 뜻 그대로다. 괄호 같은 건 뭘로 바꿀지 기계가 모르니 종전대로 거부한다.
고친 값은 **원장 `제안축명` 칸에도 되쓴다** — 원장에 적힌 제안과 실제로 보낸 값이 달라지면
원장이 거짓이 된다.
