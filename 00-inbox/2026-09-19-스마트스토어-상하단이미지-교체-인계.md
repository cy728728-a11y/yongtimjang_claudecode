## 목표

불사자로 업로드한 스마트스토어 상품의 상세페이지 **상단·하단 고정 안내이미지**(해외배송 안내,

## 접근안 — ② 위치 기반 (용팀장 선택) + 전수 안전장치

핵심 난제: 상세페이지 HTML 안에서 상단/하단 이미지를 어떻게 정확히 찾느냐. 잘못 잡으면 본문 이미지가 날아간다.

제시한 3안 중 용팀장이 **②(첫 img / 마지막 img 위치 기반)** 를 선택했다.
②는 상품마다 HTML 구조가 다르면 오폭 위험이 있으므로, 위치 기반을 유지하면서 위험만 걷어내는
**전수 빈도표 검증**을 붙이기로 했다 (①의 표본조사를 사람 대신 스크립트가 전수로 수행).

## 설계 1/3 — 전체 흐름 (승인 대기)

스토어 하나를 고르면 7단계.

1. **수집** — 상품 전량 목록 → 각 상품 상세 조회 → `detailContent` HTML을 로컬에 저장
2. **분석(안전장치)** — 1,000개에서 *첫 img* / *마지막 img* URL을 뽑아 빈도표를 만든다
   ```
   [상단 후보]  urlA.jpg   998건  ← 안내 이미지로 확정
                urlZ.jpg     2건  ← 예외, 건드리지 않음
   [하단 후보]  urlB.jpg  1000건
   ```
   한 URL로 몰리면 그게 안내 이미지인 게 증명된다. 소수파는 예외 명단으로 빼고 건너뛴다
3. **새 이미지 업로드** — 커머스API 이미지 업로드로 네이버 URL 획득
4. **드라이런** — 상품 3개의 치환 전/후 HTML 차이만 출력. 전송 안 함
5. **파일럿** — 딱 1개만 실제 수정 → 스토어에서 눈으로 확인
6. **본실행** — 전량. 처리한 상품번호 기록 → 중단해도 재개
7. **원복** — 수정 전 원본 HTML 전량 보관 + 되돌리기 스크립트

## 프로젝트는 두 덩어리로 분리

| | 내용 | 비고 |
|---|---|---|
| **A. 이미지 제작** | 108장 (54스토어 × 상단·하단) | 템플릿 1개에 상호명만 갈아끼움 |
| **B. 커머스API 교체 엔진** | 상품 5만 4천 개 | 위 7단계 |

둘은 별도 스펙으로 간다. B는 A 없이도 파일럿까지 만들 수 있고(옛 이미지를 그대로 다시 넣는 무해한 왕복 테스트),
A는 B 없이도 완성 가능하다. **먼저 설계할 것은 B** — 미지의 위험이 전부 그쪽에 있다.

## 함정 (미리 박아둠)

1. **커머스API는 상품 부분수정이 안 된다.** HTML 한 줄 바꾸려 해도 상품 전체 정보를 다시 PUT 해야 하고,
   조회 응답에는 전송하면 안 되는 읽기전용 필드가 섞여 있다. 여기서 틀리면 **가격·옵션·배송비가 엉뚱하게 바뀐다.**
   → 5단계 파일럿에서 1개 고친 뒤 가격·옵션·재고가 그대로인지 반드시 확인하고 넘어간다
2. **IP 허용목록** — 데스크탑에서만 호출된다. 맥북에서 만들고 `깃푸쉬` → 데스크탑에서 풀 받아 실행
3. **인증정보 불량 4스토어** — 본실행 전 54곳 토큰 발급 사전점검부터
4. **불사자 설정도 같이 바꿔야 한다.** 커머스API로 고쳐놔도 불사자에서 "수정전송"을 하면 옛 이미지로 덮인다.
   불사자 쪽 상하단 설정 이미지도 새 것으로 교체해둘 것 (물갈이 재업로드분은 그래야 새 이미지로 올라간다)
5. **새 이미지는 AI 생성 부적합.** 배송 안내는 글자가 정확해야 하는데 AI 이미지 생성은 글자를 못 지킨다.
   `smartstore-brand` 스킬(gpt-image-2)은 로고·배너용. 상하단 안내는 **템플릿(HTML→PNG)에 상호명만 치환**하는 방식
