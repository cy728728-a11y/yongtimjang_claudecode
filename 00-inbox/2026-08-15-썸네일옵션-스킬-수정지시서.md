## A. [문서] 접수모드는 "큐가 막혔을 때"가 아니라 **대량 회차의 기본 전략**이다 ★

## D. [코드] `audit --commit` 에 **배치 대비 누락 검사**가 없다

그런데 **`_audit_commit` 은 결과 파일을 모아 그대로 반영할 뿐, 배치 대비 누락을 세지 않는다.**

**왜 실제 위험인가** — 같은 회차의 `run` 팬아웃에서 **결과 파일 하나가 통째로 누락**되는 것을
직접 겪었다(아래 F 참조). audit 배치는 12건 단위라, 배치 하나가 조용히 빠지면 **12건이 대조
안 된 채** `###AUDIT###` 은 정상 종료로 찍힌다. 치명적이진 않다(현황판이 빈칸으로 남아 다음
prep 이 다시 집는다) — 그러나 **"감사했는데 깨끗하다"로 읽히는 게 문제**다.
SKILL.md 가 이미 같은 성격의 결함을 `§6-G 조용한 누락 방지`로 경계하고 있다.

**제안** — `verdict` 처럼 차단까지 갈 필요는 없다(audit 은 크레딧·자동반영이 안 걸린다).
`prescreen` 과 같은 수위의 **경고 + 건수 출력**이면 충분하다.

```python
# _audit_commit() 안, _heal_pids 직후

judged = {p.get("productId") for p in products}

          f"pending --audit 로 남은 배치를 마저 돌리고 다시 commit 해라: {missing[:5]}")
```

복구 내용이 SKILL §알려진 함정의 실증이다 — PE관은 원문이 전부 `얇은 모델 100m` 라 겹치던 걸
**구경(20/25/32mm)** 으로, 우편함은 `빨간 우편함` 2개를 **꽃무늬 유무**로, 라운지소파는

## 내가 헛짚었던 것 (같은 헛수고 반복 방지)

`prescreen_results` 에서 잘린 productId(24자)를 발견하고 **손으로 고쳤는데, 불필요했다.**
`_prescreen_commit` 은 이미 `_heal_pids()` 를 부르고 있고(`run_thumbs.py:691`),
`prescreen_batches_index.json` 이 있으면 **자기 배치 안 접두 매칭으로 자동 복구**한다
(`audit` 도 936행에서 같은 처리). **잘린 id 를 보면 먼저 `_heal_pids` 호출 여부와 인덱스 파일
존재를 확인하라** — 있으면 그냥 commit 하면 된다.

단, **가운데가 빠진 형태는 자동 복구가 안 된다.** `_heal_pids` 의 복구 조건은
"잘린 id 가 정본의 **접두사**" 인데, 가운데가 빠지면 접두사가 성립하지 않는다.

| 축 | 워커가 적은 id | 정본 | 빠진 것 |
|---|---|---|---|
| 옵션 팬아웃 | `U01KRZBANVAR72SRNRG0MKRW1` | `…MKRWQG1` | 가운데 `QG` (끝 `1` 은 유지) |
| 썸네일 verdict | `U01KRZBANTXWJMPJT7N4TV6P4N` | `…TV6PB4N` | 25번째 `B` 한 글자 |

**두 축에서 각각 1건씩 재현됐다** — 24자 접두 절단(자동복구됨)과는 다른 유형이고, 드물지만
계속 난다. 증상도 다르다: 접두 절단은 `[복구]` 가 찍히고 조용히 넘어가지만, 이 유형은
**누락 1 + 환각 1 이 짝으로** 나타난다.

```bash
# 누락/환각이 짝으로 나오면 가운데 누락을 의심한다 — 같은 배치 안에서 내용으로 대조
python3 -c "
import json,glob
for f in glob.glob('<배치폴더>/*.json'):
    for p in json.load(open(f,encoding='utf-8')).get('products',[]):
        if p['productId']=='<누락id>': print(f, p.get('상품명'), p.get('대표옵션명'))"
```

상품명·대표옵션명이 결과 파일의 판정 사유와 맞으면 **결과 파일의 id 만 고치고 다시 commit**
한다(재팬아웃 불필요, 비용 0). 실측 2건 다 같은 배치 안이었다.
