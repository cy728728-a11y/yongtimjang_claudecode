## 1. 이 스킬이 하는 일

네이버 검색광고 **8계정**을 한 번에 훑어서 규칙대로 분류하고, 그중 두 가지(입찰 인상·꺼진 소재 삭제)는 실제로 실행한다.

### 1-1. 판정 규칙 (⑦ 체계, 2026-10-16 확정)

| 규칙 | 조건 | 결과 | 실행 여부 |
|---|---|---|---|
| **⑦a (=①) 노출0** | 7일 노출 0 (게재중·검수대기 제외) | 입찰 **+10원** | ✅ 자동 실행 (`bids --commit`) |
| **⑦b 썸네일 변형** | 7일 노출 ≥ 50인 게재중 소재(**전 계정 1풀**) 중 CTR **하위 10%** | 썸네일 바꿀 리스트 | 리스트만 |
| **⑦c 상세 꾸미기** | 같은 풀 CTR **상위 10%** 중 상세가 미가공(중국어 원본·단순번역)인 것 | 상세 작업 리스트 | 리스트만 |
| **⑦d 정비 점검** | 30일 클릭 ≥ 20 전체 | 상세·옵션명 정비 상태 표시 (둘 다 OK면 `정비완료`) | 리스트만 |
| **③ 원인분석** | 30일 클릭 20+ 인데 구매완료 0 | 원인 볼 리스트 | 리스트만 |
| **⑤ 효자 확정** | 30일 구매완료 발생 | 효자 상품 | 리스트만 |
| **⑥ 꺼진 소재** | `enable=false` 중 `AD_ABNORMAL_INTERLOCK`(연동끊김)만 | **삭제** (백업 먼저) | ✅ 자동 실행 (`prune --commit`) |

- 기준값 50 · 10% · 20은 `scripts/ads_rules.py`의 상수 `POP_IMP_MIN` · `CTR_TAIL_PCT` · `MAINT_CLICK_MIN` 한 곳에만 있다.
- **연동끊김은 고장이 아니다.** 물갈이(20일 주기 삭제→재업로드)를 하면 옛 상품 소재가 죽은 채 남는다. 매주 수백~천 건 나오는 게 정상이다 (10-19 회차에서 1,284건 삭제).

### 1-2. 숫자 함정 3가지 (맥미니에서도 똑같다)

1. `/stats`의 `convAmt`·`ccnt`는 **장바구니가 섞인 값**이다. 매출로 쓰면 14배 부풀어 보인다. 구매완료는 `AD_CONVERSION` 리포트의 `purchase`만 쓴다.
2. `salesAmt`는 **광고비**다. 매출이 아니다.
3. 그룹 입찰 상품은 **그룹 기본입찰가에서** 올린다. 쓰이지 않던 `bidAmt`에서 올리면 오히려 내려간다.

보고서에는 구매완료 기준 숫자만 싣는다. `장바구니`·`총전환` 단어가 보고서에 나오면 버그다.

## 2. 월요일 자동 실행 흐름

`scripts/weekly_monday.py`가 같은 run-dir(오늘 날짜)로 아래를 차례로 돌린다.

```
prep → run → enrich → apply --sheet <원장> → bids --commit → prune --commit → 업무판 1행
```

| 단계 | 하는 일 | 쓰기 | 쓰는 비밀 | 제한시간 |
|---|---|---|---|---|
| `prep` | 8계정 광고 데이터 수집 | 없음 | `naver-ads.json` | 3600초 |
| `run` | 규칙 판정 → `result.json` | 없음 | — | 1800초 |
| `enrich` | ⑦c/⑦d 후보를 커머스API·불사자로 조회해 판매자상품코드, 상세·옵션 상태를 붙인다 | 없음 (읽기) | `naver-commerce*.json`, `~/.claude.json`(불사자) | 1800초 |
| `apply` | 구글시트 원장 6개 탭에 append + `report.md` | 시트 | gws 로그인 | 1800초 |
| `bids --commit` | 노출0 소재 입찰 +10원 (계정별 백업 `before_bids_<계정>.json` 먼저) | **광고 API** | `naver-ads.json` | **1800초 ← 부족 (§7)** |
| `prune --commit` | 연동끊김 소재 삭제 (백업 먼저) | **광고 API** | `naver-ads.json` | 1800초 |
| 업무판 | 업무판 `오늘` 탭에 결과 한 줄 | 시트 | gws 로그인 | — |

### 실패 정책
- **prep/run 실패** → 뒤 단계 전부 건너뜀.
- **bids/prune은 prep·run 성공에만 의존한다.** enrich·apply·업무판이 실패해도 입찰 인상과 삭제는 돈다 (불사자·시트 장애가 광고 정리를 막지 않게).
- bids가 실패해도 prune은 돈다.
- 실패한 단계는 업무판 메모 앞에 `실패: <단계>`로 찍힌다. 체크(✓)는 전 단계 성공일 때만 붙는다.

### 산출물 위치
```
~/python_work/data/naver-ads/
├── runs/<YYYY-MM-DD>/
│   ├── weekly.log            ← 단계별 전체 출력. 문제 생기면 여기부터
│   ├── weekly_result.json    ← steps = {단계: 종료코드 | "skipped"}, memo, board.status
│   ├── result.json           ← 판정 결과 (웹앱 관제탑도 이걸 읽는다)
│   ├── report.md             ← 사람이 볼 보고서
│   ├── bids_commit.json · before_bids_<계정>.json
│   ├── prune_commit.json
│   └── bulsaja_cache/        ← enrich 조회 캐시
├── ledger/<계정>.json         ← 입찰 인상 이력 (누적, 1.1MB)
├── paused-backup/             ← 삭제한 소재 백업
└── logs/
```
종료코드 `124` = 제한시간 초과다.

### 4-9. 예약관리자 설치
예약은 **`eroom_scheduler.py`가 1분마다 깨서 할 때 된 작업을 띄우는 방식**이다. 맥북에서 정시 예약(StartCalendarInterval)이 안 터져서 이렇게 바꿨다 (2026-10-17).
```bash
WS="$(pwd)"
mkdir -p "$HOME/python_work/data/scheduler/logs"
sed -e "s#__WORKSPACE__#$WS#g" -e "s#__HOME__#$HOME#g" \
  .claude/lib/launchd/com.eroom.scheduler.plist > "$HOME/Library/LaunchAgents/com.eroom.scheduler.plist"
plutil -lint "$HOME/Library/LaunchAgents/com.eroom.scheduler.plist"
launchctl bootstrap gui/$(id -u) "$HOME/Library/LaunchAgents/com.eroom.scheduler.plist"
```
- 상태: `launchctl print gui/$(id -u)/com.eroom.scheduler`
- 로그: `~/python_work/data/scheduler/logs/scheduler.{out,err}.log`, 작업별 `<작업>.log`
- 해제: `launchctl bootout gui/$(id -u)/com.eroom.scheduler`
- 맥이 잠들어 07:00을 놓치면 깨어난 첫 틱에 따라잡는다 (같은 날 1회).

> ⚠️ **예약관리자는 광고만 돌리지 않는다.** `JOBS` 표에 있는 건 전부 돈다:
> `sold-lock`(매일 00:01) · `board-rollover`(04:30) · `board-sync`(매시) · `ads-weekly`(월 07:00) · `auto-watch`(07:30)
> 맥미니에 설치하면 이 다섯 개가 다 맥미니에서도 돈다. → §6

### 4-10. 맥미니 전원 설정
- **시스템 설정 → 에너지**: "디스플레이가 꺼져 있을 때 자동으로 잠자기 방지" 켜기, "정전 후 자동 시작" 켜기

- 작업 자체는 `caffeinate -i`로 감싸져 있어서 도는 동안에는 잠들지 않는다

## 5. 수동으로 돌릴 때

```bash
P=.venv/bin/python3
S=.claude/skills/naver-ads-weekly/scripts/run_ads.py

$P $S prep                       # 수집 (쓰기 0)
$P $S run                        # 판정
$P $S enrich                     # 불사자 연결 (읽기)
$P $S apply --sheet <시트ID>      # 시트 + report.md (--sheet 빼면 md만)

$P $S bids                       # dry-run: 뭘 올릴지만
$P $S bids --commit              # 실제 인상
$P $S prune --commit             # 꺼진 소재 삭제

$P $S bids --revert              # 되돌리기 미리보기
$P $S bids --revert --commit     # 실제 되돌리기
```
공통 옵션: `--run-dir <이름>`(기본 오늘 날짜) · `--account <alias...>`(기본 전 계정)

## 6. ⚠️ 이중 실행 막기 (맥미니 켜기 전에 반드시)

`.claude/lib/eroom_scheduler.py`의 `JOBS` 표는 **git으로 공유된다.** 지금 구조에는 "이 작업은 이 기계에서만" 같은 구분이 **없다.**
맥북과 맥미니 둘 다 예약관리자가 켜져 있으면:

| 작업 | 둘 다 돌면 |
|---|---|
| `ads-weekly` | **입찰 +10원이 두 번 → +20원.** 삭제는 두 번째가 헛돎 |
| `sold-lock` | 잠금 두 번 (대부분 무해하지만 API 낭비) |
| `board-sync`·`board-rollover` | 업무판 동기화 충돌 가능 |
| `auto-watch` | 카톡 알림 두 번 |

**선택지 (추천 순):**

1. **추천: 맥북의 예약관리자를 끈다.** 맥미니가 상시 켜져 있는 기계니 자동작업을 전부 맥미니로 옮긴다.
   ```bash
   # 맥북에서
   launchctl bootout gui/$(id -u)/com.eroom.scheduler
   ```
   단, 카톡 인증·불사자 연결 같은 auto-watch 점검 대상도 맥미니 기준으로 다시 세팅해야 한다.
2. **기계별로 나눈다.** `JOBS`에 `"host": "mac-mini"` 같은 칸을 넣고 `eroom_scheduler.py`가 자기 호스트 작업만 돌게 고친다. 광고만 맥미니로 보내고 나머지는 맥북에 남길 때 필요하다. (코드 수정 필요, 아직 없음)

어느 쪽이든 **맥미니에서 첫 실전 월요일 전에** 정한다.

## 8. 문제 생겼을 때

| 증상 | 볼 곳 / 조치 |
|---|---|
| 월요일에 아무것도 안 돎 | `launchctl print gui/$(id -u)/com.eroom.scheduler` → 로드됐나. `~/python_work/data/scheduler/state.json` → 마지막 실행 키. 맥미니가 로그인 화면에 멈춰 있지 않나 |
| `bids: 124` / `prune: 124` | 제한시간 초과 → §7 |
| apply·업무판만 실패 | gws 인증 만료(7일) → `gws auth login`. 안 되면 `token_cache.json` 삭제 |
| ⑦c/⑦d 전부 `미매칭: 불사자미매칭` | 불사자 계정이 `부킹`인지, `~/.claude.json`의 `mcpServers.bulsaja` 토큰이 살아있는지 |
| `미매칭: 커머스조회실패` | `~/.eroom/naver-commerce*.json` 복사됐는지, 권한 600인지 |
| 불사자 403 | 불사자 앞단 방화벽이 Python-urllib UA를 막는다. UA 헤더를 바꿔야 한다 (이미 처리된 코드면 토큰 만료 쪽) |
| 연동끊김이 갑자기 수천 건 | 정상. 물갈이를 크게 돌린 직후다 |
| 잘못 올렸다 | `bids --revert --run-dir <회차>` (dry-run 먼저) → `--commit` |
| 잘못 지웠다 | `paused-backup/paused_<계정>_<날짜>_weekly-<날짜>.json`에 원본 있음 |

## 9. 사람 몫으로 남는 것

1. **쇼핑 소재 넣기.** 물갈이 재업로드 뒤 광고 UI에서 미투입 상품을 선택해 넣는다 (한 번에 1000개는 에러, 500개씩). 스마트스토어 상품번호를 nvMid로 바꿀 API가 없어서 자동화가 막혀 있다.
2. **⑦b·⑦c·⑦d 리스트 처리.** 썸네일 변형·상세 꾸미기·옵션명 정비는 각 스킬(bulsaja-thumbnail, bulsaja-detail-page, bulsaja-option-cleanup)로 따로 돌린다. 광고 스킬은 리스트만 만든다.
3. **7일마다 gws 재로그인.** auto-watch 카톡 알림이 오면 한다.
4. **새 광고 계정 추가.** 광고플랫폼 → 도구 → API 사용 관리에서 키 3종 발급 → `~/.eroom/naver-ads.json` `accounts` 배열에 블록 추가 (맥미니 파일에 직접). 붙인 직후 `prep && run` 결과를 한 번 훑는다.
