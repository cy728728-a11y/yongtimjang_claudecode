### 왜 그대로 있었나

2026-08-17 에 MCP `renameGroups` 가 생겨 축 저장이 가능해졌다. 그런데 **`apply --commit`
이 저장하는 축은 그 run 에 든 상품뿐**이다. 원장에 쌓인 축은 전부 **옵션이 이미 `완료`
인 상품**의 것이라 현황판 `pending` 에 안 잡힌다 — 축 필드가 없던 시절에 판정만 해둔
것이기 때문이다.

**그래서 저장부만 고쳤을 때 이 backlog 는 출구가 없었다.** 옵션을 아무리 다시 돌려도
대상에 안 들어온다. 그렇다고 700건을 통째로 재작업할 이유도 없다 — 바뀌는 건 축 표기
하나고 무엇을 파느냐는 이미 정해져 있다.

`axis` 서브커맨드가 **그 유일한 출구**다.

```bash
python .claude/skills/bulsaja-option-cleanup/scripts/run_options.py axis --sheet <시트>            # 미리보기
python .claude/skills/bulsaja-option-cleanup/scripts/run_options.py axis --sheet <시트> --commit   # 저장 + 원장 갱신
```

### ★ `product_detail` 은 휴지통 상품도 반환한다 — 삭제 확인에 쓰지 마라

그렇게 답한다). `upload_tasks` 의 `삭제후처리` 목록에 안 잡히는 것도 정상이다 —
마켓 삭제가 성공한 건은 후처리 큐를 안 탄다.
