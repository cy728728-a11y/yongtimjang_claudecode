## 2. 이번에 새로 확인한 함정

### ① `pgrep -f "run_thumbs.py prep"` 은 **남의 zsh 껍데기까지 잡는다**
실제 파이썬은 22:13에 끝났는데 다른 세션의 대기 셸이 같은 문자열을 달고 살아 있어서
내 대기 루프가 40분을 헛돌았다. 앞 인계문서 §0③가 경고한 그 함정에 그대로 걸렸다.

```bash
pgrep -f "bin/python.*run_thumbs.py"   # ← 이렇게 파이썬만 좁혀라
```

### ② `run_all.py --sheet` 는 **서브커맨드 앞**에 와야 한다 (전역 옵션)
`run_all.py prep --sheet <id>` → `unrecognized arguments`. `run_all.py --sheet <id> prep` 이 맞다.
`run_options.py` 는 반대로 서브커맨드 뒤에 붙는다. 스킬마다 다르니 `--help` 를 먼저 본다.

### ③ 하네스 백그라운드 Bash 는 **오래 못 산다**
조회 루프가 92청크(644건)에서 죽었다. 몇 시간짜리는 `nohup … & disown` 으로 **세션에서
분리**해 띄워라. `--resume` 이 있으니 죽어도 손실은 없지만 끊기는 것 자체가 시간 낭비다.

### ④ 상품명 `fix-r9` 는 **재팬아웃보다 먼저, 그리고 매 회차마다**
이번 실측: 106건 → (재팬아웃) → 35건 → (r2) → 6건 = **총 147건을 공짜로 교정**했다.
R9 단독 실패는 결정론적이라 기계가 정확히 고친다. 재팬아웃 전에 반드시 한 번 돌린다.

### ⑤ 상품명 워커는 산출물 이름을 **`draft_NNN.json` 과 `named_NNN.json` 둘 다** 쓴다
pending 계산할 때 한쪽만 세면 완료된 배치를 다시 돌린다(83건으로 잘못 셌다가 31건이 정답이었다).
`glob(named/*.json)` 으로 **둘 다** 세라.

### ⑥ 옵션 저장실패의 원인이 하나 더 있다 — **기존 이름끼리의 중복**
앞 인계문서는 "실패 원인은 사실상 이름 하나뿐(워커가 지은 이름)"이라 적었는데, 이번에
**워커가 손도 안 댄 기존 옵션명끼리 겹쳐서** 저장이 거부되는 건이 나왔다.

```
U01KN93G2Y3AA797ECH6D2Z2WXA  이름 변경 1건뿐인데 "겹치는 이름 16가지, 관련 옵션 35개"
  → 워커 메모: "중복은 모두 제외행끼리라 저장 영향 없음"  ← 틀렸다. 서버는 전 옵션을 본다
```

**→ 스킬 개선 과제**: `run_options.py` 가 **제외행 포함 전 옵션**의 이름 중복을 강제 해소해야 한다.
팬아웃을 다시 돌려도 안 풀린다(실제로 r2에서 같은 3건이 같은 에러로 또 실패).

옵션 커밋이 만든 `재작업(상품명: 기본형 부착)` 46건, 상품명 빈칸 108건.
B를 먼저 하면 상당수가 같이 풀리니 **B 다음에 한 바퀴로 돌리는 게 싸다.**

### D. 옵션축 409건 — 앱에서 수동 (MCP 불가)

저장을 막지는 않는다.

### E. 썸네일 1,415건 — 크레딧 큰 지출
직전 실측 270장 ≈ 1,350크레딧. **착수 전 예상 크레딧 보고 + 용팀장 승인 필수**(썸네일 스킬 규약).

### F. 시트에만 있고 그룹엔 없는 235건
