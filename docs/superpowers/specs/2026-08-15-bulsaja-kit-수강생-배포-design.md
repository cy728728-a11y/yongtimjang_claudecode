## 1. 배경

용팀장의 개인 워크스페이스에서 운영 중인 두 스킬을 강의 수강생에게 배포한다.

| 스킬 | 현 위치 | 규모 |
|---|---|---|
| `bulsaja-thumbnail` | `.claude/skills/bulsaja-thumbnail` (main) | SKILL.md 515줄 + 스크립트 약 3,000줄 |
| `bulsaja-shipping-fee` | worktree `shipfee-skill-install` 브랜치 (main 미병합) | SKILL.md + 스크립트 약 2,200줄 |

두 스킬 모두 용팀장 개인 환경에 깊이 결합되어 있어 그대로 복사해서는 수강생 PC에서 동작하지 않는다.

### 확인된 개인 결합

| 결합 | 내용 |
|---|---|
| `.claude/lib/eroomlib/` | 스킬 폴더 **밖**의 공유 라이브러리 13개 모듈. 같이 배포하지 않으면 import 실패 |
| `.claude/skills/_shared/` | `스킬-계약.md`, `불사자-안전규칙.md` — SKILL.md가 상대경로로 참조 |
| 구글시트 현황판 | 그룹 시트 `00_진행` 탭. **썸네일 스킬의 작업 대상 선정 자체가 이 시트 쿼리** |
| 구글시트 원장 | 그룹 시트 `썸네일` / `배송비` 탭 기록 |
| `gws` CLI + OAuth | 시트 접근 전제. OAuth 앱이 테스트 모드라 7일마다 만료 |
| 오픈차이나 ID/PW | `.env`의 `OPENCHINA_ID` / `OPENCHINA_PW`, 형제 스킬 `bdz-openchina-order-excel` 재사용 |
| `.claude/workflows/thumb-fanout.js` | 팬아웃. 스킬 폴더 밖 |
| 인명 표기 | SKILL.md·코드 주석 전반에 "이룸님" |

## 2. 목표 / 비목표

### 목표

- 수강생이 **자기 PC에서 두 스킬을 그대로 사용**할 수 있게 한다
- 설치는 **Claude Code 명령 2줄**로 끝난다
- 용팀장 개인정보(오픈차이나 계정)·개인 인프라(구글시트·gws)가 배포판에 **일절 남지 않는다**
- 스킬의 **판정 품질은 원본과 동일**하다 (기준·프롬프트·로직 변경 없음)
- 원본 스킬이 나중에 수정돼도 배포판에 옮기는 비용이 낮다

### 비목표 (이번 범위 밖)

- 팬아웃(동시 병렬 처리) 지원
- 다른 스킬(카테고리 교정·상품명·옵션정리 등) 배포
- 수강생별 사용량·과금 추적
- 수강생 결과물의 중앙 수집

## 4. 핵심 설계 — 어댑터 교체

### 문제

`run_thumbs.py` 한 파일에만 시트·현황판 호출이 **38군데**다. 이를 하나씩 제거하면 배포판 코드가 원본과 완전히 갈라져, 원본 수정 때마다 수작업 이식이 발생한다.

### 해결

스크립트는 시트를 직접 호출하지 않는다. 전부 `eroomlib`를 경유한다. 의존 방향을 확인한 결과:

```
run_thumbs.py / run_shipfee.py
        │
        ├─→ eroomlib.matrix    ─┐
        │                       ├─→ eroomlib.gsheets ─→ gws CLI ─→ 구글시트
        ├─→ eroomlib.gsheets   ─┘
        │
        ├─→ eroomlib.snapshot  ─→ 불사자 MCP   (로컬 파일 기반, 교체 불필요)
        └─→ eroomlib.bulsaja   ─→ 불사자 MCP   (교체 불필요)
```

**`matrix.py`는 시트를 직접 호출하지 않는다.** `gsheets`의 `ensure_tab` / `sheets_get` / `sheets_update` / `_run_gws` 만 쓴다.

따라서 **`gsheets.py` 한 모듈을 로컬 JSON 저장소 백엔드로 교체하면, `matrix.py`와 두 스킬의 스크립트 본문은 사실상 그대로 둘 수 있다.**

### 교체 대상

**`gsheets.py` → `localstore` 백엔드** (동일 시그니처 유지)

| 함수 | 배포판 동작 |
|---|---|
| `sheets_get(id, rng)` | 로컬 JSON에서 해당 탭·범위의 2차원 배열 반환 |
| `sheets_update(id, rng, values)` | 로컬 JSON의 해당 범위 갱신 |
| `sheets_batch_update(id, data)` | 위를 순차 적용 |
| `append_rows(id, tab, rows)` | 해당 탭 끝에 행 추가 |
| `ensure_tab(id, tab, header)` | 탭 없으면 헤더와 함께 생성 |
| `chunk_by_size(rows, budget)` | 원본 그대로 (분할 로직, I/O 없음) |
| `_run_gws(...)` | 배포판에서는 호출되지 않도록 `matrix._insert_header_row`만 로컬 구현으로 대체 |

`id`는 스프레드시트 ID 대신 **로컬 저장소 경로**를 받는다. 호출부는 문자열을 그대로 넘기므로 변경 불필요.

저장 형식: `{"탭이름": [[셀, 셀, ...], ...]}` 형태의 단일 JSON 파일. A1 표기 범위 파싱(`'탭'!A2:B200`, `A2:A`)을 지원한다.

**`matrix.index_groups()` 만 예외적으로 수정**한다. 원본은 마스터 인덱스 시트에서 `그룹명 → 스프레드시트ID`를 읽는데, 배포판은 마스터 시트가 없다. 배포판은 `그룹명 → <runs_root>/<그룹명>/board.json` 으로 해석하고, 없으면 생성한다.

### 이 설계의 이점

- 스크립트 본문 38군데를 건드리지 않는다
- 판정 로직·프롬프트·크레딧 계산이 원본과 **바이트 단위로 동일**해 품질 차이가 생기지 않는다
- 원본 스킬 수정 시 스크립트 파일만 복사하면 된다

| "이룸님" 표기, 형 전용 경로 | 전수 검색 후 제거 |

**대상 선정 대체 로직**

```
수강생이 마켓그룹명 지정
  → bulsaja_market_groups 로 groupId 해석 (기존 matrix._group_products 재사용)
  → 그룹 상품 전체 조회
  → 대표이미지 URL 검사
       cdn.bulsaja.com  → 이미 가공됨 → board.json 에 "완료" 기록, 스킵
       그 외            → 작업 대상
  → 이미 가공됨 + 대표옵션 이미지 있음 → 정합검사 대상 (원본 규칙 유지)
```

`board.json` 은 원본 현황판과 **같은 스키마**(`상품id`, `상품`, 작업 9열)를 유지한다. `matrix.py` 를 그대로 쓰기 위함이다.

**유지 (변경 없음)**

기준적격 판정 · 배경 생성 레시피 · 정합검사 · 검수→재작업 루프(2회 불합격 시 원본대체) · 실행 전 예상 크레딧 보고 · 불사자 자동 반영 · 정밀모드 · `review.html` 생성

**요율표 외부화** — `config/shipfee.ini`

```ini
[요율]
기본요금 = 5500      ; 0.5kg 기준
추가요금 = 750       ; 0.5kg 당
; ↑ 오픈차이나 결제내역 60건 실측 (2026-08)
;   다른 배대지를 쓴다면 이 두 줄만 고치면 된다

[포장비]
파손위험_낮음 = 1.05
파손위험_중간 = 1.19
파손위험_높음 = 1.42
```

형식은 `ini` 로 한다. 파이썬 표준 `configparser` 로 읽으므로 파이썬 버전을 가리지 않는다. (`toml` 은 `tomllib` 이 3.11+ 에서만 제공되어 맥 기본 파이썬 3.9에서 실패한다.)

`shipfee_rules.py` 의 하드코딩 상수를 이 파일에서 읽도록 바꾼다. 파일이 없으면 현재 값을 기본값으로 사용해 동작이 바뀌지 않게 한다.

**경동비 취급**

원본에서 경동비는 불사자에 저장할 필드가 없어 시트 전용 값이었다. 배포판에서는 `shipfee.html` 에만 표시하고, "참고용 — 직접 판단해서 사용" 문구를 함께 출력한다.

**유지 (변경 없음)**

무게·부피 판정 워커 프롬프트 · 요율 계산 · 파손위험별 포장비 · 세변합 160cm 경동 판정 · 불사자 해외배송비 자동 저장

## 10. 검증 절차

배포 전에 반드시 수행한다.

1. **단위 테스트** — 원본 테스트(`test_thumb_rules.py`, `test_shipfee_rules.py` 등)가 배포판에서 그대로 통과하는지 확인. 이 테스트들은 불사자·시트 없이 도는 순수 로직 테스트다
2. **로컬 저장소 테스트** — 새로 만드는 `gsheets` 로컬 백엔드에 대한 테스트 작성 (범위 파싱, 탭 생성, append, 갱신)
3. **설치 리허설** — 깨끗한 디렉터리에서 수강생 입장으로 `/plugin marketplace add` → `/plugin install` → `"설치 점검해줘"` → 실제 마켓그룹 소량(3~5건) 작업까지 완주
4. **결과 대조** — 같은 상품에 대해 원본 스킬과 배포판의 판정 결과가 일치하는지 표본 확인

3번을 생략하면 강의 당일 현장에서 실패한다.

---

## 11. 강의 운영 메모

- 실습은 **한 번에 20~30건**으로 지시한다. 팬아웃이 없어 대량 작업은 시간이 걸린다
- 경동비는 상품에 저장되지 않는다는 점을 설명한다
- 배송비 요율은 오픈차이나 기준이며, 다른 배대지를 쓰는 수강생은 `config/shipfee.ini` 두 줄을 고치면 된다고 안내한다
