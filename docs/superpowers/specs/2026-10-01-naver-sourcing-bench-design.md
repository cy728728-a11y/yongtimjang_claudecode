# 네이버 사입 소싱 벤치마크 (naver-sourcing-bench) — 설계

- 작성일: 2026-10-01
- 상태: 설계 승인됨 → 구현 계획 대기

## 1. 목적과 성공 기준

**목적**: 중국 사입으로 국내 판매할 상품을 찾기 위해, 네이버 쇼핑에서 "리뷰가 검증된 세부 카테고리 → 키워드 → 벤치마크 상품" 을 골라 구글 시트 1장에 정리한다.

**성공 기준**: 2026-10-08 까지 `후보` 탭에 벤치마크 상품 20행이 채워지고, 각 행의 수식 열(12~14, 17~20)이 수동 입력값을 넣는 즉시 계산된다.

### 사용자가 말한 것
- 탐색: 대 → 중 → 소 → 세부 카테고리. 세부 카테고리 중 **리뷰 1000개 이상 상품이 여러 개**인 곳 우선.
- 키워드 하나 선정 → 그 키워드로 네이버 쇼핑 재검색 → 상위 판매 상품 중 **리뷰 500+ · 판매가 1만 원 이상** = 벤치마크.
- 자동화 범위: 네이버 쇼핑 검색 + 시트 정리. 1688 은 수동.
- 180일 판매수량도 사용자가 보고 직접 입력.
- 네이버 접근 경로: Aside 브라우저 (aside-category 와 같은 경로).
- 카테고리 스캔 범위: 사용자가 대/중카테고리를 지정.

### 가정 (승인됨)
- 매출·마진 계산 기준 판매가 = **대표 옵션(최저가) 판매가**.
- 시트는 여러 회차에 걸쳐 쌓이는 **누적 시트**.
- 산식 열은 값이 아니라 **시트 수식**.

## 2. 흐름

| 단계 | 주체 | 내용 | 산출 |
|---|---|---|---|
| ① scan | 스크립트 | 지정 대/중카테고리 하위 세부 카테고리마다 리뷰 많은 순 상위 40개를 읽어 리뷰 1000+ 상품 수를 센다 | `카테고리스캔` 탭 |
| ② 키워드 선정 | 사용자 | 스캔 탭에서 세부 카테고리를 골라 키워드 1개 기입. 참고값으로 불사자 검색량·경쟁도 표시 | `카테고리스캔` 탭 `키워드` 열 |
| ③ bench | 스크립트 | 키워드 재검색 → 상위 결과 중 리뷰 500+ · 판매가 ≥ 10,000원 필터 → 1~10열 채움 | `후보` 탭 행 추가 |
| ④ 수동 입력 | 사용자 | 11(180일 판매량), 15(1688 링크), 16(1688 위안 가격) | 수식 열 자동 계산 |

## 3. 시트 구조

### `카테고리스캔` 탭
`스캔일 | 대 | 중 | 소 | 세부 | 카테고리코드 | 리뷰1000+ 상품수 | 상위 상품명 3개 | 키워드(사용자) | 검색량(참고) | 경쟁도(참고) | 상태`
— 리뷰1000+ 상품수 내림차순 정렬.

### `후보` 탭 (20열)
| # | 열 | 채움 |
|---|---|---|
| 1~4 | 대/중/소/세부 카테고리 | 자동 |
| 5 | 키워드 | 자동(②에서 받은 값) |
| 6 | 마켓명 | 자동 |
| 7 | 상품 URL | 자동 (중복 키) |
| 8 | 상품명 | 자동 |
| 9 | 옵션 개수 | 자동 (실패 시 수동) |
| 10 | 각 옵션 가격 | 자동, `옵션명:가격 / …` 한 셀 (실패 시 수동) |
| 11 | 180일 판매 수량 | **수동** |
| 12 | 일 예상 판매량 | `=K/180` |
| 13 | 일 예상 매출 | `=L*대표판매가` |
| 14 | 월 예상 매출 | `=M*30` |
| 15 | 1688 이미지 검색 링크 | **수동** |
| 16 | 1688 위안 가격 | **수동** |
| 17 | 원화 환산 | `=P*210` |
| 18 | 추정 국내 원가 | `=Q*1.4` |
| 19 | 1개당 예상 마진 | `=대표판매가-R` |
| 20 | 월 예상 마진 | `=L*30*S` |

- 대표판매가(최저 옵션가)는 21번 보조 열 `대표판매가` 에 자동 기입하고 수식이 참조한다.
- 보조 열 22 `수집일`, 23 `리뷰수` 도 둔다 (필터 근거 보존).
- 수식은 행 추가 시 그 행에 함께 기입한다. 수동 칸이 비면 수식 결과는 빈칸(`IF(K="","",…)`).

## 4. 구성 요소

- **새 스킬 `.claude/skills/naver-sourcing-bench/`**
  - `scripts/sourcing_bench.py` — 서브커맨드 `scan`, `bench`. 한국어 주석, try-except.
  - Aside 구동은 `aside-category` 의 `driver.js`·대기/휴식 옵션(`--sleep`, `--sleep-max`, `--rest-every`, `--rest-secs`)·캡챠 정착 대기 로직을 재사용 (복제 대신 공용 모듈로 뽑을 수 있으면 `_shared/` 로).
  - 카테고리 목록: `naver-category-master` 마스터 파일에서 지정 경로 하위 세부(리프) 카테고리 조회.
  - 참고 지표: 불사자 `keyword_search` (검색량·경쟁도). 실패해도 스캔은 계속.
  - 시트 기록: `gws sheets` CLI.
- **입력 예**
  - `sourcing_bench.py scan --category "생활/건강>수납/정리" --sheet <ID>`
  - `sourcing_bench.py bench --keyword "압축봉" --sheet <ID>` 또는 `--from-scan` (스캔 탭에서 키워드가 채워지고 bench 미실행인 행 일괄)

## 5. 오류 처리

- 캡챠: 정착 대기 → 여전히 캡챠면 `captcha-relay` 로 넘김.
- 파싱 실패: 해당 행 `상태=실패(사유)` 기록 후 다음 건 진행.
- `--resume`: 로컬 체크포인트(JSON)에서 완료 건 건너뜀. 시트에는 URL 중복 시 추가하지 않음.
- 옵션 상세 수집 실패: 9·10열 빈칸 + `상태=옵션수동`. 나머지는 정상 기록.

## 6. 미확정 → 구현 1단계 실측으로 확정

1. 네이버 쇼핑 검색/카테고리 결과(`shoppingResult`)에 **리뷰수·카테고리 4단·mallName·가격**이 모두 있는가.
2. 카테고리 페이지를 **리뷰 많은 순** 정렬로 열 수 있는가 (URL 파라미터).
3. 스마트스토어 상세에서 **옵션 목록·옵션가**를 Aside 로 읽을 수 있는가. 불가 시 9·10열 수동으로 확정.
4. "상위 판매 상품" 의 범위: 기본 = 키워드 검색 **랭킹순 상위 40개** 중 필터 통과분 (광고 제외).

## 7. 검증

- 실제 키워드 1개로 scan → bench 끝까지 실행.
- 시트 값 5건을 네이버 화면 값과 대조 (리뷰수·가격·카테고리) — 네이버 화면 확인은 사용자 브라우저에서 사용자가 직접.
- 수식 열: 11·16에 임의값 입력 → 12~14·17~20 계산 확인.

## 8. 범위 밖

- 1688 이미지 검색 자동화, 180일 판매량 자동 추정, 불사자 수집 연동.
