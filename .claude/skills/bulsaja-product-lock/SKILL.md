# 불사자 상품 잠금 처리

용팀장님이 상품코드(판매자상품코드/불사자코드)를 주면, 판매된 상품이 실수로 삭제되지 않도록 **잠금 처리**한다.

> **핵심 매핑**: 불사자 화면의 "잠금" 토글 = MCP의 `bulsaja_product_hide` (숨김 처리)로 동일하게 동작한다. 즉 **잠금 = 숨김(hide=true)**, **잠금 해제 = 숨김 해제(hide=false)**. (2026-07 검증 완료)

## 3원칙 (반드시 준수)

1. **조회 안 되는 코드** → 건드리지 않고 스킵 (삭제된 상품·타계정·오타 등)
2. **이미 잠금(숨김)된 상품** → 그대로 둠 (다시 처리하지 않음)
3. **잠금 안 된(공개) 상품** → 잠금(숨김) 처리

## 실행 순서

1. **조회**: 받은 코드 전부를 `bulsaja_product_find_by_code`로 검색 (한 번에 최대 50개)
   - 결과의 `못찾은코드` = 조회 안 된 코드 → 스킵
   - 각 항목의 `숨김` 값 확인: `true`면 이미 잠금, `false`면 잠금 필요
2. **필터**: `숨김:false`인 상품의 `productId`만 모음
3. **잠금 처리**: `bulsaja_product_hide`에 `hide:true`로 호출
   - 첫 호출은 `confirmationToken` 반환 → 같은 인자에 `confirm:true` + 받은 토큰으로 재호출
   - 한 번에 최대 50개
4. **보고**: 아래 형식으로 결과 정리

## 결과 보고 형식

표로 구분해서 보여준다:
- ✅ 새로 잠금 처리한 상품 (상품명)
- 이미 잠금됨 → 유지 (상품명)
- ⚠️ 조회 안 됨 → 스킵 (코드)

마지막에 한 줄 요약: `새로 잠금 N개 / 기존 잠금 유지 N개 / 조회 안 됨 N개`

## 주의

- 50개 초과 코드를 받으면 50개씩 나눠서 조회·처리한다.
- 셀러에게 표시할 때는 100% 한국어만 사용하고 내부 ID·코드·필드명을 노출하지 않는다.
- 잠금 해제(숨김 해제) 요청 시에는 `hide:false`로 동일 흐름을 태운다.
