# 불사자 안전 규칙

> 헤르메스 14(셀러 운영 허브)에서 흡수. 특정 스킬 하나가 아니라 **불사자를 다루는 모든
> 스킬**에 적용되는 공통 안전선이다. 스킬별 세부 규칙(계약·판단 로직)은 각 SKILL.md.

## 통신

- 불사자 응답은 자연스러운 한국어로만 전달한다. 내부 ID·필드명·도구명·확인키·원시 출력을
  그대로 노출하지 않는다(각 MCP 도구가 자체 `표시규칙`을 내려주면 그걸 최우선으로 따른다).
- 파괴적·유료·마켓 영향 작업(삭제·업로드·크레딧 소모·가격/배송 변경)은 대상을 한국어로
  보여주고 명시적으로 확인받는다.
  **단, `_shared/스킬-계약.md` §반영은 기본 자동이다(2026-08-06)를 따르는 스킬 흐름 안에서는
  이 확인이 종합보고(사후 전수 목록·크레딧 사용량)로 대체된다** — 스킬 SKILL.md 에 날짜와
  함께 명시된 자동화가 이 조항보다 우선한다(선례: bulsaja-thumbnail 생성 무승인 2026-08-06,
  product-name 실물불명 자동 삭제 2026-08-05). 스킬 흐름 밖의 단발 MCP 호출은 종전대로
  확인받는다.
- **이미 동의한 작업에 확인키(confirmationToken)가 돌아오면 되묻지 않고 즉시 재제출한다**
  — 이건 같은 작업의 2단계 확인이지, 새로운 승인 요청이 아니다.

## 연결·역할 확인

'연결돼 있지?'류 질문에 이전 세션 기억으로 답하지 않고 **실시간 호출**로 검증한다.
계정 **정체**(누구 계정인가)와 **역할**(소유자/관리자/직원 여부)은 다른 문제 — 닉네임·
이메일·플랜·보이는 그룹 수는 역할을 증명하지 않는다. 역할이 명시되지 않으면 "연결된
계정"만 보고하고 역할은 모른다고 말한다.

세션 MCP 연결은 **시작 시점 토큰**을 물고 있고 스크립트는 `~/.claude.json` 을 **매번 새로 읽는다.**
중간에 토큰이 바뀌면 **MCP 호출은 되는데 스크립트만 전건 실패**한다.
전건이 같은 사유로 실패하면 상품 문제가 아니라 계정을 의심하라.

## 요청 범위를 스킬 이름 밖으로 넓히지 않는다

"소싱해줘"는 표준 수집만 승인한 것이다 — 미리보기 → 그룹 확정 → 수집 → 중복 처리 →
결과 보고. **후속 가공(썸네일 생성·이미지 번역·상품명 리네임·AI 상세·상태 변경)과
마켓 게시는 별도 요청 없이 포함되지 않는다.** 마찬가지로 카테고리 저장은 여러 마켓에
동시 반영되는 쓰기다 — 요청 마켓 하나만 맞다고 전체를 커밋하지 않는다.

## 마켓 액션 전 확인

업로드·수정·삭제 전에 그룹 상세를 조회해 대상 마켓이 실제 연결 목록에 있는지 확인한다
(그룹 존재 ≠ 업로드 가능). 미연결이면 임의로 다른 마켓으로 바꾸지 않고 사유를 보고한다.
제출 후에는 진행 조회로 **접수와 실제 완료를 구분**한다 — "완료" 플래그는 작업 종료일
뿐 성공을 뜻하지 않는다. 썸네일·상세 생성은 status 값과 **생성 이미지 수(1장 이상)**로만
성공을 판정한다(이 스킬의 자동반영 방어가 바로 이 원칙의 적용 사례다).

## 검증 체크리스트 (보고 전 전부 확인)

① 실시간 호출로 검증했나(기억에 의존 안 함)
② 수집·생성 전 미리보기를 거쳤나
③ 확인키 자동 재제출은 이미 명시 요청된 작업에만 했나
④ 유료·마켓 영향 작업은 별도 동의를 받았나 — 또는 자동화 스킬 흐름이면 종합보고에 실었나
⑤ **쓰기 후 재조회로 검증했나** (성공 응답만 믿지 않는다 — `bulsaja-option-cleanup`의
   "확인 안 하고 저장 완료라 보고할 뻔했다" 사례 참조)
⑥ 실패·부분성공이면 보존·복원 경로를 남기고 실제 수치를 그대로 공개했나(부풀리지 않음)
⑦ 내부 식별자를 노출하지 않았나
⑧ 요청 범위 경계를 지켰나(위 §요청 범위)

## 실패는 감추지 않고 보존한다

쓰기가 실패하거나 부분 성공이면: 성공한 것처럼 보고하지 않는다, 실패 전 상태로 되돌릴
수 있는 백업을 남긴다(`before_*.json` 패턴), 실제 성공/실패 건수를 정확히 말한다.
`bulsaja-thumbnail`의 `before_generate.json`·`restore` 명령, `bulsaja-option-cleanup`의
`before_commit.json`·`restore` 명령이 이 원칙의 구현이다.
