# 네이버 사입 소싱 벤치마크

설계: `docs/superpowers/specs/2026-10-01-naver-sourcing-bench-design.md`
실측 기록: `evidence/probe-2026-10.md`

## 0. 시작 전 — 반드시 사용자에게 로그인 요청

작업 시작 시 가장 먼저 이렇게 말하고 답을 기다린다:

> Aside 브라우저에서 네이버에 직접 로그인해 줘. 로그인돼 있으면 캡챠가 덜 걸린다. 끝나면 알려줘.

아이디·비밀번호는 묻지도 받지도 않는다. 답을 받으면 `login-check` 로 확인한다(종료코드 3 = 아직 미로그인 → 같은 요청 반복).

## 1. 명령

```bash
PY=.venv/bin/python; S=.claude/skills/naver-sourcing-bench/scripts/sourcing_bench.py
$PY $S init --title "사입 소싱 후보"            # 최초 1회. 시트 URL 출력, ID 는 runs/config.json
$PY $S login-check
$PY $S scan --category "생활/건강>수납/정리용품"  # 대·대>중·…, 리프를 주면 그 하나만
$PY $S bench --from-scan                         # 스캔 탭에 키워드 적힌 행 일괄
$PY $S bench --keyword "바지걸이"                 # 키워드 하나 (옵션 자동 수집)
$PY $S bench --keyword "바지걸이" --no-options    # 옵션 수집 없이 빠르게 (9열 옵션수동, 원산지 전부 미확인)
$PY $S bench --keyword "바지걸이" --no-expand     # 스토어 확장 끄기 (원 후보만)
$PY $S options --keyword "바지걸이"               # 기존 후보 행에 옵션 채우기, 15조합 초과 행 삭제
$PY $S expand --keyword "바지걸이" --dry-run      # 기존 행 스토어 확장 소급 — 먼저 규모만 본다(시트 불변)
$PY $S expand --keyword "바지걸이"                # 기존 행 스토어 확장 소급 (시트 끝에 블록 append)
$PY $S expand --all                              # 전 키워드 소급 (--no-options 가능)
$PY $S origin --all --dry-run                    # 기존 행 원산지 리포트만 (중국/제외/미확인, 시트 불변)
$PY $S origin --keyword "바지걸이"                # 사용자 확인 후: 미확인 병기 + 중국 아닌 행 삭제
$PY $S annotate --row 3 --volume 12000 --competition 낮음
```

옵션: `--sleep 3 --sleep-max 9`(기본). 카테고리 경로는 네이버 마스터 표기(`생활/건강 > 수납/정리용품 > 옷걸이 > 바지걸이`)를 쓴다 — 모르면 `naver-category-master` 의 `lookup.py --leaf` 로 찾는다.
종료코드: 1 시트/Aside 실패 · 2 입력오류(없는 카테고리) · 3 로그인 필요 · 4 캡챠/차단 중단(같은 명령 재실행 = 이어서).

## 2. 흐름

1. 로그인 요청 → `login-check`
2. 사용자가 준 대/중카테고리로 `scan` → 시트 `카테고리스캔` 탭 링크와 리뷰1000+ 상위 카테고리 5개를 보고
3. 사용자가 `키워드` 열을 채우면, 각 키워드를 불사자 `bulsaja_keyword_search` 로 조회해 검색량·경쟁도를 `annotate` 로 기입
4. `bench --from-scan` → `후보` 탭 행 수 보고
5. 사용자에게 수동 칸 안내: **10 180일 판매수량, 14 1688 링크, 15 1688 위안가격**. 9열(옵션 개수)은 자동이고, 상태가 `옵션수동` 인 행만 손으로 채운다. 11~13·16~21 은 수식이라 손대지 않는다(20 쿠팡포함 월 예상마진=월마진×2, 21 쿠팡포함 월 투자금=국내원가×30일 판매량×2).

## 3. 알아둘 것

- **옵션 개수(9열)는 상세페이지 화면에서 자동 수집한다** (2026-10-02 재실측 — API 는 막혀 있고 옵션 드롭다운을 펼쳐 읽는다):
  - 9열 = 조합 수(품절 포함). 옵션별 가격 열은 2026-10-07 사용자 요청으로 삭제 — 옵션가는 대표판매가(최저 옵션가) 계산에만 쓴다.
  - 옵션 없는 단품 → 9열 `1`.
  - **옵션 조합 15개 초과 = 소싱 대상 아님** → `bench` 는 후보에 넣지 않고, `options` 는 이미 있는 행을 삭제한다(수식은 행 상대참조라 안 깨진다).
  - 못 읽음·표준그룹상품(색상 버튼형) → 9열 빈칸 + 상태 `옵션수동`. 이 행만 손으로 채운다.
  - 상품당 단품 3~4초, 2축 ~10초, 3축 30~50초.
- 계산 기준 판매가 = U열 `대표판매가` = 옵션 최저가(옵션을 못 읽으면 검색 최저가). 다르면 U열을 고친다 — 수식이 따라간다.
- **제외 마켓**: `rules.EXCLUDED_MALLS`(마켓명 부분일치, 현재 `한샘`)는 후보에 넣지 않는다. 사용자가 "X몰 빼"라고 하면 여기 추가하고 시트의 기존 행도 지운다.
- **가격비교(카탈로그) 묶음 상품은 후보에 넣지 않는다** (2026-10-07 지시). URL `/catalog/<id>`, 마켓명 `가격비교(N개몰)` — 여러 몰 합산이라 한 판매자 실적이 아니다.
- **원산지 = 중국만** (2026-10-08 지시, 원 후보·스토어확장 모두):
  - 원산지는 상세 상단 '상품정보' 칸(`원산지 | 중국산(…)`)에서 옵션 수집과 같은 방문에 읽는다. 서버 상태(PRELOADED)에는 없다.
  - `중국`/`China`/`CN`(영문 단어) 포함 → 통과. 국산·다른 국가 → 후보에서 뺀다(그 상품 스토어도 확장하지 않는다).
  - 못 읽음·`상세설명에 표시`·`기타` 처럼 국가가 없는 문구 → 빼지 않고 상태에 `원산지미확인` 병기(예 `옵션수동·원산지미확인`).
  - `--no-options` 면 상세를 안 열어 원산지를 모른다 → 전부 `원산지미확인`.
  - 후보 탭 `원산지` 열(Y)에 상세의 원산지 원문을 적는다(새 행은 bench 가 자동 기입).
  - 기존 행 소급: `origin --all` = 원산지 열 기입만, **행은 지우지 않는다**(2026-10-08 지시 — 중국 아닌 기존 행은 사용자가 원산지 열 보고 직접 판단). `--dry-run` = 리포트만.
- **스토어 확장** (2026-10-08):
  - 후보 행 하나가 올라가면 그 판매자 스토어의 전체상품 리뷰 많은순 1페이지(size=80)를 읽어, bench 와 같은 조건(리뷰 500+·1만원+·가격비교 아님·제외마켓 아님·15조합 이하·원산지 중국·중복 아님)을 만족하는 상품을 원 행 **바로 뒤에** 붙인다. 순서 = 원 상품 → 그 스토어 확장 행들 → 다음 원 상품.
  - 확장 행: 키워드(E) = 원 키워드, 마켓명 = 원 행 마켓명, 카테고리 A~D = 스토어 데이터 `wholeCategoryName`, 상태 `스토어확장` (옵션 실패 `스토어확장·옵션수동`, 원산지 미확인 `…·원산지미확인`).
  - 스토어당 한 실행에 1회만(`--from-scan` 은 키워드 사이에도 공유), 확장 행에서 다시 확장하지 않는다(재귀 없음).
  - 중복은 **상품번호** 기준(`main/products/<id>` = `<slug>/products/<id>`).
  - smartstore·brand.naver.com 둘 다 지원(실측). 단 brand 는 목록이 리뷰순이 아니라 1페이지 80개 안에서만 고른다. 슬러그를 못 구하거나 목록 데이터가 없으면 경고 후 확장만 건너뛴다(원 행은 살린다).
  - 리뷰 500+ 가 많은 스토어는 확장 후보마다 상세를 열어 오래 걸린다(네이쳐리빙 60건). 소급(`expand`)은 `--dry-run` 으로 규모를 먼저 본다.
  - `expand` 는 행 삽입 API 가 없어 시트 **끝에 블록으로** append 한다(수식은 ROW() 상대참조라 위치 무관). 대상 = 상태에 스토어확장 없는 네이버 스토어 행, 마켓명당 1건, 이미 그 마켓 확장 행이 있으면 건너뜀. 원 행 자체의 원산지는 판정하지 않는다(`origin` 몫).
- 중복: 같은 상품(상품번호)은 다시 추가하지 않는다. 재실행해도 안전하다.
- 체크포인트: `runs/scan-*.json`, `runs/bench-*.json`(검색 `page`·상세 `details`·스토어 목록 `stores`), `runs/options-*.json`, `runs/expand-*.json`, `runs/origin-*.json`. 새로 받고 싶으면 그 파일을 지운다.

## 4. 캡챠

종료코드 4 → `captcha-relay` 스킬 또는 사용자가 Aside 창에서 해결 → 같은 명령 재실행.
연속 캡챠면 `--sleep 5 --sleep-max 15` 로 올린다.
