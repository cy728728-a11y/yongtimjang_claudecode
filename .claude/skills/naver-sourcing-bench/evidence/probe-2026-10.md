## 2026-10-02 재실측 — 상세 DOM 으로 옵션 읽기 성공

내장 JSON·API 재호출(위 ❌)은 그대로 막혀 있다. 대신 상세페이지 화면의 옵션 드롭다운을 직접 펼쳐 읽는다.

- `smartstore.naver.com/main/products/<id>` 는 smartstore/brand.naver.com 으로 리다이렉트된다.
- 옵션 섹션 = 리프 텍스트가 `옵션 선택` 으로 시작하는 요소의 부모(최대 5단계 올라가 a/button 을 가진 조상).
- 축 = 섹션 안 `a[role="button"][aria-haspopup="listbox"]` (텍스트 = 축 이름). 목록 = 섹션 안 `ul[role="listbox"] li` (li 안 `a[role="option"]`). 1단 목록은 클릭 전에도 DOM 에 있다. 축 k 의 목록 = 축 k 버튼 뒤·축 k+1 버튼 앞에 있는 listbox.
- 항목 텍스트 예: `5. 찝게형 바지걸이 - 화이트 (+200원)`, `블랙 10+10개`, `블랙 (-8,000원) (품절)`. 추가금은 괄호 안 `(+N원)`/`(-N원)` 만(콤마 가능). 괄호 없는 `10+10개` 는 이름.
- 다단: 앞 축 항목을 클릭해야 다음 축 목록이 열린다 → 앞 축 값마다 (축 버튼 → 항목 클릭 → 다음 축 읽기) 재귀. 3축도 동작 확인. 조합형은 마지막 축에만 금액이 붙는다.
- 단품 = 옵션 섹션 없음 + `수량` 선택만 있음 + `div[role=radiogroup]` 없음 (예 스토리행거 3942331141).
- 표준그룹상품(`div[role=radiogroup]` 색상 버튼 + 수량 티어 텍스트) = 읽기실패 → `옵션수동`.
- 기본 판매가 = 본문 `상품 가격` 다음 첫 `N원`. 검색 대표가·쿠폰 최대할인가와 다를 수 있다 — 계산은 이 값 기준.
- 캡챠 0회 (탐색 6상품 + 라이브 확인 9페이지). 상품당 단품 ~3~4초, 2축 ~9초, 3축 30~50초.
- repl 호출당 ~120초 벽 → 드라이버가 105초 전에 남은 상품을 넘기고 Python 이 다음 호출에 다시 넣는다(라이브에서 3축 2건 후 3번째가 다음 호출로 넘어가는 것 확인).
