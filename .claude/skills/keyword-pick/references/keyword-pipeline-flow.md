# 키워드→상품명 파이프라인 흐름 (이어달리기 계약)

> 상품 하나에서 상품명까지 가는 5단계 파이프라인의 **흐름·배턴 정의서.**
> "매번 다른 스킬"이 아니라 **각 단계가 다음 단계에 넘길 표준 결과물(배턴)** 만 맞추면,
> 어느 지점에서 시작하든("가진 것부터 시작") 같은 흐름으로 이어진다.

## 전체 그림

```
상품 → ①대표키워드 → ②카테고리 → ③키워드 raw → ④키워드 선별 → ⑤상품명
       (bulsaja)     (bulsaja)    (아이템스카우트   (keyword-pick)  (product-name)
                                   /셀러라이프)
```

> **⑤ 구현 완료 (2026-07-23).** 다만 규칙이 아래 표와 달라졌다 —
> **추천키워드 6개→2개, 상품명 후보 3개→1개 확정, term count ≤7→≤6(5 권장)**,
> 진입점도 시트가 아니라 **불사자 마켓그룹**, 종착점은 **실제 rename**이다.
> 확정 규칙은 `product-name/SKILL.md`가 정본.

앞단(①②③)은 **자동화/조회**, 뒷단(④⑤)은 **선별/판단**이다.

## 각 단계 — 담당·입력·출력(배턴)

| 단계 | 담당 스킬/스크립트 | 입력(받는 배턴) | 출력(넘길 배턴) |
|------|-------------------|-----------------|-----------------|
| ① 대표키워드 추출 | 12규칙 프롬프트 `bulsaja-category-fix/references/대표검색어-도출.md`(공유 자산) | 상품명 텍스트(+이미지) | **대표키워드**(문자열, 명사 2~3개) |
| ② 셀하 카테고리 조회 | `sellha-category/scripts/sellha.py`(스킬로 분리됨) | 대표키워드 | **카테고리 경로** `대>중>소>세` + 확신도 |
| ②' 썸네일 비전 보정 | `bulsaja-category-fix` Step 3b (Claude 비전) | 확신도<70% 또는 애매한 상품 | 보정된 대표키워드 → ② 재조회 |
| ③ 키워드 raw (소량) | `itemscout-discover-export` | 카테고리 경로 | **키워드 raw xlsx**(표준 컬럼) |
| ③ 키워드 raw (대량) | `sellerlife-keyword` | (카테고리 통다운 후 필터) | 안전 키워드 xlsx(표준 컬럼) |
| ④ 키워드 6개 선별 | `keyword-pick` (`keyword-filter.py` + 판단) | 키워드 raw xlsx | **추천키워드 6개** → `[01 추천키워드]` |
| ⑤ 상품명 생성 | `product-name` (미구현) | [01] 추천키워드 + 상품 이미지 | 상품명 후보 3개 → `[02 상품명]` |

## 표준 배턴 상세

### ①→② : 대표키워드 (문자열)
- 원문 상품명 통째로가 아니라 **분야 한정어 붙인 2단어 이상**. (예 `농약 분무기`, `금속 연마 폴리셔`)
- 추출 규칙 = `bulsaja-category-fix` SKILL.md Step 3a의 12규칙 프롬프트. 재구현하지 말고 그대로 참조.

### ②→③ : 카테고리 경로 (JSON)
```json
{ "경로": "생활/건강 > 공구 > 원예공구 > 농기계",
  "계층": ["생활/건강","공구","원예공구","농기계"],
  "확신도": "82.4" }
```
- 두 사이트(셀하·아이템스카우트) 모두 **네이버 표준 카테고리** → 같은 트리로 본다.
- 차수 개수는 카테고리마다 다르다(3차 끝 / 4차 존재). **고정 상한 두지 말고 경로 끝까지 시도.**
- **선택 실패 시 얕은 차수로 폴백 금지.** `확인 필요`로 실패차수 + 그 자리의 가능옵션을 함께 보고(아래).

### ③→④ : 키워드 raw xlsx = **표준 중간 포맷(접착제)**
모든 ③ 소스가 이 컬럼으로 수렴하면 ④가 그대로 먹는다:
```
키워드 / 대표 카테고리 / 키워드 분류 / 상품수 / 총 검색수 / 경쟁강도
```
- `keyword-pick/scripts/keyword-filter.py`의 `COLUMN_ALIASES`가 **부분일치**로 이 스키마를 소비한다(별칭으로 소스 차이 흡수, 예 `네이버상품수`→`상품수`). 새 소스가 매핑 가능한 헤더의 xlsx만 내면 어댑터 끝.
- 검색량 컬럼 의미차 주의: 셀러라이프=월간, 아이템스카우트=총. 섞이면 `기준`/`선정근거` 열에 소스 표기.

### ④→⑤ : 추천키워드 6개 = `[01 추천키워드]` 행
13열: `작업일 / 상품명 / 대표키워드 / 카테고리 / 키워드 / 총검색수 / 상품수 / 원본파일링크 / 선정근거 / 기준 / 네이버해외배송비율 / 쿠팡해외배송비율 / 신규진입키워드`
- 뒤 3열은 셀러라이프 소스 전용(아이템스카우트는 빈칸). keyword-filter.py가 헤더 공백/줄바꿈 무시 매칭으로 흡수.
- 상품수 1만↓ 기본, 6개 미만이면 2만↓ 확장(keyword-filter.py 기본값), 그래도 부족하면 유사키워드 최대 10.

### ⑤ 출력 : 상품명 후보 3개 = `[02 상품명]`
- **판단 순서: ① 썸네일에 맞는 상품인가(의미) → ② 조합 제약(산술).** 이미지가 배턴에 있는 이유가 ①이다.
- 추천키워드 6개 → 상품명 후보 3개(후보당 키워드 2개), **term count ≤ 7**, 중복 term 최대 1개·2회.
- 규칙 원본: `keyword-pick/references/키워드&상품명작성에이전트.md` §6~§10 (조합 제약만 담김 — ①은 미기재).
- **설계 판단·미해결 공백: `keyword-pick/references/상품명-설계결정.md`** (판단 순서 / 소싱추천 분리 / 규칙 공백).

### 실패 배턴 : `확인 필요` (③에서 사람에게)
```json
{ "대표키워드":"아세아관리기엔진", "상태":"확인 필요",
  "셀하경로":"생활/건강 > 공구 > 원예공구 > 농기계",
  "선택성공":"생활/건강 > 공구 > 원예공구",
  "실패차수":"4차 '농기계'", "가능옵션":["경운기","관리기","트랙터"] }
```
- `확인 필요`는 다음 단계로 넘기지 않는다. 사람이 카테고리 확정 후 ③부터 다시.

## 진입점 3개 = "어느 배턴을 들고 시작하나"

| 이룸님 요청 | 시작 단계 | 흐름 |
|-------------|-----------|------|
| 불사자 상품ID 주고 상품명까지 | ① | 불사자 MCP로 상품명 확보 → ①②③④⑤ |
| 대표키워드·카테고리 이미 있음, 상품명까지 | ③ | ③④⑤ (①② 스킵) |
| 상품명 텍스트만 주고 키워드까지 | ① | ①②③④ (⑤ 생략) |

새 진입점/새 소스가 생겨도 **어댑터 1개(다운로드→표준 xlsx)** 추가면 되고, 새 저장처가 생겨도 **레시피 1개**(SKILL.md 섹션) 추가면 된다. 조합마다 스킬을 만들지 않는다.

## 관례

- **스크립트 핸드오프**: stdout 마지막에 `###XLSX###`/`###CAT###`/`###RESULT###` 마커 + 다음 줄 값. 스킬 본문(Claude)이 파싱해 다음 단계로 넘긴다.
- **①② 재사용**: 셀하 조회는 `sellha-category` 스킬(CLI), 대표키워드 12규칙은 공유 레퍼런스
  `bulsaja-category-fix/references/대표검색어-도출.md` 를 **참조**한다(복제 아님, 단일 출처).
- **아웃풋**: 스킬 아님. keyword-pick / ⑤ SKILL.md의 레시피(시트 append 기본 / 로컬 xlsx / 콘솔) 중 선택.
