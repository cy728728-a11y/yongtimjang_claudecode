# 키워드→상품명 배치 스킬 설계문서

> ④키워드선별·⑤상품명 단계를 "배치 실행 스킬"로 굳히는 설계 (architect, 2026-07-13).
> 5개 실전 테스트 + 규칙 확정 후 확정된 구조. 구현 착수용 청사진.

> ⚠️ **일부 항목이 `상품명-설계결정.md`(2026-07-19)로 보정됨.** 충돌 시 그 문서가 우선.
> 해당 지점에 인라인 표시함(소싱후보 분리, ⑤ 판단 순서).

## 권장안 (2-스킬 구성)

- **⑤ `product-name` 스킬 신설** + **④ 배치 = `keyword-pick`의 배치 모드로 확장**. 별도 오케스트레이터 스킬은 만들지 않는다.
- 배치 인프라(`run_batch.py`·`sheet_io.py`·`cat_prefilter.py`)는 keyword-pick이 소유. product-name은 §6~§10 규칙·프롬프트·term 검수만 소유하고 배치 인프라를 빌려 씀 (bulsaja가 sellha.py 빌려주는 관례와 동일).
- **상태 저장소 = 출력 시트 그 자체** (02-키워드/03-상품명 탭의 상품id 존재 여부) → 멱등·재개·중복방지가 한 메커니즘.
- 프리필터는 셀러라이프 통다운을 **파일당 1회씩만** 스트리밍 스캔 → 카테고리별 소형 xlsx.

  → **폐기(2026-07-19).** 소싱추천은 별도 작업·별도 시트로 분리. "추천 6개 미달 시 병행" 조건도 폐기. 근거 = `상품명-설계결정.md` §2.
- **상품명(⑤)**: 추천 6개 확보시에만 생성. 후보3, 후보당 키워드2, term count≤7, 중복 term 최대1개·2회. 6개 미달 = 상품명 보류.
  → 보정: 조합 제약 이전에 **썸네일 대조(이 상품이 맞는가)** 가 선행. `상품명-설계결정.md` §1·§3.

## 소스 = 셀러라이프 통다운 ZIP (12개 카테고리)

- ZIP `260712_sellerlife_전체카테고리.zip` 안에 네이버 **전 판매 대분류(면세점 제외)** 12개 xlsx 존재: 가구&인테리어·도서·디지털&가전·생활&건강(+2)·스포츠&레저·식품·여가&생활편의·출산&육아·패션의류·패션잡화·화장품&미용.
- **itemscout 폴백 삭제** — ZIP 하나로 846 사실상 전량 커버. 면세점은 구매대행 대상 아니라 제외.
- 시트명 `all`, 35열, 헤더 줄바꿈(`네이버\n상품수`), 카테고리 컬럼 값이 상품 카테고리와 표기 동일(`생활/건강>공구>전기용품>기타 전기용품`).
- 프리필터는 상품 대분류에 해당하는 카테고리 파일만 ZIP에서 추출(이미 풀린 3개는 재사용). ZIP 해제는 sellerlife `ingest.py`의 cp437→cp949 복구 로직 차용.

## 시트 출력 형식 (확정)

- **02-키워드** 15열: 상품id / 작업일 / 상품명 / 대표키워드 / 카테고리 / **구분(추천\|~~소싱후보~~\|스킵\|결과없음)** / 키워드 / 총검색수 / 상품수 / 선정근거 / 기준 / 원본파일링크 / 네이버해외배송비율 / 쿠팡해외배송비율 / 신규진입키워드
- **03-상품명** 12열: 상품id / 상품명 / 후보번호(1~3 or 보류) / 상품명후보 / 사용키워드1 / 사용키워드2 / term분해 / term count / 중복어 / 확인필요 / 추천도 / 메모
- 위치: 진입점 시트 `1DbR2upLX_DXjgjXpGPdide2SUifli_X6DTqhUTr9Syk`에 탭으로 유지 (이미 생성·5건 반영됨).
- gws CLI append/update/clear, JSON 파싱 시 `2>/dev/null`.

## 마커 행 (A방식 확정)

결과 안 나온 상품도 시트에 흔적을 남겨 재시도 루프 차단:
- 02-키워드: `구분=스킵(통다운밖/면세점)` 또는 `구분=결과없음`(전부 브랜드 등) 1행 (`소싱후보` 값은 폐기 — 위 참조)
- 03-상품명: `후보번호=보류`(추천 6 미달) 1행
- `구분`·`후보번호` 열로 필터해 데이터와 분리 가능.

## Claude vs 스크립트 경계

- 스크립트 = 기계적: 프리필터 스트리밍 / 상품수 필터·계단 태깅 / 정렬 / 시트 append.
- Claude = 판단: 브랜드 제외 / 상품직결 선별 / 선정근거 작성 / 상품명 term 검수.
- **대량(846)에서 Claude엔 후보 요약 JSON만 전달** (카테고리교정 workdata 40KB/건 토큰초과 전례 회피). 청크 = 상품 10개(~15-25KB).
- 위임 = Sonnet 서브에이전트 병렬. 메인(Opus)은 파일럿·표본 검수.

## 계단 확장 = 스크립트 왕복 없이 1패스

스크립트가 3만까지 전 구간을 계단 태그(`상품수 1만 이하`/`2만 이하 확장`/`3만 이하 확장`)와 함께 한 번에 내주고, Claude가 낮은 계단부터 채택하다 6개 차면 멈춤.
- 후보 캡: 1만↓ 전부(최대 15) + 1~2만 상위 10 + 2~3만 상위 10, 각 구간 상품수 오름차순.
- 블랙리스트 프리태깅: sellerlife `제외브랜드`/`제외키워드`로 `브랜드의심` 힌트 부착(판정은 Claude).

## 배치 실행흐름 (run_batch.py 서브커맨드 4개)

```
배치A(④ 키워드):
 1. prep-kw   : 진입점 시트 read → 교정완료&미처리 추출 → targets.json
                cat_prefilter(파일당 1스캔) → prefiltered/ + manifest.json
                batch_candidates → candidates/chunk_*.json (10상품/청크)
 2. [Claude]  : 청크별 Sonnet 선별 → picked/picked_*.json
 3. append-kw : picked 병합·형식검증 → 15열 → 청크단위 gws append
                (append 직전 02탭 A열 재대조 = 이중실행 방어)

배치B(⑤ 상품명):
 4. prep-name : 02탭 read → 상품별 추천 그룹핑 → 추천=6만 names_in/chunk_*.json
 5. [Claude]  : 청크별 후보3 + term분해 → named/named_*.json
 6. append-name: name_check 검증 → 12열 append + 보류 마커
```

- **run_dir**: `D:\python_work\data\keyword-pick\runs\<YYMMDD>\` (대용량 중간산출, git 오염 방지).
- **멱등·재개**: 완료 판정 = 출력 탭 A열 상품id 존재. prep이 미완료분만 자동 수집.
- **원자성**: 청크는 상품 단위 경계, 한 상품 행들은 한 append 호출에. 크래시 손실 = 최대 1청크(10상품).

## 파일 구성

```
.claude/skills/keyword-pick/
├ SKILL.md                  # 기존 + "배치 레시피" 섹션 (단건 흐름 보존)
└ scripts/
  ├ keyword-filter.py        # 기존 유지 — 단건 CLI 래퍼로 (하위호환)
  ├ kwlib.py                 # 신설: COLUMN_ALIASES·find_header_index·to_number·
  │                          #   build_candidates 등 공용 모듈 (하이픈 파일명이라 import 불가 → 추출)
  ├ cat_prefilter.py         # scratchpad→정식 이주 + 멀티카테고리·ZIP추출·manifest·라우팅·캐시
  ├ batch_candidates.py      # 신설: prefiltered→계단태깅·캡·블랙리스트프리태깅→chunk_*.json
  ├ sheet_io.py              # 신설: 시트 read / 완료set / 청크 append(429 백오프).
  │                          #   gws 호출은 bulsaja gws_util.py를 sys.path로 차용
  └ run_batch.py             # 신설: prep-kw / append-kw / prep-name / append-name

.claude/skills/product-name/  # 신설
├ SKILL.md                   # §6~§10 규칙 + 생성 프롬프트 + 단건·배치 레시피
└ scripts/
  └ name_check.py            # term count≤7·중복·후보3·키워드2 산술 검증(term분해는 Claude)
```

## 리스크 요약

- 대용량 스캔(260MB read_only, 파일당 수분): 파일당 1스캔 + manifest 캐시로 재스캔 방지, 백그라운드.
- gws append 쿼터(분당 60): 청크당 1호출(~85회) + sleep + 429 백오프.
- 카테고리 표기 불일치: nows 정규화, 실패 시 자동폴백 없이 `표기불일치의심` 마킹→사람 확인.
- Sonnet 선별 편차: SKILL.md 프롬프트 고정 + 블랙리스트 프리태깅 + 파일럿 검수 후 확대.
