# ⑤ 상품명 설계 결정 기록

> `키워드-상품명-배치설계.md`(2026-07-13, architect) 이후 이룸님과의 탐색에서 확정된 판단.
> 배치설계를 **대체하지 않고 보정**한다. 충돌하는 항목은 이 문서가 우선.
> 출처: thinking-partner 세션, 2026-07-19.

## 1. 판단 순서 — 의미가 먼저, 산술은 프록시

이룸님이 상품명을 지을 때의 실제 우선순위:

1. **썸네일에 맞는 상품인가** (의미 판단)
2. **1페이지에 노출될 수 있는가** (산술 조건)

`상품수 1만 이하`는 **판단 기준이 아니라 ②를 근사하는 프록시**다. 1페이지 노출에 결정적이었던 조건이라 채택된 값이지, 그 자체가 목표가 아니다.

따라서 **"④는 숫자로 뽑고 ⑤는 의미로 판단한다"는 분업은 오독**이다. 의미 판단이 두 단계 모두에서 앞에 온다. 배치설계 43행의 "Claude = 판단: 상품직결 선별"이 ④에도 의미 판단이 있음을 이미 반영하고 있다.

**구현 함의**: ⑤ 프롬프트는 "6개를 조합해 3개를 만들라"가 아니라 "이 상품에 맞는지 먼저 보고, 맞는 것들로 조합하라" 순서여야 한다.

## 2. 소싱추천 키워드는 분리한다 (배치설계 뒤집음)

### 배치설계 현행
- 16행: 소싱후보를 추천 6개 미달 시 병행 수집 (상품당 최대 10행)
- 28행: `02-키워드` 탭 `구분` 열의 값으로 `소싱후보` 동거

### 결정
**분리.** 소싱키워드는 상품id에 매이지 않는 자기 시트를 갖는다.

### 근거

두 작업은 생애주기가 **반대**다:

| | 추천키워드(⑤용) | 소싱추천 키워드 |
|---|---|---|
| 대상 | 이미 소싱해 마켓/불사자에 있는 상품 | 앞으로 소싱을 시작할 씨앗 |
| 방향 | 상품 → 키워드 | 키워드 → 상품 |
| 키 | 상품id에 매임 | 어디에도 안 매임 |
| 수명 | 1회 소비 후 끝 | 계속 남는 재고 |
| 소비자 | ⑤ 상품명 생성 | 미래의 소싱 작업 |
| 판단 | "이 상품에 맞나" | "구매대행에 될 만한가" |

**결정적 이유 — 부산물로 모으면 편향된 샘플만 쌓인다.**
상품명 작업은 이미 소싱한 상품의 카테고리 파일만 연다. 그 김에 줍는 소싱키워드는 필연적으로 *이미 하고 있는 카테고리*의 것뿐이다. 그런데 신규 소싱의 가치는 안 해본 쪽에 있다. 목적은 확장인데 수집 경로가 기존 범위에 갇힌다.

**"같은 파일 여니까 같이 보자"가 절약이 안 되는 이유.**
비싼 단계는 파일 열람이 아니라 셀러라이프 ZIP 통다운로드 1회다. 그건 어차피 공유 자산이라 분리해도 중복 비용이 생기지 않는다. 절약되는 건 파일 여는 비용이고, 잃는 건 탐색 범위다.

**배치 품질.**
한 청크에서 반대 방향 판단을 번갈아 하면 대량 배치에서 흔들린다. 불사자 카테고리 교정 846건이 굴러간 건 판정 기준이 하나로 고정돼 있어서였다.

### 공유/분리 경계

배치설계 9행의 관례("product-name은 규칙만 소유, 인프라는 빌린다")를 그대로 적용:

| 항목 | 공유 | 분리 |
|---|---|---|
| 셀러라이프 ZIP | ✅ | |
| 필터 스크립트 (`keyword-filter.py`, `cat_prefilter.py`, `kwlib.py`) | ✅ | |
| 배치 인프라 (`run_batch.py`, `sheet_io.py`) | ✅ | |
| 판단 기준·프롬프트 | | ✅ |
| 출력 시트 | | ✅ |
| 실행 트리거 | | ✅ |

### 구현 함의
- `02-키워드` 탭 `구분` 열에서 `소싱후보` 값 제거 → `추천 | 스킵 | 결과없음`
- 소싱키워드 전용 시트 신설 (상품id 열 없음). 컬럼·위치 미정
- 배치설계 16행의 "추천 6개 미달 시 병행" 조건 폐기 — 두 작업은 서로의 조건이 아니다

## 3. 규칙 문서가 판단의 절반만 담고 있다

`키워드&상품명작성에이전트.md` §6~§10은 전부 term count(≤7)·중복어로 수렴한다. 즉 상품명을 **조합 제약 문제**로만 다룬다. 통과 여부는 산술로 판정되지만, 좋은지 나쁜지는 판정 대상이 아니다.

한편 `keyword-pipeline-flow.md` 27행상 ⑤의 배턴에는 **상품 이미지**가 포함돼 있는데, §6~§10에는 이미지를 참조하는 조항이 하나도 없다.

**이유가 1번에서 드러난다.** 최우선 기준인 "썸네일에 맞는 상품인가"는 이미지 없이는 판정이 불가능하다. 이미지는 규칙보다 먼저 있었고 문서화만 안 된 것이다. §6~§10은 이룸님 판단의 후반부(조합 제약)만 옮겨 적은 상태다.

**구현 함의**: ⑤ SKILL.md는 §6~§10을 그대로 쓰면 안 되고, 앞에 "썸네일 대조" 단계를 명시해야 한다.

## Open Questions

1. **상품명 규칙 공백** — 글자수/바이트 상한, 키워드 배치 순서(앞쪽 가중치) 같은 네이버 SEO 규칙이 어디에도 정의돼 있지 않다. 현 체계는 전적으로 term count 기반이며 글자수 개념이 없다. ⑤ 구현 전 채워야 함.
2. **피드백 루프 부재** — 만든 상품명이 실제 유입/클릭을 냈는지가 ⑤로 돌아오는 경로가 설계에 없다. 카테고리 교정에는 "네이버 1페이지"라는 외부 정답지가 있었지만 상품명에는 없다.
3. **소싱키워드 시트 스펙** — 컬럼 구성, 시트 위치, 수집 트리거(상품명 작업과 별도로 돌릴지) 미정.

## 정정 사항

계단 확장(1만→2만→3만, 상한 3만)은 **이미 배치설계 15·47~51행에 반영돼 있다.** 탐색 초기에 "고정 문턱 6개"로 잘못 읽었으나 원문 확인 결과 이룸님 동작과 일치한다. 17행의 "6개 미달 = 보류"는 3만까지 열어보고도 미달일 때의 처리다.
