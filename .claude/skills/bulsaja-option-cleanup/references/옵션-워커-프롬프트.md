# 옵션 정리 워커 지시서 (팬아웃용)

> 이 문서 하나 + 배치 파일 경로만으로 **대화 맥락 없이 완주**할 수 있어야 한다.
> `optclean-fanout` Workflow 가 워커에게 이 파일을 Read 하라고 시킨다.
> **판단 규칙 전문은 배치의 `규칙문서`(옵션명-규칙.md)** — 이 문서는 절차만 담는다.

## §0. 도구 규율 (비용 규칙 — 어기면 배치당 토큰이 몇 배가 된다)

| 하지 말 것 | 왜 |
|---|---|
| `Grep`·`Glob` 로 파일 찾기 | 경로는 배치 파일에 전부 실려 있다 |
| 배치 파일·규칙 문서 **재독** | 한 번 읽었으면 컨텍스트에 있다 |
| 중간 요약을 대화에 출력 | 반환은 마지막 한 번. 워커의 말은 아무도 안 읽는다 |
| 불사자 MCP·스크립트 실행(`python` 포함) | 워커의 일이 아니다. 조회·계산·저장은 스크립트 몫 |
| 이미지를 **습관적으로** 열기 | 아래 열람 규율 — 배치의 이미지 수는 **예산 상한이지 열람 목표가 아니다** |

**이미지 열람 규율** — 옵션값 이미지는 원문·이름 텍스트만으로 판단되면 **열지 않는다.**
단 **대표썸네일 1회 열람은 상품마다 의무다**(아래 §2-8, 2026-08-01 이룸님).
옵션값 이미지를 여는 경우는 셋뿐:
1. 원문·이름으로 실물 판별 불가(이 행이 사이즈표인지 본품인지 등) → 그 옵션값 이미지 1회
2. 최저가 동률로 `대표후보` 를 썸네일 유사도로 골라야 할 때 → 동률 옵션 이미지
3. **`재작업사유` 에 `기준이미지없음`·`대표옵션의심` 이 있을 때** → 대표로 세울 옵션의
   이미지가 실물인지 확인(§2-10). **그 사유가 없으면 열지 않는다.**

**Write 는 배치당 정확히 1회** — `results/result_NNN.json` 하나만 쓴다.

## §1. 받는 것

배치 파일(`batches/batch_NNN.json`) 하나가 자기완결형이다.

```json
{"배치": 7,
 "규칙문서": "…/references/옵션명-규칙.md",
 "products": [
   {"productId": "U01KREA81YHN1V3SD217VVMTSHV", "상품명": "…", "원문명": "中文原名…",
    "카테고리": "…",
    "재작업사유": "썸네일: 대표옵션 이미지가 비제품(도면·배너) — 실물 사진이 있는 값으로…",
    "대표썸네일": "D:/…/U01…_rep_0.jpg",
    "vid고유": true,
    "차원": [{"index": 0, "이름": "색상", "원문이름": "颜色",
              "values": [{"vid": 1, "현재이름": "A. 블랙", "원문": "黑色",
                          "제외됨": false, "이미지": "D:/…jpg"}]}],
    "판매행": [{"id": "1949…", "표시명": "A. 블랙", "원문": "黑色",
               "판매가": 12300, "재고": 55, "현재제외": false, "현재대표": false}]}
 ]}
```

먼저 `규칙문서` 를 Read 1회 — §메인상품 선별 + 옵션명 규칙 1~19 전부가 판단 정본이다.

⚠️ **`productId` 는 27자다. 배치 파일에 있는 그대로 한 글자도 빠짐없이 옮겨 적어라.**
줄이거나(`U01KREA81…`), 앞부분만 쓰거나, 기억해서 다시 치지 마라 — 복사해라.
이 문서 안의 `U01…` 같은 줄임 표기는 **설명용이지 값의 형식이 아니다.**
id가 한 글자라도 다르면 감사가 그 상품을 정본에 없는 것으로 보고 **통째로 버린다**
(2026-08-09 용쌤2-1 옵션정리에서 6건이 이렇게 유실됐다).

## §2. 하는 일 — 상품 1건당

1. **메인상품 확정**: 원문명·옵션 원문·판매행을 읽고 "무엇을 파는 상품인가" 한 줄.
   ⚠️ **`현재제외`·`현재대표` 를 근거로 쓰지 마라 — 자주 뒤집혀 있다.**
   실측 7건 중 4건이 부속품이나 다른 제품을 대표로 팔고 있었고, 본품은 전부 판매제외였다
   (롤테이너: 본품 6종 185,900원대가 전부 제외, 선반 부속 87,600이 대표).
   판정은 아래 4개 신호로 직접 한다:
   ① **가격 계단** — 부속은 본품보다 뚜렷하게 싸다. 싼 것만 살아 있으면 뒤집힘을 의심
   ② **원문 접두 한자** — `加`(추가)·`送`(증정)·`单独`(단독)·`专用`(전용)·`适配器`(어댑터)
   ③ **상품명 핵심어 대조** — `양면`·`자동차광`·`스텐`·`3단` 에 해당하는 옵션이 전부
      제외돼 있으면 **그게 본품이고 상태가 뒤집힌 것**이다
   ④ **대표썸네일** — 거기 찍힌 물건이 본품이다(§2-8 에서 어차피 1회 읽는다)
2. **유지/제외 판정**: 규칙문서 §메인상품 선별의 제외 8분류. `유지` 에는 **메인상품인
   판매행 id 전부**를 넣는다 — 1.5배 상한·재고 0 걸러내기는 스크립트가 한다(먼저 빼지 마라).
   ⚠️ **"비싸서" 는 제외 사유가 아니다.** 같은 제품의 **큰 규격**(150cm 벤치 · 3x3m
   크레인 · 270mm 감압지)을 비싸다는 이유로 빼면 사유가 `비상품/메인상품 아님` 으로만
   남아 **왜 안 파는지가 사라진다**(2026-08-14 3-2 실측 — 이 지시가 이미 있었는데도
   9개 상품에서 났다). 값이 얼마든 **같은 물건이면 `유지` 에 넣어라.**
   비싼 건 스크립트가 `1.5배 상한 초과(196,000원 > 127,350원)` 로 빼고 그 숫자를 남긴다.
   → **결과를 쓰기 전에 자기 `제외` 목록을 훑어라.** 사유가 "비상품"인데 이름이 유지분과
   **같은 물건의 다른 치수·용량·톤수**면 그건 `유지` 로 옮길 것이다.
   **"이질 제품이 섞여 있다"는 보류 사유가 아니라 제외 작업 지시다** — 섞인 걸 빼는 게 이 일이다.
   ★ **뒤집힘을 복구했으면**(§2-1 에서 `현재제외` 였던 본품을 `유지` 에 넣었거나 대표를
   부속에서 본품으로 바로잡았으면) `이관` 에 `상품명` 과 `썸네일` **둘 다** 넣는다
   (2026-08-06, 사유: "옵션뒤집힘 복구 — 본품(<이름>) 기준 재작성/재생성 필요") —
   그 상품의 기존 상품명·썸네일은 부속 기준으로 만들어졌을 수 있다.
3. **옵션명 교정**: 중국어 원문 기준, 규칙 1~19. `이름` 키 = **옵션값 vid**(판매행 id 아님).
   `vid고유` 가 false 면(두 차원에 같은 vid) `"@차원index:vid"` 형식으로.
4. **기본형 마커**: 유지 대상 중 **최저가** 옵션 이름 끝에 ` 기본형`(규칙 17).
   복합옵션은 대표 조합에서 **값이 2개 이상인 마지막 차원**의 값에(값 1개 차원은 선택
   항목이 아니다 — 규칙 17 하위 절). 대표가 아닌 옵션엔 절대 금지.
   ※ 상품명이 규격어로 대표를 따로 지정한 상품은 대표가 최저가가 아닐 수 있다(규칙 19).
   그 지정은 `apply` 단계에서야 읽히므로 **너는 그대로 최저가에 붙이면 된다** —
   대표가 옮겨지면 스크립트가 마커도 같이 옮긴다(`retarget_base_suffix`).
5. **대표후보**: 최저가 **동률일 때만** 지정(썸네일과 닮은 쪽). 아니면 생략.
6. **이관**: 옵션 범위 밖 문제(썸네일에 없는 색, 상품명 오표기)는 메모가 아니라
   `이관` 배열에 — `[{"단계": "썸네일", "사유": "…"}]`. 단계 = 현황판 열 이름.

   ★ **상품명으로 되돌릴 세 가지(2026-08-06 이룸님)** — 아래에 걸리면 반드시
   `{"단계": "상품명", "사유": "…"}` 를 넣는다. 상품명은 원장이 따로라 메모로는 절대
   안 닿는다. **보류로 끝나는 상품이어도 이관은 넣는다** — 저장 여부와 무관하게 넘어간다.

   | 신호 | 예 | 사유에 쓸 것 |
   |---|---|---|
   | **스펙·규격이 원문과 다름** | 원문·옵션은 8인치인데 상품명은 '10인치' | 어느 쪽이 맞는지 근거(원문 값)까지 |
   | **대표충돌** — 상품명이 규격어로 지정한 대표가 실물에 없거나 본품이 아님 | 상품명 '3단서빙카트'인데 옵션에 3단이 없다 / 그 규격이 부속 | 지정 규격어 + 옵션에 실제로 있는 값 |
   | **뒤집힘 복구 후 지칭 불일치** | 부속만 팔리던 걸 본품으로 복구 → 상품명이 아직 부속을 가리킨다 | 복구한 본품 이름 |

   상품명이 **아예 딴 품목**이면(옵션 원문 전체가 상품명과 다른 물건) 이관이 아니라
   **`삭제후보`** 다 — 아래 7번.

7. **삭제후보**(2026-08-06 이룸님): 상품명이 가리키는 물건과 옵션 실물이 **아예 다른
   품목**이면 이름을 다시 짓는 게 아니라 **상품을 지운다.** `"삭제후보": "<근거 한 줄>"`
   을 넣는다 — 그 상품은 옵션을 저장하지 않고 `deletion_candidates.json` 으로 빠진다.
   **규격·색·세부 스펙이 다른 정도는 여기 해당하지 않는다**(그건 6번 이관이다).
   품목 자체가 다를 때만 — 상품명은 '차량용 청소기'인데 옵션 원문이 전부 신발 깔창인 식.

   ★ **품목 대조를 반드시 한 번 명시적으로 하라(2026-08-10).** §2-1 에서 정한 `메인상품`
   과 상품명을 나란히 놓고 **"둘이 같은 물건을 부르는 말인가"** 를 묻는다. 상품명은
   키워드 나열이라 그냥 읽으면 "대충 비슷한 분야"로 넘어가기 쉽다 — 2026-08-09 용쌤2-1
   에서 워커가 27건을 잡았는데 나중에 사람이 전수 대조하니 **13건이 더 나왔다.**
   그때 놓친 것들이다. 이 정도 거리는 전부 딴 품목이다:

   | 상품명이 부르는 것 | 실제 옵션 | 왜 놓치기 쉬웠나 |
   |---|---|---|
   | 평판프레스 인쇄기 | 퀵클램프 지그 | 둘 다 '공구' 라 분야가 겹쳐 보인다 |
   | 회전간판 | LED 메뉴 라이트박스 | 둘 다 '매장 사인물' 이다 |
   | 잔반처리대 | 개수대 캐비닛 | 둘 다 '업소 주방 스텐 집기' 다 |
   | 미용실의자 | 벽걸이 거울 | `미용실` 이 겹쳐서 같은 물건처럼 보인다 |
   | 갯벌삽 | 낙양삽(탐침삽) | 둘 다 '삽' 이지만 쓰는 데가 다르다 |
   | 전기톱 | 헤지트리머 | 둘 다 '정원 절단공구' 다 |
   | 스카이어닝 | 파라솔 | 둘 다 '차양' 이다 |
   | 실내자전거 | 사이클 리프트 테이블 | 자전거 주변 물건이긴 하다 |

   기준: **분야가 같다고 같은 품목이 아니다.** 사는 사람이 이걸 받고 "내가 시킨 게
   아닌데" 라고 할 물건이면 딴 품목이다. 헷갈리면 `삭제후보` 대신 6번의
   `{"단계": "상품명", …}` 이관으로 올려라 — 판단을 안 적는 것만은 하지 마라.
8. **축↔값 정합 확인(규칙 18, 2026-08-04 이룸님)**: 각 `차원` 의 `이름`·`원문이름` 이
   그 축 값들이 공유하는 속성 종류를 실제로 가리키는지 본다. 어긋나면 `축교정` 에
   `[{"차원": 0, "제안": "모델", "사유": "값이 전부 모델 구분(高速公路款/铁路款)"}]`.
   **텍스트만으로 판단한다 — 이 확인 때문에 이미지를 추가로 열지 않는다.**
   **네가 낸 제안은 그대로 저장된다**(2026-08-17 MCP `renameGroups` 도입).
   그래도 **값 이름을 축에 맞추려고 비틀지 마라** — 축이 `색상` 이어도 값이 모델이면
   값은 모델 그대로 짓는다. 축은 축대로 고친다.

   ⚠️ **배치의 `축신호` 가 붙은 축은 반드시 한 줄 낸다**(비워두지 마라). 셋 중 하나다:
   - 고칠 이름이 보이면 그 이름
   - **지금 이름이 맞으면** `{"차원": N, "제안": "유지", "사유": "…"}` — 그것도 판정이다
   - 값이 여러 종류로 섞였으면 포괄어(`종류`·`구성`)

   비워두면 코드가 대신 짓는다(`색상별로 정렬하십시오` → `색상`, 못 떼면 `종류`).
   **네가 값을 봤으니 네 이름이 더 낫다** — 코드 폴백은 최후수단이지 기본값이 아니다.
9. **대표↔썸네일 정합 확인(의무, 2026-08-01 이룸님)**: `대표썸네일` 을 **1회 Read** 하고,
   유지 중 최저가(=대표 예정) 옵션과 **같은 물건·같은 색**인지 확인한다.
   ★ **불일치면 방향부터 판정한다(2026-08-06)**: 썸네일·상품명·원문명이 가리키는 **본품이
   대표 예정 옵션이 아니면**(대표가 부속·구성품으로 보이면) 썸네일 이관이 아니라 **§2-1 로
   돌아가 메인상품 판정을 다시 하라** — 부속 오인 신호다(실증: 캠핑박스 상품에서 타공
   걸이판을 본품으로 세워 썸네일 검수가 대표옵션의심으로 반려). 대표가 본품이 맞는데
   썸네일이 딴 물건이면 종전대로 `이관` 에
   `{"단계": "썸네일", "사유": "대표옵션(<이름>)과 썸네일 불일치: <뭐가 다른가>"}`.
   네이버 요구가 "썸네일 = 대표옵션 = 상품명"이라, 이 확인이 빠지면 기작업 썸네일의
   오배치가 영영 안 잡힌다. 대표썸네일 파일이 없으면 확인 불가를 `메모` 에 남긴다.
10. **대표옵션 이미지가 실물인지 확인 — 썸네일에서 되돌아온 건만**(2026-08-07 이룸님).
    `재작업사유` 에 **`기준이미지없음`** 또는 **`대표옵션의심`** 이 있을 때만 한다.
    그 밖의 건은 종전대로 — **이 조항 때문에 이미지를 추가로 열지 마라.**

    썸네일 단계는 대표옵션 이미지를 그대로 기준으로 삼아 배경을 갈아끼운다. 그래서
    **대표옵션 이미지가 제품 사진이 아니면**(치수 도면·텍스트 배너·색상칩·로고 카드)
    거기서 더 못 간다. 옵션명으로는 이걸 알 수 없다 — 실측에서 `1m 원목벤치 월넛 기본형`
    (도면)과 `브러시 단일노즐 기본형`(실물)이 이름만으로는 전혀 구분되지 않았다.
    **이미지를 봐야만 안다.**

    절차 — 값싸게 한다:
    1. 대표로 세울 옵션(§2-4 로 정한 것)의 **`차원[].values[].이미지` 1장만** Read
    2. 제품 실물이면 끝. 그대로 대표로 세운다
    3. 비제품이면 **유지 중 다음 후보**(판매가 오름차순)의 이미지 1장을 본다 — 실물이
       나올 때까지. 대개 1~2장에서 끝난다
    4. 실물 이미지를 가진 옵션이 **하나도 없으면** 대표는 종전 규칙대로 두고 `이관` 에
       `{"단계": "썸네일", "사유": "실물기준없음: 모든 옵션 이미지가 비제품(도면·배너)"}`

    ★ **`실물기준없음` 이라는 낱말을 그대로 넣어라.** 썸네일 `prep` 이 이 낱말을 보고
    그 상품을 대표옵션 기준에서 빼 **후보 이미지에서 고르는 경로**로 보낸다. 안 넣으면
    썸네일이 같은 대표옵션을 또 기준으로 잡아 **둘 사이를 무한히 왕복한다.**
    실물 옵션이 없는 상품은 실재한다(3-2 실측 57건 중 3건이 고유 옵션이미지 1장뿐).

    판정 기준(무엇이 실물이고 무엇이 비제품인가)은 썸네일 쪽 정본이 같다 —
    `bulsaja-thumbnail/references/기준적격-판정기준.md`. **치수선·텍스트가 얹혀 있어도
    제품 사진이면 실물이다.** 순수 도면·색상칩·로고 카드만 비제품이다.

## §3. 쓰는 것 — `results/result_NNN.json` (NNN = 배치번호, 0채움 3자리)

```json
{"배치": 7,
 "products": [
   {"productId": "U01KREA81YHN1V3SD217VVMTSHV",
    "메인상품": "아크릴 3단 사이드테이블 (색상만 다름)",
    "유지": ["19491740168", "19491740169"],
    "제외": [{"id": "3254774", "사유": "맞춤제작 — 실제 수령품 확인 불가"}],
    "이름": {"1": "주황색", "2": "블랙 기본형"},
    "대표후보": "19491740169",
    "축교정": [{"차원": 0, "제안": "모델", "사유": "축은 '색상'인데 값이 전부 모델 구분"}],
    "이관": [{"단계": "상품명", "사유": "상품명 '10인치'인데 원문·옵션은 전부 8인치(8英寸)"}],
    "메모": "6색 동가·동일 치수라 치수를 이름에서 뺌"},

   {"productId": "U01KREA821ZC89N4MXM18WKTWYQ",
    "삭제후보": "상품명은 차량용 청소기인데 옵션 원문 12행이 전부 신발 깔창",
    "메모": "품목 자체가 다르다"},

   {"productId": "U01KKZX8N1SVFTK839HQH0JCWE1", "상태": "보류(옵션구조 판독불가)",
    "메모": "사유 한 줄"}
 ]}
```

- **`productId` 는 배치 파일 값을 그대로 복사한다(27자).** 위 예시 id도 27자다 —
  줄여 쓰면 그 상품이 감사에서 버려진다
- 배치의 **모든 상품이 products 에 있어야 한다.** 하나라도 빠지면 감사가 누락으로 잡아
  그 배치가 재팬아웃된다
- 판단이 불가능한 상품은 `상태: "보류(사유)"` 만 쓴다 — 억지로 찍지 않는다.
  단 **보류는 §2-1 의 4개 신호를 다 돌린 뒤 최후수단이다.** 무엇을 확인할 수 없었는지
  구체적으로 적는다("옵션구조 판독불가" 한 줄은 사유가 아니다)
- `이름` 은 **바꿀 값만** 넣어도 된다(안 바꾸는 값은 생략 가능). 제외되는 행의 이름도 고친다.
  ⚠️ **손대지 않은 기존 이름끼리 충돌해 저장이 거부될 수 있다** — 기계번역 한국어가 25자에서
  잘려 치수가 날아가면 서로 같아진다(`A. 길이 40cm 높이 30cm 두께 20c` = `U. …20c`).
  불사자는 **정렬 접두사와 공백을 뺀** 최종 이름으로 중복을 본다. 그러니 기존 이름이
  잘려 있어 보이면 **그 값들도 원문 기준으로 새로 지어라** — 치수·구성이 고유성을 만든다
- `축교정` 은 **어긋난 축만** 넣는다(멀쩡하면 생략). 비어 있어도 상품 처리는 완료다.
  ⚠️ **네가 낸 `제안` 은 그대로 저장된다** (2026-08-17 — MCP `renameGroups` 도입.
  전에는 시트 원장에 쌓아 사람이 앱에서 반영했다). 그러니 축 이름 규칙을 지켜라:
  **20자 이내 · 한국어 명사 · 중국어 금지 · 정렬/문장 표현 금지**에 더해
  **`, [ ] / { } ( ) * ? \ ^ $ |` 금지**, 그리고 **같은 상품의 다른 축과 이름이
  겹치면 안 된다**(축 둘에 `종류` 를 주면 둘 다 안 바뀐다 — 서로 다른 이름을 줘라)
- ⚠️ **`제외` 는 생략할 수 없다 (2026-08-15).** `유지` 에 넣지 않은 판매행은 **전부**
  `{id, 사유}` 로 적는다. 제외 목록은 유지 여집합으로 계산되니 비워도 결과가 같아 보이지만,
  그러면 **왜 뺐는지가 원장에서 사라져** 표본검수도 사후 재작업도 근거를 잃는다
  (4-1 실측: 워커 51%가 배열을 비웠고, 판매행 2,970행이 `(사유 미기재)` 로 남았다).
  `apply` 가 `[워커준수] 미언급` 으로 **행 단위로 세서** 재실행 대상에 올린다.
- 사유는 **분류 + 근거** 두 토막으로 쓴다 — `분류: 근거`
  분류는 규칙문서 §메인상품 선별의 8분류 낱말을 그대로 쓴다:
  `구매금지안내` · `사이즈표` · `보증금` · `추가금` · `홍보배너` · `부속품단독` ·
  `다른모델` · `불완전구성` · `가격유인`
  근거는 원문·옵션명에서 **확인한 것**만 적는다(추측 금지).
  예) `부속품단독: 원문 '单独顶（无支架）' — 지붕만, 프레임 미포함`
  예) `다른모델: 상품명·대표군은 듀얼모터인데 이 행은 단일모터 18mm`
  분류가 붙어야 `대표충돌` 을 기계로 가릴 수 있다 — `다른모델` 이면 정당한 제외,
  `(사유 미기재)` 면 사람이 본다.
- **1.5배 상한 초과·재고 0 은 적지 마라** — 스크립트가 계산해 붙인다(§2-2와 같은 말이다).
  미리 손으로 빼면 사유가 자동으로 남는 경로가 사라진다.
- ⚠️ **`현재제외`·`현재대표`·재고 정책을 제외 근거로 쓰지 마라**(§2-1과 같은 규칙).
  `현재제외 상태 유지 — 재고 저조` 같은 사유는 **뒤집힘을 못 잡는 경로**라
  `apply` 가 `[워커준수] 상태근거` 로 잡아낸다. 뒤집었다고 쓰는 건 정상이다
  (`홍보배너: 우선발송 안내문 — 기존 현재대표였으나 뒤집힘`).

## §4. 반환 (사람이 아니라 워크플로가 읽는다)

파일을 쓴 뒤, 배치별로 아래 형태의 구조화 결과만 반환한다.

```
{"batch": 7, "done": 4, "held": ["U01KKZX8N1SVFTK839HQH0JCWE1"], "error": ""}
```

- `done` = 계획을 채운 건수, `held` = `보류(…)` 로 남긴 상품id
- 배치 파일을 못 읽었거나 도중에 실패하면 `error` 에 한 줄 — **거짓 성공 금지**

## §5. 실패했을 때

- 이미지 파일이 없다 → 텍스트(원문)만으로 판단. 애매하면 보류
- 원문이 비어 있다 → 표시명으로 판단하되 확신 없으면 보류
- 배치 파일 자체가 안 읽힌다 → `error` 에 사유를 적고 그 배치는 **파일을 쓰지 않는다**
  (파일이 없어야 재팬아웃 대상이 된다)
