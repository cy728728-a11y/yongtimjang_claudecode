# 불사자 옵션 정리

> 매출 직결 스킬이다. **무엇을 팔고 무엇을 내리고 어느 가격을 대표로 세우나**를 바꾼다.
> 공통 규칙(스냅샷·현황판·계약)은 [`_shared/스킬-계약.md`](../_shared/스킬-계약.md).

## 왜 필요한가

수집된 상품의 옵션에는 **파는 물건이 아닌 행**이 섞여 있다 — 구매금지 안내, 사이즈표,
보증금·추가금, 부속품 단독, 다른 모델, "맞춤제작 고객센터 문의". 그대로 올리면
고객이 엉뚱한 걸 주문하고, 대표가격이 왜곡되고, 옵션명이 중국어·접두사로 남는다.

## 흐름

```bash
# ① prep — 현황판에서 대상 확정 → 스냅샷(옵션 포함) → 옵션 이미지 → 배치
python .claude/skills/bulsaja-option-cleanup/scripts/run_options.py prep \
  --group-name "1번_용쌤1-1" --run-dir "D:/python_work/data/option-cleanup/runs/<이름>" [--limit 5]

# ② run — Claude(또는 워커)가 배치를 읽고 판단 → results/result_NNN.json
#    판단할 것: 메인상품이 무엇인가 · 어느 행이 비상품인가 · 이름을 뭐라 지을까
#              · 최저가 동률이면 어느 쪽이 대표 썸네일과 닮았나

# ③ apply — 계산·검증 → 시트 기록 → (승인 후) 저장
python ... run_options.py apply --run-dir <R>            # 미리보기 = 승인 게이트
python ... run_options.py apply --run-dir <R> --commit   # 실제 저장
```

대상 선정은 **현황판 쿼리 1줄**이다(`00_진행` 탭의 `옵션` 열이 빈 상품). 1건이든 1000건이든 같다.
특정 상품만 하려면 `--ids`.

## run 실행 = Workflow 모드 (대량 기본, 2026-08-01)

②(run)를 메인 세션이 직접 돌리지 않는다 — 배치 200개를 순차로 읽으면 컨텍스트 누적
재과금(product-name `팬아웃-비용.md` 모드 B 안티패턴)을 밟는다. 백그라운드 워크플로로 뺀다:

1. `python … run_options.py pending --run-dir <R>` — 남은 배치를 Workflow args JSON 으로 출력
2. `Workflow` 도구를 `{name: "optclean-fanout", args: <출력 그대로>}` 로 호출.
   워커는 `agent(model: sonnet, effort: low)` — 지시서는
   [`references/옵션-워커-프롬프트.md`](references/옵션-워커-프롬프트.md), 판단 정본은
   [`references/옵션명-규칙.md`](references/옵션명-규칙.md) 하나다
3. 완료 반환의 `재팬아웃필요배치` 가 비었는지 확인. 남았으면 `pending` 재계산 후 **1회만** 재호출
4. `apply --run-dir <R>` 미리보기 — **워크플로는 results 생성까지다.** 시트 기록·저장(`--commit`)은
   미리보기 승인 게이트 뒤 메인이 한다. apply 는 감사(배치 대비 누락·환각 대조)를 먼저 찍고,
   누락이 있으면 `--commit` 을 차단한다(`--allow-missing` 은 의도된 부분 처리 전용)

> **동시 서브에이전트 기본 가이드라인(≤15)은 이 팬아웃에 적용하지 않는다** — 워커는
> 디스크에만 쓰고 상호 간섭이 없으며, 상한은 이미지예산(워커당 ≤16장)·상품상한(≤10건)과
> 하네스 동시성 캡이 관리한다. 이 문장이 그 명시적 opt-in 이다.

**재개·멱등**: `results/result_NNN.json` 존재 = 그 배치 완료. 같은 pid 가 두 파일에 오면
apply 가 마지막 파일을 채택한다. **폴백**(소량·워크플로 불가 환경): 메인 또는 Agent 워커가
같은 지시서로 배치를 직접 처리한다 — 워커 1명 = 배치 1~2개.

## 대량 그룹(수백 건)의 저장 — 반드시 지킬 것 (2026-08-04 용쌤2-1에서 학습)

저장은 **상품당 4호출**(이름 저장 → 재조회 → 포함/제외·대표·순서 저장 → 재조회)이라
**분당 10~12건**이 한계다. 700건이면 **1~1.5시간**은 정상이다. 그날 15시간이 걸린 건
느려서가 아니라 아래 3가지 때문이었다 — 다시 밟지 않는다.

| 그날의 사고 | 이제는 |
|---|---|
| 워커가 유지 옵션만 이름을 고쳐, 제외 옵션에 남은 `A. ` 접두사로 **저장이 전량 실패** | `_fill_prefix_names` 가 접두사 남은 값을 자동 정리(코드로 방어) |
| 워커가 productId 뒷자리를 잘라 적어 감사가 `--commit` 을 차단 → 재팬아웃 2회 낭비 | `_repair_truncated_ids` 가 배치 정본과 접두사 대조로 자동 복구 |
| **저장 루프가 죽은 걸 9시간 몰랐다** (분리 프로세스 + 알림 없음) | 아래 두 줄을 반드시 같이 건다 |

**① 재개는 기본이다.** `apply --commit` 은 성공한 상품을 `run-dir/committed.json` 에
건별로 남기고 다음 실행이 건너뛴다. 중단돼도 진도는 산다 — 겁내지 말고 다시 돌린다.

**② 오래 걸리는 저장은 "띄우고 잊기" 금지.** 분리 프로세스로 돌릴 거면 **진도 감시를
같이 건다.** 감시 없이 띄우면 죽은 걸 알 방법이 없다(그날의 최대 손실 = 9시간 공회전).

```bash
# 진도가 목표에 닿으면 알림 1회 — 저장을 띄운 직후 같이 건다
until [ "$(python -c "import json;print(len(json.load(open('<R>/committed.json'))))" \
        2>/dev/null || echo 0)" -ge <목표건수> ]; do sleep 60; done; echo "옵션 저장 완료"
```

**③ 분리 프로세스에 한글 인자를 넘기지 않는다.** PowerShell 로 넘긴 `--group-name
"2번_용쌤2-1"` 이 인코딩이 깨져 시트 조회 0건 → 60회차가 즉시 실패만 반복했다.
**`--sheet <시트id>` 로 넘긴다**(ASCII 라 안전하다).

**④ 시트 기록과 저장을 분리한다.** 미리보기에서 시트·검수표를 이미 썼으면
저장 회차는 `--no-sheet --no-review` 로 돌린다 — 시트 쓰기가 쿼터(429)에 걸려
저장 시작까지 몇 분을 잡아먹는다.

## 결과 파일 형식 (워커가 만드는 것)

```json
{"products": [{
  "productId": "U01...",
  "메인상품": "아크릴 3단 사이드테이블 (색상만 다름)",
  "유지": ["19491740168", "..."],
  "제외": [{"id": "3254774", "사유": "맞춤제작 — 실제 수령품 확인 불가"}],
  "이름": {"19491740168": "주황색", "19491740169": "블랙 기본형"},
  "대표후보": "19491740169",
  "이관": [{"단계": "썸네일", "사유": "대표 썸네일이 검정인데 옵션에 검정 없음"}],
  "메모": "6색 동가·동일 치수라 치수를 이름에서 뺌"
}]}
```

- `유지` = **메인상품인 판매행 id 전부**. 1.5배 상한·재고 0 걸러내기는 스크립트가 한다
  (사유가 자동으로 남는다 — 사람이 미리 빼면 왜 빠졌는지가 사라진다).
- `이름` 키 = **옵션값 vid**(판매행 id 아님). 복합 옵션이면 스크립트가 차원 좌표로 바꿔 쓴다.
  단 **두 차원에 같은 vid 가 있으면 `"@차원:vid"`** 로 줘야 한다(→ 저장은 2단계로 나뉜다 절).
- **최저가 대표옵션 이름 끝에는 ` 기본형`** 을 붙인다(규칙 17). 25자 안에서 흡수하고,
  대표가 아닌 옵션엔 붙이지 않는다. 복합옵션은 대표 조합의 **마지막 선택 항목** 값에.
- `대표후보` = 최저가가 **동률일 때만** 의미가 있다. 더 비싼 걸 지정하면 무시하고 경고한다.
- **`이관` = 옵션 범위 밖에서 발견한 문제를 그 단계에 넘긴다.** 메모에만 적으면 유실된다
  (파일럿 5건 중 3건이 그랬다). `단계` 는 현황판 열 이름(`썸네일`·`상품명`·`상세` …),
  저장 성공한 건만 넘어간다. 자세한 규칙은 [`_shared/스킬-계약.md`](../_shared/스킬-계약.md).

## 판단 규칙

**메인상품 선별** — 제외 8분류(구매금지 안내·사이즈표·보증금 등)와 주의 2줄의 전문은
[`references/옵션명-규칙.md`](references/옵션명-규칙.md) §메인상품 선별 (2026-08-01 이동 — 워커 규칙 정본을 한 파일로).

**옵션명** — 중국어 원문 기준으로 고친다(한국어 표시명은 기계번역이라 틀려 있다).
공백 포함 25자 · 정렬용 접두사(`A. `) 제거 · 군더더기 제거 · 확인된 차별점만 ·
**고유성을 지키는 최단 이름**. 전문은 [`references/옵션명-규칙.md`](references/옵션명-규칙.md).

**대표·판매범위·순서**(스크립트가 계산 — `option_rules.py`)
1. 메인상품이면서 **팔 수 있는**(가격 있고 재고 있는) 행만 후보
2. 최저가가 대표. 동률이면 대표 썸네일과 가장 닮은 것 → 그래도 동률이면 원본 순서
3. **대표가 × 1.5 = 판매 상한**(같은 값 포함). 상한 초과는 판매 제외
4. 판매가 오름차순 = 업로드 순서. **대표는 동가 그룹 안에서 맨 앞**
5. 1.5배 상한은 **메인상품 후보를 확정한 뒤에만** 적용 — 부속품이 섞인 채 계산하면
   기준가가 500원이 되어 본품이 전멸한다

**대표옵션 마커 — 대표 이름 끝에 ` 기본형`** (2026-07-30 이룸님)
네이버는 '대표상품'(추가금 0원 옵션)을 상품명으로 쓰라고 요구한다 → **썸네일 = 대표옵션 =
상품명**이 한 옵션을 지칭해야 한다. 상품명 끝에도 같은 `기본형` 이 붙어(→ `product-name` R8)
**같은 단어가 짝을 지목한다.** 25자는 그대로 — 본문을 줄여 흡수한다.
대표가 아닌 옵션엔 붙이지 않는다. 복합옵션은 **대표 조합의 마지막 선택 항목**에 붙인다.
전문 = [`references/옵션명-규칙.md`](references/옵션명-규칙.md) 규칙 17.
어긋나면 상태가 `보류(기본형)` 이 되어 **저장 전에 멈춘다.**

## 저장은 2단계로 나뉜다

불사자 MCP가 **이름 변경과 순서 변경을 같은 호출에 넣는 것을 거부한다**(쿠팡 기존 옵션
연결 보호). 그래서:

```
① renameValues 만 저장 → 재조회 → 이름 검증(중국어·접두사·25자·중복)
② includeSkuIds / excludeSkuIds + mainSkuId + skuOrder 저장 → 재조회 → 검증 6항목
```

**이름을 바꾸는 대상은 옵션값(차원)이지 판매행이 아니다.** 1차원 상품은 `vid` 로 찍고,
복합 옵션은 `vid` 가 차원마다 1부터 다시 시작하므로 반드시 `groupIndex`/`valueIndex` 로 찍는다
(스냅샷의 `vid고유` 플래그가 이걸 알려준다. vid 로 찍으면 **엉뚱한 차원이 바뀐다**).

> **두 차원에 같은 vid 가 있으면 vid 키를 거부한다**(2026-07-30). 예전엔 첫 차원에 조용히
> 붙어서 2번째 이후 차원 값은 **이름을 바꿀 방법이 아예 없었다.** 그때는 결과 JSON 의
> `이름` 키를 `"@1:1"`(차원 1의 vid 1) 형식으로 준다 — 배치의 옵션 이미지 키와 같은 관례다.

**최종 검증 7항목**(실패하면 '완료'라 하지 않는다): 옵션 수 불변 · 대표 정확히 1개이며
판매 포함 · 포함/제외가 계획과 일치 · 상한 초과가 살아있지 않음 · 판매가 무단 변경 없음 ·
표시명 중복 0 · **`기본형` 이 대표 값 하나에만 붙어 있음**(이름을 바꾼 저장에서만).

## 불사자 저장 ≠ 마켓 반영

`--commit` 은 **불사자 서버의 상품 데이터**만 바꾼다. 이미 마켓에 올라간 상품이면
판매 화면은 그대로다 — **수정 업로드를 따로** 해야 반영된다(별개 작업).
미업로드 상품이면 나중에 올릴 때 정리된 상태로 올라간다(= 정리하기 가장 안전한 타이밍).
업로드 여부는 `workdata` 의 `uploadedSuccessUrl` 이 마켓별로 값을 갖는지로 본다
(dict 자체는 항상 있으니 **값이 전부 null 인지**를 봐야 한다).

## 재개 (committed.json)

`apply --commit` 은 저장 성공한 상품id 를 `run-dir/committed.json` 에 **건별로** 적는다.
다음 실행은 그 상품을 건너뛴다. 정본은 이 파일이 아니라 불사자지만, 재저장은 같은 값을
다시 쓰는 것이라 건너뛰어도 안전하다. **처음부터 다시 돌려야 하면 이 파일을 지운다.**

## 되돌리기

`apply --commit` 은 저장 **직전에** `run-dir/before_commit.json` 을 남긴다.
스냅샷은 저장 성공 시 새 값으로 덮어써지므로 **이 백업이 유일한 원본**이다.

```bash
python ... run_options.py restore --run-dir <R> [--ids U01a U01b]
```

## 기록

- 그룹 시트 `옵션` 탭 — 상품별 메인상품·유지/제외·대표·기준가·상한·순서·상태·`옵션명변경`
  **순서·제외·대표는 id 가 아니라 이름으로 적는다** — `1 > 2 > 13` 은 사람이 승인할 수 없다.
  이미 있는 상품id 는 건너뛰지 않고 **그 행을 갱신**한다(되돌려 다시 돌리면 옛 계획이 남는다).
- `apply` 는 표 아래에 **검수표**(옵션명 기존→교정 · 판매 순서+가격 · 제외 사유)를 찍는다.
  `--no-review` 로 끌 수 있다. 세로 러너 게이트도 같은 내용을 `--emit` JSON 에서 읽어 보여준다.
- 현황판 `00_진행` 의 **`옵션` 열만** 갱신 (`완료` / `보류(사유)`)
- 스냅샷의 `옵션` 필드를 저장 후 값으로 되쓴다 → 다음 스킬이 옛 옵션을 읽지 않는다

## 알려진 함정

| 함정 | 왜 |
|---|---|
| 대표 썸네일에 없는 색이 옵션에 있음(또는 반대) | 썸네일이 재고 이미지일 수 있다. 구조로 매칭하고 **`이관`에 `썸네일`을 넣는다** |
| 치수가 전 옵션 동일 | 이름에서 뺀다. 고유성은 색·구성이 만든다(고유성을 지키는 최단 이름) |
| 기존 한국어 이름끼리 거의 같음 | 원문을 봐야 다름이 보인다(`三腿两层` vs `三腿大两层` → '대형'을 넣어 고유화) |
| 상품명이 원문과 다름(8인치인데 '10인치') | 옵션 범위 밖이다. **`이관`에 `상품명`을 넣어** 넘긴다 |
| 최저가 동률인데 대표후보 미지정 | 원본 순서로 정하고 **경고**한다. 썸네일과 다른 색이 대표가 될 수 있다 |
