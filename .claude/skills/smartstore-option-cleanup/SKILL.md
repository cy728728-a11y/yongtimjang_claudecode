# 스마트스토어 옵션 정리

## 개요

불사자 판매자상품코드 1개를 받아 판매 옵션을 정리하고 대표옵션을 지정하는 전담 절차다.

- INPUT: 불사자 판매자상품코드 1개
- OUTPUT: 정리된 옵션 저장 + 대표옵션 지정 + 이중 뷰(SKU행/옵션값행) 검증 보고

## 계정 라우팅

- "용팀장 계정" → `bulsaja` MCP 서버 / "용쌤 계정"(용쌤계정) → `bulsaja-yongssaem` MCP 서버
- 계정 언급이 없으면 용팀장 계정(`bulsaja`) 기본. 애매하면 확인.

핵심 원칙은 일곱 가지다.

1. 썸네일과 상세페이지를 먼저 보고 실제 메인상품이 무엇인지 확정한다. 저장된 상품명이나 번역된 옵션명만으로 판단하지 않는다.
2. 전체 선택 옵션에서 메인상품으로 실제 판매되는 완전한 구성을 먼저 찾고, 안내문·부속품·다른 모델·불완전 구성은 제거한다.
3. 메인상품 판매군에서 실제 업로드 판매가가 가장 낮은 옵션들을 먼저 추린 뒤, 그중 대표 썸네일의 제품과 색상·형태·구성이 가장 비슷한 옵션을 대표옵션으로 지정한다.
4. 대표옵션 판매가를 기준으로 1.5배 이하인 옵션만 판매 대상으로 유지한다. 메인상품과 무관한 옵션은 가격이 범위 안이어도 유지하지 않는다.
5. 유지 옵션을 판매가 오름차순으로 정렬한 뒤, 마지막에 **현재 정렬 순서로 업로드 순서 적용**을 반드시 실행한다. 화면상 정렬이나 보고로 끝내지 않고 실제 저장까지 완료한다.
6. 옵션명은 고객이 선택할 때 필요한 차이점만 짧게 쓰고 불필요한 설명은 생략한다. 유지 옵션끼리는 이름이 서로 같아서는 안 되며, 색상·용량·크기·구성 등 실제 차이를 추가해 모두 고유하게 만든다.
7. 유지 옵션명은 중국어 원문과 이미지를 대조해 공백 포함 25자 이내의 자연스럽고 깔끔한 한국어로 정리하며, 저장 후 대표·가격범위·순서·이름을 모두 재조회해 확인한다.

## 사용 시점

다음 요청에 사용한다.

- 판매자상품코드를 주며 옵션을 정리해 달라는 요청
- 옵션명이 번역투이거나 길어서 다듬어 달라는 요청
- 대표옵션을 규칙대로 다시 지정해 달라는 요청
- 옵션 정리 결과가 실제로 저장됐는지 검증해 달라는 요청
- 원스텝(smartstore-one-step) 파이프라인의 옵션 정리 단계

다음 작업에는 사용하지 않는다.

- 상품명 작성·수정 작업 (`smartstore-product-name` 사용)
- 옵션 가격이나 판매가를 바꾸는 작업
- 마켓 등록·수정·삭제 등 마켓 반영 작업
- 상품 코드 없이 일반적인 옵션 작명 요령만 묻는 상담
- 상품 삭제나 숨김 처리

## 단계별 절차

### 1단계: 상품·메인상품·현재 옵션 상태 확보

0. **입력이 productId(예 `U01K...`형 내부 ID)면 `bulsaja_product_find_by_code`를 쓰지 않는다** — 이 도구는 셀러가 지정한 "판매자상품코드" 전용이라 productId를 넣으면 못 찾는다("못찾은코드"). productId가 주어졌으면 `bulsaja_product_workdata(productId=...)` 또는 `bulsaja_product_detail(productId=...)`로 바로 조회한다. 입력이 실제 판매자상품코드일 때만 1을 쓴다.
1. `bulsaja_product_find_by_code`로 판매자상품코드에 해당하는 상품을 정확히 찾는다.
2. `bulsaja_product_detail`로 상품명·가격·옵션·이미지·상세 유무를 확인한다.
3. `bulsaja_product_workdata`로 현재 옵션 구조를 두 가지 뷰로 확보한다: SKU행(조합별 포함/제외·판매가·대표 상태·표시 순서)과 옵션값행(차원별 옵션명).
4. 썸네일과 상세페이지를 최우선으로 비교해 반복적으로 강조되고 실제 구매 대상으로 설명되는 제품을 메인상품으로 확정한다. 저장된 상품명이나 기계 번역은 보조 증거로만 쓴다.
5. 소스 옵션 이미지와 중국어 원문을 대조해 각 선택 옵션이 메인상품 완제품, 메인상품의 색상·크기·수량 변형, 세트, 부속품, 다른 모델, 안내문 중 어디에 해당하는지 분류한다.
6. 각 조합의 실제 업로드 판매가를 확보한다. 가격이 누락되거나 불명확하면 대표옵션과 1.5배 상한을 계산하지 말고 먼저 가격 자료를 다시 조회한다.

완료 기준: 메인상품의 시각적·구성적 정의, 현재 저장된 전체 옵션, 각 행의 실제 판매 구성·판매가·현재 대표·현재 표시 순서가 정리된 상태.

### 2단계: 메인상품 판매 옵션 선별과 비상품 제거

썸네일·상세페이지에서 확정한 메인상품과 실제로 일치하는 완전한 판매 구성을 먼저 찾는다. 색상·크기·수량·길이·정상 세트처럼 고객이 선택할 실질적 차이만 메인상품 판매 후보로 둔다.

다음은 메인상품 판매 후보에서 제외한다.

- `구매 금지`, `선택 금지`, `촬영 금지`, `이 항목 주문 금지` 류의 안내 행
- 사이즈표만 보여주는 행
- 보증금·배송비·잔금·추가금 행
- 홍보·이벤트 배너, 커스텀 제작 문의, 경고 카드
- 부속품만 단독 판매하는 행
- 썸네일·상세페이지의 메인상품과 다른 모델·디자인·제품군
- 메인상품이 빠진 불완전 구성
- 실제 수령 제품을 확인할 수 없는 가격 유인용 옵션

이런 행은 체크되어 있어도, 가격이 싸도, 재고가 있어도 절대 유지하거나 대표로 선택하지 않는다. 반대로 메인상품과 일치하는 옵션은 이름이 어색하다는 이유만으로 제외하지 않고 원문·이미지를 대조해 교정 대상으로 둔다.

완료 기준: 메인상품 판매 후보와 제외할 행이 썸네일·상세페이지·원문·옵션 이미지 근거와 함께 분리된 상태.

### 3단계: 옵션명 정리

유지된 행의 한국어 옵션명을 다음 규칙으로 만든다.

1. **원문 기준 교정**: 중국어 원문을 명명의 기준으로 삼고, 어색하거나 틀린 기계 번역은 이미지로 실물을 확인해 바로잡는다.
2. **소스 순서 보존**: 확정된 대표옵션을 맨 앞에 둬야 하는 경우가 아니면 소스(원본) 옵션 순서를 유지한다.
3. **길이 제한**: 모든 옵션명은 **공백 포함 25자 이내**의 한국어로 쓴다. 제시하거나 적용하기 전에 글자 수를 실제로 세어 검증한다.
4. **고객 선택 기준 우선**: 고객 입장에서 옵션 간 차이를 즉시 구분할 수 있도록 색상, 용량, 크기, 길이, 수량, 구성, 방식처럼 실제로 달라지는 항목만 앞세운다.
5. **모든 이름 고유화**: 판매 유지 옵션끼리는 최종 표시명이 서로 같아서는 안 된다. 색상이 같아도 용량이 다르면 `2000mAh 화이트`·`4500mAh 화이트`처럼 최소 차별점을 붙인다. 원문·이미지로 확인되지 않은 차이를 임의로 만들어 중복을 피하지 않는다.
6. **고유성을 지키는 최단 이름**: 다른 옵션과 구분되는 데 필요한 최소 정보만 남긴다. 차이를 만들지 않는 제품명, 장점, 사용 설명, 홍보 문구, 반복 표현은 생략한다.
7. **군더더기 제거**: 조사, 설명문, 반복 단어, 홍보 문구, 창고 코드, 그리고 `형`·`타입`·`제품`·`옵션`·`상품` 같은 일반어는 변형 구분에 꼭 필요하지 않으면 지운다.
8. **치수 압축**: `120×70×90cm` → `120×70×90`, `수조깊이 40cm` → `깊이40`처럼 유용한 범위에서 줄인다.
9. **확인된 차별점만 유지**: 애매한 번역에서 재질, 치수, 호환성, 성능, 구성을 지어내지 않는다.
10. **모델 코드 전파 금지**: 제외한 변형이 다른 모델군이면, 그 모델 코드를 유지된 같은 모델 옵션에 옮겨 붙이지 않는다. 고객 구분에 필요할 때만 예외다.
11. **정렬용 접두사 제거**: 상품을 설명하지 않는 알파벳 정렬 접두사는 지운다. 예: `H. 블랙 수트` → `블랙 상하세트`, `A. S` → `S`, `B. M` → `M`, `C. L` → `L`, `D. XL` → `XL`. 단, 실제 사이즈 표기인 `S`, `M`, `L`, `XL`, `XXL`, `XXXL`은 보존하고, 진짜 모델 코드는 고객에게 필요하다고 확인될 때만 남긴다.
12. **복합 라벨은 차원별로**: 결합된 옵션 라벨은 차원마다 각각 정리한다. 예: `H. 블랙 수트, A. S` → `블랙 상하세트, S`. 어느 차원에도 정렬용 접두사를 남기지 않는다.
13. **깔끔한 한국어 완성**: 유지 옵션은 고객이 한 번에 이해할 수 있는 자연스러운 한국어로 통일한다. 중국어·번역투·불필요한 영어·공장명·창고표시·홍보문구를 제거하되, 실제 모델명·사이즈·단위·색상처럼 구매 구분에 필요한 표기는 보존한다. 같은 제품명을 모든 옵션에 반복하지 말고 옵션 간 차이만 짧고 일관된 형식으로 쓴다.
14. **명명 형식 통일**: 같은 상품군은 `색상 + 구성`, `용량 + 색상`, `모델 + 길이`, `크기 + 수량`처럼 동일한 순서와 표현을 유지한다. 같은 뜻의 단어를 옵션마다 다르게 번역하지 않는다.
15. **제시 형식**: 정리된 옵션값은 최종 판매가 오름차순으로 보여주고, 글자 수 감사표는 판매자가 요청할 때만 붙인다.

완료 기준: 유지된 모든 행에 25자 이내 한국어 옵션명이 있고, 각 이름이 중국어 원문·이미지 근거와 일치하며, 판매 유지 옵션의 최종 표시명이 서로 모두 다른 상태.

### 4단계: 대표옵션·판매범위·업로드 순서 계산

1. 2단계에서 남긴 **메인상품의 완전한 판매 옵션만** 대상으로 실제 업로드 판매가를 비교한다.
2. 판매가가 가장 낮은 옵션들을 먼저 대표 후보로 추린다. 최저가 후보가 여러 개면 대표 썸네일에 보이는 제품과 색상·형태·구성이 가장 비슷한 옵션을 대표로 정한다. 썸네일만으로 구분할 수 없을 때는 상세페이지와 더 직접적으로 일치하는 옵션을 우선하고, 그래도 같으면 원본 순서가 앞선 옵션을 선택한다. 더 비싸다는 이유만으로 썸네일과 비슷한 옵션을 대표로 올리지는 않는다.
3. 대표옵션 가격을 `기준가격`으로 두고 판매 상한을 `기준가격 × 1.5`로 계산한다. 금액 계산은 정확히 수행하고, 상한과 같은 가격은 포함한다.
4. 메인상품 판매 후보 중 실제 업로드 판매가가 상한 이하인 옵션만 유지한다. 상한을 초과한 옵션은 판매 제외한다.
5. 비상품·부속품·다른 모델·불완전 구성은 가격이 상한 이하라도 유지하지 않는다. 반대로 상한 판정은 메인상품 판매 후보를 확정한 뒤에만 적용한다.
6. 유지 옵션을 실제 업로드 판매가 오름차순으로 정렬한다. 가격이 같으면 원본 순서를 유지한다.
7. 대표옵션이 정렬 결과 첫 번째인지 확인한 뒤, 마지막 작업으로 **현재 정렬 순서로 업로드 순서 적용**을 실행한다. 정렬 목록만 제시하거나 화면에만 정렬된 상태로 끝내지 말고, 전체 판매 옵션의 현재 순서를 실제 업로드 순서로 저장한다.
8. 현재 저장된 대표옵션·판매 범위·표시 순서와 새 권장 결과를 비교해 보고한다.

완료 기준: 메인상품 대표옵션 1개, 대표가격, 1.5배 상한, 유지·제외 옵션, 최저가 오름차순 업로드 순서가 모두 확정된 상태.

### 5단계: 쓰기 전 승인 — 사용자 확인 지점

쓰기 전에 반드시 다음을 표로 제시하고 승인을 받는다.

- 현재 저장 상태: 현재 옵션명, 포함/제외, 현재 대표옵션
- 권장 상태: 깔끔한 한국어 옵션명, 제외 권장 행과 사유, 메인상품 대표옵션과 최저 판매가, 대표가격의 1.5배 상한, 판매가 오름차순 업로드 순서

불사자에 저장하는 것과 이미 마켓에 등록된 상품을 갱신하는 것은 별개의 데이터 변경 작업임을 구분해 알린다. 이 스킬의 쓰기 범위는 불사자 저장까지다.

**예외 1 — 원스텝 게이트 1**: 원스텝(`smartstore-one-step`) 오케스트레이터를 경유해 실행될 때는 게이트 1 승인이 이 확인을 갈음한다. 이 경우 같은 내용을 게이트 1 보고서의 옵션표로 제출하고, 별도의 중복 질문은 하지 않는다.

**예외 2 — 포괄 사전 승인**: 용팀장이 옵션 분석안에 대해 "묻지 말고 진행" 형태의 포괄 사전 승인을 부여하고 이를 유지하는 동안에는, 현재 vs 권장 표를 보고로 제시한 뒤 별도 승인 대기 없이 저장을 진행한다. 이 포괄 승인은 불사자 저장(판매 제외·포함, 옵션명 변경)까지만 유효하며, 마켓 등록·수정·삭제에는 절대 적용되지 않으므로 마켓 반영은 반드시 별도 승인을 받는다. 용팀장이 포괄 승인을 철회하면 즉시 원래의 승인 게이트로 복귀한다. **적용 범위**: 이 예외는 이 스킬을 단독 실행할 때만 적용된다. 원스텝 파이프라인 경유 시에는 예외 1이 우선한다 — 원스텝의 "게이트 1 승인 전에는 가공 반영 쓰기 금지" 규칙이 포괄 승인보다 상위이므로, 원스텝 안에서는 포괄 승인이 있어도 게이트 1 승인 전에 저장하지 않는다.

완료 기준: 판매자 승인(또는 게이트 1 승인)이 기록된 상태. 포괄 사전 승인이 유효한 경우에는 현재 vs 권장 표를 보고로 제시한 것이 승인 기록을 갈음한다. 그 외에는 승인 없이 어떤 쓰기도 하지 않는다.

### 6단계: 이름 저장 후 대표·범위·순서 저장

옵션명 변경과 표시 순서 변경은 한 번에 섞지 않고 두 단계로 나눠 저장한다.

1. **옵션명 먼저 저장**: 2차원 옵션은 같은 값 번호가 양쪽 차원에 재사용되는지 검사한다. 번호가 겹치면 번호만으로 이름을 바꾸지 않고 차원을 구분할 수 있는 위치 기준을 사용한다. 유지 옵션의 한국어 이름과 판매 제외·포함 상태를 먼저 저장하고 재조회한다.
2. **이름 검증**: 중국어·정렬용 접두사·번역투가 남지 않았는지, 사이즈·모델·단위가 보존됐는지, 모든 이름이 공백 포함 25자 이내인지 확인한다. 요청한 이름 변경 수와 실제 변경 수가 같은지도 확인한다.
3. **판매범위 적용**: 메인상품이 아닌 옵션과 대표가격의 1.5배를 초과한 옵션을 판매 제외하고, 범위 안의 메인상품 옵션만 판매 포함 상태로 만든다.
4. **대표옵션 직접 지정**: 유지된 메인상품의 최저 판매가 후보들 중 대표 썸네일과 색상·형태·구성이 가장 비슷한 옵션 하나를 대표로 지정한다. 제외된 옵션·안내 행·더 비싼 옵션을 대표로 지정하지 않는다.
5. **현재 정렬 순서 업로드 적용**: 유지 옵션을 판매가 낮은 순으로 정렬하고 같은 가격은 원본 순서를 유지한다. 대표옵션이 첫 번째인지 확인한 다음, 마지막에 `현재 정렬 순서로 업로드 순서 적용` 작업을 반드시 실행해 정렬된 전체 판매 옵션 순서를 실제 업로드 순서로 저장한다. 단순히 낮은 가격순 보기만 적용하고 끝내지 않는다.
6. **분리 실행 원칙**: 옵션명 변경 저장을 완료·검증한 뒤 대표옵션 지정과 순서 저장을 별도 요청으로 실행한다. 이름 변경과 순서 변경을 동시에 요청하지 않는다.
7. **스냅샷과 복원**: 저장 직전 현재 이름·포함 상태·대표·순서를 기록한다. 결과가 권장안과 다르면 추가 마켓 작업을 중단하고 가능한 범위에서 이전 상태로 복원한다.

완료 기준: 한국어 옵션명, 판매 포함 범위, 대표옵션 1개, 최저가 오름차순 업로드 순서가 각각 저장 요청까지 완료된 상태.

### 7단계: 최종 검증

쓰기 후 상품 작업자료를 재조회해 다음을 각각 검증한다.

1. **메인상품 일치**: 대표옵션과 유지 옵션이 썸네일·상세페이지에서 확정한 메인상품과 실제로 일치하는지 확인한다.
2. **대표옵션**: 대표옵션이 정확히 1개이고 판매 포함 상태인지 확인한다. 먼저 메인상품 판매군 중 최저 판매가인지 검증하고, 최저가 후보가 여러 개면 그중 대표 썸네일의 제품과 색상·형태·구성이 가장 비슷한 옵션인지 다시 확인한다.
3. **1.5배 범위**: 대표가격과 상한을 다시 계산해 유지 옵션이 모두 상한 이하인지, 초과 옵션이 모두 제외됐는지 확인한다.
4. **업로드 순서**: 유지 옵션이 판매가 오름차순인지 확인하고, `현재 정렬 순서로 업로드 순서 적용` 실행 결과를 재조회한다. 저장된 실제 업로드 순서가 계획한 전체 옵션 순서와 같은지 비교하며, 같은 가격은 원본 순서를 유지해야 한다. 화면 정렬만 바뀌고 업로드 순서가 저장되지 않았다면 완료로 처리하지 않는다.
5. **옵션명**: 옵션 조합 목록과 옵션값 목록 양쪽에서 깔끔한 한국어 이름이 저장됐는지 확인한다. 중국어·불필요한 영어·정렬용 접두사가 남지 않았고 실제 사이즈·모델·단위는 보존되어야 한다. 판매 유지 옵션의 최종 표시명을 서로 대조해 중복이 하나도 없는지 검사하며, 중복이면 완료 처리하지 않고 확인된 최소 차별점을 추가해 다시 저장한다.
6. **무단 변경 방지**: 옵션 수, 판매가, 재고, 포함 상태가 계획하지 않은 방식으로 바뀌지 않았는지 확인한다.

두 목록은 독립적으로 갱신될 수 있다. 어긋남이 보이면 그대로 명시하고 완료라고 표현하지 않는다. 대표·가격범위·순서·이름이 모두 확인되기 전에는 마켓 갱신을 진행하지 않는다. 검증이 실패하면 저장 전 상태로 복원을 시도하고 불일치를 보고한다.

완료 기준: 메인상품 일치, 대표옵션, 1.5배 판매범위, 최저가 오름차순 업로드 순서, 한국어 옵션명이 모두 재조회 결과와 일치하는 상태.

## 보고 형식

판매자에게는 자연스러운 한국어만 사용한다. 내부 번호, 확인 키, 도구명, 기술 용어는 노출하지 않는다.

승인 요청(5단계) 예시:

```text
용팀장님, 옵션 정리안입니다. 확인 후 승인해 주세요.

| 구분 | 현재 | 권장 | 비고 |
|---|---|---|---|
| 행 1 | H. 블랙 수트, A. S | 블랙 상하세트, S | 접두사 제거 |
| 행 2 | H. 블랙 수트, B. M | 블랙 상하세트, M | 접두사 제거 |
| 행 3 | 배송비 차액 | 제외 | 비상품 행 |
| 행 4 | 사이즈표 참고 | 제외 | 안내 행 |

대표옵션: 현재 없음 → 「블랙 상하세트, S」 권장
대표가격: 29,900원 / 판매 상한: 44,850원
근거: 썸네일·상세페이지의 메인상품과 일치하며, 메인상품 판매군 중 업로드 판매가가 가장 낮습니다.
업로드 순서: 판매가 낮은 순으로 저장합니다.

승인하시면 저장하고, 저장 결과를 다시 조회해 보고드리겠습니다.
```

완료 보고(7단계) 예시:

```text
✅ 옵션 정리를 저장하고 재조회로 확인했습니다.

정리된 한국어 옵션: 6개 (모두 25자 이내)
제외 처리: 2개 (비상품·대표가격 1.5배 초과)
대표옵션: 블랙 상하세트, S (메인상품 최저 판매가)
판매가격 범위: 대표가격 이상, 대표가격의 1.5배 이하
업로드 순서: 판매가 낮은 순

검증 결과: 메인상품 일치, 대표옵션 1개, 판매가격 범위,
업로드 순서, 옵션 조합 목록과 옵션명 목록이 모두 권장안과 일치합니다.

마켓에 이미 등록된 상품의 갱신은 별도 작업입니다. 필요하시면 말씀해 주세요.
```

불일치가 남으면 완료라고 표현하지 않고 어긋난 항목을 그대로 보여준다.

## 흔한 실패와 방지법

1. **비상품 행을 대표로 선택**
   체크 여부·낮은 가격·재고와 무관하게, 안내·보증금·배송비·잔금·문의 행은 대표 후보에서 먼저 제거한다.

2. **메인상품 판별 전에 가격부터 비교**
   전체 옵션의 최저가부터 고르면 부속품·안내·불완전 구성이 대표가 될 수 있다. 반드시 썸네일과 상세페이지로 메인상품을 확정하고, 메인상품의 완전한 판매군 안에서 최저 판매가를 고른다.

3. **1.5배 범위를 전체 옵션에 적용**
   대표가격의 1.5배 이하여도 메인상품과 다른 모델·부속품·비상품이면 유지하지 않는다. 메인상품 판매 후보를 먼저 확정한 뒤 가격 상한을 적용한다.

4. **번호 기반 리네임으로 양쪽 차원 동시 변경**
   2차원 상품에서 value 번호가 재사용되면 번호로 리네임하지 않는다. 포함/제외만 적용하고 차원 인식 경로를 보고한다.

5. **한쪽 뷰만 검증**
   SKU행만 보거나 옵션값행만 보면 낡은 값을 놓친다. 항상 양쪽을 재조회한다.

6. **글자 수 미검증**
   공백 포함 25자를 눈대중으로 넘기지 말고 실제로 센다.

7. **접두사를 지우며 실제 사이즈까지 삭제**
   `A. S`의 `A.`만 지우고 `S`는 보존한다. 사이즈 표기 자체는 정렬 접두사가 아니다.

8. **원본 순서를 그대로 유지**
   새 규칙은 유지 옵션을 판매가 오름차순으로 정렬한다. 같은 가격인 옵션끼리만 원본 순서를 유지하며, 최종 정렬 결과를 실제 업로드 순서로 저장한다.

9. **제외 모델의 코드를 유지 옵션에 전파**
   다른 모델군의 코드는 고객 구분에 필요할 때만 남긴다.

10. **불사자 저장과 마켓 갱신 혼동**
    이 스킬의 완료는 불사자 저장·검증까지다. 마켓 반영은 별도 승인이 필요한 별개 작업이다.

11. **승인 전 쓰기**
    현재 vs 권장 표 승인(또는 원스텝 게이트 1 승인) 없이 저장하지 않는다. 단, 용팀장의 포괄 사전 승인("묻지 말고 진행")이 유지되는 동안에는 표를 보고로 제시한 뒤 승인 대기 없이 저장할 수 있다. 이 예외는 불사자 저장(제외·포함·옵션명 변경)까지만 유효하며, 마켓 등록·수정·삭제에는 절대 적용되지 않는다.

12. **옵션값 번호와 판매행 번호 혼동**
    `bulsaja_product_workdata`의 최신 결과에서 이름 변경은 옵션값 목록의 `vid`를 쓰고, 판매 제외·포함·대표옵션은 판매행 목록의 짧은 `id`를 쓴다. 원본의 긴 `skuRef`나 타오바오 원문 옵션값 번호를 넣어 `SKU_NOT_FOUND`가 나면 같은 값을 반복하지 않는다. 이름 변경만, 제외·대표만 각각 `confirm=false`로 좁혀 검증한 뒤, 두 미리보기가 모두 맞을 때 결합 요청을 한 번 실행한다.
