# 불사자 AI 상세페이지 생성 (배치)

불사자의 AI 상세페이지 생성 기능을 여러 상품에 일괄 실행하는 스킬.
접수(2단계 확인) → 비동기 생성(몇 분) → 폴링 → **완료 시 불사자가 자동 반영**.

## ⚠️ 서브에이전트/워크플로우로 위임 실행될 때 필수 (2026-07-24 사고 재발 방지)

이 스킬을 워크플로우의 하위 에이전트로 실행할 때(상위 파이프라인이 다음 단계로 자동 진행하는 구조), **자신의 턴이 끝나는 순간 그 작업에 대한 감시·재개 수단은 완전히 사라진다.** "백그라운드에서 계속 진행 중이니 나중에 확인해달라"는 식으로 미완료 상태에서 응답을 마치면 안 된다 — 그런 워치독은 존재하지 않고, 상위 파이프라인은 이 응답을 곧 "완료"로 오인해 다음 단계(업로드 등 되돌리기 어려운 작업 포함)로 진행해버린다.
- Bash `run_in_background:true`로 폴링을 던져놓고 턴을 마치지 않는다. 폴링이 오래 걸리면(수십 분 가능) `--poll-only` 재호출을 자신의 턴 안에서 반복해 실제 완료/실패가 확정될 때까지 기다린다.
- 정말 시간이 부족해 다 못 끝냈으면, "계속 진행 중"이 아니라 **"N/100건 완료, M건 미완료(체크포인트 있음, 이어서 실행 가능)"** 처럼 있는 그대로 정직하게 보고한다.

## ⚠️ 절대 규칙 (2026-07-23 사고 재발 방지, 실측 확정)

1. **10장짜리가 되려면 이미지 목록 + 장수를 "동시에" 보내야 한다.**
   실측 결과 (2026-07-23, 용쌤 계정):
   - 상품만 지정 → **1장** (7/22 96건 전부 1장 사고의 원인)
   - 상품 + 장수(sectionCount)만 → **1장** (장수 무시됨)
   - 상품 + 이미지목록(imageUrls)만 → **1장**
   - 상품 + **imageUrls + sectionCount 동시** → ✅ **요청 장수대로** ("예상 10장, 50크레딧")
   - 입력 이미지: 상품 썸네일 + 옵션 이미지 (중복 제거, 최대 10장). `detail_batch.py`가 자동 수집.
2. **접수 확정 응답의 `예상장수`로 즉시 검증** (`detail_batch.py`에 내장):
   요청 장수와 다르면 전량 접수 전에 중단. "예상 1장, 5크레딧"이면 잘못 접수된 것.
3. **작업 중복**: 같은 상품에 AI 이미지 작업이 돌고 있으면 접수가 거부됨("작업 중복") —
   스크립트가 대기열로 미뤄 말미에 재시도한다.
4. **접수 전 예상 크레딧 보고**: 건수 × 장수 × 5크레딧(일반화질) / 10크레딧(고화질).
   성공한 이미지만 차감. 무료 일일분을 넘어 보유분 차감이 예상되면 용팀장님 승인 후 진행.
5. **기작업 자동 스킵** (2026-07-23, 월간 물갈이 대비): 이미 AI 상세페이지가
   생성·반영된 상품은 접수하지 않는다 — 크레딧·시간 낭비 방지. 아래 "기작업 스킵" 참조.

## 기작업 스킵 (크레딧 낭비 방지)

- **판별 근거**: 상품 workdata의 `uploadDetailContents` 안 AI 생성 흔적 3종 —
  `aiImageGenerated`(플래그) / `aiImageOutputCount`(장수) / `aiImageGeneratedAt`(시각).
  서버 기록이 진실의 원천이라 **로컬 대장 불필요** (썸네일의 thumbnail-done.json과 다른 점).
- ⚠️ `상세페이지있음` 필드는 기준이 못 됨 — 원본 번역 이미지만 있어도 true.
- **스킵 기준**: `기존 생성 장수 >= 이번 목표 장수(sectionCount)`.
  1장 사고분(기존 1장 < 목표 10장)은 스킵되지 않고 자동 재작업 대상이 된다.
  이미지가 6장뿐이라 6장으로 완료된 상품은 6장이 정상 → 스킵.
- **비용 0**: 이미지 수집용 workdata 조회를 그대로 재사용 — 추가 API 호출 없음.
- **강제 재생성**: `--force` (용팀장님 명시 요청 시만). 체크포인트의 `완료(기작업)` 건도 재접수.
- **보고 형식**: "전체 N건 중 기작업 M건 스킵 → 실제 접수 K건" + 크레딧 견적은 접수분 기준.

## 화질

- 기본 **일반화질(standard)** — 장당 5크레딧. 고화질(high, 장당 10크레딧)은 명시 요청 시만.

## 계정 라우팅

- **용팀장 계정**(기본, `bulsaja` 서버): 스크립트 직접 실행.
- **용쌤 계정**(`bulsaja-yongssaem` 서버): `run_yong.py` 래퍼로 실행 —
  `python scripts/run_yong.py <python절대경로> scripts/detail_batch.py ...`
  (환경변수 `BULSAJA_MCP_URL/TOKEN` 주입. 토큰은 절대 출력 금지.)

## Workflow

### Step 1. 대상 수집
- 작업 폴더(run-dir)에 `products.json` 준비: `[{"productId": "..."}, ...]` 또는 ID 문자열 리스트.
- 기존 카테고리 교정 run의 `products.json` 그대로 재사용 가능.

### Step 2. 크레딧 견적 보고
- `건수 × 장수 × 5(일반)` 계산해 용팀장님께 보고. 대량이면 승인 대기.
- 기작업 스킵분은 크레딧 0 — 견적은 "예상 최대"로 보고하고, 접수 로그의
  스킵 건수를 반영해 실제 접수분 기준으로 재보고.
- 잔액 확인: `bulsaja_ai_credit_balance`.

### Step 3. 배치 실행
```
python scripts/detail_batch.py --run-dir <RUN> --pages 10
# 용쌤 계정이면: python scripts/run_yong.py <python> scripts/detail_batch.py --run-dir <RUN> --pages 10
```
- 접수: 상품별 2단계 확인(확인토큰) → 작업번호 기록 (`detail_status.json`).
- **첫 건 자동 검증**: 진행 분모 ≠ `--pages` 면 스크립트가 즉시 중단.
- 폴링: 45초 간격, 완료/실패 판정. 배시 백그라운드 10분 제한 대비 체크포인트 재개
  (`--poll-only` 로 이어서 폴링).

### Step 4. 마무리
- 실패 건은 1회 재시도(`--retry-failed`). 반복 실패는 서버측 문제 — 크레딧 미차감, 고객센터 문의 대상.
- 결과 요약(완료 신규/기작업스킵/실패/사용 크레딧) 보고. 완료분은 자동 반영이므로 별도 적용 작업 없음.
