# Transcript Organizer (전역)

녹음·영상의 말 내용을 받아 구조화된 문서로 정리한다. 사용자는 비개발자다 — 진행 보고는 쉬운 말로 짧게.

`<SKILL_DIR>` = 이 SKILL.md가 있는 폴더 (`~/.claude/skills/transcript-organizer`).
`<SCRATCH>` = 세션 스크래치패드(없으면 `/tmp`).

## Phase 0: 입력 종류별로 텍스트 확보

| 입력 | 처리 |
|------|------|
| 텍스트 파일 / 붙여넣은 원문 | 그대로 Phase 1 |
| 녹음·영상 파일 | 아래 "받아쓰기" |
| 유튜브 링크 | 아래 "유튜브" |

### 유튜브
1. 영상 ID 추출 (`watch?v=`, `youtu.be/`, `/live/`, `/shorts/` 뒤 11자).
2. 자막 받기 (설치 불필요, uvx가 알아서 받음):
   ```bash
   uvx --from youtube-transcript-api youtube_transcript_api <ID> --languages ko en --format text > <SCRATCH>/<ID>.txt
   ```
   타임스탬프가 필요하면(강의 분석 등) `--format json` 으로 받아 `(MM:SS)` 붙인 텍스트로 변환.
3. 제목·채널: `uvx yt-dlp --skip-download --print "%(title)s|%(channel)s|%(upload_date)s|%(duration_string)s" <URL>`
4. 자막이 없거나 실패하면 → 음성 받아 받아쓰기:
   ```bash
   uvx yt-dlp -x --audio-format m4a -o "<SCRATCH>/<ID>.%(ext)s" <URL>
   ```
   그다음 "받아쓰기"로.

### 받아쓰기 (맥북 로컬, 비용 0)
```bash
uvx --from mlx-whisper mlx_whisper <파일> --model mlx-community/whisper-large-v3-turbo \
  --language ko --output-format txt --output-dir <SCRATCH> --verbose False
```
- ffmpeg 필요 (`brew install ffmpeg`, 2026-11-03 설치됨). 모델은 첫 실행 때 한 번만 받음(약 1.6GB, 캐시됨).
- 1시간 녹음 ≈ 수 분. 30분 넘는 파일은 `run_in_background` 로 돌리고 완료 감시를 같이 건다.
- 타임스탬프가 필요하면 `--output-format srt`.

## Phase 0.5: 화면도 볼지 판단 (유튜브·영상 파일)

**원칙: 대본 먼저, 화면은 필요할 때만.** 화면은 토큰이 대본의 2~10배 든다(10분 영상 기준 대본 약 3~4천, 화면 100장 약 1.5~2만).

### 화면을 보는 경우 (하나라도 해당)
- 사용자가 "화면도 봐", "화면 보고", "시연 내용까지" 라고 함
- 대본을 읽어 보니 **"여기 보시면", "이렇게 누르고", "이거 복사해서"** 처럼 화면을 가리키는 말이 많고, 실제 명령어·설정값·메뉴 이름이 대본에 안 나옴 (툴 시연·설정 튜토리얼)
- 말이 거의 없는 영상 (대본이 영상 길이 대비 지나치게 짧음)

말로 다 설명하는 강의·토크·인터뷰는 **대본만** 쓴다. 판단 결과는 최종 보고에 한 줄로 밝힌다("화면은 안 봤어 — 말로 다 설명하는 영상").

### 화면 보는 방법
1. **도구**: watch 플러그인 스크립트 (`~/.claude/plugins/cache/claude-video/watch/<버전>/skills/watch/scripts/watch.py`, 버전 폴더는 `ls` 로 확인). 설정은 로컬 방식·키 없음.
   - 한국어 영상은 watch 가 영어 자동번역 자막을 잡을 수 있다 → **말 내용은 Phase 0 의 한국어 자막을 정본으로** 쓰고, watch 는 화면용으로만 쓴다.
2. **1차 훑기**: `--detail efficient --max-frames 30` (긴 영상은 대본에서 시연 구간을 골라 `--start/--end` 로 좁힌다)
3. **2차 확대(필요할 때만)**: 명령어·작은 글씨가 안 읽히는 구간만 `--start/--end --resolution 1024 --max-frames 10`
4. **화면 읽기는 보조 에이전트에 맡긴다** — `Agent`(model: `sonnet`)에게 프레임 폴더 경로와 대본을 주고 아래 형식의 장면 메모 md 를 `<SCRATCH>/<ID>_frames.md` 로 쓰게 한다. 메인 세션은 이미지를 직접 열지 않고 그 md 만 읽는다.
   ```
   | 시간 | 화면에 보이는 것 | 글자 그대로(명령어·설정값·메뉴) |
   ```
   - 비슷한 장면은 한 줄로 합침. 대본에 이미 있는 내용은 반복하지 않음.
   - 못 읽은 글자는 `(판독 불가)`, 화면에 없는 건 지어내지 않음.
   - 표 아래에 **"화면 속 용어"** 목록을 붙인다: 화면에 글자로 찍힌 고유명사·도구명·명령어·메뉴명을 표기 그대로, 처음 나온 시간과 함께 (Phase 4 오타 교정 근거로 씀).
5. **이미지 삭제**: 장면 메모가 저장되면 watch 작업 폴더(출력 끝 `Work dir:` 경로)를 바로 `rm -rf` 한다. 최종 문서에는 장면 메모 표를 "화면 메모" 섹션으로 넣는다 — 다음에 같은 영상을 다룰 땐 이미지 대신 이 문서를 읽는다.

## Phase 3: 전체 읽기 및 구조 파악
- **반드시 끝까지 전부 읽는다.** 처음 500줄은 구조 파악용 샘플일 뿐. 대용량은 700줄씩 청크.
- 화자 구분·타임스탬프 패턴 파악, 키워드 5~10개, 주제 카테고리 식별

## Phase 4: STT 오인식 교정
자동 자막·받아쓰기 결과면 수행(사람이 쓴 글이면 스킵). 고정 사전이 아니라 **맥락 기반**.
- 기준: 문맥 부적합 / 음운 유사+의미 불일치 / 표기 불안정 / 영어 음차 오류 / 고유명사 왜곡
- 용팀장 도메인 참고: 구매대행·스마트스토어·불사자·타오바오·1688·상세페이지·썸네일·마켓그룹·물갈이·실전반 등
- 확실 vs "(추정)" 구분. 확인 없이 자동 적용하고 최종 문서 "음성인식 교정 노트" 표에 투명하게 기록 (열: 원문 | 교정 | 근거)
- **화면을 본 영상이면 화면 글자가 1순위 근거다.** 장면 메모의 "화면 속 용어" 목록과 대조해, 소리가 비슷한 자막 단어는 화면 표기로 고친다(예: 자막 "재미나이" + 화면 "Gemini" → 제미나이/Gemini). 이렇게 고친 건 "(추정)" 없이 확실로 처리하고 근거 칸에 `화면 MM:SS` 를 적는다.
  - 특히 영어 도구명·명령어·파일명·메뉴명·숫자/설정값은 화면 표기를 그대로 따른다(대소문자·띄어쓰기 포함).
  - 화면과 문맥 추정이 충돌하면 화면을 따르되, 화면 글자가 `(판독 불가)` 면 문맥 추정으로 돌아가 "(추정)" 표시.

## Phase 5: 내용 분석 및 정리
- 저장 경로에 `_schema*.md` 있으면 그 구조 우선, 없으면 `<SKILL_DIR>/templates/` 의 유형별 템플릿
  - lecture: 개요 / 핵심 내용 / 핵심 요약 / 다음 작업
  - meeting: 개요 / 안건별 논의 / 결정 사항 / Action Items
  - interview: 개요 / 주요 질문·답변 / 핵심 인사이트 / 후속 작업
- 원본 최대한 보존(임의 생략 금지), 부(Part) 단위 구분, 타임스탬프 포함, 표 적극 활용, Q&A 완전 수록
- **분량**: 1시간 미만 300줄+ / 1~2시간 500줄+ / 3시간+ 700줄+
- **직접 인용 10회 이상** (`> "인용문"`)
- 사용자가 정리 외 목적(피드백·비교·대본 분석 등)을 말했으면, 정리 문서 끝에 그 목적의 분석 섹션을 붙이거나 별도 문서로 만든다.
