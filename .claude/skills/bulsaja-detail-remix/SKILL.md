# 불사자 상세페이지 리믹스

타오바오 이미지를 Fatkun으로 다운받아 커스텀 GPTs로 스마트스토어용 상세페이지
이미지를 만드는 과정은 계속 사람이 브라우저에서 직접 한다. 이 스킬은 **완성된
두 zip(타오바오 원본 + GPTs 결과물)을 받은 이후 단계**만 자동화한다 — 이미지를
추가로 생성하지 않고, 검수 후 GPTs zip을 그대로 이어붙여 반영한다.

(2026-09-03: 상단에 후킹/리뷰 이미지 2장을 gpt-image-2로 추가 생성하는 기능이
있었으나 스코프에서 제외됨 — GPTs 결과물에 이미 자체 후킹/리뷰 페이지가 포함돼
있어 중복이었고, 처리도 zip만 받는 쪽이 더 단순함.)

## 입력 3종

1. **타오바오 원본 zip** — Fatkun으로 받은 원본 상세 이미지(보통 10~15장, 검수용
   기준 자료. 파일명이 `detail-01.jpg`처럼 순번만 있는 게 특징)
2. **스마트스토어(GPTs) zip** — GPTs가 만든 가공 결과물(보통 9장 안팎, 파일명에
   `01_review_hook.png`처럼 내용이 드러남. 이게 실제로 반영되는 이미지)
3. **불사자 판매자상품코드**

## 처리 흐름

### 1단계 — 콘텐츠 검수 (Claude가 직접 비전으로 수행, 스크립트 아님— 반드시 먼저)

스크립트가 아니라 Claude가 직접 두 zip의 이미지를 **전부** `Read` 도구로 열어보고
비교한다:

1. 타오바오 원본 zip 이미지를 전부 확인해 실제 제품이 뭐고 어떤 특징이 있는지
   파악한다.
2. 스마트스토어(GPTs) zip 이미지를 전부 확인한다.
3. GPTs 결과물이 타오바오 원본에 **없는 기능·스펙을 지어냈거나(할루시네이션)**,
   제품에 대해 **잘못 설명한 부분**이 있는지 대조한다.
4. 판정:
   - **심각**(사실상 다른 상품 수준으로 안 맞음, 또는 명백히 없는 핵심 기능을
     사실처럼 단정) → 여기서 **중단**하고 무엇이 안 맞는지 사용자에게 보고. 2단계
     (반영)로 넘어가지 않는다.
   - **경미**(과장된 표현, 사소한 뉘앙스 차이 정도) → 노트만 남기고 2단계 계속
     진행. 반영 완료 후 최종 요약에 이 노트를 같이 보고한다.
   - 문제 없으면 그냥 2단계로.

상품명·옵션명을 불사자에서 조회해 대조하는 건 **이 단계에서 하지 않는다**(다른
단계에서 이미 점검되는 내용이라 중복 — 2026-09-04 확인).

### 2단계 — 반영 (스크립트, `run.py`)

검수를 통과했을 때만 실행한다.

1. 판매자상품코드 → productId 조회.
2. GPTs(스마트스토어) 결과 zip 안 이미지들을 파일명 자연정렬(숫자 인식) 순서
   그대로 사용.
3. 가로 860px 기준으로 리사이즈 후 세로로 이어붙임. 세로 픽셀이 2300px 넘으면
   낱장 경계에서만 나눠 여러 조각으로 만든다(이미지 자체를 자르지 않음) — 불사자
   서버가 높이 2400px 초과 이미지를 **에러 없이 조용히 비율유지 축소**하기 때문
   (실측 2026-09-04: 860x11349 업로드 → 실제 저장은 182x2400. 화질 저하의 진짜
   원인이었음). 2300 안전값으로 이 축소를 원천 차단한다.
4. 각 조각이 8MB(불사자 업로드 제한) 넘으면 JPEG 품질을 90→...→40 단계로 낮춰
   대응. 최저 품질에서도 넘으면 실패시키고 사람이 판단.
5. `scripts/.env`의 `BULSAJA_ACCOUNT_KEY`로 지정된 불사자 계정에 조각별로
   업로드하고, 기존 상세페이지를 조각 수만큼의 `<img>`로 교체 반영. 계정이
   여러 개면(예: 마켓용/개인용 따로 씀) 반드시 의도한 계정 이름이 맞는지
   확인한다.

MCP 도구(`bulsaja_product_find_by_code` / `bulsaja_image_upload_prepare` /
`bulsaja_detail_apply`)는 `scripts/bulsaja_client.py`가 원격 HTTP MCP를 파이썬에서
직접 JSON-RPC로 호출하므로(전송 코드는 `scripts/mcp_transport.py`에 벤더링되어
있어 외부 의존 없음), Claude가 대화 턴 안에서 MCP를 일일이 호출할 필요 없이
`run.py` 한 번 실행으로 조회→스티칭→업로드→반영까지 끝난다.

## 최초 설정 (사람마다 딱 한 번만)

이 스킬은 어느 불사자 계정을 쓸지 하드코딩돼 있지 않다 — `scripts/.env`의
`BULSAJA_ACCOUNT_KEY`로 결정된다(없으면 기본값 `bulsaja`). 스킬을 처음 쓰는
사람이면, `run.py`를 돌리기 전에 Claude가 먼저 이 절차를 안내하고 진행한다:

1. `python run.py`를 실행했는데 "mcpServers.\<계정이름\>를 찾지 못했습니다"
   에러가 나거나, `scripts/.env`가 없으면 최초 설정이 필요한 상태다.
2. 먼저 `claude mcp list`로 이미 등록된 불사자 계정이 있는지 확인한다. 있으면
   그 이름을 그대로 쓴다.
3. 없으면 사용자에게 본인 불사자 MCP 주소와 Bearer 토큰을 물어보고
   (불사자 관리자 페이지에서 발급), 원하는 계정 이름을 정해서 등록한다:
   ```bash
   claude mcp add --transport http --scope user <계정이름> \
     '<불사자 MCP 주소>' --header 'Authorization: Bearer <토큰>'
   ```
4. `scripts/.env.example`을 `scripts/.env`로 복사하고 `BULSAJA_ACCOUNT_KEY=<계정이름>`
   으로 채운다.
5. 이후부터는 정상 실행(아래 실행 절차).

OpenAI 키는 필요 없다(gpt-image-2 사용 안 함) — `.env`는 계정 이름 하나만 담는다.

## 실행

1단계(검수)를 통과한 뒤에만 실행한다.

```bash
cd .claude/skills/bulsaja-detail-remix/scripts
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 python run.py --code <판매자상품코드> --zip <GPTs(스마트스토어) 결과 zip 경로>
```

`--zip`은 항상 GPTs(스마트스토어) 결과물 zip이다 — 타오바오 원본 zip은 검수에만
쓰이고 이 스크립트에는 넘기지 않는다. 출력 폴더 기본값은 `<zip파일명>_remix/`
(zip과 같은 폴더). `--out`으로 지정 가능.

## 알려진 제약

- **업로드 티켓 스키마 확정됨**(2026-09-01 실측): `bulsaja_image_upload_prepare` 응답은
  `{upload: {url, method, fileField, ticketHeader, maxBytesPerFile}, tickets: [{clientId,
  ticket, expiresInSeconds}]}` 형태. 파일은 `upload.fileField`(현재 `"image"`) 이름의
  multipart 필드로, 개별 티켓 문자열은 `upload.ticketHeader`(현재
  `"X-MCP-Upload-Ticket"`) HTTP 헤더로 보낸다. `bulsaja_client.py`가 이 값들을
  하드코딩하지 않고 응답에서 그대로 읽으므로 서버가 바꿔도 자동으로 따라간다.
- **세로 픽셀 제한 실측 (두 가지, 헷갈리지 말 것)**:
  1) 업로드 거부: 폭 860 기준 높이 18000px까지 업로드 성공, 19000px부터
     `IMAGE_PIXEL_LIMIT`으로 거부(정확 경계 18000~19000 사이 미상). 에러가 나서
     바로 알 수 있다.
  2) **조용한 강제 축소**(진짜 중요한 쪽, 2026-09-04 발견): 업로드가 "성공"해도
     저장되는 실제 이미지는 높이 2400px 초과 시 에러 없이 비율유지 축소된다
     (예: 860x11349 -> 182x2400 실측 — 상품 화질이 눈에 띄게 나빠짐, 처음엔
     원인을 몰라서 "업스케일 탓인가" 헤맸다가 다운로드해서 실제 저장 해상도를
     찍어보고 나서야 발견함). `MAX_CHUNK_HEIGHT = 2300`(run.py)으로 이 축소가
     아예 걸리지 않게 한다 — 결과적으로 GPTs 페이지 1장(~1261px)당 조각 1개가
     되는 경우가 많다(9장 zip → 9조각 9업로드).
- **1회 실행 = 1상품**. 여러 상품을 배치로 처리하거나 중단 후 이어서 재개하는
  기능은 없다. 필요해지면 그때 얇게 얹는다.
- **두 zip을 혼동하지 말 것**: 2026-09-01에 타오바오 원본 zip을 GPTs 결과물로
  착각해 그대로 실제 상품에 반영한 사고가 있었다(파일명이 둘 다 `detail-NN.jpg`
  식으로 비슷하게 보일 수 있음). 1단계 검수 절차가 이 사고의 재발 방지 장치다 —
  검수를 생략하고 바로 `run.py`를 돌리지 않는다.
- **1단계 검수는 스크립트화하지 않는다**: 이미지 내용의 진위·과장 여부 판단은
  Claude의 비전/언어 이해가 필요한 작업이라 파이썬으로 대체할 수 없다. 매 실행마다
  Claude가 직접 두 zip을 열어봐야 한다(캐시된 이전 판단을 재사용하지 않는다).
