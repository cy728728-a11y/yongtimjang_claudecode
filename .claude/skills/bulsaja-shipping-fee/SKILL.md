# 불사자 배송비 추천

> **매출 직결 스킬이다.** 불사자 해외배송비를 바꾸면 **옵션 판매가가 차액만큼 자동으로
> 따라 움직인다**(100원 단위 반올림). 그래서 이 스킬에는 다른 축에 없는 §변경폭 게이트가 있다.
> 공통 규칙(스냅샷·현황판·계약)은 [`_shared/스킬-계약.md`](../_shared/스킬-계약.md).

## 왜 필요한가

수집 상품의 해외배송비는 불사자가 자체 산정해 넣어 둔 값이다. 실제 무게와 어긋나면
**모자랄 땐 마진이 조용히 깎이고, 남을 땐 판매가가 경쟁 상품보다 비싸진다.** 무게는
상품 데이터에 없고 **상세·옵션 이미지와 중국어 원문에만** 있어서 규칙으로는 못 뽑는다.

## 흐름

```bash
# ① prep — 현황판에서 대상 확정 → 스냅샷 → 이미지(대표1·상세2·옵션2) → 배치
python .claude/skills/bulsaja-shipping-fee/scripts/run_shipfee.py prep \
  --group-name "1번_용쌤1-1" --run-dir "<데이터루트>/shipping-fee/runs/<이름>" [--limit 5]
#    이미지는 긴 변 512px(`--max-px`, `0`=원본). 이 축이 읽는 건 치수 숫자라
#    512 로 충분하다 — _shared/스킬-계약.md §이미지 해상도

# ② run — Claude 워커가 배치를 읽고 무게·치수 추정 → results/result_NNN.json
#    판단할 것: 이게 몇 kg 인가 · 옵션마다 무게가 다른가 · 세 변이 얼마인가 · 믿을 만한가
#    ⚠ 워커는 **금액을 만들지 않는다.** 요금 산식은 shipfee_rules.py 가 정본이다

# ③ apply — 요금 계산·게이트 → 시트 기록 → Claude 표본검수 → 자동 저장
python ... run_shipfee.py apply --run-dir <R>            # 미리보기 = 표본검수 입력
python ... run_shipfee.py apply --run-dir <R> --commit   # 저장 (표본검수 통과 직후 바로)
```

대상 선정은 **현황판 쿼리 1줄**이다(`00_진행` 탭의 `배송비` 열이 빈 상품). 특정 상품만 하려면 `--ids`.

## run 실행 = Workflow 모드 (대량 기본)

공통 규약(메인 직독 금지·동시성 opt-in·재개·멱등·폴백·동시 수정)은
[`_shared/스킬-계약.md`](../_shared/스킬-계약.md) §팬아웃 공통 규약 — 여기 다시 적지 않는다.
이 축의 예산: **이미지 워커당 ≤16장 · 상품 ≤6건**(상품당 이미지가 최대 5장이라 6건이면
이미 예산에 닿는다 — 상한을 높여도 빈패킹이 쓰지 못한다).

1. `python … run_shipfee.py pending --run-dir <R>` — 남은 배치를 Workflow args JSON 으로 출력
2. `Workflow` 도구를 `{name: "shipfee-fanout", args: <출력 그대로>}` 로 호출.
   워커는 `agent(model: sonnet, effort: low)` — 지시서는
   [`references/배송비-워커-프롬프트.md`](references/배송비-워커-프롬프트.md), 판정 정본은
   [`references/배송비-기준.md`](references/배송비-기준.md) 하나다
3. 완료 반환의 `재팬아웃필요배치` 가 비었는지 확인(내부에서 이미 1회 자동 재팬아웃했다).
   남았으면 `pending` 재계산 후 **1회만** 재호출
4. `apply --run-dir <R>` 미리보기 — **워크플로는 results 생성까지다.** 시트 기록·표본검수·
   저장(`--commit`)은 메인이 한다. apply 는 감사(배치 대비 누락·환각)를 먼저 찍고,
   누락이 있으면 `--commit` 을 차단한다(`--allow-missing` 은 의도된 부분 처리 전용)

## 결과 파일 형식 (워커가 만드는 것)

```json
{"products": [{
  "productId": "U01...",
  "실물": "스틸 3단 이동식 선반",
  "무게근거": "옵션 원문 '45*39*80cm' · 스틸 프레임 3단 · 상세에 조립도",
  "무게군": [{"kg": 6.0, "행": ["*"]}],
  "부피cm": [45, 39, 80],
  "화물가능성": "의심",
  "파손위험": "중간",
  "신뢰도": "높음",
  "메모": "박스 포장 시 세변합 164cm 예상"
}]}
```

- **`무게군`** = 무게가 다른 옵션을 묶은 것. 전 옵션 동일이면 `행: ["*"]` 하나.
  **청구무게가 같은 구간이면 나누지 않는다**(1.2kg·1.4kg 는 둘 다 1.5kg 요금).
  `현재제외: false` 인 판매행만 대상이다.
- **`kg` 는 숫자다.** `"1~1.5"` 같은 범위 문자열은 버려지고 그 상품은 `보류(무게없음)` 이 된다.
- **`부피cm` 는 세 값이 다 있을 때만.** 하나라도 모르면 `세변합` 숫자만 준다.
- **`파손위험`** = 포장비 축(낮음/중간/높음). 유리·거울·액정·조명갓 → `높음`,
  섬유·고무·잡화 → `낮음`, 나머지 `중간`(기본값). **`신뢰도` 와 다른 축이다** —
  유리 화병은 무게를 확신해도 파손위험은 높다. 기준은 워커 지시서 §2-5.
- **`신뢰도: 낮음` 은 저장되지 않는다** — 사람 큐로 간다. 기준은 워커 지시서 §2-6.
- **금액(원)은 워커가 만들지 않는다.** 같은 무게가 매번 다른 요금이 되면 승인이 불가능해진다.

## 계산 규칙 (스크립트가 한다 — `shipfee_rules.py`)

```text
청구무게    = max(1.0kg, 예상무게를 0.5kg 단위 올림)
무게 요율   = 5,500 + ((청구무게 - 1.0) / 0.5 × 750)
부대비용    = 무게 구간 × 파손위험 → 실측 분위수
제안 배송비 = 요율 + 부대비용
```

**요율은 실측으로 확정됐다** — 오픈차이나 결제 내역 60건, 26개 무게(1.0~38.0kg)
**불일치 0건**(2026-08-12). 이룸님 원본 가이드의 `5,600 + 800` 은 실제와 달랐다.

전문(부대비용 분위수표·할증·경동비 산식·지역 인상율)은
[`references/배송비-기준.md`](references/배송비-기준.md) — **정본은 그 문서다.**

| 항목 | 이 스킬의 처리 |
|---|---|
| **적용무게** | **판매 옵션 중 최대**(2026-08-11 기본값). 불사자 배송비는 상품당 1개 값이라 하나를 골라야 하고, 모자란 쪽 오차가 마진을 깎는다. 대표옵션 기준도 같이 계산해 시트에 **병기**한다 |
| **부대비용(포장비)** | **요율에 더한다.** 실측 60건 중 52건(87%)에 발생, 중앙 +19%. 무게 구간별 실측 분위수를 워커의 `파손위험`(낮음/중간/높음)에 매핑 — 이룸님 지적(2026-08-12)이 그대로 판정 축이 됐다 |
| **국내 할증** | 실측 `한진택배 할증료` 가 **부대비용에 이미 포함**돼 있다. 또 더하면 이중 계상이라 `할증안내` 열에 **구간만** 적는다 |
| **경동비** | 세변합 ≥160cm 이거나 워커가 `의심`/`높음` 이면 계산. **세 변을 다 알 때만 금액을 만든다** — 없으면 `확인필요`(2026-08-13). **`배송비` 에 합산하지 않는다**. 불사자에 저장할 자리가 없어 **시트 전용** |
| **무게 교정** | 워커 추정을 실측 90건 교정표와 대조한다 — **1.0kg 미만 금지**(실측 최소가 1.0kg), **금속·유압·모터는 10kg 부터**(유압 펀처 단품 14.4kg). 정본 = [`배송비-기준.md`](references/배송비-기준.md) §2-2-0 |
| **표준운임표** | [`references/경동-표준운임.json`](references/경동-표준운임.json) — 경동택배 고시표에서 받은 **택배 열** 부피 500구간·무게 486구간 + 지역 인상율 7×7. 고시표가 바뀌면 `python scripts/fetch_kd_table.py` 로 다시 받는다(지역 인상율은 보존한다). 구간이 비면 금액 없이 `확인필요` 만 남긴다 |

## 저장 게이트 — 무엇이 걸러지나

**변경폭 상한은 기본 없다** (2026-08-12 이룸님). 산식이 맞으면 큰 차액도 정답이기
때문이다 — 12kg 왜건은 `5,600 → 23,200` 이 맞는 값인데 상한을 걸면 **정작 고쳐야 할
상품이 전부 보류로 빠진다.** 오판 방어는 무게·신뢰도 게이트가 맡는다.
필요할 때만 `--max-delta 3000` 처럼 켠다.

| 상태 | 저장 | 현황판 |
|---|---|---|
| `완료` | 저장한다 | `완료` |
| `변경없음` | 저장할 게 없다(제안 = 현재) | `완료` |
| `보류(무게없음)` | 안 함 — 워커가 무게를 못 냈다(범위 문자열·0 포함) | `보류(무게없음)` |
| `보류(신뢰도)` | 안 함 — 워커가 `낮음` 을 냈다 | `보류(신뢰도)` |
| `보류(변경폭)` | 안 함 — `--max-delta` 를 준 실행에서만 생긴다 | `보류(변경폭)` |
| `보류(저장실패)` | 시도했으나 MCP 실패 | `보류(저장실패)` |

판정 순서는 **신뢰도 → 변경없음 → 변경폭**이다. 금액을 못 믿는 상태에 `변경폭` 이라고
적으면 원인이 가려진다.

> 저장하면 옵션 판매가가 **전 옵션** 차액만큼 자동으로 움직인다(100원 반올림).
> 그래서 표본검수에서 봐야 할 1순위는 **차액 큰 건의 `무게근거`** 다 — 검수표가
> 차액 큰 순으로 정렬돼 나오는 이유다.

## 되돌리기

`apply --commit` 은 저장 **직전에** `run-dir/before_commit.json` 에 현재 배송비를 남긴다.
스냅샷은 저장 성공 시 새 값으로 덮이므로 **이 백업이 유일한 원본**이다.

```bash
python ... run_shipfee.py restore --run-dir <R> [--ids U01a U01b]
```

배송비를 되돌리면 옵션 판매가도 같이 되돌아간다(불사자가 차액을 다시 반영한다).

## 기록

- 그룹 시트 `배송비` 탭 — 상품별 실물·무게근거·적용무게·현재/제안/차액·**대표기준 병기**·
  할증안내·세변합·화물·경동비·신뢰도·상태·메모 + **요율·포장비·파손위험**(2026-08-13
  추가분은 맨 뒤에 붙었다 — 기존 행의 열이 밀리지 않게). 이미 있는 상품id 는 **그 행을 갱신**한다
- `apply` 는 **차액 큰 순** 검수표를 찍는다 — 판매가를 가장 크게 흔드는 건이 맨 위다
- 현황판 `00_진행` 의 **`배송비` 열만** 갱신
- 스냅샷의 `해외배송비` 를 저장 후 값으로 되쓴다 → 다음 회차가 옛 값을 읽지 않는다

## 불사자 저장 ≠ 마켓 반영

`--commit` 은 **불사자 서버의 상품 데이터**만 바꾼다. 이미 마켓에 올라간 상품이면
판매 화면은 그대로다 — **수정 업로드를 따로** 해야 반영된다(별개 작업).

## 알려진 함정

| 함정 | 왜 |
|---|---|
| 현재배송비에 맞추려는 워커 | 불사자가 자체 산정한 값이다. **그게 맞는지 다시 재는 게 이 작업**이라 근거로 쓰면 안 된다(지시서 §1 에 명시) |
| 이미지부터 여는 워커 | 치수는 대개 **옵션 원문 텍스트**에 있다(`45*39`·`重量5斤`). 텍스트 → 상세 → 대표 → 옵션 순서이고, 확정되면 거기서 멈춘다 |
| 옵션마다 무게가 달라 하나로 못 정함 | 그건 보류 사유가 아니다. `무게군` 으로 나눠 주면 스크립트가 최대값을 고른다. **정말 물건이 다르면** 옵션정리 범위다 — `신뢰도: 낮음` 으로 빼고 메모에 적는다 |
| 할증을 배송비에 또 더함 | 실측 `한진택배 할증료` 는 부대비용 분위수에 **이미 들어 있다**. 더하면 이중 계상 |
| 엑셀 `배송비` 열로 요율 검증 | 그 열은 포장비·할증이 섞인 **합계**다. 순수 요율은 결제 내역(`fetch_oc_actuals.py`)에만 있다 — 2026-08-12 이걸 혼동해 "산식이 안 맞는다"는 잘못된 결론을 한 번 냈다 |
| 포장비를 무게로만 봄 | 무게가 1차 예측자지만(r=0.82) 같은 무게에서 유리/거울은 훨씬 비싸다. 그게 `파손위험` 축이다 |
| 원문 치수를 무게 근거로만 쓰고 치수 칸을 비움 | 경동비가 **무게로만** 계산돼 장척을 놓친다. 1.9m 풍차가 3kg 이라 3,800원이 나왔는데 실측 경동비 중앙은 13,000원이다. 지금은 세 변이 없으면 금액을 만들지 않는다 |
| 금속·공구 세트를 5~6kg 으로 추정 | 실측에서 유압 펀처 **단품**이 14.4kg, 워터펌프 16.0kg 이다. 잭·펌프·모터·주물이 들어가면 10kg 부터 본다 |
| 경동비를 배송비에 합산 | 기준 문서 §0 — 분리한다. 마진 수식에도 넣지 않는다 |
| `무게군` 을 옵션 수만큼 쪼갬 | 청구무게가 같은 구간이면 요금이 같다. 쪼개도 결과가 안 바뀌고 토큰만 는다 |
| 범위 문자열(`"1~1.5"`) | 숫자가 아니라 버려진다 → `보류(무게없음)`. 구간을 잡았으면 **상단 숫자**를 쓴다 |
| 경동비가 계속 `확인필요` | 표준운임표 JSON 의 구간이 비었거나, 세 변을 몰라 부피가 없고 무게도 구간 밖이다. 표는 `fetch_kd_table.py` 로 다시 받는다 |
| 재수집 후 경동비가 이상함 | 구간 상한을 **앞 숫자**로 잡으면 표가 통째로 한 칸 밀린다(`4,000kg 초과 ~ 10,000kg 이하` → 4,000). `test_shipfee_rules.py` 의 `TestRealTable` 이 이걸 잡는다 |

## 표본검수 + 종합보고 (자동 반영 모델)

`apply` 미리보기가 나오면 Claude 가 **그룹당 표본 N건**(기본 10건 또는 5%, 큰 쪽)을 골라
검수표를 판정한다 — 무게근거가 실제 근거인지("추정"만 적혀 있으면 실격), 실물과 무게가
어울리는지, 차액이 큰 건이 납득되는지. 통과하면 바로 `--commit`.
**이룸님 승인을 기다리지 않는다** ([`_shared/스킬-계약.md`](../_shared/스킬-계약.md) §반영은 기본 자동이다).

- 의심건은 반영하지 않고 현황판에 `보류(표본의심)` 로 남긴다.
- **종합보고 1회**로 마감: 저장/변경없음/보류 수치 · **변경폭 게이트에 걸린 전수 목록**
  (판매가를 크게 흔들 뻔한 건이라 전수다) · 화물 대상과 경동비 · 할증 가능 건.
