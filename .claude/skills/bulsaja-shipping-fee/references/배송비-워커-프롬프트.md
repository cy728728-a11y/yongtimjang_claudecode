# 배송비 추정 워커 지시서 (팬아웃용)

> 이 문서 하나 + 배치 파일 경로만으로 **대화 맥락 없이 완주**할 수 있어야 한다.
> `shipfee-fanout` Workflow 가 워커에게 이 파일을 Read 하라고 시킨다.
> **판정 규칙 전문은 배치의 `규칙문서`(배송비-기준.md)** — 이 문서는 절차만 담는다.

## §0. 도구 규율 (비용 규칙 — 어기면 배치당 토큰이 몇 배가 된다)

| 하지 말 것 | 왜 |
|---|---|
| `Grep`·`Glob` 로 파일 찾기 | 경로는 배치 파일에 전부 실려 있다 |
| 배치 파일·규칙 문서 **재독** | 한 번 읽었으면 컨텍스트에 있다 |
| 중간 요약을 대화에 출력 | 반환은 마지막 한 번. 워커의 말은 아무도 안 읽는다 |
| 불사자 MCP·스크립트 실행(`python` 포함) | 워커의 일이 아니다. 조회·계산·저장은 스크립트 몫 |
| **금액(원) 계산** | 무게·치수만 낸다. 요금 산식은 `shipfee_rules.py` 가 정본이다 |
| 이미지를 **습관적으로** 열기 | 아래 열람 규율 — 배치의 이미지 수는 **예산 상한이지 열람 목표가 아니다** |

**이미지 열람 규율** — 여는 순서가 정해져 있고, **무게가 확정되면 거기서 멈춘다.**

1. 먼저 **텍스트**를 본다 — 상품명·원문명·옵션 원문·카테고리. 치수(`45*39`·`19cm`)나
   무게(`3kg`·`重量5斤`) 표기가 있으면 **이미지를 한 장도 열지 않고** 끝낸다.
   (`斤` = 0.5kg. `500g` 은 0.5kg.)
2. 텍스트에 없으면 **상세 이미지**를 연다(대개 치수표·스펙표가 여기 있다). 최대 2장.
3. 그래도 모르면 **대표썸네일 1장** — 크기 비교(손·가구·사람)로 구간을 잡는다.
4. **옵션 이미지**는 옵션마다 크기가 확연히 다를 때만(세트 수량·대형/소형 구분).
   `옵션이미지` 는 **어느 판매행의 것인지 표시되지 않은 표본**이다(복합옵션은 대응이
   1:1 이 아니라 붙이지 않았다). "옵션 간 크기 차이가 있나"를 보는 용도지, 특정 옵션의
   무게 근거로 쓰지 않는다 — 옵션별 차이는 **원문 텍스트**로 가른다.

## §1. 받는 것

배치 파일(`batches/batch_NNN.json`) 하나가 자기완결형이다.

```json
{"배치": 7,
 "규칙문서": "…/references/배송비-기준.md",
 "products": [
   {"productId": "U01…", "상품명": "…", "원문명": "中文原名…", "카테고리": "…",
    "현재배송비": 12420,
    "대표썸네일": "…/U01…_rep_0.jpg",
    "상세이미지": ["…/U01…_det_0.jpg", "…/U01…_det_1.jpg"],
    "옵션이미지": ["…/U01…_0_0.jpg", "…/U01…_0_1.jpg"],
    "판매행": [{"id": "1949…", "표시명": "블랙 기본형", "원문": "黑色 45*39cm",
               "판매가": 12300, "재고": 55, "현재제외": false, "현재대표": true}]}
 ]}
```

먼저 `규칙문서` 를 Read 1회 — §2(무게 추정)와 §4-1(경동비 대상)이 판단 정본이다.
`현재배송비` 는 **참고값이다. 거기에 맞추려 하지 마라** — 불사자가 자체 산정한 값이고,
그게 맞는지 다시 재는 게 이 작업이다.

## §2. 하는 일 — 상품 1건당

1. **실물 확정** 한 줄 — "무엇이 배송되는 물건인가". 상품명이 아니라 **원문·옵션 원문**
   기준이다(상품명은 가공물이라 틀려 있을 수 있다).
2. **무게 근거 찾기** — 위 열람 규율 순서대로. 찾은 근거를 `무게근거` 에 그대로 적는다
   (`옵션 원문 45*39cm · 스틸 3단` 처럼 **어디서 봤는지**를 남긴다. "추정"만 쓰면 검수 불가).
3. **무게군 나누기** — `판매행` 중 **`현재제외: false` 인 행만** 대상이다.
   - 대부분 무게군은 **1개**다(색상만 다른 상품). 억지로 쪼개지 않는다.
   - **청구무게가 같은 구간이면 나누지 않는다** — 1.2kg 와 1.4kg 는 둘 다 1.5kg 요금이다.
   - 모든 판매행이 같은 무게면 `행` 에 `["*"]` 하나만 넣는다.
   - 표기가 없어 구간으로 잡을 땐 **구간의 상단**을 쓴다(규칙문서 §2-2).
   - **낸 값을 규칙문서 §2-2-0 실측 교정표와 대조한다.** 어긋나면 추정을 고친다.
     실측 90건에서 확인된 두 가지는 예외 없이 지킨다:
     ① **1.0kg 미만은 쓰지 않는다** — 90건 중 1kg 미만이 0건이다(최소가 정확히 1.0kg).
     ② **금속·유압·모터·주물이 든 물건은 10kg 부터 본다** — 유압 펀처 단품이 14.4kg,
        워터펌프 16.0kg, 기계 스탠드 11.4kg 다. 공구 세트를 5~6kg 으로 잡으면 거의 틀린다.
4. **치수 · 화물 판정** — 세 변(cm)을 다 알면 `부피cm: [가로, 세로, 높이]`.
   대형·중량으로 보이면 `화물가능성` 을 `의심`/`높음` 으로 올린다(규칙문서 §4-1).
   - ★ **원문에서 읽은 길이·치수는 반드시 여기로 옮긴다.** `1.9米`·`600x300`·`直径450`
     을 무게 근거로만 쓰고 치수 칸을 비워두면, 스크립트가 경동비를 **무게로만** 계산해
     장척을 놓친다(실측 사고: 1.9m 정원 풍차가 3kg 이라 경동비 3,800원이 나왔는데
     실제 경동비 중앙값은 13,000원이다).
   - 한 변만 알면(장척 스틱·봉·판) 나머지 두 변을 눈대중으로 채워 `부피cm` 를 만들지 말고,
     `세변합` 에 **길이 + 나머지 두 변 추정치의 합**을 숫자로 넣는다.
   - 세 변을 못 만들면 스크립트가 경동비를 `확인필요` 로 남긴다 — 그게 정상이다.
     **틀린 금액보다 빈칸이 낫다.**
5. **파손위험** — 배대지가 포장을 얼마나 덧대야 하는가. **이게 곧 포장비다.**

실측(60건): 87%에 부대비용이 붙었고 항목이 전부 파손 대비다 — 외부포장·박스교체·
모서리 보호대·내부포장·멀티포장. 순수 요율의 **중앙 +19%**를 차지하므로 빠뜨리면
배송비가 그만큼 모자란다. 금액은 스크립트가 무게 구간과 이 값으로 계산한다.

| 값 | 언제 | 전형 |
|---|---|---|
| `높음` | 깨지거나 찍히면 못 파는 것 | 유리·도자기·거울·액정/디스플레이·조명 갓·아크릴·가구 도장면·정밀기기 |
| `중간` | 기본값. 눌리거나 긁힐 수 있는 일반 공산품 | 플라스틱 본체·전자제품·금속 조립품·박스 포장 소형가전 |
| `낮음` | 눌려도 상관없는 것 | 섬유·의류·고무·로프·부직포·잡화 소품 |

- **판단 근거는 소재와 형태**다. 얇은 판·긴 돌출부·유리면·큰 평면이 있으면 올린다.
- 세트 구성품이 많아 서로 부딪히면(`멀티포장` 항목) `높음` 쪽으로 본다.
- 애매하면 `중간`. 스크립트가 알 수 없는 값도 `중간`으로 처리한다.

6. **신뢰도** — 이 판정을 그대로 저장해도 되는가.

| 값 | 언제 |
|---|---|
| `높음` | 원문·상세에 **치수 또는 무게가 명시**돼 있다 |
| `중간` | 표기는 없지만 소재·구성·비교 크기로 구간이 좁게 잡힌다 |
| `낮음` | 이미지가 없거나 판독 불가 · 옵션마다 물건이 달라 하나로 못 묶는다 |

`낮음` 은 **저장되지 않고 사람 큐로 간다.** 애매하다고 습관적으로 `낮음` 을 쓰면 자동화가
멈추고, 근거 없이 `높음` 을 쓰면 틀린 요금이 판매가에 반영된다. 위 표대로만 고른다.

> `신뢰도` 와 `파손위험` 은 다른 축이다. 유리 화병은 무게를 확신해도(`신뢰도: 높음`)
> 파손위험은 `높음` 이다. 두 값을 같이 움직이지 마라.

## §3. 내는 것

배치 하나당 `Write` **정확히 1회** — `<runDir>/results/result_NNN.json`(NNN=배치번호 3자리 0채움).

```json
{"products": [
  {"productId": "U01…",
   "실물": "스틸 3단 이동식 선반",
   "무게근거": "옵션 원문 '45*39*80cm' · 스틸 프레임 3단 · 상세 이미지 2장에 조립도",
   "무게군": [{"kg": 6.0, "행": ["*"]}],
   "부피cm": [45, 39, 80],
   "화물가능성": "의심",
   "파손위험": "중간",
   "신뢰도": "높음",
   "메모": "박스 포장 시 세변합 164cm 예상 — 경동 인계 가능"},

  {"productId": "U01…",
   "실물": "유리 화병 3종 세트",
   "무게근거": "옵션 원문 '高35cm' · 유리 · 3개 세트",
   "무게군": [{"kg": 2.5, "행": ["*"]}],
   "화물가능성": "없음",
   "파손위험": "높음",
   "신뢰도": "중간",
   "메모": "유리 3점이 서로 부딪힘 — 개별 완충 필요"}
]}
```

- `kg` 는 **숫자**다(문자열·범위 금지). `"1~1.5"` 는 버려진다 — 상단인 `1.5` 를 쓴다.
- `행` 은 판매행 `id`. 전 옵션 동일이면 `["*"]`.
- `부피cm` 는 **세 값이 다 있을 때만.** 없으면 키를 빼거나 `세변합` 만 넣는다.
- `화물가능성` 은 `없음`/`의심`/`높음`. `파손위험`·`신뢰도` 는 `높음`/`중간`/`낮음`.
- **금액(원)은 넣지 않는다.** 넣어도 무시된다 — 포장비도 스크립트가 계산한다.

## §4. 반환

대화 반환은 배치별 결과 배열만:

```json
{"results": [{"batch": 7, "done": 3, "held": ["U01…"], "error": ""}]}
```

- `done` = 결과 파일에 담은 상품 수 · `held` = `신뢰도: 낮음` 으로 낸 상품id
- 배치를 아예 못 했으면 `error` 에 한 줄. 그 경우 `done: 0`.
