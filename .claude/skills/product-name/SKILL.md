# ⑤ 상품명 생성 (product-name)

키워드→상품명 파이프라인의 **마지막 단계**. 마켓그룹 하나(≈1000 상품)를 받아
**썸네일로 상품 정체를 확인하고 → 키워드 2~5개를 골라 → 상품명을 만들어 → 불사자에 반영**한다.

> **파이프라인 위치**: 상품→상품명 5단계 중 ⑤. 전체 흐름과 배턴 계약은
> [`../keyword-pick/references/keyword-pipeline-flow.md`](../keyword-pick/references/keyword-pipeline-flow.md).
> 이 스킬은 **규칙과 프롬프트만 소유**하고, 배치 인프라는 `keyword-pick`·`bulsaja-category-fix`에서 빌려 쓴다.

## 최상위 원칙 — 카테고리가 먼저, 그 다음이 상품명 (2026-07-24 이룸님)

**네이버 노출은 카테고리 매칭 + 키워드 매칭이다. 카테고리가 틀리면 키워드가 아무리 좋아도
그 카테고리 검색에 안 뜬다.** 그래서 순서가 있다:

1. **카테고리를 맞춘다** (`bulsaja-category-fix` 선행) — 이게 노출의 전제
2. **그 카테고리에 실재하는 키워드로 상품명을 짓는다** — 그래야 그 카테고리 검색에 노출된다

이 스킬에서 **직결어가 하나도 없는 상품은 대부분 "상품명 문제"가 아니라 "카테고리 문제"다.**
카테고리 파일에 그 상품 키워드가 없다는 건 카테고리가 틀렸다는 신호다(→ §보류 처리).

## 적합도 — 키워드는 쪼개지 말고 원문 그대로 (2026-07-24 이룸님)

**네이버는 검색어가 상품명에 그대로 있을 때 적합도 점수를 높게 준다.**
term으로 쪼개 재배열하면 그 검색어로는 상위노출이 안 된다.

```
"전동미용의자 이발의자"        ← 올바름
   '전동미용의자' 검색 → 그대로 있음 → 적합도 만점
   '이발의자'     검색 → 그대로 있음 → 적합도 만점

"전동 미용 이발 의자"          ← 틀림 (쪼개서 재배열)
   '전동미용의자' → 연속으로 없음 → '전동미용의자' 상품에 밀림
   '이발의자'     → 연속으로 없음 → 마찬가지
```

**절대 임의로 조합하지 않는다.** 고른 키워드를 원문 문자열 그대로 이어 붙이고,
남는 자리에만 원본 단어를 채운다.

### 중복 term 1종·2회 규칙의 진짜 이유

두 키워드를 온전히 넣으면 공유 term이 2번 나올 수밖에 없다 — **그걸 허용하려고 만든 규칙이다.**

```
이발의자 + 전동미용의자 → "이발의자 전동미용의자"  ('의자' 2회 = 1종 2회) ✓
```

뒤집으면, **term을 2종 이상 공유하는 키워드 쌍은 함께 쓸 수 없다.**

```
유압자키2톤 + 전동유압자키 → '유압'·'자키' 2종 중복 ✗
```

**이때는 상품수가 낮은 쪽만 원문(full)으로 넣고, 나머지는 term으로만 부분 반영한다**
(2026-07-24 이룸님 확정).

```
유압자키2톤(14,030) 을 full → "유압자키2톤 자동차 전동 받침대 수리"
전동유압자키(35,795) 는 '전동' term으로만 반영 → 그 검색어로는 상위노출 어려움(감수)
```

**조립 레시피(부분 반영을 실제로 어떻게 쓰나)** — 높은 쪽에서 **공유하지 않는 '구별 term' 1개만**
뽑아 낮은쪽 통 키워드에 붙인다. 같은 term이 2회 나오지 않게 만드는 게 핵심(중복어=없음).
```
조립식캐노피천막(21,172) < 자바라캐노피천막(29,665)   ('캐노피'·'천막' 2종 공유)
  → "자바라 조립식캐노피천막"   (자바라=구별 term / 캐노피·천막 각 1회 → 중복어 없음)
  → 실물 확인 단어로 term7 채움 → "자바라 조립식캐노피천막 원터치 접이식 2.7X3"
같은 원리: 자동비누방울머신+자동버블머신 → "자동비누방울머신 … 버블 …" ('버블'만)
          중국레고호환+중국호환블럭   → "중국레고호환 블럭 …"          ('블럭'만)
```
> 이 레시피를 빼먹고 두 키워드를 그대로 이어 붙이면 term이 2종 2회씩 되어 **R3 실패**한다
> (2026-07-25 실측: 팬아웃 워커 3명이 이 지점에서 검증실패 → 지시서에 레시피 명문화).

`name_check`가 이 상태를 **경고**로 표시한다(`적합도 만점 1개 / 부분반영 1개`).
실패가 아니다 — 규칙상 불가피한 경우이므로 그대로 내보내되 기록을 남긴다.

### 3개 이상 후보가 있을 때

중복 제약 때문에 **온전히 넣을 수 있는 건 보통 2개**다. 이때 **상품수가 낮은 것부터**
full 키워드로 쓴다(적합도 만점을 저상품수 키워드에 몰아준다).

```
전동미용의자(18,381) / 이발의자(18,074) / 미용실의자(278,411)
  → 낮은 순 2개: 이발의자 · 전동미용의자 를 full로
  → "이발의자 전동미용의자" (term 4) → 남는 자리는 원본 단어로 7까지
```

## 판단 원칙 — 의미가 먼저, 산술은 검증

**판단 순서를 뒤집지 않는다.**

1. **이 상품이 맞는가** — 썸네일을 보고 판단 (Claude). **적합성은 절대 조건**
2. **상품수 낮은 직결어를 먼저 채택** — 1페이지 노출을 노림
3. **term 6~7을 채운다 — 저상품로 모자라면 대형 키워드·원본 단어로 채운다** (2026-07-24)

### 왜 대형 키워드라도 채우나 (2026-07-24 이룸님)

상품수 낮은 키워드가 부족해 term을 4~5로 줄이면, **그만큼 검색 노출 면적이 0이 된다.**
대형 키워드는 그 단어 단독으로는 1페이지에 못 뜨지만, **여러 키워드 조합이 롱테일 검색에
걸린다.** term을 많이 넣을수록 매칭되는 검색 조합이 늘어난다 — 안 넣으면 그 기회가 사라진다.

그래서 **상품수가 높아도 term 6~7을 채운다.** 단 두 가지는 지킨다:
- **관계없는 키워드는 절대 안 붙인다.** 대형이라도 그 상품과 맞아야 한다(적합성이 상한을 만든다)
- **저상품수 직결어를 먼저 쓴다.** 대형은 term을 채우는 여유분이지 1순위가 아니다

상품수 1만 이하는 "1페이지 노출"의 프록시일 뿐, 목표가 아니다.
근거: [`../keyword-pick/references/상품명-설계결정.md`](../keyword-pick/references/상품명-설계결정.md) §1·§3

## 확정 규칙 (2026-07-24 갱신)

| 항목 | 규칙 | 근거 |
|------|------|------|
| **term 수** | **목표 7 무조건 / 4~6은 허용(경고) / 3 이하·8 이상 실패** | 임계가 카테고리별 7 또는 9. **옵션명 몫을 빼고 상품명만으로 7을 채운다**(2026-07-24 이룸님). 키워드로 부족하면 **원본 상품명 단어로 채운다**(원본은 판매자가 단 것이라 관련 보장). 원본조차 부족할 때만 4~6 허용 |
| **사용 키워드** | **2~5개**. term 7을 못 채우면 5개까지 붙이고, 그래도 부족하면 원본 단어로 term 보강 | 상품명은 후보 없이 1개 확정 |
| **중복 term** | 최대 **1종, 2회**까지 | 3회 이상 또는 2종 이상이면 순위 하락. **이 허용치는 두 키워드를 원문 그대로 넣기 위한 것**(§적합도) — 뒤집으면 term 2종 이상을 공유하는 키워드 쌍은 함께 못 쓴다 |
| **적합도** | 키워드는 **원문 그대로** 이어 붙인다. 쪼개서 재배열 금지 | 검색어가 상품명에 그대로 있어야 적합도 점수가 높다. 쪼개면 그 검색어로 상위노출 불가 |
| **동의어 중복** | **무시** (판정하지 않음) | `휴지통=쓰레기통` 같은 케이스는 사전이 없고 term별로 패널티가 달라 규칙화 불가 |
| **키워드 확보** | 최소 2개. 부족하면 상품수 1만씩 계단 확장 | 무제한까지 열되, 카테고리 파일 소진 시 보류 |
| **원본 상품명** | **완전 대체**. 단 시트에 백업 | 되돌리기 경로 확보 |

> **term 7을 무조건 채우되, 관계없는 키워드로 채우지는 않는다.** 저상품수 직결어 → 적합한
> 대형 키워드 → **원본 상품명 단어** 순으로 채운다. 원본은 판매자가 단 것이라 그 상품과 관련이
> 보장되므로, 대형까지 써도 7이 안 되면 원본에서 term을 가져와 채운다.
> 우선순위: ① 상품 적합성(관계없는 것 금지) → ② 상품수 낮은 직결어 먼저 → ③ **term 7 무조건**.

### term 정의 (원본: `키워드&상품명작성에이전트.md` §6-2)

- `term` = 네이버 검색의 최소 의미 단위(어절).
- 같은 term이 상품명에 2번 들어가도 **term count는 1**.
- `시럽통`처럼 하나의 의미 단위로 자연스러운 단어는 **1 term**으로 본다. 애매하면 `네이버 term 확인 필요` 표기.

예시 (**키워드는 원문 그대로 붙인 형태**):
```
소스디스펜서업소용    → 소스 / 디스펜서 / 업소용            term 3
펌프시럽병 카페시럽병  → 펌프 / 시럽병 / 카페               term 3, 시럽병 중복 2회
이발의자 전동미용의자 업소용 높이조절 고급
  → 이발/의자/전동/미용/의자/업소용/높이조절/고급           term 7, 의자 중복 2회
    (키워드 2개를 원문 그대로 + 원본 단어 3개로 7 채움)
```

**키워드끼리 term을 1종 공유하는 게 정상이다.** `이발의자`+`전동미용의자`가 '의자'를 공유해
2회 등장한다 — 이게 R3에서 허용하는 딱 그 경우다. 2종 이상 공유하는 쌍은 함께 쓸 수 없다.

## 저장 위치 (고정)

- **탭**: `상품명` (27열) — 시트·탭은 `--sheet` / `--tab`으로 갈아끼울 수 있다
  ```
  상품id / 작업일 / 마켓그룹 / 카테고리 / 원본상품명 / 새상품명 /
  키워드1~5 각각 (키워드N / 키워드N_상품수 / 키워드N_검색량) /
  term분해 / term수 / 중복어 / 반증 / 상태 / 메모
  ```
  키워드별 상품수·검색량을 남기는 이유: 통다운은 매번 갱신되므로 **선택 당시의 좌표는
  사후 복원이 안 된다.** 나중에 어떤 키워드가 실제로 먹혔는지 되짚으려면 지금 남겨야 한다.
- **탭**: `관련어` (8열) — 채택하지 않은 것까지 전부
  ```
  상품id / 작업일 / 카테고리 / 관련어 / 상품수 / 검색량 / 채택 / 사유
  ```
  **"안 본 것"과 "보고 버린 것"을 구분하는 유일한 기록이다.** 재검수는 여기서 시작한다.
- **스프레드시트**: **그룹별 카테고리교정 로그 시트**(2026-07-23 결정). 고정 기본값은 없다 —
  `--group-name "2번_용쌤2-1"` 을 주면 드라이브 `20-불사자-상품관리 > 카테고리교정/` 폴더에서
  `카테고리교정_<그룹명>` 시트를 찾아 쓴다. 못 찾으면 즉시 중단한다(다른 그룹 로그 오염 방지).
  - 작업 단위(마켓그룹)와 파일 단위가 일치하고, 입력(`검색어(사용)`)·출력이 한 파일에 모인다.
  - 멱등 조회 대상이 1,000행 수준으로 유지된다.
  - 전체 현황은 같은 폴더의 `00_마스터-인덱스`에 그룹별 요약 한 줄씩.
  - 시트를 직접 지정하려면 `--sheet <id>`.
- **상태 값**: `생성완료` · `검증실패` · **`보류(실물불명)`** · **`보류(카테고리의심)`** ·
  `보류(키워드부족)` · `스킵(카테고리미설정)` · `반영완료`
  - **`보류(실물불명)`** = J열도 없고 증거 4종(썸네일·원문명·옵션명)으로도 실물을 못 정함
    → 카테고리교정 `recheck` 이미지 사다리로 보강(Step 5). **실물을 모르면 키워드를 못 고른다**
  - **`보류(카테고리의심)`** = 실물은 아는데 카테고리 뷰에 직결어가 **하나도** 없음
    → 카테고리가 틀렸다는 신호. 카테고리 재확인 대상(Step 5)
  - `보류(키워드부족)` = 직결어는 있으나 2개를 못 채움 (카테고리는 맞음)
- **run_dir**: `D:\python_work\data\product-name\runs\<이름>\` (중간산출물, git 오염 방지)
- **상태 저장소 = 시트 그 자체**. 상품명 탭 A열에 상품id가 있으면 처리 완료 → 재실행해도 건너뜀(멱등).

## Prerequisites

- 워크스페이스 `.venv` (openpyxl, requests)
- `gws` CLI 인증 — 시트 기록용
- 불사자 MCP 연결 (`~/.claude.json`)
- **셀러라이프 통다운 raw** — `D:\python_work\data\sellerlife\runs\<YYMMDD>\raw\`
  없으면 `sellerlife-keyword` 스킬로 먼저 받는다.
- **대상 상품의 카테고리가 교정돼 있어야 한다.** 미교정이면 `bulsaja-category-fix` 먼저.
  (카테고리가 틀리면 엉뚱한 카테고리 파일에서 키워드를 찾는다)
- **카테고리교정 시트의 J열(실물판정)·K열(썸네일URL)을 재활용한다.** 신버전(v1.7.0~) 교정분은
  J열이 채워져 있어 실물을 그대로 이어받는다. 구버전 그룹은 J열이 비어 있어 이 스킬이 증거로
  직접 판정하고 그 결과를 J열에 backfill한다(§Step 3-1·§Step 4). 이 계약의 반대쪽은
  `bulsaja-category-fix` Step 5(시트 J·K 기록)다.

## Workflow

### Step 1. 대상 확인

이룸님께 확인할 것:
- **마켓그룹** (이름 또는 groupId) — `bulsaja_market_groups`로 목록 조회 가능
- 통다운 날짜(`--source-date`) — 기본은 가장 최근 raw 폴더

### Step 2. prep — 썸네일·카테고리·키워드후보 수집

```bash
python .claude/skills/product-name/scripts/run_names.py prep \
  --group-id <ID> --group-name "2번_용쌤2-1" \
  --run-dir "D:/python_work/data/product-name/runs/<이름>" \
  --source-date 260712 [--limit 20] [--no-parent]
```

한 번에 하는 일:
1. 마켓그룹 → 전체 상품목록 (`collect_group.py`)
2. 상품명 탭 대조 → 미처리분만 추림 (멱등)
3. 상품별 현재 카테고리 + 썸네일 URL + **원문명·옵션명**(가공 전 증거) (`bulsaja_mcp.py workdata`)
3b. **카테고리교정 시트 J·K 읽기** — `실물판정`(J)·`썸네일URL`(K) → `jk_map.json`
4. 카테고리 미설정 상품은 `skipped.json`으로 분리
5. **썸네일 다운로드** (`fetch_thumbs.py`) → `thumbs/`. **단 K열(썸네일URL)이 있는 상품은 건너뛴다**
   (신버전 그룹은 카테고리 교정이 실물을 이미 판정했으므로 썸네일은 확인용 → 필요할 때만 fetch)
6. 셀러라이프 통다운에서 카테고리별 키워드 추출 (`cat_prefilter.py`) → `prefiltered/*.xlsx`
7. **카테고리 뷰 생성** (`cat_view.py`) → `views/*.txt` + **카테고리 단위 배치** → `batches/batch_*.json`
   (배치 product에 `실물판정`·`썸네일URL`·`원문명`·`옵션명`을 실어 보낸다)

산출물:
- `views/<카테고리>.txt` — 그 카테고리 키워드 **전 행**(브랜드 O 제외) + 특징어 인덱스
- `batches/batch_001.json` — 카테고리 1개분. 같은 카테고리 상품은 한 배치에 묶인다(최대 10건)

```json
{"카테고리": "가구/인테리어>침실가구>서랍장",
 "카테고리뷰": ".../views/가구인테리어_침실가구_서랍장.txt",
 "카테고리파일": ".../prefiltered/가구인테리어_침실가구_서랍장.xlsx",
 "상위뷰": ".../views/상위_가구인테리어_침실가구.txt",
 "products": [{"productId": "U01...", "원본상품명": "...", "썸네일경로": "...",
   "실물판정": "자키+에어펌프+전동렌치 세트",   // J열. 있으면 이게 실물(신버전)
   "썸네일URL": "https://...",                  // K열. 썸네일경로가 비면 여기서 fetch
   "원문명": "沪工电动液压千斤顶...",             // 중국어 원문(가공 전)
   "옵션명": ["3톤 세단 모델잭...", "..."]}]}      // 실제 판매 단위(가공 전)
```
> `실물판정`이 빈 문자열이면 구버전 그룹 — 원문명·옵션명·썸네일로 직접 판정한다(§Step 3-1).

> **첫 실행은 통다운 스캔(수 분~수십 분) 때문에 오래 걸린다.** 백그라운드로 돌린다.
> 같은 run-dir로 재실행하면 manifest 캐시가 걸려 재스캔하지 않는다.

### Step 3. [워커] 배치별 상품명 생성

배치 하나 = 카테고리 하나. **카테고리 뷰를 1회 읽고, 상품은 1건씩 순차 처리**한다.
여러 상품을 한꺼번에 판단하지 않는다 — 토큰 이득은 뷰를 1회만 읽는 데서 이미 다 나오고,
섞어서 판단하면 뒤 상품이 앞 상품 결론에 끌려간다.

#### 위임 — 한 그룹은 컨텍스트 하나에 안 들어간다 (팬아웃)

**한 그룹(≈1000 상품) Step 3 판단 총량 ≈ 4.4M 토큰**(설계근거.md §비용). 1M 컨텍스트 하나로
불가능하다. 그래서 **오케스트레이터는 Step 3을 직접 하지 않고, 배치를 워커에 분담**한다.
워커에 먹이는 지시서는 [`references/배치-워커-프롬프트.md`](references/배치-워커-프롬프트.md)
(하네스-무관 · 배치 경로 하나만 받으면 완주 · 결과는 `named/named_NNN.json` Write, 반환은 요약 1줄).

가능한 이유는 **디스크 우선 설계**다 — 배치가 자기완결형(뷰 경로·썸네일·증거 4종을 다 실음),
상태저장소 = 디스크(`named_*.json`) + 시트(멱등). 워커를 띄우는 수단만 하네스별로 다르다:

- **모드 A — Claude Code**: `Agent` 도구로 **Sonnet 서브에이전트 팬아웃**. 라우팅 규칙상
  판단+비전 작업은 Sonnet. 각 서브에이전트에 위 지시서 + 맡을 배치 경로(들)를 준다.
  오케스트레이터(메인)는 요약만 받고 **표본 검수(Step 6)만** 한다 — 뷰·썸네일이 메인에 안 실린다.
- **모드 B — 하네스-무관(코덱스 등, 서브에이전트 없음)**: `batches_index.json`을 **인덱스 범위로
  K등분** → K개 독립 프로세스/세션이 각자 자기 범위의 배치만 처리. 서브에이전트 프리미티브가 필요 없다.
  (`run_names.py status --chunks K`가 남은 배치를 K등분해 할당표를 찍어준다.)
- **모드 C — 소수 잔여분**: 오케스트레이터가 직접 몇 배치 처리 후 컨텍스트 리셋, 반복.

**재개·중복안전**: `named/named_NNN.json`이 있으면 그 배치는 완료다 — 없는 배치만 재분배한다.
같은 배치를 겹쳐 돌려도 `named_NNN.json`은 멱등 덮어쓰기고, append가 시트 A열로 done_ids를
재조회하므로 사고가 없다. 그래서 모드 A/B를 섞어 돌려도 된다.

**3-1. 실물 정체를 확정한다 — J열이 있으면 믿고, 없으면 증거 4종으로 판정한다.**

상품명은 실제 상품을 오해시킨다 (`낚시텐트 매트` → 실제는 유아 놀이매트). 그래서 정체를
먼저 확정한다. 배치 product dict의 필드를 이 순서로 본다(prep이 카테고리교정 시트와
workdata에서 실어 보낸다 — 추가 조회 없음):

- **`실물판정`(J열)에 값이 있으면**(신버전 교정분) 그게 실물이다. 카테고리 교정이 이미
  증거 4종(한국어 상품명·중국어 원문명·옵션명·썸네일)으로 판정한 결과다.
  **판정을 다시 하지 않는다.** 썸네일은 **확인용**으로만 — `썸네일경로`가 있으면 열고,
  없으면 `썸네일URL`로 필요할 때만 받는다(K열 있으면 prep이 다운로드를 건너뛴 것).
- **`실물판정`이 비어 있으면**(구버전 그룹) 증거로 직접 판정한다:
  한국어 상품명(**용의자** — 키워드 나열로 왜곡됨) + `원문명`(중국어 원문, 가공 전) +
  `옵션명`(실제 판매 단위, 구성·형태가 드러남) + 썸네일(`썸네일경로` Read).
  판정 결과를 `named_*.json`의 **`실물판정` 필드에 적는다** — append가 이걸 카테고리 시트
  빈 J열에 backfill해서, 다음에 그 그룹을 다시 볼 때 신버전처럼 재활용된다.
- **넷을 다 봐도 무슨 물건인지 모르겠으면** `상태: "보류(실물불명)"`.
  억지로 찍지 않는다(→ §Step 5에서 카테고리교정 `recheck` 이미지 사다리로 보강).
- `썸네일경로`·`썸네일URL`이 둘 다 없고 J열도 비면 상품명 텍스트로만 판단하고 메모에 `썸네일없음`.

> **왜 원문명·옵션명까지 보나** (`bulsaja-category-fix` v1.7.0, 2026-07-24 개편과 동일 원리):
> 한국어 상품명과 썸네일은 **둘 다 불사자 가공 후** 산출물이라 **같이 틀린다** — 서로
> 대조해도 안 걸린다. 가공 **전** 원본인 중국어 원문명·옵션명이 있어야 실물이 드러난다
> (실증: `자동차 전동 자키 받침대…` → 원문 `千斤顶+充气泵+电动扳手` = 자키+에어펌프+전동렌치 세트,
> '받침대'는 실물에 없음).
> **증거 4종 판별 기준·상세 →
> [`../bulsaja-category-fix/references/대표검색어-도출.md`](../bulsaja-category-fix/references/대표검색어-도출.md)**
> (두 스킬 공유 자산 — 이 원리의 단일 출처).

**3-2. 카테고리 뷰에서 관련어를 전부 뽑는다 — 여기가 이전 실패 지점이다.**

뷰의 구조:
```
# 범주어(변별력 없음·필수): 의자(145) · 체어(43)
## 특징어 인덱스 — 희소할수록 변별력이 크다. 여기가 훑기의 진입점
이발(2): 이발의자, 이발소의자
바버(2): 바버샵의자, 바버의자
미용(8): 미용전동의자, 전동미용의자, 미용실의자, ...
## 전체 — 키워드 / 상품수 / 월검색 / 쇼핑성
[의자] 145행
...
```

- **특징어 인덱스부터 본다.** 이 상품과 관련될 만한 특징어 항목을 전부 펼친다
- 인덱스는 빈도 2 이상만 담는다. **빈도 1짜리 직결어는 인덱스에 없으므로**
  `[범주어]` 블록도 훑는다 (`일자그라인더`가 실제로 이 경우였다)
- 제외: 브랜드·모델명, 다른 상품(랫풀다운 vs 백익스텐션), 원본에서 확인 안 되는 소재·효능·인증
- **쇼핑성 `-` 는 배제 사유가 아니다.** 실측상 정답 키워드의 절반이 `-` 였다
- leaf 뷰에 직결어가 없을 때만 `상위뷰`를 연다. 다른 상품 키워드일 위험이 크므로 썸네일과 더 엄격히 대조

**관련어는 채택 여부와 무관하게 전부 기록한다.** 채택 안 한 것에는 `사유`를 적는다 —
채택보다 상품수가 낮은데 사유가 비면 R7에서 실패한다.

**3-3. 키워드를 고른다 — term 7을 무조건 채운다. 채우는 순서가 정해져 있다.**
우선순위: ① 상품 적합성 → ② 상품수 낮은 직결어 먼저 → ③ **term 7 무조건**

term 7을 아래 순서로 채운다:
1. **저상품수 직결어** — 1페이지 노출을 노림 (예: `9칸서랍장` 3,867)
2. **적합한 대형 키워드** — 저상품수로 모자라면 상품수 높아도 붙인다. 검색 노출 면적 확보
   (예: `미니서랍장` 25만 — 다른 검색 조합에 걸린다)
3. **실물과 맞는 원본 단어 + 옵션명·원문 확인 단어** — 그래도 7이 안 되면 여기서 가져온다.
   - **원본 상품명 단어**는 판매자가 단 것이라 대개 관련이 보장되지만, **실물이 정정된
     상품에서는 실물과 어긋나는 단어를 쓰지 않는다**(예: 자키+에어펌프+전동렌치 세트로
     판정된 상품의 원본 `받침대`는 실물에 없음 → 제외).
   - 대신 **옵션명·중국어 원문에서 확인된 구성·형태·규격의 한국어 표현을 term 재료로 인정**한다
     (예: 그 자키 세트의 `에어펌프`·`전동렌치`는 옵션명에서 확인됨 → 재료로 쓴다).
     실물에 실제로 있는 것을 쓰는 것이므로 R10(상품명에 없는 속성 추측 금지)과 충돌하지 않는다.
   - (예: 바람개비의 `풍차·윈드밀·장식` — 실물과 일치하므로 그대로 재료)

- **관계없는 키워드는 절대 금지.** 대형이라도 그 상품과 맞아야 한다(적합성이 상한)
- 원본에서 확인되는 특징어(색·소재·형태·용도)는 키워드가 아니어도 term에 넣는다
  (예: `북유럽 우드 식탁 천장 LED 펜던트 조명`의 'LED'·'북유럽'·'천장'은 원본 term)
- 원본조차 단어가 부족해 7이 안 되면 4~6으로 내보낸다(경고). 하지만 **원본을 다 뒤진 뒤여야 한다**

**3-4. 상품명을 조립한다 — 키워드는 원문 그대로, 쪼개지 않는다.**

조립 순서(§적합도):
1. **상품수 낮은 키워드부터 원문 그대로 이어 붙인다.** 공유 term이 1종인 쌍을 고른다
   → `이발의자 전동미용의자` (의자 2회 = 1종 2회 ✓)
2. **남는 자리를 원본 상품명 단어로 채워 term 7까지** → `이발의자 전동미용의자 업소용 높이조절 고급`
3. `term분해`는 **등장 순서대로 전부** 나열(중복 포함) → `[이발, 의자, 전동, 미용, 의자, 업소용, 높이조절, 고급]`
   term수는 스크립트가 고유 개수로 센다(= 7)

- **키워드를 term으로 쪼개 자연스러운 어순으로 재배열하지 않는다.** 그러면 적합도가 0이 된다
- 8은 패널티 구간이라 넘지 않는다. 옵션명은 별도로, 상품명 term에는 넣지 않는다(2026-07-24 변경)

**3-5. 반증(B)을 돌리고 답한다. 생략 불가.**

- 없으면 `반증`에 `없음` + 한 줄 이유. **전부에 사유를 달 필요는 없다**
- 상품수·검색량은 이미 뷰 본문에 있다. 다시 조회하지 않는다

**3-6. 보류는 사유에 따라 세 상태로 나눈다.** (term 4는 보류 사유가 아니다 — 경고만)

## 검증 규칙 (name_check.py)

| | 규칙 | 실패 조건 |
|---|------|-----------|
| R1 | term 분해가 상품명을 정확히 분할 | term을 이어붙인 게 상품명(공백제거)과 다름 |
| R2 | 고유 term 수 **4~7** (목표 7 무조건) | 3 이하 또는 8 이상. 4~6은 통과+경고 |
| R3 | 중복 term 1종·2회 | 2종 이상 중복 / 같은 term 3회 이상 |
| R4 | 사용 키워드 **2~5개** | 1개 이하 / 6개 이상 / 키워드 중복 |
| R5 | **적합도** — 키워드가 상품명에 **연속 문자열 그대로** | 어느 키워드도 그대로 없으면 실패. 일부만 만점이면 경고 |
| **R6** | **절차 — 관련어 목록·반증 답변 존재** | 둘 중 하나라도 비면 실패 |
| **R7** | **채택보다 싼 관련어에 사유 존재** | 채택 최저 상품수보다 낮은 관련어에 `사유`가 빔 |

R6·R7은 산술이 아니라 **절차** 검증이다. 이전 파일럿의 실패는 규칙 위반이 아니라
(R1~R5 전부 통과) **후보를 다 안 보고 스스로 잘라 찍은 것**이었다.
R7은 "자릿수 2개 낮은 키워드를 놔두고 비싼 걸 골랐다"를 기계가 잡는다.

단건 모드(`--name`)는 R6·R7을 건너뛴다 — 규칙만 빠르게 볼 때 쓴다.

## 설계 근거·실측·한계 → [`references/설계근거.md`](references/설계근거.md)

규칙의 "왜"와 실측·한계는 별도 파일로 분리했다(본문은 규칙·절차만). 요지:

- **왜 필터를 걷어냈나** — 범주어(60~65%)/특징어(1~8%)를 단일 60% 컷으로 처리해 직결어가
  경쟁 진입 전 전멸. 상위 N컷도 불가(놓친 키워드 순위 148~231위). → **전 행 읽기** + 브랜드열 감축.
  비용은 오히려 감소(9.1M→4.4M tok — 진짜 비용은 필터가 아니라 상품별 후보 복사였다)
- **상위 카테고리 폴백**(`--parent-fallback`) — leaf에 직결어가 0~1개일 때만 여는 구명줄.
  2차 접두 묶음에서 어근 걸리는 행만 보태 `상위뷰`로. 평소엔 안 읽는다(`--no-parent`로 끔)
- **주의력 장치 D·B** — 전 행 읽기의 병목은 Claude의 주의력. D=`cat_view.py` 특징어 인덱스,
