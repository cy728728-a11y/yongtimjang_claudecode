# ⑤ 상품명 생성 (product-name)

키워드→상품명 파이프라인의 **마지막 단계**. 마켓그룹 하나(≈1000 상품)를 받아
**썸네일로 상품 정체를 확인하고 → 키워드 2~5개를 골라 → 상품명을 만들어 → 불사자에 반영**한다.

> **파이프라인 위치**: 상품→상품명 5단계 중 ⑤. 전체 흐름과 배턴 계약은
> [`../keyword-pick/references/keyword-pipeline-flow.md`](../keyword-pick/references/keyword-pipeline-flow.md).
> 이 스킬은 **규칙과 프롬프트만 소유**하고, 배치 인프라는 `keyword-pick`·`bulsaja-category-fix`에서 빌려 쓴다.

## 최상위 원칙 — 카테고리가 먼저, 그 다음이 상품명 (2026-07-24 이룸님)

**네이버 노출은 카테고리 매칭 + 키워드 매칭이다. 카테고리가 틀리면 키워드가 아무리 좋아도
그 카테고리 검색에 안 뜬다.** 그래서 순서가 있다:

1. **카테고리를 맞춘다** (`bulsaja-category-fix` 선행) — 이게 노출의 전제
2. **그 카테고리에 실재하는 키워드로 상품명을 짓는다** — 그래야 그 카테고리 검색에 노출된다

**직결어가 하나도 없는 상품은 대부분 "상품명 문제"가 아니라 "카테고리 문제"다**(→ Step 5 ②).

## 확정 규칙 (요약 — 전문은 워커 지시서)

| 항목 | 규칙 |
|------|------|
| **term 수** | **내용어 목표 6 무조건** / 4~5 허용(경고) / 3 이하·7 이상 실패. 옵션명 몫은 빼고 센다 |
| **대표옵션 마커** | 상품명 맨 끝에 **`기본형` 고정 부착**(딱 1번). **term 수에 세지 않되 `term분해`의 마지막 원소**로 넣는다 |
| **채우는 순서** | ① 저상품수 직결어 → ② 적합한 대형 키워드 → ③ 실물과 맞는 원본 단어·옵션명/원문 확인 단어 |
| **사용 키워드** | **2~5개**. 상품명은 후보 없이 1개 확정 |
| **적합도** | 키워드는 **원문 그대로** 이어 붙인다. term으로 쪼개 재배열하면 그 검색어로는 상위노출 0 |
| **배치** | 원본 단어(a·b·c)와 키워드(1·2)를 **`a 1 b 2 c` 로 번갈아**. 자리 부족하면 `c→b→a` 순으로 삭제, 키워드는 안 자름 |
| **중복 term** | 최대 **1종·2회**. 뒤집으면 term 2종 이상을 공유하는 키워드 쌍은 함께 못 쓴다(→ 부분 반영 레시피) |
| **동의어 중복** | **판정하지 않음** (사전이 없고 term별 패널티가 달라 규칙화 불가) |
| **키워드 확보** | 최소 2개. 부족하면 상품수 1만씩 계단 확장(무제한), 카테고리 파일 소진 시 보류 |
| **원본 상품명** | **완전 대체**. 단 시트 E열에 백업(되돌리기 경로) |

**우선순위: ① 상품 적합성(관계없는 것 금지) → ② 상품수 낮은 직결어 먼저 → ③ 내용어 6 무조건.**
적합성이 상한을 만든다 — 대형 키워드라도 그 상품과 맞아야 한다.

### 대표옵션 마커 `기본형` (2026-07-30 이룸님)

**네이버는 '대표상품'(추가금 0원인 대표옵션)을 상품명으로 작성하라고 요구한다** →
**썸네일 = 대표옵션 = 상품명**이 같은 옵션 하나를 지칭해야 한다. 상품명 맨 끝과
**대표옵션명 끝**에 같은 `기본형` 을 붙여 짝을 지목한다
(옵션 쪽 = [`../bulsaja-option-cleanup/references/옵션명-규칙.md`](../bulsaja-option-cleanup/references/옵션명-규칙.md) 규칙 17).

**이 스킬은 대표옵션이 무엇인지 몰라도 된다** — 무조건 끝에 붙인다. 스킬 간 데이터 계약을
새로 만들지 않는 게 이 방식의 요점이다. 마커는 고정 접미어라 변별력이 0이므로 term 수에서 뺀다.

**색상 예외** — 배치의 `옵션동일가`가 true면(판매 옵션이 전부 같은 가격 = 추가금 0원)
색상을 term으로 채우지 않아도 된다. 대표옵션의 색은 썸네일이 보여준다.
`prep` 이 스냅샷 옵션 가격을 비교해 계산한다(`_same_price_options`) — **워커는 옵션 가격을
볼 수 없으므로**(배치의 `옵션명`은 문자열뿐) 이 플래그가 유일한 근거다.

**반쪽 마커 이관** — `rename --commit` 성공 후, 대표옵션명에 `기본형` 이 없는 상품은
현황판 `옵션` 열에 재작업 플래그를 찍는다(`_handoff_base_suffix`). 마커는 신규 처리분에만
적용하므로 "옵션은 옛 규칙으로 끝났고 상품명만 이번에 도는" 상품이 생긴다 — 그 짝을 복구하는 경로.

### 상품명에 쓰면 안 되는 표현 (2026-07-27, 헤르메스 02 흡수)

| | 항목 |
|---|---|
| **써도 되는 것** (증거에서 확인됨) | 상품 종류 · 형태 · 설치방식 · 사용장소 · 색상 · 보이는 구조 · 명시된 전원방식 · 실제 구성품 |
| **쓰면 안 되는 것** (증거에 명시 없으면 = 추측) | 소재 · 규격 · 용량 · 하중 · 성능 · 무선/충전식 · 조립방식 · 인증 · 원산지 · 내구성 · 브랜드 · 과장어 |

> **금지 단어 목록이 아니라 "근거 있으면 쓴다"는 규칙이다.** 원문·옵션명에 `无线`/무선이 있으면
> 쓰고, 옵션명에 `3톤`이 있으면 규격도 쓴다.

**단일상품 지칭 원칙** — 상품명은 물건 **한 개**를 가리켜야 한다. `색상 선택`·`다양한 색상`·
`옵션 선택`·`모음` 처럼 여러 변형을 묶는 표현은 넣지 않는다.

**term 정의** — 네이버 검색의 최소 의미 단위(어절). 같은 term이 2번 들어가도 term count는 1.
`시럽통`처럼 하나의 의미 단위로 자연스러운 단어는 1 term. 애매하면 `네이버 term 확인 필요` 표기.
(분해 예시 → [`references/설계근거.md`](references/설계근거.md) §term 분해 예시)

## 저장 위치 (고정)

- **탭 `상품명` (29열)** — `--sheet`/`--tab`으로 교체 가능
  ```
  상품id / 작업일 / 마켓그룹 / 카테고리 / 원본상품명 / 새상품명 /
  키워드1~5 각각 (키워드N / 키워드N_상품수 / 키워드N_검색량) /
  term분해 / term수 / 중복어 / 반증 / 상태 / 메모 / 속성제안 / 태그제안
  ```
  키워드별 상품수·검색량을 남기는 이유: 통다운은 매번 갱신되므로 **선택 당시의 좌표는 사후
  복원이 안 된다.** AB·AC(속성제안·태그제안)는 2026-07-27 추가 — 기존 시트는 append가
  헤더만 1회 채운다(뒤에 붙여 앞 열은 안 밀린다).
- **탭 `관련어` (8열)** — `상품id / 작업일 / 카테고리 / 관련어 / 상품수 / 검색량 / 채택 / 사유`
  **"안 본 것"과 "보고 버린 것"을 구분하는 유일한 기록.** 재검수는 여기서 시작한다.
- **스프레드시트** — 그룹별 카테고리교정 로그 시트. 고정 기본값 없음.
  `--group-name "2번_용쌤2-1"` → 드라이브 `20-불사자-상품관리 > 카테고리교정/`에서
  `카테고리교정_<그룹명>` 시트를 찾는다. **못 찾으면 즉시 중단**(다른 그룹 로그 오염 방지).
  직접 지정은 `--sheet <id>`. 전체 현황은 같은 폴더 `00_마스터-인덱스`.
- **run_dir**: `D:\python_work\data\product-name\runs\<이름>\` (중간산출물, git 오염 방지)
- **상태 저장소 = 시트 그 자체.** 상품명 탭 **A열에 상품id가 있으면 처리 완료**로 본다
  (상태값 무관) → 재실행해도 건너뜀. 재작업은 `--redo`로만 뚫는다.

## Workflow

### Step 1. 대상 확인

- **마켓그룹**(이름 또는 groupId) — `bulsaja_market_groups`로 목록 조회
- 통다운 날짜(`--source-date`) — 기본은 가장 최근 raw 폴더

### Step 2. prep — 썸네일·카테고리·키워드후보 수집

```bash
python .claude/skills/product-name/scripts/run_names.py prep \
  --group-id <ID> --group-name "2번_용쌤2-1" \
  --run-dir "D:/python_work/data/product-name/runs/<이름>" \
  --source-date 260712 [--limit 20] [--no-parent]

# 1건~몇 건만 (신규 상품 건별 등록 · 보류 재작업)
python .claude/skills/product-name/scripts/run_names.py prep \
  --group-id <ID> --group-name "<그룹>" --run-dir "<R>" --ids U01abc U01def [--redo]
```

> **`--ids`** = 지정한 상품만. 마켓그룹에 없는 id는 경고로 알린다.
> **`--redo`** = `--ids`와 함께만. 시트 A열에 이미 있는 건도 재대상으로(카테고리 변경 후 재작업 전용).
> 멱등 판정이 **A열 존재 기준이라 상태를 비우는 것만으로는 안 걸린다.** 면제는 1회용 —
> `append`가 `redo.json`을 소진한다.

> **현황판** — `append`·`rename` 이 그룹 시트 `00_진행` 탭의 **상품명 열만** 갱신한다
> (`eroomlib/matrix.py`). `생성완료`는 아직 불사자 미반영이라 `진행중(미반영)`,
> `rename` 이 반영하면 `완료`가 된다. 스킬 공통 규칙은 [`_shared/스킬-계약.md`](../_shared/스킬-계약.md).

> **공용 스냅샷** — ③의 `workdata`와 ⑤의 썸네일은 상품id 기준 캐시(`eroomlib/snapshot.py`)를
> 먼저 본다. 카테고리 교정이 이미 받아둔 그룹이면 조회 0회. 무시하려면 `--force`.
> `rename` 이 성공하면 **스냅샷의 `상품명`만 되쓴다** → 다음 스킬이 옛 상품명을 읽지 않는다.

하는 일: ①마켓그룹→상품목록 ②상품명 탭 대조로 미처리분만(멱등) ③`workdata`로 현재 카테고리·

(`cat_prefilter.py`) ⑦카테고리 뷰 생성 + **카테고리 단위 배치**(`cat_view.py`)

산출물 — `views/<카테고리>.txt`(전 행 + 특징어 인덱스) · `batches/batch_001.json`(카테고리 1개분, 최대 10건):

### Step 3. [워커] 배치별 상품명 생성

**판단 규칙 전문은 [`references/배치-워커-프롬프트.md`](references/배치-워커-프롬프트.md) §3-1~3-7이다.**
오케스트레이터는 규칙을 읽지 않는다 — 배치를 나눠주고, 결과를 모으고, 표본만 검수한다.

#### 위임 — 한 그룹은 컨텍스트 하나에 안 들어간다

한 그룹(≈1000 상품) Step 3 판단 총량 **≈ 4.4M 토큰**. 1M 컨텍스트 하나로 불가능하다.
가능한 이유는 **디스크 우선 설계** — 배치가 자기완결형(뷰 경로·썸네일·증거 4종을 다 실음),
상태저장소 = 디스크(`named_*.json`) + 시트(멱등). 워커를 띄우는 수단만 하네스별로 다르다:

- **모드 A — 수동 팬아웃(폴백)**: `Agent` 도구로 **Sonnet 서브에이전트 팬아웃**.
  각 워커에 위 지시서 + 맡을 배치 경로를 준다. **워커 1명 = 배치 1~2개.**
  Agent 호출은 **한 메시지에 몰아서** 낸다. 메인은 요약만 받는다
- **모드 B — 서브에이전트 없는 하네스 전용**: `run_names.py status --chunks K`가 남은 배치를
  K등분해 할당표를 찍는다. **클로드 코드에서는 쓰지 않는다**(이유 → 팬아웃-비용.md)
- **모드 C — 소수 잔여분**: 오케스트레이터가 몇 배치 처리 후 컨텍스트 리셋, 반복

> **비용 규칙 3개와 근거 → [`references/팬아웃-비용.md`](references/팬아웃-비용.md).**
> 요지: ①워커 1명=배치 1~2개 ②팬아웃 구간은 Opus로 돌리지 않는다 ③메인 턴 수를 줄인다.
> 셋 다 지키면 341건 $494 → ≈$140.

#### Step 3 실행 = Workflow 모드 (기본, 2026-07-29)

오케스트레이션을 백그라운드 워크플로(`pname-fanout`)로 뺀다 — 메인 세션 컨텍스트 재과금
(867건 실측 92M 토큰)이 사라지고, `/model`·`/clear` 수동 중단점이 **없다.**

1. pending 계산(디스크 스캔): `batches/` vs `named/` 대조로 named 없는 배치를 고르고,
   viewKB 는 **각 배치의 `카테고리뷰` 파일 크기(`os.path.getsize`)** 로 잰다 — batches_index.json
   에는 뷰 경로만 있고 크기가 없다. 파이썬 한 줄 스크립트로 `[{n, path, viewKB}]` 를 만든다
   (워크플로는 파일시스템이 없어 호출자가 넘겨야 한다).
2. `Workflow` 도구를 `{name: "pname-fanout", args: {runDir, promptPath, batches}}` 로 호출.
   워커는 `agent(model: sonnet, effort: low)` — 메인 모델과 무관하다.
3. 완료 알림의 반환값에서 보류 목록·검증 결과를 읽는다. **`재팬아웃필요배치` 가 있거나,
   pending 을 다시 계산했을 때 남은 배치가 있으면**(워커가 named 를 못 쓰고 죽은 경우 —
   check 는 존재하는 named 만 보므로 이걸 못 잡는다) 해당 named 를 지우고 **1회만** 재호출.
   둘 다 비어야 Step 4(append)로 간다. 재호출 후에도 남으면 보류로 이룸님 보고.

> **동시 서브에이전트 기본 가이드라인(≤15)은 이 팬아웃에 적용하지 않는다** — 워커는
> 디스크에만 쓰고 상호 간섭이 없으며, 상한은 뷰예산(워커당 ≤30KB)과 하네스 동시성 캡이
> 관리한다. 이 문장이 그 명시적 opt-in이다.

**재개·중복안전**: `named/named_NNN.json` 존재 = 그 배치 완료. 겹쳐 돌려도 멱등 덮어쓰기고,
append 가 시트 A열 done_ids 를 재조회하므로 사고가 없다(디스크가 정본).

**폴백**: Workflow를 못 쓰는 상황(구버전 하네스 등)은 모드 A(수동 Agent 팬아웃, 워커 1명=

| **R7** | **채택보다 싼 관련어에 사유 존재** | 채택 최저 상품수보다 낮은 관련어에 `사유`가 빔 |
| **R8** | **대표옵션 마커** — 끝이 `기본형`, 딱 1번, `term분해` 마지막 원소 | 안 끝남 / 2번 이상 / term분해 마지막이 아님 |
| **R9** | **배치** — 원본 단어와 키워드가 `a 1 b 2 c` 로 번갈아 놓였는가 | 키워드끼리 붙은 뒤에 원본 단어가 남아 있음(= 앞자리를 비우고 뒤에 몰았다) |

R6·R7은 산술이 아니라 **절차** 검증이다. 파일럿의 실패는 규칙 위반이 아니라(R1~R5 전부 통과)
**후보를 다 안 보고 스스로 잘라 찍은 것**이었다. R7은 "자릿수 2개 낮은 키워드를 놔두고 비싼 걸
골랐다"를 기계가 잡는다.

단건 확인(R6·R7 건너뜀):
```bash
python .claude/skills/product-name/scripts/name_check.py \
  --name "가정용 무선 각얼음 빙수기 눈꽃 슬러시 기본형" \
  --terms "가정용,무선,각얼음,빙수기,눈꽃,슬러시,기본형" --keywords "무선빙수기,각얼음빙수기"
```
