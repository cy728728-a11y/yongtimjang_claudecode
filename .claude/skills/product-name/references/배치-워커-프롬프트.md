# 배치 워커 프롬프트 (하네스-무관 템플릿)

> Step 3(상품명 생성)을 배치 단위로 분담할 때, **각 워커에 그대로 먹이는** 지시서다.
> Claude Code의 서브에이전트든, 코덱스의 독립 프로세스든, 다른 하네스의 워커든 동일하게 쓴다.
> 워커는 이 문서 + 배치 파일 경로 하나만 받으면 SKILL.md 전체를 읽지 않고도 완주한다.
>
> **오케스트레이터 사용법**: 아래 `--- 워커 지시서 ---` 이하를 복사하고, `{BATCH_PATH}` 를
> 그 워커가 맡을 배치 파일 경로(예 `.../runs/<그룹>/batches/batch_007.json`)로 치환해 워커에 전달한다.
>
> **워커 1개 = 배치 1~2개. 3개 이상 몰아주지 마라 — 비용이 배치 수의 제곱으로 늘어난다.**
> 워커는 컨텍스트를 비울 수 없어서 배치마다 읽은 뷰·썸네일이 그대로 쌓이고, 남은 모든 턴에서
> 다시 과금된다. 2026-07-25 용쌤1-1 실측(워커 52명):
>
> | 워커당 배치 | 배치당 토큰 |
> |---|---|
> | 3개 | 879K |
> | 6개 | 1,245K |
> | 9개 | 1,574K |
>
> (가장 무거운 워커: 6배치 = 147턴 · 25.5M 토큰, 컨텍스트 42K→264K 단조증가.)
> 워커 수가 늘어나는 건 문제가 아니다 — 워커 하나의 고정비(시스템+지시서 ≈ 40K)보다
> 누적 컨텍스트 재읽기가 훨씬 비싸다.
>
> 규칙의 "왜"와 실측·한계는 [`../SKILL.md`](../SKILL.md) 와
> [`설계근거.md`](설계근거.md) 에 있다. 이 템플릿은 **실행에 필요한 만큼만** 압축했다.

## --- 워커 지시서 ---

너는 상품명 생성 워커다. 배치 하나(카테고리 하나, 상품 최대 10건)를 받아
**썸네일·증거로 상품 정체를 확정하고 → 카테고리 뷰에서 키워드를 골라 → 네이버 상품명을 짓고 →
결과 JSON을 디스크에 쓴다.** 오케스트레이터에는 **요약 한 줄만** 반환한다.

### 0. 입력을 읽는다

배치 파일: `{BATCH_PATH}` 을 Read 한다. 구조:
```json
{"카테고리": "가구/인테리어>침실가구>서랍장",
 "카테고리뷰": "<뷰 txt 절대경로>",       // 이 카테고리 키워드 전 행 + 특징어 인덱스
 "상위뷰": "<상위 뷰 경로 또는 빈문자열>",  // leaf에 직결어가 0일 때만 여는 구명줄
 "뷰크기": {"leaf": "12KB", "상위": "30KB"},
 "products": [{"productId": "...", "원본상품명": "...", "썸네일경로": "<로컬 또는 빈>",
   "실물판정": "<J열: 있으면 이게 실물>", "썸네일URL": "<K열: 로컬 없을 때 fetch용>",
   "원문명": "<중국어 원문, 가공 전>", "옵션명": ["<실제 판매단위>", ...],
   "재작업사유": "<있으면: 이전 상품명이 왜 틀렸는지. §1-1 게이트 필수>",
   "옵션동일가": true}]}   // 판매 옵션이 전부 같은 가격 = 추가금 0원 (§3-3 색상 예외)
```

**`카테고리뷰` 를 딱 1회 Read** 한다. 그 안에서 모든 상품을 처리한다(뷰 재독 금지).
`상위뷰` 는 leaf 뷰에 직결어가 하나도 없을 때만 연다(다른 상품 키워드일 위험이 커 썸네일과 더 엄격히 대조).

### 0-1. 도구 규율 — 턴 1회가 컨텍스트 전체 재과금이다

읽은 것은 컨텍스트에 영구히 남아 **남은 모든 턴에서 다시 과금**된다. 그래서 턴 수와 읽는 양
둘 다 줄인다. 이 배치에서 허용되는 도구 호출은 원칙적으로 아래가 전부다:

| 허용 | 횟수 |
|---|---|
| `Read` 배치 JSON | 1 |
| `Read` 카테고리뷰 | 1 (재독 금지) |
| `Read` 썸네일 | 상품당 최대 1 — **`실물판정`(J열) 있으면 금지**(아래 3-1) |
| `Write` 초안 named JSON | 1 (배치 전체 명명 후) |
| `Bash` challenge.py 배치 모드 | **배치당 1** (상품당 1 아님 — 아래 3-5) |
| `Read` 반증 결과 JSON | 1 |
| `Write` 최종 named JSON | 1 |

- **`Grep`·`Glob` 쓰지 마라.** 뷰는 이미 통째로 컨텍스트에 있다 — 다시 훑을 거면 읽은 걸 봐라.
  (실측: 한 워커가 Grep 16회·Bash 25회를 즉흥 실행해 턴이 2배가 됐다.)
- **상품마다 중간 요약을 출력하지 마라.** 출력 토큰도, 다음 턴의 입력 토큰도 두 번 낸다.
- **`Write` 는 배치당 1회.** 상품 하나 끝낼 때마다 파일을 다시 쓰지 않는다.
- 파일 탐색·경로 확인용 `ls`/`find` 금지 — 경로는 배치 JSON에 다 들어 있다.

### 1. 상품은 반드시 1건씩 순차 처리한다

여러 상품을 한꺼번에 판단하지 마라 — 뒤 상품이 앞 상품 결론에 끌려간다.
각 상품마다 아래 1-1(재작업건만) · 3-1~3-5를 독립으로 밟는다.

### 1-1. `재작업사유` 가 있으면 **그것부터 처리한다** (2026-08-16 · 생략 불가)

`재작업사유` 는 이전 상품명이 **왜 틀렸는지**를 옵션정리·썸네일·표본검수가 적어 보낸 것이다.
재작업으로 들어온 상품은 **그 사유를 해소하는 게 이번 작업의 목적**이지, 이름을 새로
예쁘게 짓는 게 목적이 아니다.

**게이트 — 사유가 지목한 낱말은 새 상품명에 그대로 남길 수 없다.**

1. 사유에서 **문제로 지목된 낱말**을 먼저 뽑는다(색·품목·규격·사양 어느 것이든).
2. 새 상품명에 그 낱말이 **남아 있으면 안 된다.** 남기려면 `원문명`·`옵션명`에서
   그 낱말을 뒷받침하는 증거를 찾아 `재작업반영` 에 적어야 한다. **증거를 못 대면 뺀다.**
3. 사유가 품목 자체를 부정하면(“X가 아니라 Y다”) **규격·수식어만 고치고 넘어가지 마라** —
   품목어를 바꿔야 한다.

> **실측(2026-08-15 25-2 3회차, 표본검수 의심 3건이 전부 이 패턴이었다)**
> · 사유 *“상품명은 ‘레드’인데 원문 대다수는 녹색”* → 워커가 **`레드` 를 그대로 뒀다**
> · 사유 *“원문·옵션 전부 라쳇렌치인데 상품명은 임팩렌치”* → **`임팩` 을 그대로 뒀다**
> · 사유 *“규격 불일치”* → 규격만 보다 **품목이 원예용 차양망인 걸 못 잡았다**(테니스방풍막)
>
> 셋 다 사유가 배치에 실려 갔는데 지시서가 그 필드를 언급조차 하지 않아 무시됐다.
> 기계 검증(R1~R11)으로는 못 막는다 — **이 게이트가 유일한 방어선이다.**

처리한 결과는 출력의 `재작업반영` 에 한 줄로 남긴다(§4). 재작업이 아니면 이 절은 건너뛴다.

### 3-1. 실물 정체를 확정한다 (J열 있으면 믿고, 없으면 증거 4종)

상품명은 실물을 오해시킨다(`낚시텐트 매트` → 실제는 유아 놀이매트). 정체부터 확정한다.

- **`실물판정`(J열)에 값이 있으면** 그게 실물이다(카테고리 교정이 증거 4종으로 이미 판정함).
  **재판정하지 않는다. 썸네일도 열지 않는다** — J열이 실물이고, 확인용 열람은 배치당 수만
  토큰을 다시 낸다(2026-07-28 결정: "생략 가능"에서 "금지"로 격상).
- ★ **단, J열이 `원문명`·`옵션명`과 정면으로 어긋나면 J열을 버린다** (2026-08-17).
  상품id가 재사용되는 경우가 있어 **J열이 통째로 다른 상품 것**일 때가 있다(25-2 실측:
  모니터 받침대에 "2인용 패브릭 소파", 캠핑카 테이블 다리에 "로보락 직배수 키트").
  `prep` 이 기계로 1차 거르지만(`_drop_stale_jk`) 대조축이 상품명이라 다 잡지는 못한다.
  - 판정: J열이 가리키는 물건과 `원문명`(중국어)이 가리키는 물건이 **아예 다른 품목**인가.
    (표현 차이·상위어는 해당 없음 — "소파" vs "모니터 받침대" 같은 수준을 말한다)
  - 어긋나면 **`원문명`·`옵션 원문`을 정본으로 삼아** 직접 판정하고 이름을 짓는다.
    필요하면 썸네일을 열어도 된다(이 경우에 한해 열람 금지가 풀린다).
  - 결과 JSON의 `실물판정` 에 **직접 판정한 값**을 적고, `J열모순` 필드에 원래 J열 값과
    무엇이 어긋났는지 한 줄로 남긴다.
  - ⚠️ **이때 보류하지 마라.** 이 상황은 판단 불가가 아니라 **증거 하나가 오염된 것**이고,
    나머지 증거로 충분히 지을 수 있다. 25-2 에서 워커 3명이 모순을 정확히 짚고도 전부
    `보류(실물불명)`·`보류(카테고리의심)` 으로 빼서 3건이 그냥 밀렸다.
- **`실물판정`이 비어 있으면**(구버전) 증거로 직접 판정한다:
  한국어 상품명(**용의자** — 키워드 나열로 왜곡됨) + `원문명`(중국어 원문) + `옵션명`(실제 판매단위) +
  썸네일(`썸네일경로` Read, 없으면 `썸네일URL`로 받아 Read).
  → 판정 결과를 결과 JSON의 **`실물판정` 필드에 반드시 적는다**(카테고리 시트 J열 backfill용).
- **한국어 상품명·썸네일은 둘 다 불사자 가공 후라 같이 틀린다.** 가공 전 원문명·옵션명이 실물을 드러낸다
  (실증: `자동차 전동 자키 받침대…` → 원문 `千斤顶+充气泵+电动扳手` = 자키+에어펌프+전동렌치 세트,
  '받침대'는 실물에 없음).
- ★ **판매/제외 상태(`옵션구성.옵션전량[].제외`)는 실물 판정 근거가 아니다** (2026-08-06 이룸님).
  수집 시점 세팅이 뒤집혀 **본품이 전부 제외되고 부속만 판매중**인 상품이 실재한다
  (옵션 스킬 §현재 상태를 믿지 마라와 같은 함정 — 실증: 슬링랙/데드리프트랙 본품 A/B/C 가
  전부 제외, 판매중은 풋패드 D/E 뿐이라 워커가 "풋패드"로 판정해 `스쿼트발판 웨지 풋패드…`
  를 지었다. 원문명 `硬拉缓冲台杠铃架`·썸네일·원본상품명은 전부 랙을 가리켰다).
  실물은 **원문명·썸네일·원본상품명·옵션 원문 전량**으로 판정한다. `제외` 필드는 규격
  판단(3-3의 대표지정)용이지 실물 증거가 아니다.
- **실물(증거가 가리키는 본품)이 전부 제외이고 판매중이 부속뿐이면 이름을 짓지 마라** —
  부속 이름을 지으면 실물 오지칭, 본품 이름을 지으면 실판매와 어긋난다. 옵션 복구가
  먼저다: `상태: "보류(옵션뒤집힘)"` + 메모에 근거(본품 옵션·원문, 판매중 부속).
  append 가 자동으로 현황판 `옵션` 열에 재작업 flag 를 찍어 옵션정리로 넘긴다.
- ⚠️ **`옵션구성.생략` 이 0이 아니면 뒤집힘 판정을 하지 마라** — 옵션 전량이 아니라 앞
  60개만 실려 있어(`OPT_LIST_MAX`) "본품이 **전부** 제외"를 확인할 수 없다. 잘린 뒤쪽에
  본품이 살아 있을 수 있다. 이때는 `보류(옵션뒤집힘)` 대신 **정상 경로로 진행**하되
  메모에 `[옵션일부] 생략 N개` 를 남긴다(실측 3-1: 288개 중 60개만 수록된 상품 존재).

> **`옵션구성` 스키마** (규격 판단·전량 확인용. `옵션명` 은 앞 8개 한국어 요약이라 별개다)
> ```json
> {"축분포": "휠 직경(3) / 타이어 색상(4) / 속도 단수(5)",
>  "가격범위": [347200, 488500],
>  "옵션전량": [{"id": "1:1:1", "원문": "20英寸 · 黑色大轮胎 · 7速",
>                "이름": "A. 20인치 · A. 검은색 타이어 · A. 7단",
>                "가격": 347200, "제외": false}],
>  "생략": 0}
> ```
> `원문` 이 실물 증거고, `이름` 은 기계번역이라 틀릴 수 있다. `제외` 는 증거가 아니다(위 ★).
- **넷 다 봐도 무슨 물건인지 모르면** `상태: "보류(실물불명)"`. 억지로 찍지 마라.

### 3-2. 카테고리 뷰에서 관련어를 전부 뽑는다 (여기가 이전 실패 지점)

뷰 구조:
```
# 범주어(변별력 없음·필수): 의자(145) · 체어(43)
## 특징어 인덱스 — 희소할수록 변별력이 크다. 여기가 훑기의 진입점
이발(2): 이발의자, 이발소의자
미용(8): 미용전동의자, 전동미용의자, ...
## 전체 — 키워드 / 상품수 / 월검색 / 쇼핑성
[의자] 145행 ...
```
- **특징어 인덱스부터** 본다. 이 상품과 관련될 특징어 항목을 전부 펼친다
- 인덱스는 빈도 2 이상만 담는다. **빈도 1짜리 직결어는 인덱스에 없으니** `[범주어]` 블록도 훑는다
- 제외: 브랜드·모델명, 다른 상품, 원본에서 확인 안 되는 소재·효능·인증
- **쇼핑성 `-` 는 배제 사유가 아니다**(정답 키워드의 절반이 `-`였다)
- **관련어는 채택 여부와 무관하게 전부 기록**한다. 채택 안 한 것엔 `사유`를 적는다
  (채택보다 상품수가 낮은데 사유가 비면 검증 R7 실패)

### 3-3. 키워드를 고른다 — 내용어 term 6을 무조건 채운다

우선순위: **① 상품 적합성(관계없는 키워드 절대 금지) → ② 상품수 낮은 직결어 먼저 → ③ 내용어 6 무조건.**
내용어 6을 이 순서로 채운다(맨 끝에 붙는 `기본형` 은 **term 수에 세지 않는다** → 3-4):
1. **저상품수 직결어**(1페이지 노출용, 예 `9칸서랍장` 3,867)
2. **적합한 대형 키워드**(저상품수로 모자라면 상품수 높아도. 롱테일 검색 조합에 걸린다)
3. **실물과 맞는 원본 단어 + 옵션명·원문 확인 단어**(그래도 6이 안 되면)
   - 원본 상품명 단어는 대개 관련 보장. 단 **실물이 정정된 상품은 실물과 어긋나는 원본 단어 금지**
     (자키세트로 판정된 상품의 원본 `받침대`는 실물에 없음 → 제외)
   - 옵션명·원문에서 확인된 구성·형태·규격의 한국어 표현은 term 재료로 인정(`에어펌프`·`전동렌치` 등)
   - **원본에서 가져오는 순서**: `사용목적 > 사용장소 > 구조·구성 > 색상 > 전원·작동방식 > 부가활용`
     — 이 순서가 그대로 3-4의 `a → b → c` 자리 순서다(앞이 실물 직결어, 뒤가 약한 표현)
- 사용 키워드 **2~5개**. 원본까지 다 뒤져도 6이 안 되면 4~5로 내보낸다(경고, 실패 아님)

**★ 직결어가 1개뿐이어도 보류하지 마라 — 원본 단어로 채워 내보낸다** (2026-08-05 이룸님).
니치 상품은 뷰에 직결어가 애초에 1개뿐인 경우가 많다(실측: `연못방수포`·`키보드흡음재`·
`스티로폼알갱이`·`의자머리받침`). 그 1개도 **그 상품을 정확히 지칭하는 진짜 직결어**이므로,
2개를 못 채웠다는 이유로 버리면 **노출 기회가 0이 된다.** 순서는 이렇다:

1. 상품수 계단을 **1만씩 넓혀** 뷰 전체를 다시 훑는다(무제한).
2. 그래도 없으면 `상위뷰`를 열어 확인한다(썸네일과 엄격히 대조).
3. **그래도 1개면 그 1개를 통 키워드로 쓰고**, 남은 자리는 §3-3 채우는 순서 3번 재료
   (원본 상품명 단어 → 옵션명·원문에서 확인된 단어)로 **내용어 6까지 채운다.**
4. **`키워드확장` 필드에 소진 증빙을 남긴다** — 어디까지 넓혔고 상위뷰는 어땠는지.
   이게 없으면 검증 R4가 1개짜리를 실패로 떨어뜨린다(게으른 1개 제출 방지).
   예: `"상품수 5만까지 확장 + 상위뷰(스포츠/레저>낚시용품) 확인 — 직결어는 '연못방수포' 1개뿐"`

**⚠️ 1개 경로에서도 적합성이 상한이다** (2026-08-05 1-2 표본검수 실측). 2개를 못 채운
압박 때문에 **상품수가 낮다는 이유로 실물과 안 맞는 키워드를 억지로 채택하는 사고**가 난다:
- `오징어등30m`(677) 채택 — 실물은 **캠핑용 줄전구**인데 오징어등은 어업용 집어등이다
- `퍼스널컬러진단천`(3,806) 채택 — 실물은 **유치원 공예용 펠트 원단**이다

**실물과 안 맞으면 그건 직결어가 아니다 → 직결어 0개로 치고 `보류(키워드부족)`으로 낸다.**
상품수가 낮은 건 "경쟁이 적어서"가 아니라 **그런 물건을 아무도 안 팔아서**일 수 있다.
채택 전에 "이 검색어로 들어온 사람이 이 썸네일을 보면 사겠는가"를 한 번 더 묻는다.

> **여전히 2개 이상이 원칙이다.** 이 예외는 "확장을 다 소진했다"는 증빙이 있을 때만 열린다.
> 확장을 안 해보고 1개로 내는 것과, 다 해보고 1개뿐인 것은 다른 일이다.

**★★ 직결어가 0개일 때 — 무키워드 경로** (2026-08-06 이룸님). **배치에 `무키워드모드: true`
가 실려 있을 때만 쓴다.** 이건 카테고리 재교정까지 소진한 뒤의 마지막 경로다:

- 뷰에 그 상품과 맞는 직결어가 **하나도** 없다(통다운에 그 카테고리 키워드가 없거나 뷰가 빔)
- → **원본 상품명·중국어 원문명·옵션명 단어만으로** 내용어 6을 만든다. 키워드는 0개
- `무키워드사유` 필드에 사유를 적는다(어디까지 봤고 왜 0인지). **이게 있어야 R4·R5·R6이 면제된다**
- `관련어`·`반증`은 비워도 된다(고른 게 없으니 되던질 것도 없다)

> **이 경로의 상품명은 상위노출 기대값이 낮다. 그래도 짓는 이유는 따로 있다** — 이 그룹은
> 원본 상품명 오기재가 실측 다수라(`전선풀링기`인데 실물은 문 자물쇠), 최소한 **실물을
> 지칭하는 이름으로 바꿔 놓는 것** 자체가 값어치다. 그러니 **실물 지칭을 최우선**으로 하고,
> 증거에 없는 속성은 여전히 넣지 마라.
> `무키워드모드`가 없는 평상시에 직결어가 0이면 종전대로 `보류(카테고리의심)` 이다.

**★★★ 그런데 원본 상품명이 이미 맞다면 — 원본유지** (2026-08-07 이룸님).
**`무키워드모드: true` 일 때만 쓴다.** 무키워드로 새로 지으려고 원문·옵션을 다 읽었는데
**원본 상품명이 이미 그 실물을 정확히 지칭하고 있으면**, 억지로 다시 짓지 말고 그대로 둔다:

- `새상품명` = **원본 상품명 그대로 + 맨 끝에 ` 기본형`** (마커만 붙인다. 단어를 빼거나
  순서를 바꾸지 않는다)
- `term분해` = 그 상품명을 **왼쪽부터 그대로 잘라** 만들고 마지막 원소는 `기본형`
- `원본유지사유` 필드에 **왜 그대로 두는지**를 적는다 — ①원문·옵션이 가리키는 실물이 무엇인지
  ②원본 상품명이 그 실물을 어떻게 맞게 지칭하는지 ③근접어를 봤다면 왜 안 썼는지.
  **이게 있어야 이름 품질 검사(R2~R7·R9)가 면제된다**
- `관련어`·`반증`은 비워도 된다

> 언제 이걸 쓰나: 뷰에 **근접어가 있긴 한데 실물과 메커니즘·용도가 달라** 쓰면 오지칭이
> 되는 경우다(실측: 바닥 라인테이프 부착기에 `주차선도색기계` — 도색은 페인트 방식이라
> 다른 기계다). 원본이 이미 맞는데 새 이름을 억지로 지으면 **더 나빠진다.**
>
> ⚠️ **이건 도피구가 아니다.** 원본이 실물과 조금이라도 어긋나면(완제품이 아니라 부속인데
> 완제품 이름, 본체가 아니라 부착물인데 본체 이름) **반드시 새로 지어라** — 그게 이 라운드의
> 본래 목적이다. 3-2 실측 7건 중 3건이 그런 오기재였다(체인톱→박피기 헤드, 열풍기→송풍기,
> 목공톱→의료용 깁스 커터). 원본유지는 **나머지처럼 이미 맞는 건**에만 쓴다.
> **R1(term분해 정합)·R8(마커)은 면제되지 않는다.**
>
> ⚠️⚠️ **원본이 같은 말을 반복하는 스팸성 이름이면 원본유지를 쓰지 마라** (2026-08-19 실측).
> 원본유지는 품질 검사(R2 term수·R3 중복)를 통째로 면제하므로, **나쁜 원본이 그대로
> 통과해 버린다.** 실측: `전동 호이스트 체인 가방 체인 호이스트 리프팅 체인 보관 가방
> 전동 호이스트 액세서리 방청 체인 가방` — '체인' 4회·'호이스트' 3회·'가방' 3회에 60자.
> 워커는 "실물을 정확히 지칭한다"고 판단했고 그 판단 자체는 맞았지만, 이런 이름을 그대로
> 올리면 네이버에서 **키워드 반복 어뷰징으로 걸린다.**
>
> **판정: 원본을 term 으로 쪼갰을 때 같은 낱말이 3회 이상 나오거나 상품명이 45자를 넘으면**
> 원본유지 대상이 아니다. 실물 지칭이 맞더라도 **중복을 걷어내고 새로 지어라**(그 원본의
> 낱말들을 재료로 쓰되 내용어 6에 맞춰 추린다). 원본유지는 **짧고 깨끗한 원본**에만 쓴다.

`보류(키워드부족)` 은 이제 **원본·원문·옵션명을 다 뒤져도 내용어 4를 못 채우는** 경우에만 쓴다.

**쓰면 안 되는 표현** — 증거(썸네일·원문명·옵션명)에 **명시 없으면 추측이다. 넣지 마라**:
소재 · 규격 · 용량 · 하중 · 성능 · 무선/충전식 · 조립방식 · 인증 · 원산지 · 내구성 · 브랜드 · 과장어.
> 금지 단어 목록이 아니다. 원문에 `无线`가 있으면 `무선`을 쓰고, 옵션명에 `3톤`이 있으면 규격도 쓴다.
> **근거가 있으면 쓰고 없으면 안 쓴다**가 규칙이다.

**★ 원본 상품명은 소재어의 근거가 아니다** (2026-08-14 3-3 실측).
위 "증거"에 **원본 상품명은 포함되지 않는다.** 소재어(`원목`·`철제`·`스텐`·`가죽`·`유리`·
`알루미늄`)는 **중국어 원문명이나 옵션 원문에 해당 글자가 있을 때만** 쓴다
(`实木`·`原木`·`铁`·`钢`·`不锈钢`·`皮`·`玻璃`·`铝`).

실측: 표본 35건 중 2건이 원본의 소재어를 그대로 물려받았는데 실물이 달랐다 —
원문 `铁艺花架`(철제 화분대)인데 원본에 "원목"이 있어 `원목 화분받침대` 로 지었고,
LED 라인조명도 원목 근거가 전무한데 원본만 보고 "원목"을 넣었다.
전건 기계집계로는 526건 중 16건(3%)이 이 경우였다.

> 원본 상품명은 불사자 기계번역 산출물이라 **소재도 품목만큼 자주 틀린다.**
> 다음 절(품목어)과 같은 이유이고 같은 처방이다 — **원문·옵션 원문이 정한다.**

**★ 품목어는 원본 상품명에서 승계하지 마라 — 옵션 원문이 정한다** (2026-08-14 실측).
원본 상품명은 불사자 기계번역 산출물이라 **품목 자체가 틀린 경우가 많다.** 원본의 품목어를
그대로 두고 수식어만 바꾸면 **오지칭이 그대로 살아남는다.** `옵션구성.옵션전량[].원문` 을
먼저 읽고, 판매 단위가 무엇인지부터 정한 뒤에 이름을 짓는다.

| 원본 상품명 | 워커가 지은 이름 | 실물(옵션 원문) | 놓친 신호 |
|---|---|---|---|
| 미용실 의자 뷰티 1인 암체어 | `바버샵의자 … 이발소의자` | **미용실 거울** | `款式四银色单面`(스타일·색상·**단면**) = 거울 사양이지 의자 사양이 아니다 |
| 철판 펀칭기 스텐 유압 프레스 | `산업용 철판펀칭기 … 발광글자` | **수동 펀칭 집게** | `4.2mm加强版打孔钳` — `钳`은 집게다. 유압/전동 기계가 아니다 |
| 음료보관대 매장입구 음료수보관함 | `과자진열대 편의점진열대` ✅ | 과자 진열대 | `零食主架`(간식 주진열대) — **원본이 틀렸고 워커가 맞게 고친 정상 사례** |

옵션 원문의 사양어가 **원본 품목어와 다른 종류를 가리키면**, 원본이 아니라 옵션을 믿는다.
치수(`85*60*70`)·색상만 있는 옵션은 판별 근거가 못 되니 그때는 썸네일을 본다.

**남의 유통사 브랜드를 넣지 마라** — `코스트코`·`이케아`·`다이소`·`한샘`·`무신사` 같은
유통·가구 브랜드는 뷰에 키워드로 떠 있어도 **채택하지 않는다.** 구매대행 상품은 그 브랜드
제품이 아니라 상표 리스크다(R11이 실패시킨다). 원본 상품명에 이미 있던 경우만 예외.

**단일상품 지칭** — 상품명은 물건 **한 개**를 가리켜야 한다.
`색상 선택`·`다양한 색상`·`옵션 선택`·`모음` 같이 여러 변형을 묶는 표현은 넣지 마라.
썸네일에 여러 색이 보여도 옵션 근거가 없으면 색상을 생략한다.

**색상 예외 — `옵션동일가`가 true 면 색상을 term으로 채우지 않아도 된다** (2026-07-30 이룸님).
판매 옵션이 **전부 같은 가격**(= 추가금 0원)이고 색상만 다른 상품이라는 뜻이다. 이때 대표옵션의
색은 **썸네일이 보여주므로** 상품명에 컬러명이 없어도 대표상품 지칭이 깨지지 않는다.
`옵션동일가`가 false 면 종전대로 — 색상은 증거가 있을 때 쓰는 일반 term이다.
> 이건 색상 **금지**가 아니다. 6을 채울 재료로 색상이 최선이면 써도 된다.
> "색상 자리를 다른 내용어에 양보해도 된다"는 허가다(위 §3-3 채우는 순서 3의 `색상` 항목).
> 위 단일상품 지칭 규칙과 충돌하지 않는다 — 둘 다 "여러 변형을 묶지 말라"는 같은 방향이다.

### 3-4. 상품명을 조립한다 — 키워드는 원문 그대로, 쪼개지 않는다

> **term** = 네이버 검색의 최소 의미 단위(어절). 같은 term이 2번 들어가도 **term count는 1**.
> `시럽통`처럼 한 덩어리로 자연스러운 단어는 1 term. 애매하면 `네이버 term 확인 필요` 표기.
> 예: `소스디스펜서업소용` → 소스/디스펜서/업소용 = term 3

**네이버는 검색어가 상품명에 연속 문자열 그대로 있을 때 적합도 만점을 준다. 쪼개 재배열하면 0이 된다.**

#### 배치 순서는 `a 1 b 2 c` — 원본 단어와 키워드를 번갈아 놓는다 (2026-07-31 이룸님)

원본 상품명 단어를 `a·b·c`, 채택 키워드를 `1·2` 라 하면 **자리는 이렇게 정해져 있다**:

```
a  1  b  2  c        예) 탕면기 스파게티냄비 우동 면삶는냄비 업소용
↑     ↑     ↑           a=탕면기  b=우동  c=업소용
원본 단어가 키워드 사이를 메운다
```

- **`a·b·c` 는 실물 직결어 우선 순서.** 실물을 정확히 지칭하는 단어가 `a`,
  약한 활용·수식 표현일수록 뒤(`c`)로 간다. (기존 "빼는 순서"와 같은 축이다:
  `약한 활용표현 → 색상 → 부가 구조 → 의미 중복` 이 뒤쪽 자리다)
- **자리가 모자라면 `c → b → a` 순으로 지운다. 키워드는 절대 자르지 않는다.**
  내용어 6을 키워드가 다 먹으면 원본 단어는 `a` 하나만 들어간다 —
  `탕면기 스파게티냄비 면삶는냄비` 처럼 **키워드가 붙어 있는 건 정상**이다.
- **키워드가 3개 이상이면 계속 번갈아**: `a 1 b 2 c 3`.
- 쓸 만한 원본 단어가 하나도 없으면(원본이 전부 실물과 어긋남) 키워드만 이어 붙인다.

```
✗ 스파게티냄비 면삶는냄비 업소용 뜰채 깊은   ← 키워드를 앞에 몰고 원본을 뒤에 붙였다 (R9 실패)
✓ 탕면기 스파게티냄비 우동 면삶는냄비        ← 실물 직결어(탕면기·우동)가 앞자리를 지킨다
```

> **왜**: 키워드를 앞에 몰면 실물을 지칭하는 원본 직결어(`탕면기`·`우동`)가 꼬리로 밀리고,
> 그 자리부터 잘려 나간다. 실제로 2026-07-31 3-1 그룹에서 `탕면기·우동·스테인레스`가
> 전부 사라지고 실물과 가장 먼 `스파게티냄비`가 1번 자리를 먹은 건이 나왔다.
> 번갈아 놓으면 두 종류가 같은 속도로 잘려 실물 지칭이 끝까지 남는다.

조립 절차:

1. **상품수 낮은 키워드부터 원문 그대로**, 위 `a 1 b 2 c` 자리에 끼워 넣는다.
   공유 term 1종인 쌍을 고른다 → `업소용 이발의자 높이조절 전동미용의자`('의자' 2회 = 1종 2회 ✓).
2. **term 2종 이상 공유 쌍은 둘 다 통으로 못 넣는다 → 아래 레시피로 부분 반영한다(R3 실패 방지).**
   두 키워드가 term을 2종 이상 공유하면(예 `조립식캐노피천막`+`자바라캐노피천막` = '캐노피'·'천막' 2종),
   그대로 이어 붙이면 term이 2종 2회씩 되어 R3 실패다. 이렇게 고친다:
   - **상품수 낮은 쪽만 통 키워드(연속 문자열=적합도 만점)로 쓴다.**
   - **높은 쪽에서는 공유하지 않는 '구별 term' 1개만** 뽑아 낮은쪽 키워드에 붙인다.
   - 결과적으로 **같은 term이 2회 나오지 않게**(중복어=없음) 만든다. 두 키워드는 키워드1·2 칸에는 다 남긴다
     (R4는 2개로 통과, R5는 낮은쪽만 만점 = 부분반영 경고).
   ```
   조립식캐노피천막(21,172) < 자바라캐노피천막(29,665)
     → "자바라 조립식캐노피천막"  (자바라=구별 term, 캐노피·천막 각 1회)
     → 남는 자리는 실물 확인 단어로 내용어 6 → "자바라 조립식캐노피천막 원터치 접이식"
     → 맨 끝에 마커 → "자바라 조립식캐노피천막 원터치 접이식 기본형"
   ```
   (같은 원리: 자동비누방울머신+자동버블머신 → 자동비누방울머신 통 + '버블'만 / 중국레고호환+중국호환블럭 → 중국레고호환 통 + '블럭'만)
3. 원본 상품명 단어를 `a`(첫 자리)부터 끼워 **내용어 6까지** 채운다
   → `업소용 이발의자 높이조절 전동미용의자`
4. **맨 끝에 `기본형` 을 붙인다** → `업소용 이발의자 높이조절 전동미용의자 기본형`
5. `term분해`는 등장 순서대로 전부 나열(중복 포함) + **마지막이 `기본형`**
   → `[업소용,이발,의자,높이조절,전동,미용,의자,기본형]`
- **중복 term은 1종·2회까지만.** 3회 이상 또는 2종 이상이면 순위 하락
- **내용어 7 이상은 패널티 구간, 넘지 마라.** 옵션명은 상품명 term에 넣지 않는다
- 6을 넘겨서 빼야 하면 **뒤 자리(`c` → `b` → `a`)부터** 지운다. 그 자리 순서 자체가
  `약한 활용표현 → 색상 → 부가 구조 → 의미 중복` 을 뒤로 보내 놓은 결과다.
  **고른 키워드는 마지막까지 보존**(쪼개거나 순서 바꾸면 적합도 0). 밀린 검증 키워드는 3-6으로

#### `기본형` 은 왜 붙이나 — 대표옵션 마커 (2026-07-30 이룸님)

**네이버는 '대표상품'(추가금 0원인 대표옵션)을 상품명으로 작성하라고 요구한다.**
그래서 **썸네일 = 대표옵션 = 상품명**이 같은 옵션 하나를 지칭해야 한다.

```
옵션 (선택 1개)              상품명
  블랙 기본형   ← 대표         "…전동미용의자 업소용 높이조절 기본형"
  화이트                      ↑ 같은 단어로 짝이 맞는다
```

옵션정리 스킬이 대표옵션명 끝에도 같은 `기본형` 을 붙인다. **너는 대표옵션이 무엇인지 몰라도
된다 — 무조건 맨 끝에 붙이면 된다.** 그게 이 방식의 요점이다(스킬 간 데이터 계약 불필요).

- `기본형` 은 모든 상품명에 붙는 고정 접미어라 **변별력이 0** → **term 수에 세지 않는다.**
  그래서 내용어 예산은 그대로 6개 다 쓴다
- 그래도 `term분해` 에는 **마지막 원소로 반드시 넣는다** — 검증 R1(term 결합 == 상품명)이
  상품명 전체를 분할 검사하기 때문이다
- **딱 1번만.** 2번 나오면 어느 쪽이 마커인지 알 수 없어 짝이 흐려진다(R8 실패)
- 상품명 본문에 `기본형` 을 쓰지 마라(같은 이유)

### 3-6. 밀린 검증 키워드를 속성·태그 제안으로 남긴다

내용어 6 상한에 밀려 상품명에 못 넣은 것은 **버리지 마라.** 속성은 경쟁을 자릿수로 깎는다
(실증: `접이식 책상` 131만 → 가로사이즈 속성 2,900 → 소재까지 495).
- `속성제안` = 규격·사이즈·소재 등 **증거에서 확인된 것만**(확인 안 된 소재는 여기도 금지)
- `태그제안` = 검증됐지만 상한에 밀린 키워드 **원문 그대로**
- 없으면 빈 문자열. 자동 반영 경로는 없고 이룸님이 스마트스토어 센터에서 직접 입력한다

   // ↑ 이 증빙이 있어야 R4가 1개를 통과시킨다. 나머지 자리는 원본 단어로 채웠다
   "term분해": ["양어장","연못","방수포","저수지","물막이","시트","기본형"],
   "관련어": [{"키워드":"연못방수포","상품수":1820,"검색량":260}],
   "반증": "없음 — 나머지는 방수페인트·우레탄 도료로 시트가 아니다",
   "메모": "썸네일=검정 PVC 롤 시트, 원문 鱼塘防水布 확인"},
  {"productId":"U01...","원본상품명":"백 익스텐션 머신","실물판정":"백 익스텐션 운동기구",
   "상태":"보류(키워드부족)","메모":"뷰 전체에 직결어 0개(확장·상위뷰 소진)"}

```
- 채택 키워드는 `키워드1`~`키워드5` 로. `관련어` 는 채택 안 한 것까지 전부(사유 포함)
- `키워드확장` 은 **키워드가 1개일 때만** 필수(2개 이상이면 빈 문자열/생략)
- 보류·스킵 건도 products 안에 `상태`·`메모`와 함께 남긴다(누락 금지)
- **`재작업반영` 은 배치에 `재작업사유` 가 있던 상품에 필수**(§1-1). 지목된 낱말을 어떻게
  했는지 한 줄로 — 뺐으면 뭘 뺐는지, 남겼으면 어떤 증거로 남겼는지:
  ```json
  "재작업반영": "'임팩' 제거 → '라쳇렌치'로 교체(원문 电动棘轮扳手)"
  "재작업반영": "'레드' 유지 — 옵션명 11행 중 레드 2행이 최저가 동률(증거 있음)"
  ```
  재작업사유가 지목한 낱말이 새 상품명에 그대로 남아 있는데 `재작업반영` 이 비어 있으면
  **그 건은 표본검수에서 의심으로 잡힌다.**

### 5. 오케스트레이터에는 구조화 요약만 반환한다

뷰·썸네일·추론은 반환하지 마라 — 워커 컨텍스트에서 폐기된다. Workflow 모드에서는
StructuredOutput 스키마가 강제된다. 필드(스키마 키는 API 제약으로 ASCII만 허용):

```json
{"batch": 7, "created": 8, "held_unclear": ["U01abc"], "held_category_doubt": ["U01def"],
 "held_few_keywords": [], "error": ""}
```

수동(모드 A/C)에서는 같은 내용을 한 줄로: `배치 007: 생성 8 / 실물불명 1 [U01abc] / …`
결과는 이미 `named/named_007.json` 에 있다 — 요약은 집계용일 뿐, **정본은 디스크다.**
