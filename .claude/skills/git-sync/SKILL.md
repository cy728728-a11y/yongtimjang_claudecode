# git-sync — 묻지 말고 바로 실행

> ⚠️ **핵심: 확인 질문 금지. 파일 내용 검토 금지. 변경사항 요약 금지.**
> 용팀장님은 PC를 오가며 빠르게 쓰려는 것이다. 옥신각신하면 이 스킬은 실패한 것이다.

## 명령 매핑

| 용팀장님이 말하면 | 실행 |
|---|---|
| "깃푸쉬" · "깃푸시" · "git push" · "올려줘" | `./sync.ps1 push` |
| "깃풀" · "git pull" · "받아줘" | `./sync.ps1 pull` |
| "싱크" · "동기화" · "깃 정리" | `./sync.ps1` |

작업 디렉토리는 `C:\Users\workspace`. PowerShell 도구로 실행한다.

## 하지 않을 것

- `git status` 먼저 찍어보고 브리핑 ❌
- "이 파일 올려도 될까요?" 확인 ❌ — **전부 올린다.** 통화녹음·개인 노트 포함. 저장소 공개 여부는 이미 용팀장님이 알고 판단한 사안(2026-07-27, Public 유지 결정).
- 커밋 메시지 제안 ❌ — 스크립트가 `sync: 날짜시각 (PC이름)`으로 자동 생성
- 민감정보 스캔 ❌
- 작업 후 변경 파일 목록 나열 ❌

## 답변 형식

스크립트 출력을 보고 **한 줄로만** 답한다.

- 성공: `푸시 완료 (3e95ad6..0fe2614)` 또는 `받기 완료` 또는 `변경 없음`
- 실패: 에러 원인 한 줄 + 다음 조치 한 줄

## 충돌났을 때만 예외

스크립트가 `[충돌]`을 내면 그때만 개입한다:
1. `git status`로 충돌 파일 확인
2. 양쪽 내용 병합 (주로 `40-personal/46-todos/active-todos.md` — 두 PC의 todo를 **합집합**으로 남긴다)
3. `git add .` → `git rebase --continue` → `./sync.ps1 push`

## 참고

- 스크립트: `C:\Users\workspace\sync.ps1` (UTF-8 BOM 필수 — PowerShell 5.1이 BOM 없으면 한글 깨져 파싱 실패)
- git 사용자 정보가 없는 새 PC면 스크립트가 알아서 설정
- 원격: `origin/main` (Public 저장소)
