# 비즈 300 마켓 세팅

용팀장이 사입 물건이 올 때까지 비즈 300개를 각 스토어에 **판매중이지만 전시중지** 상태로 미리 깔아 두는 작업. 마켓 하나씩 돈다. 2026-11-12 25-1에서 처음 끝까지 검증했다.

## 고정 조건 (바꾸지 말 것)

- 불사자 계정: 부킹(용쌤). 원본: `용팀장_테스트` 그룹(300개). 대상: `용쌤N-M` 그룹만(쿠팡·타임제로·열·송·엽·엔잡곰 제외).
- 등록한도: "마켓별 등록수량 현황" 시트 `작업계획` 탭 A~D열. 현재 등록 수: 커머스 상품검색 전체 건수.
- 업로드는 **반드시 불사자로**. 커머스API로 직접 등록하지 않는다(불사자 연결이 끊김).
- 업로드 후 세팅은 커머스API로 스토어에 직접 넣는다. **불사자 수정업로드는 하지 않는다**(용팀장이 직접 관리, 하면 가격·세팅이 덮임).
- 스토어 최종 상태: 판매중 / 전시중지 / 묶음배송 가능(기본 묶음그룹) / 유료 2,500원 선결제 / 국내 "상품출고지" / 반품 2,500 / 교환 5,000 / 즉시할인 없음 / 판매가 100원(실제 판매가도 100원).
- 지역별 추가배송비는 묶음그룹 설정을 따른다(상품에 넣으면 저장 에러).

## 순서 (마켓 하나 기준, 예: 25-1)

스크립트 폴더: `.claude/skills/bead-store-setup/scripts/`, 실행은 프로젝트의 `.venv/bin/python`.

1. **상태 보기** `status.py 25-1` — 한도·현재·빈자리·확보필요, 그룹의 비즈 복사본 수·업로드·잠금, 스토어 비즈 상태.
2. **300개 채우고 잠금** `fill_and_lock.py 25-1` — 원본에서 빠진 비즈를 그룹에 복사, 비즈 전부 잠금.
3. **빈자리 확보**(확보필요 > 0일 때만) `free_slots.py 25-1` 로 고른 목록 확인 → `free_slots.py 25-1 run`.
   - 후보: 업로드됨 + 잠금 안 됨 + 비즈 아님. 30일 유입 적은 순 → 업로드 오래된 순.
   - 지우기 전 불사자 메모 맨 앞에 `[삭제] 날짜 · 사유` 기록. 스스에서만 삭제(불사자 원본 유지).
   - 지운 뒤 `status.py`로 빈자리 350 이상 확인.
4. **업로드** `upload.py 25-1` — 접수가 한 번에 다 안 들어가면(약 240개씩) 몇 분 뒤 다시 돌린다(진행 중인 건 중복으로 막혀 안전).
   - 실패 작업은 `bulsaja_upload_tasks` 재시도 1번, 최대 약 15분 기다리고 또 실패면 건너뛰고 "N개 제외"로 보고.
5. **스토어 세팅** `store_fix.py 25-1 one` 로 1개 확인 → `store_fix.py 25-1 all`. 가격을 바꾸려면 세 번째 인자(예: `store_fix.py 25-1 all 300`).
   - 수정 전 원본은 `data/backup_<마켓>.jsonl`. 저장 뒤 다시 불러와 위 최종 상태와 하나라도 다르면 실패로 셈.
6. **마무리 확인** `status.py 25-1` — 스토어 비즈 300 · 모두 (판매중, 전시중지, 100, 100) · 불사자 잠금 300.

## 보고 형식 (한글·반말·비개발자 말로)

마켓별 한 줄: `25-1: 한도 1000 / 삭제 90 / 업로드 300 (제외 0) / 세팅 300 / 잠금 300 / 최종 등록 950`.
실패·제외가 있으면 몇 개·왜만 덧붙인다.

## 함정

- 목록 조회의 업로드 상태는 늦게 반영될 수 있다. 스토어 건수가 정본.
- 국내 출고지가 여러 개라도 주소가 같으면 "상품출고지"를 쓴다. 주소가 서로 다르거나 기본 묶음그룹이 둘 이상이면 `store_fix.py`가 멈춘다 → 사람에게 확인.
- 1-2처럼 다른 PC에서 이미 100원·10% 할인·전시중으로 바꿔 둔 마켓이 있다. 스킬 기준(할인 없음·전시중지)으로 덮어쓴다.
- 마켓마다 가격 구조가 다르다. 25-1은 옵션가가 전부 0원이었지만, 1-3 등은 옵션마다 0/2,100/3,700원처럼 차이가 있다. 네이버는 옵션가를 판매가의 100%까지만 허용(100원이면 0~100원)해서 저장이 400으로 거절된다 → `store_fix.py`가 판매가보다 큰 옵션가를 0으로 맞춘다(원래 옵션가는 backup에 있음). 즉 100원 세팅이면 옵션 상관없이 전부 100원이 된다.
- 한 번에 많이 삭제하면 불사자가 "일부만 처리"(PARTIAL)로 답하는데, "대기열 접수됨"인 건 실제로 지워진다. 50개씩 나눠 넣고 접수된 건 성공으로 센다.
- 네이버가 나중에 등록불가로 바꾼 태그 단어(예: "서브")가 있으면 저장이 거절된다 → 그 태그만 빼고 저장한다.
- 여러 마켓은 `run_all.py <동시 수>`로. 결과는 `data/run_all.jsonl`, "완료"가 아닌 마켓은 다시 돌리면 그 마켓만 다시 한다.
- 트래픽 조회는 빨리 부르면 429(요청 과다). 스크립트가 기다렸다 다시 하고, 조회 결과는 `data/traffic_<마켓>.json`에 쌓여 이어서 돈다.
- 유입 0인 상품은 거의 없다(봇 조회로 1회가 흔함). 유입 1회 이하면 사실상 유입 없음.
