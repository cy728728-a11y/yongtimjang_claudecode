# 불사자 카테고리 교정 (셀하 기준)

불사자 상품의 잘못된/미설정 카테고리를 **네이버 정답 카테고리**로 교정하는 스킬.

핵심 아이디어: **셀하(sellha.kr)** 가 상품명(또는 키워드)이 속한 네이버 카테고리 경로를
`생활/건강 > 공구 > 원예공구 > 농기계` 처럼 보여준다(아이템스카우트와 달리 **확장 프로그램 없이** 렌더).
그 경로의 **최종 차수(예 `농기계`)** 를 불사자 카테고리 검색에 넣으면 동일 경로가 나오고, 그걸로 저장한다.
셀하 = 네이버 카테고리이므로, 불사자 스마트스토어 후보의 전체 경로가 셀하 경로와 **정확히 일치**한다 → 매칭이 자명.

> **제안 우선(proposal-first) + 자동 승인 예외**: 카테고리는 실판매 데이터다. 기본은 상품별 `이전→제안`
> 표/시트를 보여주고 **이룸님 승인 후에만** 저장한다.
> **자동 승인(이룸님 확정 2026-07-12, 임계 70으로 하향 2026-07-24)**: 상태가 `변경대상`이고
> **셀하 확신도 ≥ 70%** 인 건은 이전
> 카테고리 유무와 무관하게 **승인 없이 바로 저장**한다. 확신도 70% 미만, 그리고
> `부분일치확인요`/`매칭불가`/`sellha조회실패`는 자동 저장하지 않고 제안표로 수동 승인·보류한다.
> **마켓 범위(이룸님 확정, 2026-07-12)**: 저장은 전 마켓 동시 반영(쿠팡 포함)으로 그대로 진행한다
> — 도구가 스마트스토어 단독 저장을 지원하지 않으므로. 이룸님은 스마트스토어 기준으로 검증한다.

## Workflow

### Step 1. 대상 상품 수집
대상 상품 ID를 모으는 경로 두 가지:
- **(A) 시트 A열에서 읽기 (기본, 마켓그룹 단위 작업)**: 이룸님이 `카테고리교정_<마켓그룹명>` 시트 A열에
  상품 ID를 채워둔다 → `gws sheets spreadsheets values get` 으로 A·G(상태)열을 읽어 대상 확보.
- **(B) 불사자 MCP 조회**: `bulsaja_product_list`(keyword/최신순) 또는 `bulsaja_product_find_by_code`.

- **재개 스킵(중단·재개 안전장치)**: 시트에서 **`상태`(G열)가 이미 채워진 행은 건너뛴다.**
  `자동저장완료`/`저장완료`/`이미정확`/`매칭불가`/`sellha조회실패`/`부분일치확인요`/`보류(정체불명)`/`승인보류`
  = 1바퀴 처리가 끝난 것(뒤 3개는 후처리 큐로 따로 소진한다).
  **`상태`가 빈 상품 ID만** Step 2~6을 돌린다. → PC를 덮었다 켜도 처음부터 다시 하지 않고 이어서 진행.
- **소수 테스트 기본**: 처음엔 3~5개로 검증 후 확대(이룸님 확정 사항).
- 각 상품에서 `productId` 와 `상품명` 을 추린다.

### Step 2. 현재(이전) 카테고리 읽기 (불사자 MCP)
각 `productId` → `bulsaja_product_workdata(mode="full")` →
`data.uploadCategory.ss_category` 의 `name`(스마트스토어 현재 카테고리).
- `name` 이 빈 문자열이면 **"미설정"** (= 이전 카테고리 없음).
- 이 값이 로그의 **이전 카테고리** 컬럼.

### Step 3a. 실물 정체 판별 → 대표 검색어 추출 (기본, 2026-07-24 개편)

**한국어 상품명은 정답지가 아니라 용의자다.** 상품명·썸네일은 둘 다 불사자 가공 **후** 산출물이라
**같이 틀린다.** 그래서 가공 **전** 원본(**②중국어 원문명·③옵션명**)을 독립 증거로 함께 본다.
증거 4종(①한국어 상품명 ②중국어 원문명 ③옵션명 ④썸네일)은 추가 호출 비용 없이 `prep` 이
`names.json` 으로 모아 넘긴다(②③은 `workdata` 응답에, ④는 `prep` 이 전건 미리 받아둠).

증거 4종을 종합해 **A 일치 / B 정정확정 / C 정체불명** 셋 중 하나로 판정한다.
- **A·B** → 실물 기준 대표 검색어 도출 → 셀하. **B는 미루지 않고**(셀하 두 번 방지) `실물판정` 기재.
- **C** → `상태:"보류(정체불명)"`, 셀하를 태우지 않고 2바퀴(Step 3b)로. **조금이라도 애매하면 C.**

#### 위임 — 하네스-무관 팬아웃

정체판별(Step 3a)은 자기완결 청크(`names.json`)에 대한 병렬 작업이다. **디스크 우선 설계**라
워커 띄우는 수단만 하네스별로 다르다(상태저장소 = `keywords.json` + 시트 G열, 멱등):
- **모드 A — Claude Code**: `Agent` 도구로 Sonnet 서브에이전트 팬아웃. 각자 청크 Read → `kwout_i.json` Write.
- **모드 B — 하네스-무관(코덱스 등, 서브에이전트 없음)**: `names.json`(또는 청크 파일들)을 인덱스
  범위로 K등분 → K개 독립 프로세스가 자기 범위만 처리. 서브에이전트 프리미티브 불필요.
- **재개**: `kwout_i.json`(또는 `keywords.json`의 그 productId) 있으면 완료. 겹쳐 돌려도 멱등.

> **증거 4종 상세·실증·판정 기준·대표검색어 12규칙 프롬프트 전문(실측 튜닝)·예시 →
> [`references/대표검색어-도출.md`](references/대표검색어-도출.md).**
> 이 파일은 `product-name` 스킬도 실물 판정에 함께 참조하는 **공유 자산**이다(원문 그대로 유지).

`keywords.json` 출력 형식:
```json
[{"productId":"U01...","name":"차량용 유압자키","실물판정":"자키+에어펌프+전동렌치 세트",
  "근거":"원문 千斤顶+充气泵+电动扳手, 옵션 전건 동일"},
 {"productId":"U01...","상태":"보류(정체불명)","실물판정":"","근거":"원문=조명, 옵션=거치대, 썸네일 판독 불가"}]
```

#### 대표 검색어 추출 (판정한 실물 → 검색어)

**원문 상품명을 그대로 넣지 않는다.** 판정한 실물 기준으로 **대표 검색어**(분야 한정어를 붙인
2단어 이상)를 뽑는다. 단일 넓은 단어는 대중 분야(자동차·주방·미용)로 오검색되므로 분야를 못 박아야
확신도가 오른다(실측: 1인용소파 34%→원목 라운지체어 100%).

> **12규칙 프롬프트 전문·예시 → [`references/대표검색어-도출.md`](references/대표검색어-도출.md)** (실측 튜닝, 원문 유지).
> 규칙 10(상품명에 없는 속성 추측 금지)은 지키되, **원문·옵션에서 확인된 구성은 추측이 아니다.**

각 상품 `{productId, 핵심어}` 를 JSON으로 만들어 셀하 스크래퍼에 넘긴다(한 번 로그인 후 일괄):
```bash
# 입력 예: [{"productId":"UB36...","name":"브레이크패드"}, {"productId":"UB37...","name":"미니오두막"}, ...]
#   ("name" 필드에 원문이 아니라 도출한 핵심어를 넣는다)
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe \
  .claude/skills/sellha-category/scripts/sellha.py \
  --input <입력.json> --output <결과.json> --headless
```

- 항목별 반환: `productId · 검색어 · 카테고리경로 · 최종차수 · 확신도 · 상태 · error`
- `상태`: `성공` | `조회실패`(검색결과 없음) | `파싱실패` | `로그인실패`
- 검색에 쓴 핵심어를 **Step 5 `검색어(사용)` 열에 반드시 기재**.
- 애드혹 조회는 `--query "키워드1" "키워드2"` (productId 없이).

#### 인자
| 인자 | 설명 |
|------|------|
| `--input`, `-i` | 배치 입력 JSON: `[{"productId","name"}]` (`name`=도출한 핵심어) |
| `--query`, `-q` | 키워드 직접 조회(공백 구분 다수) |
| `--output`, `-o` | 결과 JSON 저장(미지정 시 콘솔) |
| `--headless` | Chrome 창 숨김(로그인·조회 헤드리스 OK) |

### Step 3b. 2바퀴 — `보류(정체불명)` 큐 증거 보강 (한 바퀴 다 돈 뒤)

**중간에 멈추지 않는다.** 1바퀴(A·B)를 전건 다 돌린 뒤 C 큐만 모아서 처리한다.
그래야 ① 판단이 동질적인 뭉치에 집중되고 ② 그 그룹이 어떤 상품군인지 이미 파악된 상태에서 본다.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe \
  .claude/skills/bulsaja-category-fix/scripts/run_all.py recheck \
  --run-dir "D:/python_work/data/category-fix/runs/<이름>"
```
`keywords.json` 에서 `상태`가 `보류…` 인 건을 자동으로 추려 **이미지 사다리**를 싼 것부터 내려받는다
(`--ids` 로 직접 지정도 가능). 산출: `recheck.json` + `recheck/` 이미지.

**이미지 사다리 (싼 것부터)**:
1. **남은 썸네일 2·3장** — `workdata` 가 이미 6장까지 받아둔 URL이라 **사실상 공짜**. 여기서 상당수 풀린다.
2. **옵션 이미지** (`uploadSkus[].urlRef`, 최대 3장) — 옵션은 실물 변형이라 정체가 드러난다.
   **상세페이지 원본 이미지에 가장 가까운 소스**다.
3. 그래도 불명 → **이룸님께 보고**. 혼자 추측해서 엉뚱한 카테고리에 넣지 않는다.

> **상세페이지 이미지 자체는 안 쓴다.** `workdata` 의 `uploadDetailContents.renderContent` 는 비어 있어
> 별도 호출·타오바오 직크롤이 필요하고, 상품당 수십 장 세로 이미지라 대량에는 비현실적이다.
> 옵션 이미지가 그 대용이며, 원문명·옵션명(텍스트)이 이미 상세페이지와 **같은 소스**다.

**절차**: `recheck.json` 의 `추가이미지` 경로를 **Read 로 열어 직접 본다** → 원문명·옵션명원문과 종합해
실물 확정 → Step 3a 12규칙으로 검색어 재도출 → `keywords.json` 의 해당 건을 갱신(`상태` 제거 + `name` 기재)
→ `finish` 재실행(셀하 `--resume` 라 기존 성공분은 재조회하지 않는다).

### Step 4. 최종 차수 → 불사자 매칭 (불사자 MCP)
셀하 `최종차수` 를 `bulsaja_product_category(keyword=최종차수)` 로 조회 →
`마켓별후보.스마트스토어` 후보 중 **전체 경로가 셀하 경로와 일치**하는 것을 고른다.
- 경로 정규화: 양쪽 모두 `>` 주변 공백 제거 후 비교
  (셀하 `생활/건강 > 공구 > 원예공구 > 농기계` ↔ 불사자 `생활/건강>공구>원예공구>농기계`).
- **정확 일치** → 그 카테고리로 확정.
- 최종차수는 같은데 상위 경로가 다르면(동명 카테고리) → **부분일치**로 플래그.
- 후보가 없으면 → **매칭불가** 플래그.

> 부분일치·매칭불가라고 바로 포기하지 않는다. 아래 **저장 4단계 폴백**으로 최대한 저장한다(2026-07-17 확립).

## 저장 4단계 폴백 (2026-07-17, 987건 전량 완주로 확립)

**핵심 원리**: `bulsaja_product_category` 는 **keyword 자동매칭만** 지원한다(카테고리 code 직접지정 불가).
자동매칭 = keyword 검색 스마트스토어 후보의 **1순위**. 그래서 동명 최종차수(leaf)를 그대로 넣으면
엉뚱한 상위경로가 1순위로 잡혀 어긋난다(미용가위→반려동물, 기타튜닝용품→PC부품, 피규어→모형, 글러브→야구).
목표 셀하경로로 저장되게 하려면 **keyword를 조정**해 원하는 경로를 1순위로 끌어올려야 한다.

정확일치가 안 되는 부분일치·매칭불가 건은 아래 순서로 처리한다(각 단계 실패분만 다음 단계로):

**1단계 — leaf + 분야 한정어 유도 저장 (정확일치)**
목표 셀하경로 leaf 앞에 **상위 세그먼트(중/소분류) 핵심어**를 붙인 keyword로 `preview(confirm=False)` →
그 경로가 목표 셀하경로와 **정확일치**할 때만 commit. 정확일치만 저장하므로 안전.
- 예: `미용가위`(반려동물로 튐) → `헤어 미용가위`(뷰티소품 1순위), `기타튜닝용품`(PC부품) → `자동차 기타튜닝용품`, `글러브`(야구) → `권투 글러브`, `천막` → `캠핑 천막`.
- 스크립트: `category_steer.py --input steer.json --sheet <id>` (mode 기본 exact).
  입력 `[{productId,row,target=목표셀하경로,keyword?}]`. leaf의 `/`(예 `인테리어파티션/가벽`)는 각 조각도 후보로.
- 자동 candidate가 leaf를 못 부르면(짧은 leaf `볼`, 검색랭킹에 형제가 이김) 그 건만 2단계로.

**2단계 — 실물 재확인 후 재검색 저장**
1단계도 안 되거나 확신도가 낮으면 **원문명·옵션명·추가 이미지로 실물을 다시 파악**(Step 3b `recheck`) →
대표 검색어 재도출 → 셀하 재조회(`sellha.py`) → 새 경로로 1단계 유도 저장.
- 상품명이 실제 상품을 오해시키는 경우가 매우 많다(실증: `아이스컵뚜껑`=계량컵, `이사 컨베어`=방수타포린,
  `키링메달`=시상메달, `원목기타`=완구기타, `요골 부목 운동기구`=손목보호대). **실물 증거가 결정적.**
- 절차: `run_all.py recheck --run-dir <R> --ids <id...>` → `recheck.json` 의 이미지·원문명·옵션명 확인 →
  실제 검색어로 `sellha.py --input <재조회.json>` → `category_steer.py` 저장.

**3단계 — 유사(근접) 카테고리 저장**
목표 셀하경로가 **불사자 카테고리 체계에 아예 없거나**(셀하가 더 세분화됨) leaf가 keyword로 도달 불가하면,
같은 계열의 **근접 카테고리**로 저장한다. `category_resolve(경로)` 로 존재여부를 먼저 확인.
- 부재 실증: `음향가전>이어폰/이어셋>유선이어폰/이어셋`(4단) → 불사자엔 `음향가전>이어폰`(3단)까지만.
  `청소기>청소기부속품` → 불사자에 없음. `피규어` leaf → keyword가 형제 `모형/다이캐스트`로만.
- 근접 저장: `category_steer.py` 입력에 `mode:"near"`, `keyword:"근접 유도어"` → 정확일치 무시하고 저장,
  시트 **I열에 `근접저장(셀하≠불사자)` 플래그** 로 남겨 사후 구분 가능하게.
- **근접 저장은 이룸님 승인 사항**(셀하 정확경로가 아니므로). 근접조차 애매하면 4단계로.

**4단계 — 보고 (이룸님 수동지정)**
1~3단계로도 못 맞추면 시트에 상태를 남기고 이룸님께 **목록으로 보고**한다. 이룸님이 불사자 UI에서 찾은
정확 경로를 알려주면, 그 경로를 `target` 으로 1단계(유도 저장)를 그대로 돌려 저장한다
(code 직접저장은 불가하나, 목표경로 leaf+한정어 유도로 대부분 저장됨. 실증: `식기>볼` → `샐러드볼 식기`).
- 상품 자체가 삭제되었거나 상품명↔썸네일이 모순이면 저장하지 않고 상태만 기록(예 `상품삭제(이룸님)`).

> 대량(수백~천 건)일 때: apply(1차 정확일치 자동저장) 이후 남은 `부분일치확인요`·`매칭불가` 큐를
> 위 1→2→3→4 순으로 후처리한다. 1단계는 `category_steer.py` 로 배치, 2단계 썸네일은 의심/잔류 건만 선별.

  **후속 `product-name` 스킬이 이 열을 읽어 재활용한다** — 썸네일을 다시 판독하지 않아도 되게.
  - **양방향 계약**: 이 스킬(v1.7.0~)이 J열을 채운다. **J열이 빈 구버전 그룹**은 후속
    `product-name`이 증거 4종으로 직접 판정한 뒤 **그 결과를 이 J열에 backfill**한다
    (J{row} 단일 셀 update — 다른 열 불변). 그래서 한 번 상품명 작업을 거친 구버전 그룹은
    다음부터 신버전처럼 J열 재활용이 된다.

    - `카테고리교정` folderId=`1bVa3y725YCCSrOtx_bqBylBpvaXvwm2w` ← 시트는 여기 생성

### Step 6. 승인 → 저장 (불사자 MCP)
**저장 분기 (2026-07-12 규칙)**:
- **자동 저장**: 상태=`변경대상` **AND 확신도 ≥ 70%** → 승인 없이 바로 저장. 시트 상태 `자동저장완료`.
  - 처리 전 "자동 저장 대상 N건 / 수동 검토 M건" 요약을 이룸님께 먼저 통보(진행은 막지 않음).
- **수동 승인**: 확신도 < 70% 인 `변경대상` → 제안표로 보여주고 승인받은 것만 저장. 상태 `저장완료`.
- **폴백 후처리**: `매칭불가`/`부분일치확인요`/`sellha조회실패` 는 여기서 끝이 아니라 **저장 4단계 폴백**
  (위 섹션)으로 넘겨 유도·실물재확인·근접 순으로 최대한 저장한다. `이미정확`/`승인보류` 만 최종 미저장.
- **`보류(정체불명)`**: 셀하를 안 태웠으므로 저장 대상이 아니다. **한 바퀴를 다 돈 뒤** Step 3b(`recheck`)로
  실물을 확정한 다음 다시 `finish` 를 태운다.

승인(자동/수동)된 행 저장:
```
bulsaja_product_category(productId=<id>, keyword=<셀하 최종차수>)
```
- 이 호출이 마켓 카테고리를 자동 매칭해 상품에 저장한다.
- **주의**: 이 저장은 **모든 마켓**(스마트스토어/쿠팡/ESM/11번가/해외직구)을 같은 키워드로 한꺼번에
  지정한다. **스마트스토어(ss_category)** 는 셀하 경로와 정확히 일치하지만, 쿠팡·해외직구 등 타 마켓은
  같은 키워드로 자동매칭돼 **부정확할 수 있다**(예: `농기계`→쿠팡 '사다리/운반용품'). 이룸님은 네이버
  셀러이므로 스마트스토어 기준으로 검증한다. 타 마켓까지 정밀히 맞추려면 마켓별로 별도 확인 필요.
- 저장 후 해당 행 상태를 `저장완료`로 갱신(구글시트도 갱신).
- `이미정확`/`sellha조회실패`/`매칭불가`/`부분일치확인요`는 **저장하지 않고** 상태만 기록.

## 중단·재개 안전장치 (2026-07-12)

이 스킬은 이룸님 PC에서 돈다 → **PC 절전/종료 시 그 자리에서 멈춘다**(클라우드 백그라운드 아님).
손실 없이 이어가기 위한 규칙:

1. **불사자 저장은 서버 즉시 반영** — 이미 `bulsaja_product_category` 로 저장된 카테고리는 PC를 꺼도 유지.
2. **시트가 체크포인트** — 상품 1건 처리가 끝날 때마다 그 행 `상태`(G열)를 **즉시 update**(Step 5).
3. **재개 = 상태 빈 것만** — 다시 실행하면 Step 1에서 시트 A·G열을 읽어 **`상태`가 채워진 행은 스킵**,
   빈 행만 Step 2~6 진행. 처음부터 다시 하지 않는다.
4. **중복 저장은 무해** — 혹시 같은 상품을 다시 저장해도 같은 키워드→같은 결과라 문제없음(멱등적).

재개 트리거 예: "25-2 카테고리 교정 이어서 해줘" → 해당 마켓 시트 로드 → 미완료 ID부터.

## 대량처리 파이프라인 (직접 HTTP MCP, 수백~수천 건)

수십 건 이상은 인라인(대화) 처리 불가 — `bulsaja_product_workdata`(~6KB+/건) 응답이 컨텍스트에
쌓여 토큰 초과. **불사자 MCP는 원격 HTTP 서버**(`~/.claude.json > mcpServers.bulsaja-yongssaem`:
`https://api.bulsaja.com/mcp` + Bearer)이므로, **파이썬이 대화 밖에서 JSON-RPC 직접 호출**해
무거운 조회·저장 응답을 스크립트 안에서 소비하고 요약만 파일·시트로 남긴다 → 컨텍스트 안 태움.

**스크립트** (`scripts/`):
- `bulsaja_mcp.py` — 원격 HTTP MCP 클라이언트. 토큰은 `~/.claude.json`에서 런타임 로드(출력 금지).
  서브커맨드: `probe`(실동작 검증) / `workdata`(현재카테고리 + **정체증거 4종** 요약:
  상품명·원문명·옵션명(8)·썸네일(6). 옵션명원문·옵션이미지·원본링크도 함께 보관) /
  `apply`(미리보기→경로비교→커밋 1패스 + 시트 건건기록, `--dry-run`/`--threshold`/`--sheet`).
  저장은 2단계 확인식: `confirm=False`(미리보기=천연 dry-run, 지정될카테고리+토큰) → `confirm=True`+토큰.
- `collect_targets.py` — 시트 A·G열 읽어 **G 빈 행만**(+행번호). `--limit`로 청크.
- `sellha.py` — 셀하 배치 조회. `--resume`(성공건 스킵, 증분저장)로 장시간 안전.
- `sheet_log.py` — 행 B:H update(건건 체크포인트). `gws_util.py`가 gws 호출(‘>’ 리다이렉트 회피 위해
  npm 셔임 대신 node로 run.js 직접 호출).
- `category_steer.py` — **저장 4단계 폴백의 유도 저장기**. 목표 셀하경로 leaf+분야한정어 candidate로
  preview→정확일치 commit(exact 모드), 또는 지정 keyword로 근접 commit(near 모드, I열 플래그).
  입력 `[{productId,row,target,keyword?,mode?}]`. apply 후 남은 부분일치·매칭불가 큐를 이걸로 저장.
- `run_all.py` — 3단계 오케스트레이터. 중간에 Claude 정체판별이 껴서 원샷 불가:
  - `prep --run-dir R [--limit N] [--skip-thumbs]`: collect → workdata → **썸네일 전건 다운로드**
    → `products.json` + `names.json`(증거 4종)
  - **(Claude/서브에이전트가 `names.json` 증거 4종 → `keywords.json`:
    `[{productId, name=대표검색어, 실물판정, 근거}]`, C는 `상태:"보류(정체불명)"`)**
  - `finish --run-dir R`: sellha(**보류 제외**, resume) → merge(products+keywords+sellha) → apply(실저장+시트)
  - `recheck --run-dir R [--ids ...]`: 2바퀴 — 보류 건의 남은 썸네일 + 옵션 이미지를 받아 `recheck.json`

**run-dir 은 `D:\python_work\data\category-fix\runs\<이름>\`** (이룸님 확정 2026-07-24).
그룹당 썸네일 ~1000장이라 스킬 폴더에 두면 git 레포가 부푼다 — `product-name` 스킬과 같은 디스크에 둔다.

**실행 순서**:
1. `bulsaja_mcp.py probe` — HTTP MCP 실동작 1순위 검증.
2. `run_all.py prep --run-dir D:/python_work/data/category-fix/runs/<날짜>` (또는 `--limit N` 청크).
3. `names.json` 증거 4종으로 **정체 판별 + 키워드 추출**(Step 3a). 수백 건은 팬아웃으로 분담 —
   각 청크 파일 Read + **썸네일경로를 Read 로 열어봄** → `kwout_i.json` Write → 병합 `keywords.json`.
   위임 수단(Claude 서브에이전트 / 코덱스 등 다중 프로세스)은 **§Step 3a 참조.**
   **★키워드 규율(파일럿 교훈)**: 상품 고유 명사를 넓은 category성 단어로 바꾸지 말 것. 분야 한정어만
   '추가'. (오답 예: 침대안전바→"보행보조기"(보행차로 튐), 조바이스→"바이스클램프"(홀딩클램프로 튐).)
4. `run_all.py finish --run-dir <R>` — sellha(~15s/건, 백그라운드) → apply.
   apply가 확신도≥임계(기본 70) AND 경로정확일치만 자동 커밋, 나머지는 시트에 상태만 남겨 수동 큐.
5. **2바퀴**: `run_all.py recheck --run-dir <R>` → 이미지 확인 → `keywords.json` 갱신 → `finish` 재실행.
6. 재개: 시트 G가 체크포인트 → 다시 prep 하면 다음 청크 자동. sellha는 `--resume`.

**리스크(파일럿 확인)**: 셀하 확신도 100%여도 키워드가 상품을 잘못 대표하면 **확신에 찬 오답**.
확신도는 "키워드↔카테고리"이지 "키워드↔상품"이 아님. 방어 =
**증거 4종 정체판별**(2026-07-24, 최대 방어선) + 키워드 규율 + `매칭불가`(전체경로 불일치 자동차단)
\+ <70% 수동보류 + `보류(정체불명)` 2바퀴.
> **개편 전 이 자리엔 "썸네일 전수확인은 대량엔 비현실적"이라 적혀 있었다.** 그래서 의심 건만 봤고,
> **상품명·썸네일이 함께 틀린 건은 의심조차 안 됐다.** 지금은 원문명·옵션명이 텍스트라 전건 확인이
> 사실상 공짜이고, 썸네일도 어차피 후속 `product-name` 이 전건 여니 여기서 한 번에 처리한다.

**결과 검토 기준 (2026-07-16 이룸님 확정)**: 네이버 가격비교(셀하가 미러링) 카테고리는 **의미론적
실질이 아니라 빅데이터 업로드 분포** — "사람들이 그 키워드 상품을 실제로 어느 카테고리에 많이 올렸나".
이 스킬 목적이 곧 "네이버가 실제 노출하는 카테고리 맞추기"이므로 **카테고리가 의미상 이상해 보인다는
이유로 오답 판정하지 말 것**(예: 뷔페워머기→식기>접시, 수심측정기→낚시 어탐기 — 이룸님이 대표키워드
가격비교 1페이지로 검증, 전부 정답). **진짜 오답 = 대표키워드(검색어)가 상품을 잘못 대표한 것만**
(keyword↔product mismatch). 검토 시 카테고리↔상품이 아니라 **검색어↔상품명(필요시 썸네일)** 을 대조한다.
대분류변경(I열)도 오답 신호 아님. [[naver-price-category-is-bigdata]]
