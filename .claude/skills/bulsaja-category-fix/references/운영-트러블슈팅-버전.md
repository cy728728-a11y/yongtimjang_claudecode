# 불사자 카테고리 교정 — 동작 원리 · 트러블슈팅 · 버전 이력

> SKILL.md 에서 분리한 안정·참조성 섹션(리팩터 Step6b). 운영 중 필요할 때 연다.
> 관련: [[bulsaja-category-fix-skill]] · [[대표검색어-도출]]

## 동작 원리 (조회 스크립트, 2026-08-04 Aside 전환)

1. `aside repl` 로 **이미 떠 있는 Aside 브라우저에 붙는다**(셀레늄·별도 크롬 실행 없음).
   로그인 절차가 없다 — 이룸님 브라우저 세션의 네이버 로그인을 그대로 쓴다.
2. 조회용 탭은 Aside 앱 안에 열렸다가 세션이 끝나면 사라진다.
3. 카테고리 조회는 **네이버 가격비교 직접 진입**:
   `search.shopping.naver.com/search/all?query=<검색어>`
4. 불사자 확장이 그린 `추출된 카테고리` 블록에서 `N순위 대분류 > … > 최종` 을 파싱한다.
   확장 UI 는 **shadow DOM**(Plasmo, `PLASMO-CSUI`) 안이라 `document.body.innerText` 로는 안 잡힌다 —
   shadow root 를 재귀로 훑어야 한다. 최종차수 = 1순위 경로를 `>`로 나눈 마지막 조각.
5. 확신도는 확장이 안 주므로 **1페이지 상품들의 카테고리 분포를 직접 센다.**
   네이버가 지연 로딩이라 스크롤 없이는 상품이 4~7개만 DOM 에 있다 → `End` 키로 끝까지 내린 뒤 집계.

(조회 스크립트는 `aside-category` 스킬로 분리됨 — `skills/aside-category/scripts/aside_category.py`.
 구버전 셀하 스크립트는 `skills/sellha-category/` 에 남아 있으나 **막혀서 못 쓴다**.)

## 트러블슈팅

- **전건 `파싱실패(확장 패널 미검출)`**: 순서대로 본다 — ① Aside 앱이 떠 있나 ② 불사자 확장이
  Aside 에 설치·활성인가 ③ 네이버 로그인이 살아 있나. 그 다음에야 파싱 로직을 의심한다.
  브랜드 키워드/신조어는 카테고리가 없을 수 있음(정상적인 `조회실패`).
- **`차단감지`·`캡챠감지`**: 남은 건을 건드리지 않고 즉시 중단한다. 캡챠는 `captcha-relay` 스킬로
  푼다 — 화면을 찍어 Aside 에게 답만 물어보고(공유 폴더 릴레이), 입력·제출은 Claude 가 한다.
  Claude 가 스스로 답을 추론해 넣지 않는다. 푼 뒤 `--resume`. 차단은 시간을 두고 `--resume`.
  실물 캡챠는 "보안 확인을 완료해 주세요" **영수증 퀴즈형**이라 본문에 `captcha` 문자열이 없다 —
  `driver.js` 의 `input[name*="captcha"]` 셀렉터만 잡으므로 그 조건을 지우면 `파싱실패`로 뭉개진다.
  sleep 을 0 으로 줄이면 몇 건 만에도 뜬다(기본 1~3초를 낮추지 말 것).
- **`finish` 가 조회 0건으로 죽는다** (`fetch failed: other side closed` → `결과가 비어 있다` →
  `RuntimeError: aside_category.py 실패 (exit 1)`): `aside repl` 의 **호출당 ~120초 하드 리밋**이다.
  한 호출에 넣은 건수 × ~9.4초가 120초를 넘으면 **그때까지 조회한 것까지 전부 유실**된다.
  현재는 `aside_category.py` 가 자동 청크 분할(≈7건/호출)로 막고 있으므로, 이 증상이 다시 보이면
  **건당 소요가 늘어난 것**을 의심한다(네이버 지연 로딩·스크롤). `--chunk` 를 낮춰 재실행.
  진단 전문 → [`aside-category/SKILL.md` §120초 벽](../../aside-category/SKILL.md).
- **`finish` 재실행이 후처리 기록을 덮어쓴다 (2026-08-04 실측 → ★v1.8.3 에서 종결·수정됨)**:
  옛 `apply` 는 `decisions.json` 전 건의 시트 `B:K` 를 덮어써서, `steer`·근접·consensus 로
  `저장완료` 가 된 행이 원래 판정값으로 회귀했다(실측 `저장완료` 75→18. 불사자 서버 저장은
  무사, 시트 원장만 거짓). **현행 `apply` 는 시트 G열을 먼저 읽어 완료 4종
  (`matrix.CATFIX_DONE`)을 건너뛰므로 재실행이 안전하다** — 회귀 테스트 15건(§v1.8.3).
  일부러 덮어쓰려면 `--overwrite-done`(재교정 필수 플래그)만 그 보호를 뚫는다.
- **불사자 매칭 안 됨**: 최종차수 이름이 애매/동명이면 `부분일치`·`매칭불가`로 뜬다 → **저장 4단계 폴백**
  (leaf+분야한정어 유도 → 썸네일 재검색 → 근접 → 보고)으로 처리. `category_steer.py` 로 배치 유도.
- **동명 카테고리**: 최종차수가 여러 상위경로에 존재 → 자동매칭이 1순위(엉뚱한 상위)를 고른다.
  leaf 앞에 상위 분야 한정어를 붙여 원하는 경로를 1순위로 끌어올린다(폴백 1단계).
- **조회 경로가 불사자에 없음**: `category_resolve(경로)` 가 실패하면 불사자 체계에 그 경로가 없는 것
  (네이버가 더 세분화). 근접 카테고리로 저장(폴백 3단계, `mode:"near"`) 하거나 이룸님께 보고.
- **짧은 leaf 도달 불가**(`볼`·`솔` 등 1~2글자): 검색 랭킹에서 형제·타 카테고리에 밀린다 → 상위 한정어
  조합(`샐러드볼 식기`)이나 동의어(`믹싱볼`)로 유도. 그래도 안 되면 이룸님 지정 경로로 재시도.
