# 저장 4단계 폴백 · 대량처리 파이프라인

> 본체: [`../SKILL.md`](../SKILL.md). 이 파일은 **정확일치가 안 될 때의 저장 전략**과
> **수백~수천 건 배치 실행 방법**을 담는다. 소량(수십 건 이하) 작업에서는 열 필요가 없다.

## 저장 4단계 폴백 (2026-07-17, 987건 전량 완주로 확립)

**핵심 원리**: `bulsaja_product_category` 는 **keyword 자동매칭만** 지원한다(카테고리 code 직접지정 불가).
자동매칭 = keyword 검색 스마트스토어 후보의 **1순위**. 그래서 동명 최종차수(leaf)를 그대로 넣으면
엉뚱한 상위경로가 1순위로 잡혀 어긋난다(미용가위→반려동물, 기타튜닝용품→PC부품, 피규어→모형, 글러브→야구).
목표 조회경로로 저장되게 하려면 **keyword를 조정**해 원하는 경로를 1순위로 끌어올려야 한다.

정확일치가 안 되는 부분일치·매칭불가 건은 아래 순서로 처리한다(각 단계 실패분만 다음 단계로):

**1단계 — leaf + 분야 한정어 유도 저장 (정확일치)**
목표 조회경로 leaf 앞에 **상위 세그먼트(중/소분류) 핵심어**를 붙인 keyword로 `preview(confirm=False)` →
그 경로가 목표 조회경로와 **정확일치**할 때만 commit. 정확일치만 저장하므로 안전.
- 예: `미용가위`(반려동물로 튐) → `헤어 미용가위`(뷰티소품 1순위), `기타튜닝용품`(PC부품) → `자동차 기타튜닝용품`, `글러브`(야구) → `권투 글러브`, `천막` → `캠핑 천막`.
- 스크립트: `category_steer.py --input steer.json --sheet <id>` (mode 기본 exact).
  입력 `[{productId,row,target=목표조회경로,keyword?}]`. leaf의 `/`(예 `인테리어파티션/가벽`)는 각 조각도 후보로.
- 자동 candidate가 leaf를 못 부르면(짧은 leaf `볼`, 검색랭킹에 형제가 이김) 그 건만 2단계로.

**2단계 — 실물 재확인 후 재검색 저장**
1단계도 안 되거나 확신도가 낮으면 **원문명·옵션명·추가 이미지로 실물을 다시 파악**(Step 3b `recheck`) →
대표 검색어 재도출 → 재조회(`aside_category.py`) → 새 경로로 1단계 유도 저장.
- 상품명이 실제 상품을 오해시키는 경우가 매우 많다(실증: `아이스컵뚜껑`=계량컵, `이사 컨베어`=방수타포린,
  `키링메달`=시상메달, `원목기타`=완구기타, `요골 부목 운동기구`=손목보호대). **실물 증거가 결정적.**
- 절차: `run_all.py recheck --run-dir <R> --ids <id...>` → `recheck.json` 의 이미지·원문명·옵션명 확인 →
  실제 검색어로 `aside_category.py --input <재조회.json>` → `category_steer.py` 저장.

**3단계 — 유사(근접) 카테고리 저장**
목표 조회경로가 **불사자 카테고리 체계에 아예 없거나**(네이버가 더 세분화됨) leaf가 keyword로 도달 불가하면,
같은 계열의 **근접 카테고리**로 저장한다. `category_resolve(경로)` 로 존재여부를 먼저 확인.
- 부재 실증: `음향가전>이어폰/이어셋>유선이어폰/이어셋`(4단) → 불사자엔 `음향가전>이어폰`(3단)까지만.
  `청소기>청소기부속품` → 불사자에 없음. `피규어` leaf → keyword가 형제 `모형/다이캐스트`로만.
- 근접 저장: `category_steer.py` 입력에 `mode:"near"`, `keyword:"근접 유도어"` → 정확일치 무시하고 저장,
  시트 **I열에 `근접저장(셀하≠불사자)` 플래그** 로 남겨 사후 구분 가능하게.
- **근접 저장은 Claude 판정으로 자동 저장한다**(2026-08-06 이룸님 — 세분화 차이만 허용, 종합보고 전수 목록 필수). 근접조차 애매하면 4단계로.

**4단계 — 보고 (이룸님 수동지정)**
1~3단계로도 못 맞추면 시트에 상태를 남기고 이룸님께 **목록으로 보고**한다. 이룸님이 불사자 UI에서 찾은
정확 경로를 알려주면, 그 경로를 `target` 으로 1단계(유도 저장)를 그대로 돌려 저장한다
(code 직접저장은 불가하나, 목표경로 leaf+한정어 유도로 대부분 저장됨. 실증: `식기>볼` → `샐러드볼 식기`).
- 상품 자체가 삭제되었거나 상품명↔썸네일이 모순이면 저장하지 않고 상태만 기록(예 `상품삭제(이룸님)`).

> 대량(수백~천 건)일 때: apply(1차 정확일치 자동저장) 이후 남은 `부분일치확인요`·`매칭불가` 큐를
> 위 1→2→3→4 순으로 후처리한다. 1단계는 `category_steer.py` 로 배치, 2단계 썸네일은 의심/잔류 건만 선별.

## 대량처리 파이프라인 (직접 HTTP MCP, 수백~수천 건)

수십 건 이상은 인라인(대화) 처리 불가 — `bulsaja_product_workdata`(~6KB+/건) 응답이 컨텍스트에
쌓여 토큰 초과. **불사자 MCP는 원격 HTTP 서버**(`~/.claude.json > mcpServers.bulsaja`:
`https://api.bulsaja.com/mcp` + Bearer)이므로, **파이썬이 대화 밖에서 JSON-RPC 직접 호출**해
무거운 조회·저장 응답을 스크립트 안에서 소비하고 요약만 파일·시트로 남긴다 → 컨텍스트 안 태움.

**스크립트** (`scripts/`):
- `bulsaja_mcp.py` — 원격 HTTP MCP 클라이언트. 토큰은 `~/.claude.json`에서 런타임 로드(출력 금지).
  서브커맨드: `probe`(실동작 검증) / `workdata`(현재카테고리 + **정체증거 4종** 요약:
  상품명·원문명·옵션명(8)·썸네일(6). 옵션명원문·옵션이미지·원본링크도 함께 보관) /
  `apply`(미리보기→경로비교→커밋 1패스 + 시트 건건기록, `--dry-run`/`--threshold`/`--sheet`).
  저장은 2단계 확인식: `confirm=False`(미리보기=천연 dry-run, 지정될카테고리+토큰) → `confirm=True`+토큰.
- `collect_targets.py` — 시트 A·G열 읽어 **G 빈 행만**(+행번호). `--limit`로 청크.
- `aside_category.py` — 카테고리 배치 조회(`aside-category` 스킬). `--resume`(성공건 스킵)로 장시간 안전.
- `sheet_log.py` — 행 B:H update(건건 체크포인트). `gws_util.py`가 gws 호출(‘>’ 리다이렉트 회피 위해
  npm 셔임 대신 node로 run.js 직접 호출).
- `category_steer.py` — **저장 4단계 폴백의 유도 저장기**. 목표 조회경로 leaf+분야한정어 candidate로
  preview→정확일치 commit(exact 모드), 또는 지정 keyword로 근접 commit(near 모드, I열 플래그).
  입력 `[{productId,row,target,keyword?,mode?}]`. apply 후 남은 부분일치·매칭불가 큐를 이걸로 저장.
- `run_all.py` — 3단계 오케스트레이터. 중간에 Claude 정체판별이 껴서 원샷 불가:
  - `prep --run-dir R [--limit N] [--skip-thumbs]`: collect → workdata → **썸네일 전건 다운로드**
    → `products.json` + `names.json`(증거 4종)
  - **(Claude/서브에이전트가 `names.json` 증거 4종 → `keywords.json`:
    `[{productId, name=대표검색어, 실물판정, 근거}]`, C는 `상태:"보류(정체불명)"`)**
  - `finish --run-dir R`: 카테고리 조회(aside — 코드상 단계 이름은 `sellha` 유지. **보류 제외**, resume) → merge(products+keywords+sellha) → apply(실저장+시트)
    - **원장 보호(2026-08-04)**: `apply` 는 시작할 때 시트 G열을 1회 읽어 **완료 행**
      (`저장완료`·`자동저장완료`·`이미정확`·`상품삭제…`)을 대상에서 뺀다. 후처리(`steer`·근접저장·
      consensus)로 저장된 행이 재실행에 되돌아가지 않는다. 전건 덮어쓰기는 `--overwrite-done`.
      시트 G열을 못 읽으면 **진행하지 않고 exit 4** — 조용히 덮어쓰느니 멈춘다.
  - `recheck --run-dir R [--ids ...]`: 2바퀴 — 보류 건의 남은 썸네일 + 옵션 이미지를 받아 `recheck.json`

**run-dir 은 `<데이터루트>/category-fix/runs/<이름>`** (`workspace.toml [paths].category_fix_runs`).
그룹당 썸네일 ~1000장이라 스킬 폴더에 두면 git 레포가 부푼다 — `product-name` 스킬과 같은 디스크에 둔다.

**실행 순서**:
1. `bulsaja_mcp.py probe` — HTTP MCP 실동작 1순위 검증.
2. `run_all.py prep --run-dir <데이터루트>/category-fix/runs/<날짜>` (또는 `--limit N` 청크).
3. `names.json` 증거 4종으로 **정체 판별 + 키워드 추출**(Step 3a). 수백 건은 팬아웃으로 분담 —
   각 청크 파일 Read + **썸네일경로를 Read 로 열어봄** → `kwout_i.json` Write → 병합 `keywords.json`.
   위임 수단(Claude 서브에이전트 / 코덱스 등 다중 프로세스)은 **§Step 3a 참조.**
   **★키워드 규율(파일럿 교훈)**: 상품 고유 명사를 넓은 category성 단어로 바꾸지 말 것. 분야 한정어만
   '추가'. (오답 예: 침대안전바→"보행보조기"(보행차로 튐), 조바이스→"바이스클램프"(홀딩클램프로 튐).)
4. `run_all.py finish --run-dir <R>` — 카테고리 조회(aside, ~10초/건, 백그라운드) → apply.
   apply가 확신도≥임계(기본 70) AND 경로정확일치만 자동 커밋, 나머지는 시트에 상태만 남겨 수동 큐.
5. **2바퀴**: `run_all.py recheck --run-dir <R>` → 이미지 확인 → `keywords.json` 갱신 → `finish` 재실행.
6. 재개: 시트 G가 체크포인트 → 다시 prep 하면 다음 청크 자동. 조회는 `--resume`.

**리스크(파일럿 확인)**: 확신도 100%여도 키워드가 상품을 잘못 대표하면 **확신에 찬 오답**.
확신도는 "키워드↔카테고리"이지 "키워드↔상품"이 아님. 방어 =
**증거 4종 정체판별**(2026-07-24, 최대 방어선) + 키워드 규율 + `매칭불가`(전체경로 불일치 자동차단)
\+ <70% 수동보류 + `보류(정체불명)` 2바퀴.
> **개편 전 이 자리엔 "썸네일 전수확인은 대량엔 비현실적"이라 적혀 있었다.** 그래서 의심 건만 봤고,
> **상품명·썸네일이 함께 틀린 건은 의심조차 안 됐다.** 지금은 원문명·옵션명이 텍스트라 전건 확인이
> 사실상 공짜이고, 썸네일도 어차피 후속 `product-name` 이 전건 여니 여기서 한 번에 처리한다.

**결과 검토 기준 (2026-07-16 이룸님 확정)**: 네이버 가격비교 카테고리는 **의미론적
실질이 아니라 빅데이터 업로드 분포** — "사람들이 그 키워드 상품을 실제로 어느 카테고리에 많이 올렸나".
이 스킬 목적이 곧 "네이버가 실제 노출하는 카테고리 맞추기"이므로 **카테고리가 의미상 이상해 보인다는
이유로 오답 판정하지 말 것**(예: 뷔페워머기→식기>접시, 수심측정기→낚시 어탐기 — 이룸님이 대표키워드
가격비교 1페이지로 검증, 전부 정답). **진짜 오답 = 대표키워드(검색어)가 상품을 잘못 대표한 것만**
(keyword↔product mismatch). 검토 시 카테고리↔상품이 아니라 **검색어↔상품명(필요시 썸네일)** 을 대조한다.
대분류변경(I열)도 오답 신호 아님. [[naver-price-category-is-bigdata]]
