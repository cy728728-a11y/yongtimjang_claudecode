# 카테고리 판정 워커 지시서 (팬아웃용)

> 이 문서 하나 + 배치 파일 경로만으로 **대화 맥락 없이 완주**할 수 있어야 한다.
> `catfix-fanout` Workflow 가 워커에게 이 파일을 Read 하라고 시킨다.
> **판정 규칙 전문은 [`대표검색어-도출.md`](대표검색어-도출.md)** — 이 문서는 절차만 담는다.

## §0. 도구 규율 (비용 규칙 — 어기면 배치당 토큰이 몇 배가 된다)

| 하지 말 것 | 왜 |
|---|---|
| `Grep`·`Glob` 로 파일 찾기 | 경로는 배치 파일에 전부 실려 있다 |
| 배치 파일·규칙 문서 **재독** | 한 번 읽었으면 컨텍스트에 있다 |
| 중간 요약을 대화에 출력 | 반환은 마지막 한 번. 워커의 말은 아무도 안 읽는다 |
| 썸네일을 **여러 번** 열기 | 이미지 1장 = 수백 토큰. 상품당 1회 |
| 불사자 MCP·셀하 호출 | 워커의 일이 아니다. 조회는 스크립트가 이미 끝냈다 |

**Write 는 배치당 정확히 1회** — `named/named_NNN.json` 하나만 쓴다.

## §1. 받는 것

배치 파일(`batches/batch_NNN.json`) 하나가 자기완결형이다.

```json
{"batch": 7,
 "규칙문서": "…/references/대표검색어-도출.md",
 "이미지수": 6,
 "products": [
   {"productId": "U01…", "row": 42,
    "상품명":   "자동차 전동 자키 받침대 오렌지 작키 …",   ← ① 용의자(가공 후)
    "원문명":   "沪工电动液压千斤顶12V多功能车载充气泵…",   ← ② 가공 전 원본
    "옵션명":   ["3톤 세단 모델잭에어펌프", "…"],            ← ③ 실제 판매 단위
    "썸네일경로": "D:/…/thumbs/U01….jpg"}                    ← ④ 눈으로 확인
 ]}
```

**증거 4종의 성격은 규칙문서 §증거 4종 표를 그대로 따른다.** 한국어 상품명은 정답이 아니다.

## §2. 하는 일 — 상품 1건당

1. **읽는다**: 상품명·원문명·옵션명 (텍스트 3종 먼저). 중국어는 번역 없이 직접 읽는다.
2. **본다**: 썸네일 `Read` 1회. **텍스트 3종만으로 이미 명확하면 열지 않는다**(이미지가 제일 비싸다).
3. **판정한다**: 규칙문서 §판정 3분류 — `A 일치` / `B 정정확정` / `C 정체불명`.
   **조금이라도 애매하면 C.** 억지로 찍지 않는다.
4. **대표 검색어를 뽑는다**(A·B만): 규칙문서 §대표 검색어 추출 프롬프트 12규칙 그대로.
   - 판정한 **실물** 기준. 원본 상품명을 그대로 넣지 않는다
   - **분야 한정어 + 핵심 명칭** 2단어 이상. 단일 넓은 단어는 대중 분야로 오검색된다
   - 브랜드·색상·크기·수량·호환기종 제거. 단 카테고리를 가르는 형태·구동방식은 남긴다
   - **상품 고유 명사를 넓은 category성 단어로 바꾸지 않는다** — 한정어만 '추가'한다
     (오답 실측: 침대안전바→"보행보조기", 조바이스→"바이스클램프")

## §3. 쓰는 것 — `named/named_NNN.json` (NNN = 배치번호, 0채움 3자리)

```json
{"batch": 7,
 "results": [
   {"productId": "U01…", "name": "차량용 유압자키",
    "실물판정": "자키+에어펌프+전동렌치 세트",
    "근거": "원문 千斤顶+充气泵+电动扳手, 옵션 전건 동일"},

   {"productId": "U01…", "상태": "보류(정체불명)",
    "실물판정": "", "근거": "원문=조명, 옵션=거치대, 썸네일 판독 불가"}
 ]}
```

- 배치의 **모든 상품이 results 에 있어야 한다.** 하나라도 빠지면 `merge` 가 누락으로 잡아
  그 배치가 통째로 재팬아웃된다
- `name` 은 A·B 판정에만. C는 `상태`만 쓰고 `name` 을 비운다
- **`실물판정` 은 비워 두지 않는다**(C 제외) — 후속 `product-name` 스킬이 이 값을 그대로
  재활용해 썸네일 재판독을 생략한다. 이게 두 스킬의 계약이다
- `근거` 는 한 줄. 어느 증거가 결정적이었는지만 적는다

## §4. 반환 (사람이 아니라 워크플로가 읽는다)

파일을 쓴 뒤, 배치별로 아래 형태의 구조화 결과만 반환한다.

```
{"batch": 7, "created": 6, "held_unclear": ["U01…"], "error": ""}
```

- `created` = `name` 을 채운 건수
- `held_unclear` = `보류(정체불명)` 로 넘긴 상품id
- 배치 파일을 못 읽었거나 도중에 실패하면 `error` 에 한 줄로 남긴다 — **거짓 성공 금지**

## §5. 실패했을 때

- 썸네일 파일이 없다 → 텍스트 3종만으로 판정. 애매하면 C
- 원문명·옵션명이 둘 다 비었다 → 상품명만으로는 근거가 부족하다. **C 로 보낸다**
- 배치 파일 자체가 안 읽힌다 → `error` 에 사유를 적고 그 배치는 파일을 쓰지 않는다
  (파일이 없어야 재팬아웃 대상이 된다)
