# 정합검사(audit) 판정 기준 — 기존 대표 vs 대표옵션

> `run_thumbs.py audit` 가 만든 `audit_batches/audit_batch_NNN.json` 을 판정하는
> 지시서다(Claude 직접 또는 팬아웃 워커). 이 문서 하나 + 배치 파일만으로 대화 맥락
> 없이 완주할 수 있어야 한다. **크레딧 0 — 어떤 MCP·생성 도구도 부르지 않는다.**
>
> 배경: `가공됨(cdn.bulsaja.com)` 은 "손을 댔다"는 뜻이지 "맞게 됐다"는 뜻이 아니다.
> 2026-08-05 실측(1-3 그룹 백필 419건 표본 30) 불일치 19건 = 68% — AI 배경교체가 색을
> 바꾸고 없던 것을 그려 넣는다(곰·로봇 손·장미·짐볼·의자·색상코드 글자).

## 받는 것

```json
{"배치": 1, "판정기준": "…/정합검사-판정기준.md", "products": [
  {"productId": "U01…", "상품명": "…", "대표옵션명": "3000W",
   "대표옵션이미지경로": "…/U01…_main_0.jpg",
   "현재대표": "https://cdn.bulsaja.com/…", "현재대표경로": "…/U01…_cur_0.jpg"}
]}
```

## 하는 일 — 상품 1건당

`대표옵션이미지경로` 와 `현재대표경로` 를 **각 1회** Read 하고 나란히 대조한다.
질문은 하나다: **현재 대표 썸네일이 대표옵션과 같은 물건인가.** `대표옵션명`(스펙·색
표기)도 판단 근거다 — 이미지끼리 비슷해도 표기 스펙이 다르면 불일치다.

| 판정 | 기준 |
|---|---|
| **불일치** | 다른 제품 / 색 다름 / 구성 개수 다름 / 없던 것 추가됨(소품·손·완성 연출) / 스펙 표기가 대표옵션과 다름(예: 대표옵션 3000W ↔ 썸네일 8500W) / **색상코드 등 글자가 박힘**(`#FEFA50` 류) |
| **일치** | 배경·각도·조명만 다름 — 제품 자체는 같다 |
| **대표옵션의심** | 어긋난 쪽이 썸네일이 아니라 **대표옵션이다** — 대표옵션 이미지가 `상품명` 이 가리키는 **본품이 아닌 모든 경우**. ①부속품·구성품 단독컷(실증: 상품명 `알루미늄캠핑박스` ↔ 대표옵션 `걸이형` = 타공 걸이판) ②**홍보 배너**(실증: `4행정 농업용 관리기` ↔ 대표옵션이 운동선수 모델 브랜드 배너) ③**구조 도식·치수도면**(실증: `벽걸이 위스키진열장` ↔ 대표옵션이 배관 구조 도식) ④색상칩·로고카드. 사유 필수 — 무엇이 본품이고 대표옵션이 무엇으로 보이는지 |
| **대조불가** | 이미지가 안 열림·형태가 달라 판단 자체가 불가 |

- 제품 차이를 '일치'로 낮추지 않는다 — 애매하면 불일치가 아니라 **대조불가**다.
- **불일치 판정 전에 방향을 본다**(2026-08-06): 현재 대표가 본품이고 대표옵션이 부속이면
  그건 불일치가 아니라 **대표옵션의심**이다 — 썸네일을 재작업해봐야 부속 기준으로 다시
  생성될 뿐, 옵션 단계가 대표를 복구해야 풀린다.
- ★ **판정값과 사유가 같은 쪽을 가리켜야 한다** (2026-08-19 2-2 3회차 실측 2건).
  `불일치` 는 **"썸네일이 틀렸다"**는 뜻이다. 사유에 "대표옵션이 배너다"·"대표옵션이
  도식이다"라고 써 놓고 판정값을 `불일치` 로 두면 값과 사유가 서로 다른 말을 하는 것이고,
  받는 쪽은 **같은 비제품 대표옵션을 기준으로 재생성만 반복한다**(무한 루프).
  결과를 쓰기 전에 스스로 물어라: **내 사유가 탓하는 쪽이 썸네일인가, 대표옵션인가.**
  대표옵션을 탓하고 있으면 판정값은 `대표옵션의심` 이다.
  위 실측 2건 모두 현재 대표는 실물이 맞았고 대표옵션 쪽이 비제품이었다 — 워커가 예시
  (부속 단독컷)에만 매칭하고 이 규칙을 적용하지 못했다. 그래서 예시를 넷으로 넓혔다.
- 대조불가는 재작업이 아니다(별도 집계) — audit --commit 이 flag 하지 않는다.
- 대표옵션의심은 audit --commit 이 **옵션 열 재작업 flag** 로 넘긴다(썸네일 열은 보류).

## 쓰는 것 — `audit_results/audit_result_NNN.json` (NNN = 배치번호, 0채움 3자리)

```json
{"배치": 1, "products": [
  {"productId": "U01…", "판정": "불일치", "사유": "대표옵션 3000W인데 8500W 표기"},
  {"productId": "U01…", "판정": "일치", "사유": ""},
  {"productId": "U01…", "판정": "대조불가", "사유": "옵션 이미지가 부속품 단독컷"}
]}
```

- 판정값은 `일치`/`불일치`/`대표옵션의심`/`대조불가` 넷뿐. **불일치·대표옵션의심은 사유
  필수**(그대로 현황판 재작업 문구에 실려 다음 prep·워커가 읽는다 — 구체적으로).
- 배치의 **모든 상품이 products 에 있어야 한다.**
- ⚠️ **`productId` 는 27자다. 배치의 `productId` 필드를 그대로 복사한다 — 이미지
  파일명에서 베끼지 마라.** 파일명 앞부분은 **24자로 잘린** 형태라 거기서 옮겨 적으면
  배치에 없는 id가 되고 그 상품의 판정은 버려진다(2026-08-14 verdict 축 실측 2건).
- Write 는 배치당 정확히 1회. 같은 이미지를 여러 번 열지 않는다.

## 다음 단계

전 배치 판정 후 `python run_thumbs.py audit --run-dir <R> --commit` —
불일치 → 재작업 flag(다음 prep 이 자동으로 다시 집어간다), 일치 → `완료(정합확인)`,
대조불가 → 집계만.
