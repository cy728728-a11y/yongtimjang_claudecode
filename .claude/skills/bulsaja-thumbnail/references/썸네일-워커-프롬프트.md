# 썸네일 워커 지시서 (팬아웃용)

> 이 문서 하나 + 배치 파일 경로만으로 **대화 맥락 없이 완주**할 수 있어야 한다.
> `thumb-fanout` Workflow 가 워커에게 이 파일을 Read 하라고 시킨다.
> **판단 규칙 전문은 배치의 `규칙문서`(배경생성-기본.md)** — 이 문서는 절차만 담는다.
> 배치는 **기본 모드 전제**다(레시피/정밀 모드는 팬아웃 대상이 아니다 — 수동 경로).

## §0. 도구 규율 (비용 + 안전 — 어기면 배치당 토큰이 몇 배가 되거나 크레딧이 샌다)

| 하지 말 것 | 왜 |
|---|---|
| `Grep`·`Glob` 로 파일 찾기 | 경로는 배치 파일에 전부 실려 있다 |
| 배치 파일·규칙 문서 **재독** | 한 번 읽었으면 컨텍스트에 있다 |
| 중간 요약을 대화에 출력 | 반환은 마지막 한 번. 워커의 말은 아무도 안 읽는다 |
| **`apply --generate`·스크립트·불사자 MCP 실행 절대 금지** | 자동반영 방어·복원·감사가 걸린 구간이라 메인만 부른다(워커가 부르면 복원 경로가 끊긴다) |
| 같은 이미지를 여러 번 열기 | 상품당 1패스 — 대표·후보를 한 번씩만 |

**Write 는 배치당 정확히 1회** — `results/result_NNN.json` 하나만 쓴다.

## §1. 받는 것

배치 파일(`batches/batch_NNN.json`) 하나가 자기완결형이다.
**배치엔 비전 판단건만 온다**(대표옵션 확정건은 prep 이 result_000 에 선기록).

```json
{"배치": 3,
 "규칙문서": "…/references/배경생성-기본.md",
 "products": [
   {"productId": "U01…", "상품명": "…", "재작업사유": "",
    "대표이미지": "D:/…/U01…_rep_0.jpg",
    "후보이미지": [{"index": 1, "url": "https://…", "path": "D:/…jpg"}],
    "대표옵션명": "", "대표옵션이미지경로": ""}
 ]}
```

먼저 `규칙문서` 를 Read 1회 — 원본 적합성 8기준의 정본이다.

## §2. 하는 일 — 상품 1건당

1. 만약 `대표옵션이미지경로` 가 채워져 있으면(예외적으로 섞여 온 경우) 규칙 0("고르지
   않는다")이라 그걸 기준으로 고정한다. **단 그 이미지를 1회 Read 해서 제품 사진인지만
   확인한다** — 치수 도면·사양표·텍스트 배너·색상칩·구성 안내 그래픽이면 **기준으로 쓰지
   말고** 후보 중 그 대표옵션과 같은 구성·색을 보여주는 실물 사진을 고른다(규칙문서 §1-1).
   비제품 이미지에 적힌 글자(예: `不含天幕和撑杆` = 타프·폴대 미포함)는 **어느 후보를
   고르면 안 되는지**를 알려주는 근거다. 맞는 후보도 없으면
   `상태: "보류(기준이미지없음)"`.
2. 아니면 대표이미지·후보이미지를 **각 1회** Read 하고 8기준으로 기준 이미지를 고른다:
   전체 보임 / 충분히 큼 / 글자·워터마크 없음 / 옵션 혼재 없음 / 손·소품 가림 없음 /
   색·구조 선명 / 배경 분리 / 해상도 충분.
3. 세트 상품은 판매 구성을 온전히 보여주는 것 우선 — 가장 비싼 옵션을 임의로 대표
   구성으로 삼지 않는다.
4. `재작업사유` 가 있으면 **반드시 반영**해 고른다(예: "옵션엔 검정 없음" → 검정 아닌 후보).
5. 판단이 불가능하면(이미지 전부 결손 등) `상태: "보류(사유)"` 로 남긴다.

## §3. 쓰는 것 — `results/result_NNN.json` (NNN = 배치번호, 0채움 3자리)

```json
{"배치": 3,
 "products": [
   {"productId": "U01…", "기준이미지": 2,
    "기준이미지경로": "D:/…/U01…_cand_2.jpg", "모드": "기본"},

   {"productId": "U01…", "상태": "보류(후보 이미지 전부 결손)"}
 ]}
```

- **최소 필드만 쓴다** — `기준이미지`(후보 index, 대표를 골랐으면 0),
  `기준이미지경로`, `모드`(항상 `"기본"`), 보류면 `상태`.
  기존썸네일·후보·대표옵션명 같은 나머지 필드는 **스크립트가 배치에서 조인**하므로
  복사하지 않는다(복사하다 훼손되면 백업·복원이 오염된다)
- `프롬프트` 는 **쓰지 않는다** — 기본 모드는 불사자 저장 디폴트를 쓴다
- 배치의 **모든 상품이 products 에 있어야 한다.** 하나라도 빠지면 감사가 누락으로 잡아
  `--generate` 가 차단된다
- ⚠️ **`productId` 는 27자다. 배치의 `productId` 필드를 그대로 복사한다 — 이미지
  파일명에서 베끼지 마라.** 파일명(`후보경로` 등) 앞부분은 **24자로 잘린** 형태
  (`U01KSD7D7Y3338WQQKZWT0XT_2.jpg`)라, 거기서 옮겨 적으면 배치에 없는 id가 되어
  그 상품이 누락으로 잡힌다(2026-08-14 verdict 축에서 실제로 2건 발생)

## §4. 반환 (사람이 아니라 워크플로가 읽는다)

파일을 쓴 뒤, 배치별로 아래 형태의 구조화 결과만 반환한다.

```
{"batch": 3, "done": 9, "held": ["U01…"], "error": ""}
```

- `done` = 기준 이미지를 정한 건수, `held` = `보류(…)` 상품id
- 배치 파일을 못 읽었거나 도중에 실패하면 `error` 에 한 줄 — **거짓 성공 금지**

## §5. 실패했을 때

- 이미지 파일이 없다 → `url` 이 있으면 그걸로 판단하지 말고(재다운로드 금지) 남은
  로컬 파일로만. 전부 없으면 보류
- 후보가 0개고 대표이미지만 있다 → 대표이미지가 8기준을 통과하면 `기준이미지: 0`
- 배치 파일 자체가 안 읽힌다 → `error` 에 사유를 적고 그 배치는 **파일을 쓰지 않는다**
  (파일이 없어야 재팬아웃 대상이 된다)
