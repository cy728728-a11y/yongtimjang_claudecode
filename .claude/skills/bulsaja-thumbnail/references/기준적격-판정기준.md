# 기준적격(prescreen) 판정 기준 — 이 한 장으로 제품이 특정되나

> `run_thumbs.py prescreen` 이 만든 `prescreen_batches/pbatch_NNN.json` 을 판정하는
> 지시서다(Claude 직접 또는 팬아웃 워커). 이 문서 하나 + 배치 파일만으로 대화 맥락
> 없이 완주할 수 있어야 한다. **크레딧 0 — 어떤 MCP·생성 도구도 부르지 않는다.**
>
> 배경: `prep` 은 대표옵션 이미지가 있으면 **비전 판단 없이** 그걸 기준이미지로 확정한다
> (규칙 0 선기록 — 워커 비용 0). 3-2 그룹은 73건 중 **57건(78%)** 이 이 경로로 나갔고,
> 그 대표옵션을 표본 12건 열어보니 **9건이 도면·배너**였다. 이 검사는 그 구멍을 막는다.

## 이 검사가 묻지 않는 것

**"도면이냐"를 묻는 게 아니다.** 2026-08-07 실측에서 치수 도면·정보 배너를 기준으로 태운
3건(그릇진열장·신발장·핀조명)이 **전부 깨끗하게 생성됐다** — 모델이 배너에서 제품만 뽑아냈다.
도면이라는 이유로 제외하면 멀쩡한 결과를 버리고 크레딧을 다시 쓴다.

**묻는 것은 하나다 — 이 한 장을 기준으로 배경을 갈아끼울 때 만들 제품이 하나로 정해지는가.**
사고는 도면에서 난 게 아니라 **여러 제품·변형이 한 장에 있을 때** 났다.

## 받는 것

```json
{"배치": 1, "판정기준": "…/기준적격-판정기준.md", "products": [
  {"productId": "U01…", "상품명": "가지치기 장대톱 전지톱 고지톱 기본형",
   "대표옵션명": "5m 알루미늄 원형봉 기본형",
   "기준이미지경로": "…/thumbs/U01…_9.webp", "후보수": 4, "출처": "선기록"}
]}
```

`출처` 는 이 기준이 어디서 왔는지다 — `선기록`(대표옵션 확정) 또는 `후보`(run 워커가
후보 이미지에서 고른 것). **판정 기준은 둘이 완전히 같다**(묻는 건 "이 한 장에서 만들
제품이 하나로 정해지나" 하나뿐). 다른 건 판정 뒤 처리뿐이라 스크립트가 알아서 가른다 —
워커는 `출처` 를 신경 쓰지 않는다.

## 하는 일 — 상품 1건당

`기준이미지경로` 를 **1회만** Read 한다. 다른 이미지는 안 본다(후보는 열리지도 않는다 —
고르는 건 다음 단계 일이다). `상품명`·`대표옵션명` 은 판단 근거로 같이 읽는다.

| 판정 | 기준 |
|---|---|
| **단일특정** | 만들 제품이 하나로 정해진다. **치수선·화살표·브랜드 로고·하단 텍스트바가 얹혀 있어도 제품이 하나면 여기다** — 배경 생성이 그것들을 걷어내고 제품만 남긴다 |
| **다중혼재** | 한 장에 **여러 제품·변형·구성품**이 있어 무엇을 그릴지 정해지지 않는다. 구성품 나열 그리드 · `A款/B款/C款` 같은 변형 스키마 · 2분할 비교컷 · 본품+사은품 세트 |
| **실물없음** | 제품 실물 사진이 **아예 없다.** 순수 치수 도면(선화) · 색상칩/원단 스와치 · 로고·브랜드 카드 · 글자만 있는 안내문 |

### 경계 — 실측에서 갈린 것 (2026-08-07, 눈으로 연 12건)

**`단일특정` 으로 봐야 하는 것** — 텍스트가 많아도 제품은 하나다:

| 상품 | 이미지에 있는 것 |
|---|---|
| 업소용 원목벤치 | 벤치 1개 + 치수선(100/30/45cm) + 하단 `实木长条凳1m【胡桃色】` 텍스트바 |
| 모서리 초슬림신발장 | 신발장 1개 + 치수(135/50/17cm) + 우측 기능 설명 패널 |
| 원목 그릇진열장 | 선반 1개 + 칸 치수 + `小号` 배지 |
| 대기실 소파 | 소파 1개 + 치수 + 하단 특징 2줄 |
| 무대 핀조명 | 조명 1개 + 치수 + 리모컨 설명 패널 (**리모컨은 부속 설명이지 만들 제품이 아니다**) |

**`다중혼재`** — 무엇을 그릴지 정해지지 않는다 (3-2 그룹 57건 중 6건, 10.5%):

| 상품 | 왜 |
|---|---|
| 갈매기 식탁펜던트조명 | `A款/B款/C款` 세 형태가 한 장에. **검수에서 Sonnet 은 "단일헤드 블랙", Haiku 는 "3종 스키마"로 서로 다르게 오독해 사유 오분류로 남았다** — 이 검사를 만든 실증 |
| 세차 물호수릴 | `40米水枪套装+手推车` — 본체 + 부속 8칸 그리드 |
| 우레탄발포기 | 본체(`银色-800`) + `送` 사은품 8칸 그리드(호스·필터·렌치·장갑) |
| 이동식 강연대 | `外部展示`/`内部展示` 2분할 비교컷 |
| 하수구에어백 | 크기가 다른 에어백 5~6개가 한 장에 |
| 수련회 에어사다리 | 색상별로 다른 래더 구성이 한 장에 배열 |

**판정이 갈리면 `다중혼재` 다.** 놓치면 사고(재생성 크레딧)고, 과잉이면 다음 단계 워커가
후보에서 고르는 것뿐이다(**크레딧 0**). 비용이 비대칭이다.

### 이 검사가 못 잡는 것 — 생성 환각 (2026-08-07 실증)

**기준이 깨끗해도 생성이 없던 물건을 그려 넣을 수 있다.** `가지치기 장대톱` 은 기준이
톱 한 자루 단독컷(`5米高空锯` · `此款不送锯套`)이었는데 **생성본에 톱집이 생겼다.**
기준은 `단일특정` 이 맞고, 이건 prescreen 이 아니라 **검수(verdict) 가 잡을 건이다**
([`검수-판정기준.md`](검수-판정기준.md) §제외 사유는 생성본에서 관찰된 것이어야 한다).
기준적격을 통과했다고 생성본을 덜 보지 않는다.

## 글자는 버리지 말고 읽는다

비제품 이미지의 글자가 곧 판단 근거다(`배경생성-기본.md §1-1` 과 같은 원칙).
`送`·`赠`(사은품) · `套装`(세트) · `A款/B款` · `多规格可选`(여러 규격) 같은 표기는
**한 장에 여러 개가 섞여 있다**는 신호다.

**단, 글자만으로 판정하지 않는다 — 그림에 실제로 여러 개가 있어야 한다.**
`此款不送锯套`(이 모델은 톱집 미포함) 처럼 **없다고 적힌** 표기는 오히려 한 개라는 뜻이다
(장대톱 실증 — 글자만 보고 세트로 오독하면 멀쩡한 기준을 승격시킨다).

**사유에는 그 근거를 인용한다.** "배너다"가 아니라 "`40米水枪套装+手推车` 표기 + 부속 8칸
그리드" 처럼 이미지에서 실제로 읽고 본 것을 적는다 — 다음 단계 워커가 그걸 읽고 후보를 고른다.

## 쓰는 것 — `prescreen_results/presult_NNN.json` (NNN = 배치번호, 0채움 3자리)

```json
{"배치": 1, "products": [
  {"productId": "U01…", "판정": "단일특정", "사유": ""},
  {"productId": "U01…", "판정": "다중혼재",
   "사유": "세트 배너 — `40米水枪套装+手推车` 표기 + 호스·커넥터·장갑 부속 8칸 그리드"},
  {"productId": "U01…", "판정": "실물없음", "사유": "치수 선화 도면만 있고 제품 사진 없음"}
]}
```

- 판정값은 `단일특정`/`다중혼재`/`실물없음` 셋뿐. **다중혼재·실물없음은 사유 필수.**
- 배치의 **모든 상품이 products 에 있어야 한다.** 빠뜨리면 그 건은 검사 없이 생성된다.
- ⚠️ **`productId` 는 27자다. 배치의 `productId` 필드를 그대로 복사한다 — 이미지
  파일명에서 베끼지 마라.** 파일명 앞부분은 **24자로 잘린** 형태다. 거기서 옮겨 적으면
  배치에 없는 id가 되어 그 건은 판정이 버려진다(= 검사 없이 생성된다).
- Write 는 배치당 정확히 1회. 같은 이미지를 여러 번 열지 않는다.
- 모르는 값·판정 누락은 `다중혼재` 로 처리된다(fail-closed) — 그래도 **일부러 비우지 않는다.**

## 다음 단계

`python run_thumbs.py prescreen --run-dir <R> --commit`

| 판정 | 처리 (`출처: 선기록`) | 처리 (`출처: 후보`) |
|---|---|---|
| 단일특정 | 그대로 생성 | 그대로 생성 |
| 다중혼재 | 선기록에서 빼고 `batches/` 로 승격 → run 팬아웃이 후보에서 실물을 고른다 | **그대로 생성**(세기만 한다) — 워커가 이미 후보에서 고른 기준이라 되물으면 같은 답이 온다 |
| 실물없음 | 선기록에서 빼고 썸네일 `보류(기준이미지없음)` + **옵션 열 재작업 flag** — 억지로 도면을 태우지 않는다. 뿌리가 옵션이라 대표옵션을 실물 사진이 있는 값으로 다시 세워야 풀린다 | 결과에 `보류(기준이미지없음)` 을 실어 **생성에서 뺀다** — 다음 `apply` 가 같은 곳(썸네일 보류 + 옵션 flag)으로 보낸다 |

> **`출처: 후보` 검사는 2026-08-19 에 들어왔다.** 그전엔 선기록만 봐서, `실물기준없음` 으로
> 넘어와 비전 배치로 간 건들이 생성 전 검사를 하나도 안 받았다 — **후보에도 실물이 없는
> 상품에 크레딧을 태웠다**(11건 중 최소 5건).
