# 배경생성 — 기본 모드 (헤르메스 07 흡수: 배경만 교체, 저변형·안전)

> 대량 가로 작업의 표준 경로. 프롬프트를 비우면 불사자 저장 디폴트가 쓰인다(실측 확인).
> 이 문서는 SKILL.md 의 요약을 구체화한다 — 여기가 실행 규칙의 본체다.

## 역할

배경만 교체하는 것이 **의도**다. 그러나 **실측(2026-08-05, 1-3 그룹 표본 30건 중
불일치 19건 = 68%)은 제품 자체도 변조된다** — 색을 바꾸고(녹색→민트, 살구→카라멜),
없던 것을 그려 넣고(곰·로봇 손·장미·짐볼·의자), 스펙 표기를 바꾼다(3000W→8500W).
"저변형"을 전제로 검수를 건너뛰면 안 된다 — **검수 3축의 ①제품 정확성은 절대 자동
통과시키지 않는다.** 구도·공간·조명까지 바꾸는 고변형 연출은
[`AI레시피.md`](AI레시피.md)(레시피 모드)로 라우팅한다 — "예쁘게/연출/레시피"를
지명하지 않는 한 이 문서를 따른다.

## 1. 기준 이미지 선택 (8기준)

전체 보임 · 충분히 큼 · 글자·워터마크 없음 · 옵션 혼재 없음 · 손·소품 가림 없음 ·
색·구조 선명 · 배경 분리 · 해상도 충분.

**우선순위**: 판매 구성을 온전히 보여주는 깨끗한 원본 > 글자 없는 단품·세트 >
옵션 이미지 > 중국어·치수선 있는 설명 이미지.

- **배치에 `대표옵션이미지경로`가 있으면 판단이 끝난다 — 그게 기준 이미지다**(2026-07-30 이룸님).
네이버가 '대표상품'(추가금 0원 옵션)을 상품명으로 쓰라고 요구하므로 썸네일도 그 옵션이어야 한다.
아래 신뢰 순서는 **대표옵션이 없을 때**(옵션정리 미완료·단일상품) 적용한다.

### 1-1. 예외 — 대표옵션 이미지가 '제품 사진이 아니면' 기준으로 쓰지 않는다 (2026-08-06 이룸님)

규칙 0은 **어느 옵션인가**를 정하는 규칙이지 **어느 사진인가**를 정하는 규칙이 아니다.
옵션 이미지 자리에 제품 사진이 아닌 것이 들어있는 상품이 실재한다 — 그걸 그대로 태우면
배경교체가 도면을 뭉개서 정체불명 이미지를 만든다.

**비제품 이미지 유형**: 치수 도면·사양표 · 텍스트 배너/안내문 · 색상칩·원단 스와치 ·
로고/브랜드 카드 · 구성 안내 그래픽(부속 나열 + 설명 글).

| 대표옵션 이미지가 | 기준 이미지 |
|---|---|
| 제품 사진이다 | **그대로 고정**(규칙 0) |
| **비제품이다** | **후보 중 그 대표옵션과 같은 구성·색을 보여주는 실물 사진**을 고른다 |
| 비제품인데 맞는 후보도 없다 | `상태: "보류(기준이미지없음)"` — 억지로 도면을 태우지 않는다 |

**비제품 이미지의 글자는 버리지 말고 판단 근거로 읽는다.** 거기 적힌 구성 안내가 곧
"어느 후보를 고르면 안 되는가"를 지시한다.

> 실증(2026-08-06, `U01KSAKSYN7JRQ09A0RAS7Z4WMZ` 타프용 모기장): 대표옵션 `S 샴페인`의
> 옵션 이미지가 치수 도면이었고 거기 `单一蚊帐，不含天幕和撑杆`(모기장 단품 — 타프·폴대
> 미포함)이라고 적혀 있었다. 그대로 태운 생성본은 뼈대만 남고 `S码` 글자가 박혀 검수 제외.
> 후보 5장 중 **2·4번이 모기장 단품 실물**이라 정답이었고, 기존대표·1·3번은 **타프까지 친
> 연출컷**이라 대표옵션이 팔지 않는 구성이었다(검수 3축 ③오인 위험).

⚠️ **선기록건은 워커가 이미지를 아예 안 본다.** `prep` 은 `대표옵션이미지경로` 가 있는 상품을
`results/result_000.json` 에 **선기록하고 배치에서 뺀다**(워커 비용 절감). 3-2 그룹은 73건 중
**57건(78%)** 이 이 경로였고, 그 대표옵션을 표본 12건 열어보니 **9건이 도면·배너**였다.

**그래서 `prescreen` 이 생성 전에 잡는다** (2026-08-07 — [`기준적격-판정기준.md`](기준적격-판정기준.md)):

```bash
python … run_thumbs.py prescreen --run-dir <R>          # 선기록건 기준이미지 1장씩 판정
# → pending --prescreen → Workflow thumb-fanout(mode:prescreen) → 아래로 반영
python … run_thumbs.py prescreen --group-name "…" --run-dir <R> --commit
#   단일특정 → 그대로 생성 / 다중혼재 → batches/ 승격(run 워커가 후보에서 고름)
#   실물없음 → 썸네일 보류(기준이미지없음) + 옵션 열 재작업 flag(대표를 실물로 다시 세울 것)
```

**묻는 것은 "도면이냐"가 아니라 "제품이 하나로 특정되나"다.** 치수 도면을 기준으로 태운
3건(그릇진열장·신발장·핀조명)이 전부 깨끗하게 생성됐다 — 도면 자체는 사고 원인이 아니다.
문제는 여러 제품·변형이 한 장에 있을 때다(갈매기조명 `A款/B款/C款` · 물호수릴 부속 8칸
그리드 · 강연대 2분할). 3-2 그룹 실측으로 선기록 57건 중 **6건(10.5%)** 이 걸렸다.

> **기준이 깨끗해도 생성 환각은 따로 있다.** 장대톱은 기준이 톱 한 자루 단독컷이었는데
> 생성본에 톱집이 생겼다 — 그건 `prescreen` 이 아니라 검수가 잡는다.

> 폴백 — `prescreen` 을 안 돌렸거나 그래도 새어나갔으면 **검수 단계에서 Claude 가 잡는다.**
> 검수 3축 ①에서 생성본이 뭉개졌으면 원인이 "기준이 비제품 이미지"인지 확인하고 아래로 복구한다:

```bash
# ① 후보를 직접 보고 대표옵션과 같은 구성의 실물을 고른 뒤,
#    선기록을 덮어쓰는 결과 파일을 새로 쓴다(_results 는 "마지막 파일이 이긴다")
#    → results/result_900.json 에 {"products":[{"productId":…, "기준이미지":2,
#       "기준이미지경로":"<run-dir>/thumbs/…_cand_2.jpg", "모드":"기본"}]}
# ② 그 상품만 재생성 (누적 2회 한도에 포함)
python … run_thumbs.py apply --group-name "…" --run-dir <R> --ids U01… --generate
```

저장된 상품명은 정체 증거가 아니다 — 원본 이미지 > 옵션 구조 > 현재 대표 순으로 신뢰한다.
- **세트 상품은 가장 비싼 옵션을 임의로 대표 구성으로 정하지 않는다.** 실제 판매 구성이
  기준이다.
- 재작업 대상(다른 단계에서 이관된 건)은 사유를 먼저 본다 — 예: "대표엔 검정인데 옵션엔
  검정 없음"이면 판매 옵션에 있는 색을 담은 후보를 기준으로 삼는다.

## 2. 제품 불변 요소 (검수 기준이 되는 것)

윤곽·색·로고·인쇄 문자·버튼/구멍/연결부의 **개수와 위치**·구성품 개수·케이블 위치.
"정확히 유지" 같은 추상 문구가 아니라, 확인한 숫자와 위치를 실제로 대조한다.

## 3. 검수 3축

1. **제품 정확성** — 동일 제품·색·비율·부품 개수·버튼/구멍/힌지 위치·추가/누락·
   옵션 구성 일치. 로고 문자·패턴 반복부·부품 개수는 **확대해서 별도로** 확인한다
   (모델이 가장 자주 틀리는 지점).
2. **클릭성** — 1초 인지·크기·명암 분리·용도 전달·합성 경계·글자 생성 여부
   (**색상코드 `#RRGGBB` 류 포함** — 디폴트 프롬프트의 hex 값이 이미지에 렌더링된
   사고 3건 실측, 2026-08-05)·**모바일 목록 크기 축소 확인**·경쟁과 구분.
   큰 화면에서만 보고 통과시키지 않는다.
3. **오인 위험** — 소품이 구성품처럼 보이는가·과장·판매 안 하는 옵션이 노출되는가.

## 4. 판정

- **사용가능** — 3축 통과
- **주의** — 디테일 확정 불가(자동 적용 금지). Claude 가 대표옵션·원본 후보를 추가
  대조해 재판정하고, 그래도 확정 불가면 `보류(판정)` 으로 빼서 종합보고에 싣는다
- **제외** — 형태·비율·색·로고·부품 수 중 하나라도 다름. **제품 차이를 '주의'로 낮추지 않는다.**

## 5. 재생성

실패 원인을 구체적 변형점으로 반영해 재시도. **같은 프롬프트 반복 금지** — 문제가
반복되면 픽셀 보존을 더 강하게 지시하는 방향으로 바꾼다. **상품당 누적 최대 2회**
(재생성을 태울 때마다 1씩 쌓인다 — 레시피 모드의 A/B 안 사이에도 한도는 상품 단위다.
`run_thumbs.py` 의 누적 카운트가 기준).

**불합격 자동 처리 규칙(2026-08-06 이룸님)** — Claude가 묻지 않고 수행한다:
- 불합격 사유가 **제품에 박힌 글자 변조**(브랜드 표기·각인)면 재생성하지 않고
  넘어간다(보류 종결, 기존 대표 유지). AI 글자 재현은 재시도해도 같은 유형으로 또 틀린다.
- **기준이 비제품 이미지(도면·배너·색상칩)라 생성본이 뭉개진 경우**는 같은 기준으로 다시
  태우지 않는다 — §1-1 대로 **기준을 실물 후보로 갈아끼운 뒤** 재생성한다(맞는 후보가
  없으면 `보류(기준이미지없음)`).
- 그 외 불합격(구성·색·형태·이미지 손상)은 대표옵션 이미지를 기준으로 재생성한다.
- **2회째도 불합격이면 대표옵션 원본 이미지를 그대로 대표로 저장**한다(크레딧 0).
  **불사자에 즉시 반영한다 — 별도 승인 게이트를 두지 않는다**(원본은 실물 그 자체라
  정합이 보장된다. 2026-08-06 이룸님). 저장 후 재조회 확인은 §6과 동일.
  원본의 워터마크·중국어 글자 여부는 **보고에만** 남긴다(반영을 막는 사유가 아니다).
  현황판 값은 `완료(대표옵션 원본)` — 시트 원장에도 같은 상태로 기록한다(공백 포함,
  `run_thumbs.py` 문자열과 동일해야 파싱이 안 깨진다).
- 종료 보고에 처리 유형별 상품id를 포함한다.

## 6. 반영 후 확인

`thumbnail_update` 저장 후 재조회해서 첫 이미지가 `https://`인지 확인한다.
`file://`·윈도우 절대경로·로컬 경로는 절대 입력하지 않는다(호스팅 안 됨 → 깨진 이미지).
공개 주소가 없으면 '호스팅 대기'로 남기고 완료라 하지 않는다.
