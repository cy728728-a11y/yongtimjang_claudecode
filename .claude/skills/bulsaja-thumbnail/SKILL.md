# 불사자 썸네일

> 이미지가 승인 대상이라 텍스트 검수표가 안 통한다(2026-07-28 실전 교훈). 검수는 항상
> 로컬 HTML 페이지로 한다. 공통 규칙(스냅샷·현황판·계약)은
> [`_shared/스킬-계약.md`](../_shared/스킬-계약.md),
> 불사자 공통 안전선(통신·검증·실패 보존)은 [`_shared/불사자-안전규칙.md`](../_shared/불사자-안전규칙.md).

## 왜 필요한가

수집 직후 대표 썸네일은 타오바오 원본(워터마크·중국어·경쟁사 로고 노출)이다. 불사자
내부 AI로 배경을 바꾸면 워터마크 없는 깨끗한 대표이미지를 만들 수 있다. 다만 생성은
크레딧이 들고(장당 5), **승인 없이도 대표이미지가 자동 반영될 수 있어**(실측 확인)
방어 로직 없이 돌리면 승인 전 이미지가 그대로 판매화면 후보가 된다.

| 프롬프트 | 생략(불사자 저장 디폴트 사용, 실측 확인) | Claude 가 직접 작성 |
| 규칙 | [`references/배경생성-기본.md`](references/배경생성-기본.md) | [`references/AI레시피.md`](references/AI레시피.md) |
| 검수·판정·승인·반영 | 공통(아래) | 공통(아래) |

엔진은 `bulsaja_thumbnail_ai_generate` 하나. 헤르메스 07(외부 배경교체: 로컬 파일·Gemini
edit·리사이즈)은 채택하지 않는다 — 엔진 통일로 불필요.

## 흐름

```bash
# ① prep — 현황판 대상 확정 → 스냅샷 → 기작업(이미 가공됨) 자동 완료 처리 → 후보 이미지 → 배치
python .claude/skills/bulsaja-thumbnail/scripts/run_thumbs.py prep \
  --group-name "1번_용쌤1-1" --run-dir "D:/python_work/data/thumbnail/runs/<이름>" [--limit 5] [--ids U01...]

# ② run — Claude 가 배치를 읽고 기준 이미지 선택(+레시피 모드면 배경전략·프롬프트 작성)
#    → results/result_NNN.json

# ③ apply — 게이트 2번
python ... run_thumbs.py apply --run-dir <R>              # 미리보기(대상+기준이미지+예상크레딧)
python ... run_thumbs.py apply --run-dir <R> --generate   # 게이트1 승인 후: 실제 생성(크레딧 소모)
#   → review.html 생성. 브라우저로 열어 [기존대표|생성본|원본후보] 비교
python ... run_thumbs.py apply --run-dir <R> --commit     # 게이트2 승인 후: decisions.json 대로 반영
```

대상 선정은 **현황판 쿼리 1줄**(`00_진행` 탭의 `썸네일` 열이 빈 상품 + 재작업). prep이
스냅샷 대표 URL을 보고 **이미 `cdn.bulsaja.com`이면 자동으로 '완료' 백필**하고 대상에서 뺀다
(판별 규칙은 아래 §기작업 판별).

**대표 원본이 404면 삭제 대상** (2026-08-01 이룸님) — 타오바오에서 이미지가 내려간 것은
소싱 원본 소멸 신호다. prep이 그 상품을 워커에 보내지 않고 `deletion_candidates.json` +
현황판 `보류(원본404·삭제대상)` 로 기재해 이룸님께 보고한다. 실제 삭제는 이룸님 몫.

## run 실행 = Workflow 모드 (대량 기본, 2026-08-01)

②(run)를 메인 세션이 직접 돌리지 않는다 — 배치 100개를 순차로 읽으면 컨텍스트 누적
재과금(product-name `팬아웃-비용.md` 모드 B 안티패턴)을 밟는다. 백그라운드 워크플로로 뺀다:

- **prep 이 대표옵션 확정건을 선기록한다** — `대표옵션이미지경로` 있는 상품은 판단이
  0(규칙 0 "고르지 않는다")이라 prep 이 직접 `results/result_000.json` 에 기록하고
  배치에서 뺀다. **배치 = 비전 판단건만.** 옵션정리를 먼저 돌린 그룹이면 팬아웃 자체가
  거의 필요 없어진다(순서: 옵션 → 썸네일이 여기서도 이득).
- 대량 팬아웃 시 **`prep --batch-size 4` 권고** — 상품당 이미지가 최대 6장(대표1+후보5)이라
  기본 10건이면 배치 하나(~60장)가 이미지예산(24장)을 단독 초과해 패킹이 무의미해진다.

1. `python … run_thumbs.py pending --run-dir <R>` — 남은 배치를 Workflow args JSON 으로 출력
2. `Workflow` 도구를 `{name: "thumb-fanout", args: <출력 그대로>}` 로 호출.
   워커는 `agent(model: sonnet, effort: low)` — 지시서는
   [`references/썸네일-워커-프롬프트.md`](references/썸네일-워커-프롬프트.md).
   워커 결과는 **판단 필드만** 남기고, 나머지(기존썸네일 등)는 apply 가 배치(정본)에서
   조인한다 — 워커 환각이 백업·복원 경로에 못 들어간다
3. 완료 반환의 `재팬아웃필요배치` 가 비었는지 확인. 남았으면 `pending` 재계산 후 **1회만** 재호출
4. `apply --run-dir <R>` 미리보기까지. **워크플로·워커는 `--generate` 를 절대 부르지 않는다**
   — 크레딧 소모·자동반영 방어가 걸린 게이트1이다. `--generate` 는 이룸님 승인 후 메인이
   직접 부르고, 감사에서 누락 상품이 있으면 차단된다(`--allow-missing` 은 의도된 부분 생성 전용)

> **동시 서브에이전트 기본 가이드라인(≤15)은 이 팬아웃에 적용하지 않는다** — 워커는
> 디스크에만 쓰고 상호 간섭이 없으며, 상한은 이미지예산(워커당 ≤24장)·상품상한(≤8건)과
> 하네스 동시성 캡이 관리한다. 이 문장이 그 명시적 opt-in 이다.

**재개·멱등**: `results/result_NNN.json` 존재 = 그 배치 완료. **폴백**(소량·워크플로 불가
환경): 메인 또는 Agent 워커가 같은 지시서로 배치를 직접 처리한다 — 워커 1명 = 배치 1~2개.

## 기작업 판별 (자동 필터, 캘리브레이션 실측 2026-07-28)

| 대표 URL 호스트 | 의미 |
|---|---|
| `img.alicdn.com`(그 외 외부) | 미가공 원본 → 대상 |
| `cdn.bulsaja.com`(경로 무관) | 가공됨(AI썸네일/AI상세 생성 완료) → 자동 완료 처리, 대상 제외 |

수집 방식(직접 URL/MCP)은 URL에 영향 없음을 신규 수집 2건으로 직접 반증했다.
`cdn.bulsaja.com` 안의 경로(`mcp-assets/`·`sourcing-product/`·`products/`·`ai-image/output/`
4종 관측)는 구분하지 않는다 — 호스트만 본다. 판정은 항상 **대표(0번)만** 본다(후보 자리에
가공된 URL이 섞여 있어도 무시).

## 결과 파일 형식 (Claude가 만드는 것 — `run` 단계)

```json
{"products": [{
  "productId": "U01...",
  "상품명": "원목바텐의자 바체어",
  "기준이미지": 3,
  "기준이미지경로": "<run-dir>/thumbs/U01..._cand_3.jpg",
  "모드": "레시피",
  "프롬프트": "제품 잠금: ... (레시피 모드만 채운다. 기본 모드는 비워서 디폴트 사용)"
}]}
```

- **`대표옵션이미지경로`가 있으면 그게 기준 이미지다 — 고르지 않는다**(아래 절).
- `기준이미지` = 배치의 `후보이미지[].index` 중 하나(원본 적합성 8기준으로 고른다).
  세트 상품은 판매 구성을 온전히 보여주는 것 우선, 임의로 최고가 옵션을 대표로 삼지 않는다.
- 기본 모드는 `프롬프트`를 비운다 — 채우면 디폴트 대신 그 프롬프트가 쓰인다.
- 재작업 대상(옵션정리 등에서 이관된 건)은 배치의 `재작업사유`를 반드시 반영해 기준 이미지를
  고른다(예: 바체어 — "옵션엔 검정 없음" → 검정 아닌 후보를 기준으로).

## 판단 규칙 (기준 이미지 선택 — 두 모드 공통)

### 0. 대표옵션이 있으면 그게 기준이다 (2026-07-30 이룸님)

**네이버는 '대표상품'(추가금 0원인 대표옵션)을 상품명으로 작성하라고 요구한다** →
**썸네일 = 대표옵션 = 상품명**이 같은 옵션 하나를 지칭해야 한다.
상품명·옵션명은 `기본형` 이라는 같은 단어로 짝을 맞추지만(→ `product-name` R8 ·
`bulsaja-option-cleanup` 규칙 17), **썸네일은 글자가 없어서 마커를 쓸 수 없다.**

그래서 배치에 `대표옵션명`·`대표옵션이미지`·`대표옵션이미지경로`를 싣는다.

| `대표옵션이미지경로` | 기준 이미지 |
|---|---|
| **있음** | **그 이미지로 고정.** 아래 8기준으로 고르지 않는다 |
| 없음 | 종전대로 후보 중에서 8기준으로 고른다 (옵션정리 미완료·단일상품) |

> 이걸 안 막으면 무슨 일이 나나: 유압자키 옵션이 3톤 28,000 / 5톤 41,000 / 10톤 68,000 일 때
> 대표옵션은 최저가 3톤인데, 후보 중 잘 나온 사진을 고르다 **10톤 사진**이 대표가 될 수 있다.
> 고객은 10톤을 보고 들어오는데 추가금 0원 대표상품은 3톤이다.
>
> `prep` 이 끝나면 `대표옵션 기준 이미지 N건 / 비전 판단 M건` 을 찍는다 — M이 크면
> 옵션정리를 먼저 돌리는 게 맞다(순서: 옵션 → 썸네일).

### 1. 대표옵션이 없을 때 — 원본 적합성 8기준

전체 보임 / 충분히 큼 / 글자·워터마크 없음 / 옵션 혼재 없음 /
손·소품 가림 없음 / 색·구조 선명 / 배경 분리 / 해상도 충분. 세트는 가장 비싼 옵션을
임의로 대표 구성으로 정하지 않는다. 상세는 [`references/배경생성-기본.md`](references/배경생성-기본.md).

## 자동반영 방어 (apply --generate 가 자동 수행, 실측 확인된 위험)

생성 완료 직후 대표이미지가 **승인 없이 이미 바뀌어 있을 수 있다**(2026-07-28 파일럿
실측 확인 — 헤르메스 06 §7 경고와 일치). `apply --generate`는 생성 직후 재조회해서
대표가 바뀌었으면 게이트2 승인 전까지 **원래 순서로 자동 복원**한다. 이 복원은 무료
(`thumbnail_update` 재호출뿐). 복원 자체가 실패하면 반드시 경고를 남기고 멈춘다.

## 검수 페이지 (게이트2 자료)

`apply --generate`가 `review.html`을 만든다 — 상품별로 [기존 대표 | **대표옵션(기준)** |
생성본(미승인) | 원본 후보들]을 나란히 표시(전부 공개 https 주소라 업로드 없이 그대로 임베드).
재작업 사유·소모 크레딧도 같이 보인다. 이 페이지는 **표시 전용**.

**대표옵션을 생성본 바로 왼쪽에 두는 이유**: 승인할 때 판단해야 하는 게
"생성본이 대표옵션과 **같은 물건**인가"다. 떨어져 있으면 대조가 안 된다.
대표옵션명은 카드 머리글에도 적는다.

`--commit`을 부르는 행위 자체가 이미 review.html을 보고 난 뒤의 승인이다 — 그래서
`decisions.json`이 없으면 생성 성공분 전부를 **사용가능**으로 반영한다. 일부만
거를 때만 그 상품id만 적어 재정의한다:

```json
{"U01...": {"판정": "제외", "사유": "색상 일치하지만 그림자가 부자연스러움"}}
```

검수 기준(3축, 두 모드 공통): ①제품 정확성(색·비율·부품 개수·구멍/버튼/힌지 위치·
누락/추가 없음) ②클릭성(1초 인지·모바일 목록 축소 확인·경쟁과 구분) ③오인 위험(소품이
구성품처럼 보이는가·판매 안 하는 옵션 노출). 재생성은 안당 최대 2회, 이후에도 주의/제외면
기존 대표 유지(`decisions.json`에 안 넣으면 자동으로 보류 처리된다).

## 되돌리기

`apply --generate`는 생성 직전에 `run-dir/before_generate.json`을 남긴다.

```bash
python ... run_thumbs.py restore --run-dir <R> [--ids U01a U01b]
```

## 불사자 저장 ≠ 마켓 반영

`--commit`은 불사자 서버의 대표이미지만 바꾼다. 이미 마켓에 올라간 상품은 판매 화면이
그대로다 — 수정 업로드를 따로 해야 반영된다. 미업로드 상품이면 다음 업로드 때 반영된다
(정리하기 가장 안전한 타이밍). 업로드 여부는 `workdata`의 `uploadedSuccessUrl` 각 마켓
값이 전부 null 인지로 본다.

## 기록

- 그룹 시트 `썸네일` 탭 — 상품별 모드·기존대표·생성본·판정·사유·크레딧·상태
- 현황판 `00_진행`의 **`썸네일` 열만** 갱신(`완료`/`보류(판정)`/`보류(생성실패)`)
- 스냅샷의 `썸네일` 필드를 저장 후 값(생성본을 대표로 한 배열)으로 되쓴다

## 알려진 함정

| 함정 | 왜 |
|---|---|
| 대표에 없는 색이 옵션에 있음(또는 반대) | 옵션정리에서 이관된 재작업 신호. 배경생성으로 안 풀린다 — 판매색이 담긴 후보를 기준 이미지로 써야 한다(바체어 사례) |
| 생성 후 재조회 안 하고 완료 보고 | 자동반영을 놓친다. 반드시 재조회 → 방어 → review.html 순서 |
| `decisions.json` 없이 `--commit` | 생성 성공분 전부 사용가능으로 반영된다(`--commit` 호출 자체가 review.html을 본 뒤의 승인이라는 전제) |
| 세트 상품 대표를 최고가 옵션으로 오인 | 판매 구성을 온전히 보여주는 원본이 우선이지 가격 순이 아니다 |
| mcp-assets 경로를 보고 "가공 안 됨"으로 오판 | 경로는 무시, 호스트(`cdn.bulsaja.com`)만 본다 |
