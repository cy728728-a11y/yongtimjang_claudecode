# 쿠팡 후보 선별

## 이 스킬이 푸는 문제

스마트스토어는 대량업로드가 맞다 — 많이 올려놓고 팔리는 걸 찾는 그물이다.
쿠팡은 아니다. **취소·반품이 잦으면 계정정지**고, 스마트스토어처럼 "마진 낮으면
고객에게 연락해 추가금 받기"가 통하지 않는다.

그래서 방향을 뒤집는다. **이미 팔린다고 검증된 것만** 올린다.

## 핵심 전제 3가지 (실측으로 확인됨, 2026-09-13)

1. **잠금 상품이 곧 대표다.** 팔린 상품은 삭제 방지로 잠가 둔다. 실측에서 주문
   3회 이상 후보 155건 중 **141건(91%)이 잠금 상태**였다. 같은 원본의 사본은
   수십 개씩 있지만(코너책장 1종 = 사본 27개) 잠긴 건 실제 팔린 1개뿐이다.
   → 주문시트의 판매자상품코드가 **대표를 직접 가리킨다.**
   → `dedup.choose_representative()`(완료작업수 기준)는 **쓰지 않는다** — 그건
     "잘 다듬어졌지만 안 팔린 사본"을 고른다.

2. **중복 병합 키는 MCP 응답의 `불사자코드`다.**
   ⚠️ 스냅샷 파일의 `불사자코드` **필드**는 이름이 잘못 붙어 있어 실제로는
   판매자상품코드다. 서로 다른 값이니 혼동하지 마라.

   | 코드 | 실체 |
   |---|---|
   | 주문시트 R열 = 판매자상품코드 = 스냅샷 `불사자코드` 필드 | 사본마다 **고유** |
   | MCP 응답 `불사자코드` | 사본 전체가 **공유** ← 병합 키 |
   | 타오바오상품번호 | 원본 소스 (workdata 에만 있음) |

3. **배송비가 진짜 리스크다.** 실측 배송비를 수량으로 나눠 단위당으로 정규화해도
   같은 상품 편차가 **중앙값 34%**, 후보 154개 중 **98개가 20% 초과**다.
   스마트스토어에서는 추가금으로 흡수했지만 쿠팡에서는 전부 손실이다.
   → 채택값은 중앙값이 아니라 **P75**. 배송비 교정이 복사의 **선행 조건**이다.

## 시험 복사로 확정된 사실 (2026-09-13, 1건 실측)

후보 1위(옷걸이, 주문 33건)를 쿠팡 그룹에 실제로 복사해 확인했다.

| 항목 | 결과 | 함의 |
|---|---|---|
| **판매가 배수** | **1.00** (46,700원~ → 46,700원~) | 쿠팡 그룹 가격설정이 스마트스토어와 같다. → **마진 공식이 그대로 유효하다**(수수료 차이만 빼면 된다) |
| **잠금 승계** | **승계된다** (복사본도 `잠금: true`) | `product_hide` 재적용 단계가 **불필요**하다. 대신 복사본을 지우려면 **잠금부터 풀어야** 한다 |
| **불사자코드** | **새로 발급되지 않는다** (원본과 동일) | 판매자상품코드만 새로 발급된다. 주문시트 R열은 판매자상품코드라 **스마트스토어/쿠팡 실적 구분은 가능하다** |
| **복사 응답의 신 productId** | 확인 못 함 — 전후 diff 로 매핑 | 배치를 20건으로 제한하는 이유 |

**불사자코드가 승계된다는 사실이 중복 방어의 근거를 바꾼다.** `copied.jsonl` 은
run-dir 안에만 있어서 새 run-dir 로 돌리면 방어선이 사라진다. 그래서 `gate` 가
매번 **쿠팡 그룹 전건을 실제로 읽어** 타오바오상품번호로 대조한다
(`--skip-group-check` 로 끌 수 있지만 재복사 위험을 감수하는 것).

## 명령

```
RUN=<data_root>/coupang/runs/$(date +%Y%m%d-%H%M)
S=.claude/skills/coupang-candidates/scripts/run_coupang.py
PYTHONPATH=.claude/lib .venv/bin/python3 $S <서브커맨드> --run-dir $RUN
```

| 단계 | 명령 | 성격 |
|---|---|---|
| S0·S1 | `prep` | 주문시트 12탭 집계 → 실적·배송비 원장 |
| S2 | `resolve --min-orders 3` | 상위 코드 → 불사자 조회(50개/콜) |
| S3 | `build` | 불사자코드 병합 → 대표 1건 |
| S4 | `ship` | 실측 배송비(P75) vs 불사자 입력값 대조 |
| S5 | `gate --min-margin 20 --limit 100` | 쿠팡보정 가중마진 게이트 + 쿠팡 그룹 실물 대조 |
| S6 | `apply --commit [--limit N]` | 쿠팡 그룹으로 복사 **(쓰기)**. `--limit` 은 시험 복사용 |
| S7 | `verify` | 중복 0 증명 · 판매가 검산 |
| — | `sheet` | 원장 5개 탭 기록 |

`apply` 는 `--commit` 없이는 미리보기만 한다.

**배송비는 복사를 막지 않는다** (2026-09-13 용팀장 지시). 쿠팡 상품은 배송비를
**건건 직접 확인**하므로 대략적인 값이 들어 있으면 되고, 사람이 매 건 보는 통제가
자동 판정보다 정확하다. 측정값은 원장 `배송비` 탭에 참고용으로 남는다 —
`P75(채택)` 열이 실제 지불액 기준 권장값이다. 막고 싶으면 `--strict-shipping`.

## 마진 공식 — 정의가 흔들리면 게이트가 무의미하다

```
행 유효조건: 결제금액 · 이익 · 마진률 셋 다 유효
코드 가중마진 = Σ이익(유효행) / Σ결제금액(유효행) × 100
쿠팡보정마진  = 가중마진 − (쿠팡수수료 − 스마트스토어수수료)
```

**산술평균 금지.** `마진률` 들의 단순 평균은 소액 주문 1건이 대형 주문 10건과 같은
가중치를 갖는다 — 실측에서 한 코드가 단순평균 31.4% vs 가중 11.6% 로 20%p 벌어졌다.
공식은 `coupang_rules.py` 에 박고 단위테스트로 묶었다.

**결측은 fail-closed.** 행 단위로 버리고(매출 집계에는 남김), 코드 전체가 결측이면
`마진미상` 으로 **탈락**시킨다. 게이트의 존재 이유가 손실 차단인데 모르는 걸
통과시키면 게이트가 없는 것과 같다.

**쿠팡 수수료율 표는 비어 있다** — 전부 상한 10.8% 로 계산된다.
미검증 숫자를 넣으면 낙관적으로 틀리고, 비워 두면 보수적으로만 틀린다.
`references/쿠팡-수수료율.md` 참조.

## 주문시트의 함정 4가지

정본: `1D--UaQRTt3ofTQo087F0-HrcebR9SistTBmXezIwY90` (★마진율계산기★). **읽기 전용.**

1. **`판매자 상품 코드` 열은 `2025 10` 탭부터만 있다.** 앞 9개 탭에는 아예 없어
   자동으로 건너뛴다. 집계창은 12개월이다.
2. **열 구성이 월마다 다르다**(47~67열). 열 위치를 박으면 반드시 어긋난다 —
   3행 헤더명으로 찾는다.
3. **헤더에 줄바꿈이 섞여 있다**(`A+B+C+D\n지출계`). 공백·개행을 지운 뒤
   **정확일치 우선, 없으면 부분일치**. `배송비` 는 7개 열에 부분일치하므로
   정확일치가 이겨야 I열(실지불 해외배송비)을 집는다.
4. **결측은 빈칸이 아니라 `"  - "`** 또는 `"입력하기"`.

R열의 약 11%는 base64형(`PTk/PT0/...`)이고 전부 `17-2 / 17-3 / 2-1` 그룹이다.
불사자 코드가 아니라 **이 3개 그룹은 구조적으로 후보에서 빠진다.**

## 하지 않는 것

- **배송비 반영.** 측정·대조까지만 한다. 쿠팡 상품의 배송비는 용팀장이 등록 전에
  건건 직접 확인한다. 일괄 반영이 필요하면 `bulsaja-shipping-cost` 스킬로 넘긴다
  (요율표·포장 현실성 검증·별도 최종 동의 게이트가 그쪽에 있다).
- **현황판(`00_진행`) 기록.** `matrix.TASKS` 에 `쿠팡` 을 넣으면 `이력` 열을
  덮어쓴다(아래 참조). 재복사 방어는 `copied.jsonl` + 원장 `복사` 탭이 한다.
- **쿠팡 물갈이.** 물갈이는 스마트스토어 전시 최신성 회복용이다. 쿠팡은 삭제·
  재등록이 계정 지표에 악영향이라 사이클에 넣지 않는다.
- **쿠팡 사고 감시.** 올린 뒤 반품·품절취소를 보는 건 별도 스킬이 필요하다(미구현).

## 현황판에 열을 추가하면 안 되는 이유

`matrix.HEADER = ("상품id","상품") + TASKS + (LEDGER,)` 라 `TASKS` 끝에 `쿠팡` 을
붙이면 `이력` **앞**에 끼어든다. 실제 그룹 시트는 두 상태가 섞여 있다 —
11열(이력 없음)과 12열(이력 있음). 12열 시트는 `ensure()` 의 겹침 검사에 걸려
확장을 거부하는데, `task_col("쿠팡")` 은 이름으로 위치를 계산하므로 12번째 열,
즉 **`이력` 열을 가리킨다.** 저장하면 이력이 조용히 덮인다.

이건 코드 주석이 경고하는 바로 그 실패 유형이다(2026-08-19 왕복 종결 사고).
넣으려면 `이력` **뒤**로 가는 헤더 마이그레이션이 선행돼야 한다.

## 재개 · 안전

- **S6 이전은 전부 읽기 전용** — 언제 끊겨도 손실 0.
- `market_group_copy` 에는 **중복 방지가 없다.** `copied.jsonl` 이 유일한 방어선이니
  **run-dir 를 지우지 마라.**
- 복사 배치는 20건. 응답이 신 productId 를 안 줄 때 전후 diff 로 매핑하는데,
  배치가 크면 매핑 오류 피해가 커진다.
- 작업 전 `bulsaja_my_profile` 로 계정을 확인한다(용쌤/용팀장 계정이 다르다).

## 검증 (verify 가 하는 것)

- **V3 중복 0 증명**: 쿠팡 그룹 전건의 타오바오번호 유니크수 == 총상품수.
  아니면 중단하고 초과분을 지운다.
- **V4 판매가 검산**: 복사 후 판매가가 게이트 전제와 어긋나는지. 쿠팡 그룹의
  가격 설정이 가정과 다르면 게이트가 통째로 무의미해진다.

`verify` 가 못 하는 것 — 쿠팡 실제 등록 확인(`업로드된마켓`)과 육안 검수는
업로드 후에 별도로 한다.
