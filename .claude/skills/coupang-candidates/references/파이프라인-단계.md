# 파이프라인 단계 상세

## 명령 순서

```
prep → resolve → build → ship → gate → apply → verify → sheet
        [읽기 전용 — 언제 끊겨도 손실 0]      [쓰기]   [읽기]
```

## 각 단계

| 단계 | 산출 파일 | 재개 방식 |
|---|---|---|
| `prep` | `sales.json` · `ranked.json` | 매번 전체 재계산(시트 읽기 2콜) |
| `resolve` | `resolved.json` · `unresolved.json` | 코드 단위 upsert — 이미 있으면 스킵 |
| `build` | `groups.json` · `reps.json` · `build_dropped.json` | 순수 재계산, 멱등 |
| `ship` | `ship_diff.json` · `ship_fix_ids.json` | pid 단위 upsert — 이미 대조했으면 스킵 |
| `gate` | `candidates.json` · `rejected.json` | 순수 재계산, 멱등 |
| `apply` | `copied.jsonl` (건건 즉시 append) · `before_copy.json` | **`copied.jsonl` 에 있는 원본 pid 는 절대 재복사 안 함** |
| `verify` | `verified.json` | 상태 기반 |
| `sheet` | 구글 원장 5개 탭 | append |

## copied.jsonl 이 왜 유일한 방어선인가

`bulsaja_market_group_copy` 에는 **중복 방지 옵션이 없다**. 같은 상품을 같은 그룹에
두 번 복사하면 중복본이 그대로 늘어난다. 그래서:

1. `apply` 는 매 배치마다 `copied.jsonl` 에 **즉시** append 하고 `fsync` 한다.
2. 재실행 시 그 파일에 있는 원본 pid 는 후보에서 뺀다.
3. 이 파일을 지우면 방어선이 사라진다 — **run-dir 를 지우지 마라.**

## 배송비 게이트

`apply` 는 `배송비교정필요 == True` 인 후보가 남아 있으면 **중단한다**.
배송비가 틀리면 복사 시 재계산되는 판매가가 틀리고, 마진 게이트가 통째로 무의미해지기
때문이다. 알고도 진행하려면 `--allow-unfixed-shipping`.

배송비 반영 자체는 이 스킬이 하지 않는다 — `bulsaja-shipping-cost` 스킬이 한다
(요율표·포장 현실성 검증·별도 최종 동의 게이트가 그쪽에 있다).
