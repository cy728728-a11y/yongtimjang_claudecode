# Aside 카테고리 조회 (aside-category)

Aside 브라우저로 네이버 가격비교를 열어 **키워드 → 카테고리 경로 + 확신도 + 카테고리코드**를 뽑는 단일 목적 도구.

`sellha-category` 와 **역할이 같고 스키마가 호환**된다. 호출부는 스크립트 경로만 바꾸면 된다.
실제 상품 카테고리 저장·교정 흐름은 `bulsaja-category-fix` 가 담당하고, 이 스킬은 "경로 조회"만 한다.

## 셀하 대비 (2026-08-04 실측)

| | sellha-category | **aside-category** |
|---|---|---|
| 구동 | 셀레늄 + 전용 크롬 프로필 | Aside 브라우저(이룸님 상시 세션) |
| 프로필 준비 | 복사 → 웹스토어 확장 설치 → 로그인 (수작업) | 없음 |
| 보안프로그램 | 셀레늄 크롬이 ~30초에 강제종료됨 | 셀레늄 아님 — 무관 |
| 속도 | 3~10초/건 + 긴 휴식 | **10초/건** (확신도 계산) / **3.5초/건** (`--no-count`) |
| 반환 | 경로 · 확신도 | 경로 · 확신도 · **카테고리코드** · **후보목록(1~3순위)** |

## 준비

1. **Aside 브라우저 설치** (macOS 15+ 전용) — `aside.com/download`. CLI 는 `~/.local/bin/aside`.
   다른 경로면 `ASIDE_BIN` 환경변수로 지정한다.
2. **불사자 확장이 Aside 에 설치**되어 있어야 한다. 카테고리는 네이버가 아니라 이 확장이 계산한다.
3. **네이버 로그인** 세션이 살아 있어야 한다.

셋 중 하나라도 빠지면 전건 `파싱실패(확장 패널 미검출)` 가 난다. 자격증명 파일·`.env` 는 필요 없다.

## 사용

```bash
PY=".venv/bin/python"      # 윈도우: .venv/Scripts/python.exe
S=".claude/skills/aside-category/scripts/aside_category.py"

# 1) 키워드 즉시 조회 (stdout JSON)
"$PY" "$S" --query "무선마우스" "낚시텐트"

# 2) 배치: [{"productId":"..","name":".."}] JSON → 결과 JSON
"$PY" "$S" --input targets.json --output result.json --resume

# 3) 경로만 빠르게 (확신도 생략, 3배 빠름)
"$PY" "$S" --no-count --input targets.json --output result.json
```

| 옵션 | 기본 | 뜻 |
|---|:---:|---|
| `--resume` | — | output 의 **성공건만** 건너뛰고 실패건 재시도 |
| `--no-count` | — | 확신도 계산 생략(스크롤 안 함). 확신도 `null` |
| `--sleep` / `--sleep-max` | 1.0 / ×3 | 조회 간 대기. 실제 대기는 이 사이 난수(연속 실수 — `1.734초` 처럼 밀리초 단위) |
| `--rest-every` / `--rest-secs` | 0(안 쉼) / 120 | **N청크마다 쉰다.** 아래 §차단을 늦추는 두 축 |
| `--panel-tries` | 24 | 확장 패널 대기 횟수(×0.5초) |
| `--chunk` | 자동(≈7) | repl 호출 1회에 넣을 건수. **아래 120초 벽 참조** |
| `--timeout` | 건당 40초 | 청크 타임아웃 |

### 차단을 늦추는 두 축 — 간격과 총량은 다르다 (2026-08-06)

| 축 | 옵션 | 무엇을 바꾸나 |
|---|---|---|
| **간격** | `--sleep 3 --sleep-max 12` | 조회 1건 사이의 텀. 범위를 넓힐수록 규칙성이 줄어든다 |
| **총량** | `--rest-every 5 --rest-secs 180` | 5청크(≈35건)마다 3분 쉰다. **연속 조회 누적량**을 끊는다 |

`--sleep` 만 올리면 건당 시간만 길어지고 **연속으로 두드리는 총량은 그대로**다. 캡챠는
누적량에 더 반응하므로 둘을 같이 쓴다. `--no-count` 는 건당 9초→2초라 **역효과**다
(같은 시간에 더 많이 두드린다) — 차단이 잦을 땐 쓰지 않는다.

### ★ `캡챠감지` 가 났는데 열어보면 멀쩡하다 — 정착을 기다린다 (2026-08-18 실측)

**네이버 '보안 확인을 완료해 주세요' 화면은 스스로 통과되는 중간 화면일 때가 있다.**
같은 URL 을 시점별로 찍은 실측:

| 시점 | 화면 |
|---|---|
| 1.2초 | 캡챠 입력창 2개(`rcpt_answer_*`·`vcpt_answer_*`) + "보안 확인을 완료해 주세요" |
| 5.2초 | **캡챠 흔적 0개 · 정상 검색결과** |

`driver.js` 가 `goto` 직후 1.2초에 한 번만 보고 끊었기 때문에 **멀쩡한 조회가 전건
`캡챠감지` 로 죽었다.** 1-3 그룹 15건이 이틀 동안 이것 때문에 못 넘어갔다.

**증상으로 알아보는 법** — 아래가 다 맞으면 이 결함이지 진짜 차단이 아니다:
- 손으로 그 URL 을 열면 캡챠가 없다(`captcha_relay.py open` → `capture` 로 확인)
- 쉬는 시간을 늘려도 라운드당 1~2건만 나가고 계속 같은 자리에서 끊긴다
- `captcha_relay.py solve` 가 `needs_human`("캡챠 질문을 확인할 수 없음")을 돌려준다

**고쳤다**: `driver.js` 의 `CAPTCHA_SETTLE_TRIES`(5) × `CAPTCHA_SETTLE_MS`(2000) —
캡챠로 보이면 즉시 끊지 않고 최대 10초까지 다시 본다. **진짜 캡챠는 사람이 풀기 전엔
안 사라지므로 이 대기로 오판이 생기지 않는다.** 차단(`차단`)은 종전대로 즉시 중단이다.

### `파싱실패(확장 패널 미검출)` 가 전건 나면 — 조회가 아니라 확장을 본다

캡챠를 넘겼는데 이게 나오면 **불사자 확장이 죽은 것**이다(2026-08-18~19 실측: 이틀치 작업이
여기서 멈췄다). 카테고리는 네이버가 아니라 이 확장이 계산하므로 확장 없이는 조회가 0건이다.

```bash
# 앱 탭으로 열어 화면을 직접 본다 — repl 탭이 아니라 앱 탭이어야 확장 상태가 그대로 보인다
python .claude/skills/captcha-relay/scripts/captcha_relay.py open --url "<검색 URL>" --wait 10
python .claude/skills/captcha-relay/scripts/captcha_relay.py capture --match "<query= 인코딩 조각>"
# → 찍힌 png 를 Read 로 열어 '키워드 인사이트 · 추출된 카테고리' 블록이 있는지 본다
```

네이버 로그인은 살아 있는데(우상단 닉네임 보임) 그 블록만 없으면 **확장 문제**다 —
스킬이 못 고친다. 이룸님께 Aside 앱에서 확장 켜짐·확장 내 로그인을 확인해 달라고 보고한다.
쉬었다 재시도해도 안 풀린다(14시간 쉬고도 동일했다).

**캡챠·차단이 잡히면 그 청크에서 끝내고 남은 청크를 돌지 않는다**(driver 가 그 청크를 끊고,
러너가 다음 청크로 넘어가지 않는다). 계속 두드릴수록 오래 막히기 때문이다. 푼 뒤 `--resume`.

> 캡챠는 [`captcha-relay`](../captcha-relay/SKILL.md) 스킬로 푼다 — **명령·검증 절차는
> 그 SKILL.md 가 정본**이다(판단은 Aside 위임, 입력·제출은 Claude). 풀리면 `--resume`,
> `needs_human`·타임아웃이면 재조회하지 않고 이룸님에게 보고한다.

### ★ `aside repl` 은 호출 1회당 ~120초 하드 리밋 (2026-08-04 실측)

**120초를 넘기면 연결이 끊기고(`fetch failed: other side closed`), 그때까지 조회한 결과도
전부 유실된다.** stdout 이 호출 종료 시 한꺼번에 나오는 구조라 부분 저장이 불가능하다.

| 건수 | 결과 |
|---:|---|
| 1건 | 성공 8.6초 |
| 5건 | 성공 43.5초 |
| 20건 | **실패 — 정확히 120.19초, 0건** |
| 40건 | **실패 — 정확히 120.20초, 0건** |
| 300건 | **실패 — 0건** |

그래서 스크립트가 **벽의 65% 아래로 자동 청크 분할**한다(확신도 계산 시 ≈7건/호출).
청크마다 `--output` 에 즉시 쓰므로 다음 청크에서 죽어도 앞은 남고, 청크 실패 시 1회 재시도한 뒤
그 청크만 건너뛰고 **exit 2** 로 보고한다 → `--resume` 으로 다시 돌리면 그 건만 재조회한다.

`--chunk` 로 덮어쓸 수 있지만 **올리지 말 것.** 조회가 느려지는 요인(네이버 지연 로딩, 스크롤)이
붙으면 그대로 벽에 닿는다. 되레 `--sleep-max` 를 올렸다면 청크를 줄여야 한다.

> **교훈**: 이 결함은 엔진 전환 때부터 있었지만 스모크가 10건(~87초)이라 벽 아래로 지나가
> 안 보였고, 첫 대량 실행에서 드러났다. **새 엔진에 배치를 붙일 땐 "한 호출에 몇 초짜리를
> 몇 건 넣는가"를 먼저 잰다.**

`--profile` · `--headless` · `--restart-every` · `--block-wait` 는
sellha 호출부 호환용으로 **받기만 하고 무시**한다.
(`--rest-every`/`--rest-secs` 는 무시 목록에서 빠졌다 — 2026-08-06부터 **실동작**하는
차단 완화 기능이다. 위 §차단 표 참조.)

## 반환 (항목별 dict)

| 필드 | 뜻 |
|---|---|
| 검색어 · productId | 조회 키워드 / (배치 입력 시) 입력 id 그대로 |
| 카테고리경로 | 1순위 '대분류 > … > 최종차수' |
| 최종차수 | 경로 마지막 차수(불사자 카테고리 검색 키워드로 씀) |
| 확신도 | **1페이지에서 1순위 경로가 차지한 %** (아래 정의 참조) |
| 카테고리코드 | 네이버 카테고리 번호(예 `50002927`). 1순위에만 있음 |
| 후보목록 | 확장이 준 1~3순위 경로 배열. **2개 이상이면 키워드가 갈린다는 뜻** |
| 표본수 | 확신도 계산에 쓴 1페이지 상품 수(보통 44~47) |
| 마켓 · url | `네이버` / 조회한 검색 URL |
| 상태 | 성공 / 조회실패(검색결과없음) / 파싱실패 / **차단감지** / **캡챠감지** |
| error | 실패 사유 |

### 확신도의 정의 — 셀하와 같다

**1페이지 상품들의 카테고리 중 1순위 경로가 차지한 비율.** 셀하 확신도와 같은 정의이므로
`bulsaja-category-fix` 의 **자동저장 임계 70 을 그대로 쓴다.**

확장이 주는 "N순위"는 이 분포를 등수로만 보여준 것이다. 실측(`왜건`):

```
확장 1순위 스포츠/레저 > 캠핑 > 캠핑왜건        ← 실측 35/47건 = 74.5%
확장 2순위 가구/인테리어 > 주방가구 > 왜건/카트  ← 실측  8/47건
확장 3순위 스포츠/레저 > 캠핑 > 기타캠핑용품     ← 실측  4/47건
```

> ⚠️ **순위 개수를 확신도로 환산하지 않는다.** 근거 없는 임의 매핑이다. 확신도는 반드시 실제로 센 값이거나 `null` 이다.
> `--no-count` 로 뽑은 결과는 확신도가 `null` 이므로 **자동저장 게이트에 넣지 않는다** — 경로만 볼 때 쓴다.

**확신도는 "키워드↔카테고리"의 몰림이지 "키워드↔상품"의 정확도가 아니다.**
검색어가 상품을 잘못 대표하면 확신도 100%여도 오답이다. 방어는 앞단 정체 판별(증거 4종)이 한다.

## bulsaja-category-fix 에 물리기

`run_all.py` 의 `SELLHA_SCRIPT` 가 가리키는 경로만 이 스크립트로 바꾼다.
반환 키(`카테고리경로`·`최종차수`·`확신도`·`상태`)가 같아 병합부는 손대지 않아도 된다.

```python
SELLHA_SCRIPT = os.path.join(SCRIPT_DIR, "..", "..", "aside-category", "scripts", "aside_category.py")
```

`--profile` 을 넘겨도 무시되므로 기존 호출 라인을 그대로 둬도 동작한다.

## 트러블슈팅

- **전건 `확장 패널 미검출`**: 순서대로 본다 — ① Aside 브라우저가 떠 있나
  ② 불사자 확장이 Aside 에 설치·활성인가 ③ 네이버 로그인이 살아 있나.
  그 다음에야 파싱 로직을 의심한다.
- **결과가 이전 키워드 것 같다**: 드라이버가 패널에 박힌 `‘키워드’` 를 대조한 뒤에만 읽으므로
  구조상 안 생긴다. 그래도 의심되면 `--panel-tries` 를 늘린다.
- **표본수가 10 미만**: 스크롤이 덜 됐다. `--scroll-wait` 를 올린다(네이버 지연 로딩).
- **`차단감지` · `캡챠감지`**: 남은 건을 건드리지 않고 **즉시 중단**한다(계속 두드리면 더 오래 막힌다).
  캡챠는 `captcha-relay` 스킬로 푼다(판단은 Aside, 입력·제출은 Claude). 푼 뒤 `--resume`.
  차단은 시간을 두고 `--resume`. 둘 다 성공건은 건너뛰므로 중복 조회가 없다.

  > 캡챠를 따로 빼는 이유: `정상` 으로 흘리면 뒤에서 패널을 못 찾아 `파싱실패(확장 미검출)` 로
  > 뭉개진다. 그러면 원인이 캡챠인데 확장·로그인을 뒤지게 된다.
- **`Path escapes Project and session roots`**: 옛 버전 흔적. 현재 드라이버는 파일을 쓰지 않는다.
