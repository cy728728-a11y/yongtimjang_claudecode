# 해외배송비 측정·추천·반영

## 계정 라우팅

불사자 MCP는 두 계정으로 등록되어 있다.

- **용쌤 계정** (`mcp__bulsaja-yongssaem__*`): `N번_용쌤X-X` 등 일반 마켓그룹. 계정 지정 없이 "마켓"이라고만 하면 기본값.
- **용팀장 계정** (`mcp__bulsaja__*`): "용감한 용팀장" 그룹(유튜브·강의용).

용팀장님이 계정을 명시하면 그 계정의 도구를 쓴다. 지정이 없으면 용쌤 계정으로 먼저 조회하고, 상품코드가 안 나오면 용팀장 계정도 확인한다.

## 개요

불사자 수집상품 1개(또는 수동 입력된 무게·부피)를 받아 예상 해외배송비를 검토하고, 사용자가 적용을 요청한 경우 안전한 미리보기·최종 확인·저장 검증까지 수행한다. INPUT 1개 → OUTPUT 1개 원칙을 따른다.

- INPUT: 불사자 수집상품 1개, 또는 무게·부피 수동 입력
- OUTPUT: 예상 해외배송비 + 계산 근거 + 포장 현실성 판정 + 필요 시 실제 반영 결과

두 경로를 구분한다.

1. **불사자 인공지능 추천 경로(수집상품 우선):** 상품 상세·전체 가공자료·원본 상품 정보와 함께 해외배송비 추천을 조회한다. 추천 크기와 무게를 판매 중 옵션의 실제 형상·최소 포장 가능 크기와 교차검증한다.
2. **수동 계산 경로:** 확인된 포장 무게 또는 불사자가 제공한 예상 청구무게를 `references/rate-table.md`의 해운 특가 요율에 대입한다. 1.0kg부터 100.0kg까지는 제공된 표를 적용하고, 중간 무게는 다음 0.5kg 구간으로 올린다. 100kg 초과분은 검증된 증가 규칙인 0.5kg당 800원을 그대로 연장한다. 가로·세로·높이만 있고 실제 부피무게 계산식이 없으면 임의로 청구무게를 만들지 않는다.

### 100kg 중량 상품 처리

- 예상 청구무게가 100kg 이하이면 일반 절차로 추천·검토·반영한다.
- 예상 청구무게가 100kg을 넘어도 추천 해외배송비 계산과 입력은 계속 진행한다. 100kg 요금 164,000원에 초과 0.5kg 구간마다 800원을 더한다.
- 100kg 초과는 용팀장님의 선호 소싱 범위를 벗어나는 중량 상품이다. 반영 완료 보고의 첫 부분에 `100kg 초과 예상`, 적용한 청구무게, 추천·입력 배송비를 눈에 띄게 경고한다.
- 중량 경고는 적용 중단 사유가 아니다. 상품 구조상 추천 무게 자체가 비현실적이거나 근거가 없는 경우에만 적용을 중단하고 실측을 요청한다.

### 추천액 반영 절차

사용자가 적용까지 요청했을 때만 다음 순서를 지킨다.

1. 현재 상품 해외배송비와 추천액을 확인한다. 마켓그룹 기본 배송 설정과 상품별 해외배송비는 별도 값이므로 혼동하지 않는다.
2. 추천 포장 크기를 판매 중인 모든 옵션의 물리적 최소치와 비교한다. 예를 들어 받침판 한 변이 30cm인데 추천 포장이 15cm라면 명백한 불일치다. 조립 높이는 분해 포장될 수 있으므로 그대로 포장 길이로 단정하지 않되, 분해되지 않는 판·프레임·본체의 최대 치수보다 작은 포장은 거부한다.
3. 포장 근거가 현실적일 때만 가격 변경 미리보기를 요청한다. 미리보기에서 기존 배송비, 새 배송비, 차액, 옵션 판매가 조정 방식을 사용자에게 보여준다.
4. **미리보기를 보여준 뒤 별도의 최종 동의**를 받아야 한다. 과거의 포괄 승인만으로 이 단계를 생략하지 않는다.
5. 같은 확인 정보로 실제 적용한다(`bulsaja_price_update`). 미리보기 후 시간이 지났거나 다른 상품 변경으로 확인 정보가 만료돼 새 확인 정보가 반환되면, **상품·변경 방식·새 배송비가 직전 승인안과 완전히 같은지 먼저 대조**한다. 모두 같고 사용자가 방금 최종 승인한 작업이면 같은 승인 범위로 새 확인 정보를 사용해 즉시 한 번 재시도한다. 금액·상품·변경 방식 중 하나라도 다르면 재실행하지 말고 새 미리보기를 보여준 뒤 다시 동의를 받는다.
6. 적용 성공 후 `bulsaja_shipping_cost_recommend`와 `bulsaja_product_workdata(mode=full)`를 함께 재조회한다. 추천 조회의 현재 해외배송비와 전체 작업자료의 `uploadOverseaDeliveryFee`가 적용액과 같은지 교차검증한다. `original_deliveryFee`와 `overseaDeliveryFee`는 원본·과거 호환 값으로 0원이 남을 수 있으므로 이 둘만 보고 적용 실패로 판정하지 않는다. `uploadDelivery.delivery_fee`는 국내 기본 배송 설정이므로 상품별 해외배송비와 혼동하지 않는다.
7. 옵션 가격은 차액만큼 100원 단위로 조정됐는지 확인한다. 변경 기능이 판매 제외 옵션 행의 계산가격도 함께 갱신할 수 있으므로, **판매 중 옵션 수·최저가·최고가·대표옵션 가격**을 별도로 집계하고 제외 옵션이 다시 판매 상태로 바뀌지 않았는지도 확인한다. 사용자에게는 판매 중 옵션 기준 가격 범위만 우선 보고하고, 제외 옵션 가격까지 바뀐 사실은 필요한 경우 별도로 설명한다.
8. 추천 포장이 현실과 맞지 않으면 적용하지 않는다. 확인된 포장 실측이나 신뢰 가능한 물류 근거를 확보한 뒤 수동 계산 경로로 전환한다.

배송비 변경은 옵션 판매가에도 차액을 반영할 수 있는 가격 변경 작업이다. 따라서 추천 조회는 읽기 전용이지만 실제 반영은 가격 변경 작업으로 취급한다.

## 사용 시점

다음 요청에 사용한다.

- 판매자상품코드를 주며 해외배송비를 계산해 달라는 요청
- 무게·부피를 직접 알려주며 배송비를 계산해 달라는 요청
- 원스텝 파이프라인에서 배송비 측정 단계를 위임받은 경우
- 이 상품이 배송비를 빼고도 남는지 참고치를 봐 달라는 요청

다음 작업에는 사용하지 않는다.

- 사용자의 적용 요청·변경 미리보기·최종 동의 없이 상품 판매가나 배송비를 변경하는 작업
- 국내 택배비·반품비 계산
- 배대지 결제·정산·통관 실무 처리
- 요율표 없이 "대충 얼마쯤"을 어림잡아 달라는 요청 — 요율표가 없으면 계산하지 않는다
- 관세·부가세 등 세금 계산 (요율표 범위 밖이며 근거 없이 추정하지 않는다)

## 단계별 절차

### 1단계: 계산 경로 선택

- **불사자 수집상품:** 상품 상세, 전체 가공자료, 원본 상품 정보, 인공지능 배송비 추천을 함께 조회한다. 추천된 예상 청구무게가 있으면 해운 특가 요율에 대입하고 상품 구조와 모순되는지 검증한다.
- **수동 무게 입력:** `references/rate-table.md`의 최소 1.0kg·0.5kg 단위 올림·0.5kg당 800원 증가 규칙을 적용한다.
- **크기만 입력:** 제공된 요금표에는 부피무게 계산식이 없으므로 임의 계산하지 않고, 실제 부피무게 계산식 또는 청구무게 확인을 요청한다.

완료 기준: 근거가 있는 예상 청구무게 또는 실무게가 확보되어 해운 특가 요율을 적용할 수 있거나, 무게 근거 부족으로 계산 불가 판정이 난 상태.

### 2단계: 입력 해석

- **판매자상품코드 입력:** 계정 라우팅 원칙대로 `bulsaja_product_find_by_code`로 정확한 상품을 찾는다. 지정된 계정(또는 기본값인 용쌤 계정)에서 못 찾으면 다른 계정도 확인한다. 그래도 못 찾으면 코드 재확인을 요청하고 멈춘다.
- **무게·부피 수동 입력:** 단위(kg/g, cm/mm)를 확인하고 kg·cm로 통일한다. 단위가 불명확하면 되묻는다. (사용자 확인 지점 2)

완료 기준: 대상 상품이 하나로 확정됐거나, 수동 입력값이 단위까지 확정된 상태.

### 3단계: 무게·부피 확보 — 데이터 소스 우선순위

반드시 아래 순서대로 시도하고, 어느 소스에서 얻었는지 보고에 명시한다.

1. **불사자 수집 데이터:** `bulsaja_product_detail`과 `bulsaja_product_workdata`에서 무게·크기 필드를 확인한다. 옵션(SKU)별 무게가 있으면 그 값을 쓴다.
2. **상세페이지 스펙 이미지:** 수집 데이터에 무게·크기가 없으면 상세페이지 이미지 중 스펙 표기가 있는 이미지를 비전으로 직접 확인해 추출한다. 이때 어떤 이미지의 어떤 표기(예: "重量: 1.2kg", "尺寸: 32×18×10cm")에서 읽었는지 추출 근거를 반드시 함께 기록한다. 표기가 흐릿하거나 해석이 갈리면 확정하지 않는다.
3. **둘 다 없으면:** "측정 불가 — 수동 확인 필요"로 정직하게 보고하고 종료한다. 상품 종류·크기 인상으로 무게를 지어내는 것을 절대 금지한다.

옵션별 무게가 서로 다르면 확인된 범위(최소~최대)를 그대로 보고하고, 임의로 하나를 대표값으로 정하지 않는다. 대표값이 필요하면 어느 옵션 기준인지 사용자에게 확인한다. (사용자 확인 지점 3)

완료 기준: 실무게(그리고 확보 가능하면 가로·세로·높이)가 출처와 함께 확정됐거나, 측정 불가 판정이 난 상태.

### 4단계: 청구무게 계산

1. 요율표에 기입된 부피무게 계산식으로 부피무게를 계산한다. 요율표에 기입된 식 외의 통상 공식을 임의로 대입하지 않는다.
2. **청구무게 = 실무게와 부피무게 중 큰 값.**
3. 치수를 확보하지 못해 부피무게를 계산할 수 없으면, 실무게만으로 계산하되 "부피무게 미반영 — 실제 청구액은 더 높을 수 있음"을 보고에 명시한다.

완료 기준: 청구무게와 그 판정 근거(실무게 vs 부피무게 비교)가 정리된 상태.

### 5단계: 요율 구간 적용

1. 청구무게가 1.0kg 미만이면 최소 구간인 1.0kg으로, 그 외 중간 무게는 다음 0.5kg 구간으로 올린다.
2. 100kg 이하는 제공된 해운 특가표를 적용한다. 모든 구간은 0.5kg당 800원씩 증가하며 `4,000원 + 1,600원 × 청구무게(kg)`와 일치한다.
3. 100kg을 넘으면 100kg 요금 164,000원에서 같은 증가 기준을 연장한다. 추천 배송비 입력은 계속 진행하되, 용팀장님에게 100kg 초과 중량 상품이라고 별도 경고한다.
4. 100kg 초과 경고에는 적용 청구무게, 입력 배송비, 선호 소싱 범위 밖이라는 점을 함께 적는다.
5. 가로·세로·높이만 있고 실제 부피무게 계산식이 없으면 통상 공식을 임의 적용하지 않는다. 확인된 실무게만 있다면 실무게 기준 참고액이라고 명시한다.

완료 기준: 적용 구간과 예상 배송비가 확정되고, 100kg 초과 여부와 후속 처리 방식까지 정리된 상태.

### 6단계: 판매가 대비 마진 참고치

1. 불사자 상품 데이터에서 현재 판매가가 확인되면, 예상 배송비가 판매가에서 차지하는 비율과 판매가에서 예상 배송비를 뺀 잔여 금액을 참고치로 제시한다.
2. 이 참고치에는 소스원가 환산·마켓 수수료·세금이 포함되지 않았음을 반드시 명시한다.
3. 판매가가 확인되지 않으면 이 항목을 생략하고 그 사실만 알린다. 판매가를 추정하지 않는다.

완료 기준: 마진 참고치가 한계 고지와 함께 제시됐거나, 판매가 미확인으로 생략이 명시된 상태.

### 7단계: 결과 보고

아래 보고 형식으로 자연스러운 한국어만 사용해 보고한다. 내부 번호, 확인 키, 도구명은 노출하지 않는다. 원스텝 파이프라인 경유 시에는 같은 내용을 게이트 1 보고서의 배송비 항목으로 전달한다.

## 원스텝 파이프라인 연동 (세로 러너, 2026-08-12)

상품 1건씩 전 단계를 훑는 세로 러너 `eroomlib/runner/onestep.py` 의 6번째 단계(00_진행
매트릭스 예약 순서 그대로: 카테고리→상품명→옵션→썸네일→상세→**배송비**)로 편입되어 있다.
onestep 이 부르는 스크립트 진입점은 이 스킬의 대화형 절차와 **같은 계산 규칙**을 코드로
고정한 것이다 — 규칙이 둘로 갈리지 않게, 요율 계산은 `scripts/shipping_rate.py` 한 곳에만
있고 대화형 경로도 결국 같은 표(`references/rate-table.md`)를 본다.

```
prep  --ids <상품id...> --run-dir <R> [--sheet <시트id>]
      스냅샷(판매중옵션·옵션이미지·썸네일) + bulsaja_shipping_cost_recommend(AI추천) +
      현재 해외배송비를 모아 shipping_evidence.json 을 만든다. (scripts/run_shipping.py)

run   (Claude 차례 — 스크립트 없음)
      shipping_evidence.json 을 읽고 §단계별 절차 1~5단계 그대로 판단해
      shipping_decision.json 을 만든다. 형식:
      [{"productId", "실무게", "부피무게"(선택), "무게출처",
        "포장정합판정": "적합"|"부적합"|"확인불가", "판정사유",
        "측정불가": bool}]

apply --run-dir <R> [--commit] [--sheet <시트id>]
      shipping_decision.json → scripts/shipping_rate.py 로 요율 재검증 → 현재 배송비와
      diff → **항상 price_update(confirm=False)로 미리보기를 새로 받는다**(토큰을 저장해
      재사용하지 않는다 — §흔한실패 11의 만료 문제를 구조적으로 피한다). --commit 이면
      그 자리에서 바로 confirm=True 로 저장까지 한다. 그룹 시트 `06-배송비` 탭에 건건
      append, 00_진행 매트릭스 `배송비` 열은 --commit 때 열 통짜 1회 갱신.
```

- prep 산출물 `shipping_evidence.json` 과 apply 산출물 `shipping_result.json` 은 자기완결형
  이다 — 워커가 대화 맥락 없이 파일 경로만으로 판단·검증할 수 있어야 한다(스킬-계약).
- 포장정합판정이 "부적합"이면 apply 는 가격을 건드리지 않고 `반영보류(포장불일치)` 로
  남긴다 — 반영은 §추천액 반영 절차의 "포장이 현실과 맞지 않으면 적용하지 않는다"를
  코드로도 지킨다.
- 100kg 초과라도 계산·입력은 계속하고, `onestep.py gate` 화면과 게이트 신호
  (`ship.over_100kg` 등, `runner/signals.py`)에 별도로 뜬다.
- 대화형 단독 호출(원스텝 경유가 아닐 때)은 이 스크립트를 몰라도 된다 — §단계별 절차를
  그대로 따르면 같은 결과가 나온다. 크기만 있고 부피무게 계산식이나 청구무게가 없으면
  양쪽 경로 모두 **"부피무게 계산 근거 없음 — 계산 불가"**로 반환한다.

```text
상품: 소형 가정용 배수펌프
실무게: 1.2kg (수집 데이터의 무게 항목)
부피무게: 0.9kg (확인된 실제 계산식 적용 시)
판정무게: 1.2kg — 실무게가 부피무게보다 큼
청구 구간: 1.5kg — 다음 0.5kg 구간으로 올림

예상 해외배송비: 6,400원 (제공된 해운 특가표 기준)

판매가 대비 참고치:
- 현재 판매가 18,900원 기준 배송비 비중 약 34%
- 배송비 차감 후 잔여 12,400원
- 소스원가·마켓 수수료·세금은 포함하지 않은 참고치입니다.
```

100kg 초과 상품은 일반 결과보다 먼저 다음 경고를 붙인다. 배송비 계산과 입력은 중단하지 않는다.

```text

예상 청구무게: 101.0kg
추천·입력 해외배송비: 165,600원
```

## 흔한 실패와 방지법

1. **무게가 없는데 상품 종류로 추정**
   "이 정도 크기면 보통 1kg쯤"은 금지다. 근거가 없으면 측정 불가로 보고한다.

2. **요율표가 비었는데 통상 요율로 계산**
   다른 배대지의 일반적인 요율을 대입하지 않는다. 요율표 값이 없으면 계산 자체를 거부한다.

3. **부피무게 공식 임의 적용**
   6000 나누기가 통상적이라는 이유로 요율표에 기입되지 않은 식을 쓰지 않는다. 기입된 식만 사용한다.

4. **단위 혼동**
   g을 kg으로, mm를 cm로 읽는 실수를 막기 위해 추출 직후 단위를 명시적으로 변환·기록한다. 1200g→1.2kg처럼 변환 과정을 보고에 남긴다.

5. **부피무게 생략 후 침묵**
   치수가 없어 실무게만 썼다면 "실제 청구액은 더 높을 수 있음"을 반드시 알린다. 말없이 낙관적인 값만 보고하지 않는다.

6. **옵션별 무게 차이 무시**
   옵션마다 무게가 다른데 하나만 보고 전체인 것처럼 말하지 않는다. 범위를 보고하고 대표 기준은 사용자에게 확인한다.

7. **마진 참고치를 실제 마진으로 표현**
   소스원가·수수료·세금이 빠진 참고치임을 매번 명시한다. "이만큼 남습니다"라고 단정하지 않는다.

8. **추천 조회와 실제 반영을 한 단계로 처리**
   추천은 읽기 전용이지만 반영은 옵션 판매가까지 바꾸는 가격 작업이다. 추천 포장의 현실성 검증 → 변경 미리보기 → 사용자에게 기존값·새값·차액 보고 → 별도 최종 동의 → 적용 → 재조회 검증 순서를 지킨다.

9. **상품별 해외배송비와 마켓그룹 기본 배송비 혼동**
   서로 다른 설정일 수 있다. 현재값을 보고할 때 어떤 값인지 확인하고, 실제 반영 후에는 상품 전체 가공자료의 상품별 해외배송비를 기준으로 검증한다.

10. **인공지능 추천 포장을 무검증 신뢰**
    추천 포장이 판매 중 옵션의 분해되지 않는 최대 부품보다 작으면 적용하지 않는다. 조립 높이만 보고 과대 포장으로 단정하는 것도 금지하며, 판·프레임·본체처럼 실제 포장 최소치를 만드는 치수를 우선한다.

11. **확인 정보 만료를 새 작업으로 오해**
    최종 승인 뒤 확인 정보만 만료됐고 대상 상품·변경 방식·배송비가 동일하면 새 확인 정보로 한 번 재시도한다. 셋 중 하나라도 달라졌다면 기존 승인을 재사용하지 않고 새 미리보기와 최종 동의를 받는다.

12. **원본·호환 배송비 값 0원을 적용 실패로 판정**
    전체 작업자료의 원본 배송비나 과거 호환 값에는 0원이 남을 수 있다. 업로드용 해외배송비 저장값과 배송비 추천 조회의 현재값을 함께 확인하고, 국내 기본 배송 설정은 별도로 본다.

13. **제외 옵션의 계산가격 변경을 판매 재개로 오해**
    배송비 차액 계산이 제외 옵션 가격에도 반영될 수 있다. 판매 여부와 계산가격은 별도이므로 제외 상태가 유지되는지 확인하고, 판매 중 옵션만 따로 세어 가격 범위와 대표옵션을 보고한다.

14. **보고에 내부 정보 노출**
    판매자 보고에는 내부 번호·확인 키·도구명·저장 항목명을 쓰지 않고 상품명 중심으로 전달한다.

15. **계정을 착각해 "상품 없음"으로 오판**
    지정 계정(또는 기본값 용쌤 계정)에서 못 찾았다고 바로 실패 처리하지 않는다. 다른 계정도 확인한 뒤에 코드 재확인을 요청한다.
