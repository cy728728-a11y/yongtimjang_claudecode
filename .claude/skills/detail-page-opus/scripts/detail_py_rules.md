# 규칙 (계정 스킬 smartstore-detail-page 2026-10-23-opus-v1 + 11/04 카피 보강 + 11/19 비교 장)

## 사실
- 사실은 원본 사진과 _facts(타오바오 제목·옵션·SKU)에서만. 자동 생성 상품명·AI 썸네일(upload-thumb)로 기능·재질·구성을 확정하지 않는다.
- 원본 수치 중 한 곳에만 나오거나 교차 확인이 안 되는 것은 뺀다. 실제 판매 구성과 다르게 읽힐 수 있는 수치·구성도 뺀다. 판매 제외 옵션은 상세에 넣지 않는다.
- 상위 옵션에만 있는 부속을 기본형에 포함된 것처럼 쓰지 않는다.

## 컷 (cuts)
- 원본 사진 영역을 칸 단위로 잘라 컷을 만든다. bbox 는 **원본 파일 픽셀 좌표 [x0,y0,x1,y1]** — 모음의 빨간(100px)·파란(50px) 눈금 숫자로 읽는다. 타일 위 빨간 글씨가 파일명·원본 크기다.
- 사진 위 중국어 카피 띠·아이콘·원형 확대컷·판매처 로고 띠는 bbox 로 잘라낸다. 잘라도 남으면 그 컷은 안 쓴다. 제품 본체에 인쇄된 글자는 괜찮다.
- 가로 600px 미만 컷은 작은 칸(grid 3열·zigzag)에만. 흐릿한 컷은 안 쓴다. 같은 사진이 여러 파일(source=thumb=option)이면 하나만 컷으로.
- usable 컷의 70% 이상을 쓴다. 한 컷은 한 번만(대표 제품컷만 최대 2회). 장 메시지에 맞는 종류(사용장면/제품단독/디테일/구성품/사이즈/옵션)를 배정한다.
- 키는 영문 대문자 짧게(READ, SIZE5, O3W 등).

## 구성
- 장수 = 확인된 메시지 수와 서로 다른 usable 컷 수 중 작은 쪽(보통 7~10). 같은 컷·비슷한 카피로 장수를 늘리지 않는다.
- 흐름: 1) 가장 강한 사용 장면 + 결과 중심 H1(제품명 아님) 2) 리뷰형 후킹 장(quote: 큰 따옴표 문장 1개 + 보조 1줄, 별점·후기 수·닉네임·"내돈내산" 금지) 3~) 핵심 장점 → 특징 → 구조·조작부 → 사용 장면 → 활용 → 사용 준비 → 구성품(원본에 있을 때만) → 옵션 장(판매 옵션이 2개 이상이고 차이가 사진으로 분명할 때) → 마지막 spec 장(확인된 스펙만 + 구매 전 확인 2~3개: 사이즈·호환·전원·조립 중 확인된 것 우선).
- 원본에 같은 상품의 개선형 vs 일반형(升级·新款 vs 旧款·普通款) 비교 사진 쌍이 있을 때만 compare 장 — 기존 장 하나를 바꾼다(장 수 유지). 사진으로 보이는 차이만, 다른 브랜드·"타사"·"싸구려" 금지.
- 세트·구성품이 여러 종이면 numbered 장을 하나 넣는다 — 구성품이 한 장에 늘어선 사진이 있으면 cut 과 marks 를 꼭 넣는다(글 목록만 있는 장은 휑하다)(이름을 사진 위 번호와 맞춰 짚어 주는 장이 없으면 단조롭다). 같은 레이아웃만 반복하지 말고 9가지를 고루 쓴다.
- 옵션 장이 있으면 색·모양을 나열하는 grid 장을 따로 만들지 않는다(같은 내용 두 번 금지). 옵션 장 컷은 치수선·라벨 없는 깨끗한 사진(source 쪽)을 우선한다.
- 한 칸(컷)에는 제품 하나 또는 한 장면만. 원본이 여러 칸으로 나뉜 사진이면 칸 하나만 잘라낸다. 칸 경계선·옆 칸 일부·주황/빨강 표시선이 들어가지 않게 bbox 를 안쪽으로 10~20px 여유 있게 잡는다.
- **같은 레이아웃 연속 2장 금지.** 배경은 ivory ↔ beige 번갈아. bleed 사진 장과 톤 배경 장을 섞는다.

## 카피
- 타깃 1명 + 그 사람이 쓰는 장면 1개를 원본 근거로 정하고, 모든 장을 그 사람에게 말하듯 쓴다. "누구나·모든 분" 금지.
- H1 은 두 줄 [윗줄(보통 굵기), 아랫줄(굵게)], 합쳐 10~18자 안팎. 각 장 H1 은 4공식 중 하나: ① 숫자+구체성 ② 질문형 공감 ③ 타깃 지정 ④ 결과 제시. 연속 2장 같은 공식 금지. 공포 조장 금지.
- 스펙을 쓰면 같은 장에 "그래서 고객이 할 수 있는 것" 한 줄(사실→기능→혜택). 혜택 없는 스펙 나열 장 금지(마지막 spec 장 예외).
- 불편은 구체적 장면 한 줄로(추상어 "불편함·스트레스" 금지). 해요체 구어. 번역투(~를 제공합니다/~가 가능합니다/~에 적합합니다) 금지.
- 교차 확인된 숫자에만 일상 비유 1개(장마다 최대 1개), 다른 브랜드 비교 금지.
- 금지어(이미지 안 어디에도): 공급처, 판매자에게 확인, 원본, 합성, 연출, 타오바오, 업로드, 파일, 해상도, 추출, 편집, 생성, AI, GPT, 코드, 혁신적, 프리미엄, 완벽, 최고, 100%, 특가, 선착순, 무조건, 고품질, 고급, 최고급, 국내산, 국내생산, 1위, 베스트, 재구매, 판매량, 살펴보세요, 확인해 주세요, 제공합니다, 가능합니다, 적합합니다, 누구나, 모든 분, 후기, 별점, 내돈내산, 정품, 인증. 한자·중국어·이모지·✓ 금지.
- 글자 길이: 본문 한 줄은 한글 22자 안팎(32px, 폭 764px)까지. zigzag 줄은 사진 380px 기준 한 줄 11자 안팎. grid 3열 칸 제목 8자·보조 10자 안팎, 2열은 제목 12자·보조 14자. 넘치면 프로그램이 FIT 오류로 돌려보낸다 — 그때는 글씨가 아니라 문장을 줄인다.

## 레이아웃 (pages[].layout) — 이 9가지만
공통 필드: n(1부터), layout, bg("ivory"|"beige"), pill(알약 라벨 2~8자), h1:[윗줄, 아랫줄], sub(선택, 15~28자), body(사진 아래 본문 0~2줄), formula("① 숫자+구체성" 등)
- photo: cut, bleed(true=좌우 꽉), focus:[x,y](0~1, 잘릴 때 남길 중심), wm:[x,y](워터마크 중심, 제품 로고·설명 피해서)
- quote: quote:["“윗줄", "아랫줄”"], sub, cut, focus, body — pill·h1 없음
- grid: cols(2|3), cells:[{cut, title, sub, focus, wm}] 2~6칸
- zigzag: rows:[{cut, pill, lines(2~4줄), side("left"|"right", 번갈아), w(사진 폭 280~440)}] 1~3줄
- options: cells:[{cut, name(옵션명 다듬은 짧은 이름), sub, fit("cover"|"contain")}] — 판매 옵션만, 번호는 프로그램이 붙임
- spec: rows:[[항목, 값], …] 3~7개(값은 확인된 것만), checks:[구매 전 확인 2~3줄] — 마지막 장
- numbered: cut(선택, 구성품이 한 장에 모인 사진), marks:[0~1 위치](선택 — 사진 속 물건이 왼→오로 늘어서 있으면 각 물건 가로 중심, items 순서와 같게), items:[이름 또는 {name, sub}] 3~12개(이름 한글 12자 안팎), cols(1|2, 5개 이상이면 2), body, foot(작은 회색 한 줄 — 옵션별 차이 등) — **세트 구성 N종·구성품 목록·단계 순서**처럼 이름을 번호로 짚어 줘야 하는 장. 원본에 구성품 이름표(1*~9* 등)가 있으면 그 순서를 따른다.
- table: cut(큰 사진 1장), rows:[[항목(6자 안팎), 설명(한두 줄, 줄당 18자 안팎)], …] 2~6개, body — **사진 한 장의 부위·기능을 항목별로 설명**할 때(스펙 숫자 나열 아님 — 숫자 위주면 spec).
- compare: band:[흔한 쪽 한 줄, 이 상품 한 줄], pairs:[{common:컷, this:컷, common_cap, this_cap}], body, foot("왼쪽은 비교용 다른 OO 사진이에요")

## 보호 표시 힌트 (protect) — 프로그램이 워터마크를 자동 배치한다. 예외만:
- FORCE_COMPLEX_CUTS: 배경·소품이 복잡한 현장 컷 키 목록(불투명도 23%)
- AVOID: {컷: [[x0,y0,x1,y1] 사진 칸 비율 0~1]} 제품 로고·각인·치수 글자를 덮지 말아야 할 영역
- NO_WM: 워터마크 넣지 않을 컷(글자·도표 위주 컷)
- COLOR_FIX: {컷: [r,g,b]} 흰 바탕 컷이라 자동 색이 묻힐 때 [40,38,34]
