# 힉스필드 콘텐츠 팩토리 (질문 한 줄 → 애니메이션)

> **관련**: [[AI-영상-제작]] · [[숏폼-만약에-포맷]] · [[하입덕-스레드]]
> **Facets**: AI영상 · 숏폼 · 릴스 · 프롬프트 · 크레딧비용 · 코드기반 애니메이션

## 핵심 (현재 아는 것의 요약)

힉스필드(Higgsfield)의 **콘텐츠 팩토리**는 "만약 ~라면?" 질문 한 줄과 장면 설명을 넣으면 이야기·장면·자막이 들어간 애니메이션 한 편을 통째로 만들어 주는 기능이다.
장면을 그림으로 그리는 게 아니라 **클로드가 코드로 짜서 움직이는 방식**이라, 화면에 숫자를 띄우는 영상도 숫자가 흐트러지지 않는다. 그래서 "숫자가 실시간으로 오르는" 만약에 영상에 특히 잘 맞는다.

지금 조회수가 크게 나오는 "만약에" 숏폼의 공통 뼈대는 세 가지다.
1. 첫 장면에 질문이 뜬다
2. 화면 위 숫자가 실시간으로 오른다 (HUD·진행바)
3. 숫자 크기에 맞춰 장면이 점점 커진다 (손바닥 → 지갑 → 금고 → 도시)
마지막은 첫 질문을 다시 띄워 끝낸다.

**프롬프트 설계 원칙 (실험으로 확인된 것)**
- 길이는 **60초**. 20초는 장면이 1초씩 지나가 숫자를 못 따라간다. "각 단계에 여유를 둔다"를 넣으면 단계마다 2~4초 머문다.
- **숫자는 날짜별로 직접 적어 준다.** 그러면 원 단위까지 정확히 나온다. (예: 31일차 10억 7,374만 원)
- **"밝고 선명한 조명"**을 명시해야 끝까지 밝다. 안 쓰면 보라색 톤에 끝이 어두워진다.
- 그림체는 **"3D 로우폴리"처럼 스타일 이름**으로 적는다. "실사 톤"은 평면 일러스트로 나온다.
- 1인칭 **손은 각지게 나온다.** 손 장면은 편집에서 짧게.
- **마지막 1초는 검은 화면**이라 올리기 전에 잘라낸다.

**비용**: 화면 예상 크레딧과 실제 차감이 다르다. 먼저 넉넉히 잡고 끝나면 남는 만큼 돌려주는 방식이라 잔액에 여유를 둬야 한다.

- 릴스 "1원 vs 10억" 애니메이션의 프롬프트 원문 공개. 한국어 화면(`higgsfield.ai/ko/content-factory`)에서 60초·1편으로 생성, 20분 소요.
- 사용 순서: 콘텐츠 팩토리 열기 → "만약 ~라면?" 질문 + 장면 설명 입력 → 길이(15초~5분)·에피소드 수(1~4편) 선택 → 생성 → 내 생성 목록에서 내려받기.
- 비용 실측 (같은 주제로 두 번):

| 설정 길이 | 완성 영상 | 걸린 시간 | 화면 예상 | 실제 차감 |
|---|---|---|---|---|
| 20초 | 20초 | 약 15분 | 약 21크레딧 | 81크레딧 |
| 60초 | 61초 | 약 20분 | 약 63크레딧 | 100크레딧 |

- 20초 vs 60초 비교로 얻은 교훈 6가지(길이·숫자·밝기·그림체·손·끝부분)는 위 핵심에 반영.
- 처음 가입은 "MCP 3일 무료 체험"으로 시작 가능 (소개 링크: higgsfield.ai/s/higgsfield-content-factory-ig-sebia-ai-SUmocQ).

#### 프롬프트 뼈대 (내 주제로 갈아 끼울 네 자리)

| 자리 | 원문 예 | 바꿀 것 |
|---|---|---|
| 첫 질문 | 만약 오늘 1원을 받고 매일 2배가 된다면? 아니면 지금 당장 10억? | 내가 궁금한 "만약에" 질문 |
| 날짜별 숫자 | 1일차 1원 → 5일차 16원 → … → 40일차 5,498억 | 내 주제에서 변하는 값(높이·인구·온도·매출) |
| 장면 확대 순서 | 손바닥 동전 → 지갑 → 금고 → 은행 금고 → 한강 지폐 탑 → 서울 도심 | 숫자가 커질 때 같이 커질 장면 |
| 마지막 화면 | "29일까지 참을 수 있는 사람만 이긴다" → 첫 질문 재등장 | 첫 질문으로 돌아가는 한 줄 |

고정으로 두면 좋은 문구: `3D 로우폴리 스타일` · `밝고 선명한 조명` · `큰 숫자 HUD로 실시간 표시` · `각 단계에 여유를 둔다` · `숫자가 커질수록 카메라가 뒤로 빠진다` · `내레이션 없이 한국어 자막과 경쾌한 효과음만`.

## 적용 (내 맥락에서 실제 사용)

- **하입덕 스레드·유튜브 숏폼 소재**: 구매대행 숫자를 "만약에"로 바꾸면 그대로 쓸 수 있다. 예) "만약 하루 상품 10개를 1년 올린다면?" → 1일 10개 → 30일 300개 → 365일 3,650개 → 노출·주문 수가 같이 커지는 장면. "만약 수수료 5%를 1년 모았다면?"도 같은 틀.
- **강의 인트로**: 실전반 라이브 첫 장면에 질문 하나 띄우고 숫자 오르는 60초 영상으로 열기. 기존 `motion-graphic` 스킬(리모션)로 만들던 것과 역할이 겹친다 → 숫자가 오르는 "만약에" 류는 힉스필드, 글자 중심 인사·초대 영상은 리모션.
- **속도 원칙 재확인**: 리모션 작업에서 세운 "장면 최소 3.5초, 글자 다 읽힐 때까지 멈춤" 원칙이 여기서도 똑같이 검증됐다("각 단계에 여유를 둔다" 없이는 못 따라감). AI 영상 도구 바뀌어도 이 원칙은 유지.
- **비용 습관**: 불사자 크레딧 작업과 같은 규칙 적용 — 생성 전에 예상 크레딧을 보고하되, 힉스필드는 예상치의 1.6~4배가 선차감된다고 알고 잔액을 본다.
