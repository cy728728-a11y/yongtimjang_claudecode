# 1부. 기초 용어 (설명용 사전)

## A. AI 기본 개념

### 1) AI
- **정의**: 사람처럼 생각하고 판단하는 컴퓨터 프로그램.
- **설명 포인트**: 엄청난 양의 데이터를 학습하고, 그 안에서 **패턴을 찾아** 규칙을 일일이 안 알려줘도 스스로 판단한다.

### 2) 생성형 AI (Generative AI)
- **정의**: 글·그림·영상·코드를 **직접 만들어내는** AI.
- **비교 포인트**: 예전 AI는 주로 "분류" 정도만 했다 → 이제는 "생성"까지 한다. 이 차이가 생성형 AI의 핵심.

### 3) LLM (거대 언어 모델, Large Language Model)
- **정의**: 그중에서도 **텍스트(글자)** 를 학습하고 생성하는 데 특화된 생성형 AI.
- **예시**: GPT, 제미나이, 클로드가 모두 LLM.
- **연결**: 클로드 코드도 이 LLM 기술 기반. 다만 **코딩에 특화된 방식**으로 쓴다.

### 4) 프롬프트 / 프롬프트 엔지니어링
- **프롬프트**: LLM에게 보내는 **명령어·질문**. (ChatGPT에 치는 메시지가 프롬프트)
- **프롬프트 엔지니어링**: 더 나은 답이 나오도록 **좋은 프롬프트를 짜는 기술**.
- **설명 포인트(부담 덜기)**: "거창해 보이지만 결국 **애기한테 명확하게 요청하는 기술**이고, 글짓기에 가깝습니다. 어렵게 여길 필요 없어요."

### 5) 할루시네이션 (환각)
- **정의**: AI가 **없는 사실을 있는 것처럼** 말하는 현상.
- **예시**: 존재하지 않는 논문 인용, 없는 법률을 있다고 설명, 가짜 통계 제시.
- **왜 생기나(핵심)**: AI는 정답을 "아는" 게 아니라 **그럴듯한 다음 단어를 예측**하는 방식으로 작동하기 때문.
- **결론**: 그래서 AI 답변은 **검증하는 과정**을 꼭 넣는 게 좋다.

### 6) AI 에이전트
- **정의**: 스스로 판단하고 **행동까지** 하는 AI.
- **비교**: 초기 챗봇 = 물어보면 "답만" 함. 에이전트 = **계획을 세우고 → 도구를 골라 쓰고 → 문제 생기면 해결하고 → 최종 결과물까지** 만든다.
- **연결(중요)**: 클로드 코드가 바로 AI 에이전트다. "웹사이트 만들어 줘" 하면 → 필요한 파일 결정 → 코드 작성 → 파일 생성 → 오류 나면 수정 → 완성된 페이지 표시. **사람이 일일이 안 시켜도 목표만 주면 알아서 한다.**

## B. 컴퓨터 기본 개념

### 7) GUI (그래픽 유저 인터페이스)
- **정의**: 마우스·키보드로 **화면을 보며 조작**하는 방식. (우리가 평소 쓰는 그 방식)
- **속사정**: 컴퓨터 입장에선 사실 복잡함. 버튼 클릭 = 좌표 파악 → 그 좌표의 그래픽 요소 확인 → 기능 실행. 여러 겹의 레이어가 있음.

### 8) CLI (커맨드 라인 인터페이스)
- **정의**: **글자(명령어)를 입력**해서 소통하는 방식.
- **장점**: 사람은 겁나지만 컴퓨터한테는 더 직관적이고 군더더기 없어 **효율적**. 게다가 명령을 **저장해뒀다 실행**할 수 있어 **자동화에 유리**.

### 9) 터미널 / cmd / 파워셸
- **터미널**: CLI로 컴퓨터와 소통하는 **애플리케이션**. 명령어 입력하고 결과 보여주는 그 "까만 창".
- **cmd(명령 프롬프트)**, **파워셸(PowerShell)**: 윈도우의 터미널 프로그램 종류. 둘 다 명령 해석기이고, **파워셸이 좀 더 세련된 버전**이라고 이해.
- **정리 멘트**: "명령으로 소통하는 방식 = CLI, 그걸 실행하는 프로그램 = 터미널, 터미널 종류엔 cmd·파워셸이 있다."

### 10) IDE (통합 개발 환경) / VS 코드
- **정의**: **코딩 전용 프로그램**. (워드가 문서 작성 프로그램이면, IDE는 코딩 프로그램)
- **예시**: VS 코드, 커서, 안티그래비티 등. 영상은 **VS 코드**로 진행 (다른 건 자체 AI 기능이 많아 설명이 분산되므로).
- **왜 쓰나(핵심 장점)**: 한 화면에서 다 된다. 클로드 코드를 터미널만으로 쓰면 뭐가 만들어지는지 안 보이는데, IDE와 함께 쓰면 **터미널로 소통하면서 파일이 생성·수정되는 걸 실시간으로 본다.**

### 11) 경로(Path) / 디렉토리(Directory)
- **경로**: 파일·폴더의 **주소**. (집 주소 "서울시 강남구 ○○로 123"처럼, 파일마다 주소가 있음)
- **디렉토리**: **폴더의 다른 이름**. 터미널에선 '폴더'보다 '디렉토리'라고 더 많이 씀. 같은 뜻.

### 12) 로컬(Local) vs 클라우드(Cloud) — ★가장 중요한 구분★
- **로컬**: **내 컴퓨터**. ("로컬에서 실행" = 내 컴퓨터에서 실행)
- **클라우드**: 인터넷 어딘가의 **다른 컴퓨터(회사 서버)**. (구글 드라이브, 네이버 클라우드 등)
- **왜 중요한가(이걸로 클로드 종류 차이를 설명)**:
  - **클로드 웹버전** = 클라우드에서 동작. 앤트로픽 서버에서 AI가 돌고 결과만 브라우저에 보여줌 → **내 컴퓨터 파일을 직접 못 건드림.**
  - **클로드 코드** = 로컬 + 클라우드 **조합**. 내 컴퓨터 파일을 직접 제어하면서 AI 두뇌는 클라우드에서 빌려옴 → **내 파일을 읽고·수정·생성할 수 있다.**
- 👉 구독자에게 이 대비 하나만 확실히 심어주면 "왜 클로드 코드가 특별한가"가 한 방에 이해됩니다.

## C. 개발 환경 용어

### 13) Node.js / 파이썬(Python)
- **Node.js**: 원래 웹 브라우저에서만 돌던 **자바스크립트**를, 내 컴퓨터에서도 직접 실행하게 해주는 **실행 환경**.
- **파이썬**: 그 자체가 **프로그래밍 언어**. 데이터 처리·자동화에 강점.
- **참고(프로그래밍 언어란)**: 컴퓨터는 원래 모든 걸 0과 1(이진법)로 처리 → 이걸 **사람이 이해하기 쉽게 표현한 것**이 프로그래밍 언어.
- **실용 조언**: 둘 다 필수는 아니지만, 클로드와 작업하다 보면 JS·파이썬 코드를 자주 쓰게 되니 **미리 설치 권장**.

### 14) API / API 키
- **API**: 프로그램끼리 **서로 소통하는 방법(약속·규칙)**.
- **비유(날씨앱)**: 날씨앱이 직접 온도를 재는 게 아니라, 기상청 서버에 "서울 날씨 알려줘" 요청 → 기상청이 "25도" 응답. 이렇게 **다른 프로그램의 정보를 요청하고 응답받는 규칙**이 API.
- **API 키**: 일종의 **비밀번호**. 서버가 "누가 요청했는지" 확인하고 무분별한 사용을 막기 위해 발급. 영어·숫자 섞인 긴 문자열이고, **사용량만큼 과금**되는 경우가 많음 → **절대 외부에 노출 금지.**

### 15) 토큰(Token) / 컨텍스트(Context)
- **토큰**: AI가 글을 이해·생성할 때 쓰는 **기본 단위**. 사람은 단어 단위로 보지만 AI는 토큰 단위(한 단어일 수도, 단어보다 작을 수도). **왜 중요? → 비용과 직결**. 많은 AI가 입력·출력 토큰량으로 과금하거나 사용량을 제한함. → **불필요하게 긴 대화보다 처음부터 명확한 요청**이 효율적.
- **컨텍스트**: AI가 **현재 대화에서 참고하는 정보의 범위**. "아까 그거" 해도 알아듣는 이유가 앞 내용이 컨텍스트에 있기 때문.
- **한계(중요)**: 무한 기억이 아님. 클로드는 **최대 약 20만 토큰** 수준까지 처리하고, 넘으면 **오래된 내용부터 반영이 안 될 수 있음**. → 대화가 길어지면 중요한 내용을 다시 정리해 전달하거나, **새 대화를 시작**하는 게 좋다. **메모리 기능**으로 특정 정보를 따로 저장하는 것도 방법.

## D. 웹 개발 용어

### 16) 프론트엔드 / 백엔드
- **프론트엔드**: **눈에 보이는 부분** (버튼·이미지·글자·색상 등 사용자가 직접 보고 클릭하는 것).
- **백엔드**: **안 보이는 부분** (로그인 확인·데이터 저장·결제 처리 등 뒤에서 일어나는 작업).
- **비유(식당)**: 프론트 = 홀·메뉴판·인테리어 / 백엔드 = 주방·재료 창고·주문 시스템.

### 17) HTML / CSS / 자바스크립트 (웹 3요소)
- **HTML** = 웹페이지의 **뼈대** (제목·버튼·이미지 위치 지정). 집의 기둥·벽 세우기.
- **CSS** = **꾸미기** (제목 빨간색, 버튼 둥글게, 배경 파란색). 페인트칠·인테리어.
- **자바스크립트** = **동작** (버튼 누르면 메시지, 스크롤하면 애니메이션). 전기·조명·스위치·자동문·센서 설치.

### 18) 프레임워크 / 라이브러리
- **프레임워크**: 집을 빠르게 짓도록 **미리 만들어진 설계 구조(틀)**.
- **라이브러리**: 필요한 도구만 꺼내 쓰는 **공구함(도구 모음)**.

### 19) 스크립트 / 워크플로우
- **스크립트**: 순서대로 실행되는 **명령어 모음** (1.파일 열고 2.수정 3.저장 4.다음 파일). **자동화의 기본**. → 요리 레시피 하나.
- **워크플로우**: 여러 작업이 연결된 **전체 과정** (메일 도착 → 첨부 저장 → 데이터 정리 → 슬랙 알림). → 주문·조리·서빙·결제까지 식당 운영 전체.

## E. 협업 도구 용어

### 20) 깃(Git)
- **정의**: 코드의 **변경 이력을 기록**하는 도구.
- **비유(찰떡)**: "보고서_v1, v2, 최종, 진짜최최종" 이렇게 저장해본 적 있죠? 깃은 이걸 **자동으로** 해준다. 언제 뭘 바꿨는지 다 기록되고, **이전 버전으로 되돌리기**도 가능.
- **주의**: 윈도우 사용자는 클로드 코드 설치의 **필수 사전 설치 항목**.

### 21) 깃허브(GitHub)
- **정의**: 깃으로 관리하는 코드를 **인터넷에 저장하는 서비스**. ("코드용 구글 드라이브")
- **장점**: 컴퓨터 고장나도 안전, 협업 가능, 언제 어디서든 접근.

### 22) 저장소(레포지토리) / 배포(Deploy)
- **저장소(레포)**: 한 프로젝트에 필요한 **모든 파일이 든 폴더**. 이걸 깃허브에 올리면 "깃허브 저장소".
- **배포**: 내가 만든 걸 **인터넷에 공개**하는 것. 내 컴퓨터에서만 보던 걸 남도 볼 수 있게 런칭 → **주소가 생기고 누구나 접속 가능**.

## F. 클로드(Claude) 자체 정리

- **클로드**: 앤트로픽(Anthropic)이 만든 LLM 기반 생성형 AI **서비스이자 브랜드이자 모델명**.
- **사용 형태 3가지**:
  1. **클로드 웹/앱** — 브라우저·모바일
  2. **코워크(코드) — 데스크톱 버전**
  3. **클로드 코드** — ★오늘의 주인공★
- **클로드 코드 정의**: "대화형 인터페이스 + 터미널 + 파일 시스템 작업"이 결합된 **코딩 특화 환경** = 쉽게 말해 **까만 화면(터미널)에서 동작하는 AI 코딩 도구.**

# 2부. 실습 (화면 시연 순서대로)

## STEP 0. 요금제
- 클로드 코드는 **최소 유료 플랜(프로)** 부터 사용 가능. 카드 등록·구독 필요.
- 순서 권장: 처음엔 **프로 플랜** → 익숙해지고 목적이 확실해지면 **맥스 플랜**.

## STEP 1. 두 가지 사용 경로
- **① 초보자용 — 데스크톱 앱**: claude.com/download에서 다운로드 → 로그인 → 상단 '코드' 탭 → 폴더 선택 후 시작. 터미널이 부담스러우면 이 방법.
- **② 본격 사용 — 터미널**: 더 유연하고 빠름. 영상은 이 방식으로 진행. (단, **깃 설치가 먼저 되어 있어야** 오류가 안 남)

## STEP 2. 사전 설치 (하나씩 따라가기)
순서대로: **깃 → 깃허브 연결 → 파이썬 → Node.js → VS 코드**

1. **깃 설치**: git-scm.com → Install → OS에 맞게 다운로드 → 대부분 기본값 Next. (에디터만 VS 코드로 선택하면 편함)
2. **터미널에 클로드 코드 설치**: "클로드 코드 설치" 검색 → 공식 문서 → 윈도우용 명령어 복사 → 파워셸에 붙여넣고 실행 → 설치 완료 → `claude` 입력 → 모드 선택(1번) → 연결 방식(1번, 클로드 계정 구독) → 브라우저 로그인 → 폴더 신뢰 확인 후 시작.
   - 테스트: "대한민국 역사 요약해 줘" 같은 일반 대화도 됨.
   - 창을 꺼도 됨. 다시 파워셸 열고 `claude`만 치면 재실행.
3. **깃허브 연결**: 가입 후, 클로드에게 "깃허브 연결하려는데 필요한 거 설치·진행해줘" 요청 → 클로드가 중간중간 허가를 물음(→ "Yes, and don't ask again" 선택) → `gh auth login` 진행(브라우저 로그인 + 코드 붙여넣기) → `gh status`로 연결 확인.
4. **파이썬 설치**: python.org → Download → 설치 시 **"Add python.exe to PATH" 체크** → cmd에서 `python` 입력, `5+5` → `10` 나오면 성공.
5. **Node.js 설치**: nodejs.org → OS 맞게 다운로드 → 기본값 설치.
6. **VS 코드 설치**: 다운로드 → 기본 설정 설치 → 실행.

## STEP 3. VS 코드에서 실제로 만져보기
- 파일 → **폴더 열기(Open Folder)** 로 작업할 폴더 지정 (예: 바탕화면에 'claude' 폴더 새로 만들어 선택).
- **좌측 패널** = 그 폴더 안 파일·폴더 목록 (실시간 반영). **우측 상단** = 파일 열어서 내용 확인·수정(Ctrl+S 저장).
- 상단 **터미널 → New Terminal** → 아래에 터미널 창 → `claude` 입력 → 폴더 신뢰 → 시작.
- 플러스(+)·화살표로 **여러 터미널(cmd·파워셸)을 동시에** 열어 각각 클로드 실행 가능 → **여러 작업 동시 진행.**

**동작 감 잡기 시연:**
- "현재 경로 파일 확인해서 알려줘" → 파일 목록·내용 출력.
- "이 파일과 같은 내용으로 5개 더 만들어 'copy' 폴더에 저장해줘" → 폴더·파일 실시간 생성.
- "현재 경로 모든 파일·폴더 삭제해줘" → 삭제(삭제는 확인을 요구함).
- 👉 **핵심 메시지**: "내가 지정한 폴더에서 원하는 걸 말하면, 클로드가 알아서 파일을 만들고·고치고·지우며 목표를 달성한다."

## STEP 4. 토이 프로젝트 (5분 컷)
- `claude --dangerously-skip-permissions` 로 실행 → **중간 허가 과정 스킵**(효율↑, 작업 성격에 따라 판단).
- "브라우저에서 실행할 수 있는 **지뢰찾기 게임** 만들어줘" → 5분 안에 완성, 실제 플레이·난이도 변경 가능.
- "이 지뢰찾기를 **소개하는 웹사이트** 만들어줘" → 특징·플레이 방법·난이도 선택까지 있는 페이지 완성.

## STEP 5. 커맨드(슬래시 명령어)
- **커맨드 = AI에게 주는 메시지가 아니라, 클로드 코드라는 '도구 자체를 제어'하는 기능.** `/`(슬래시) 입력 후 명령어.
- 비유: **운전 = 코딩, 계기판·설정 메뉴 = 커맨드.**
- 종류가 매우 많음 → **다 외우지 말고 우선순위 높은 것만.**
  - `/help` : 소개 + 주요 단축키.
  - `/status` : 내 작업 환경 전체 정보. 4개 탭 — **Status**(버전·경로·로그인), **Config**(환경 변경, 예: 테마), **Usage**(5시간·1주 한도, 모델별 남은 사용량), **Statistics**(사용 통계 시각화, R키로 기간 변경).
  - `/model` : 모델 선택 + 추론 강도 조절.
    - **오퍼스(Opus)**: 복잡한 추론·긴 문서·고난도 코딩에 강함. 대신 느리고 토큰 소모 큼.
    - **소넷(Sonnet)**: 성능·속도 밸런스. 일반 업무에 적당.
    - **하이쿠(Haiku)**: 가장 빠르고 가벼움. 간단한 분류·요약·빠른 응답에 적합.

## STEP 6. 4가지 모드 (Shift+Tab으로 전환)
1. **기본(Default) 모드**: 파일 쓰기·명령 실행마다 매번 승인 요청. **가장 안전하지만** 흐름이 끊길 수 있음.
2. **자동 편집(Edit) 모드**: 파일 편집은 자동 승인, **명령어 실행만** 승인 요청.
3. **플랜(Plan) 모드**: 읽고 탐색은 하되 **직접 수정 안 함**. 분석·변경 **계획만 제시** → 사용자 승인 후 실행. **복잡·중요한 작업 전에 범위 먼저 파악**해서 사고 방지.
4. **바이패스(Bypass) 모드**: `--dangerously-skip-permissions`. 승인 다 건너뜀.

## STEP 7. 확장 프로젝트 + 배포 (전체 흐름 체험)
- **명확한 프롬프트가 핵심**: "목적/방법/기타 요청사항"을 나눠서 전달.
  - 예: (목적) 간단한 게임 5종 모음 사이트 / (방법) 현재 폴더 기존 파일 재구성 / (기타) 홈에서 게임 선택 가능하게, 지뢰찾기 외 게임 아이디어 제안.
- 플랜 모드로 **계획 확인** → 자동 편집 모드로 실행 → '미니게임 컬렉션' 사이트 완성(카드 짝맞추기 등 추가).
- **깃허브 업로드**: "미니게임 저장소 만들고 커밋·푸시해줘. 앞으로 변동 생기면 항상 깃·깃허브 자동 커밋해줘."
  - `/BTW`(작업 중 끊지 않고 질문): "우리 앱 용량 얼마야?" → 작업 유지하며 답변.
- **배포(GitHub Pages)**: "정적 웹이니 깃허브 페이지로 배포해줄 수 있어?" → 무료 플랜은 **퍼블릭 저장소** 필요 → 공개 전환 후 배포 → 저장소 Settings → Pages 탭 → 생성된 **URL 클릭 시 실제 사이트 접속.** (복잡한 페이지는 다른 배포 방식 필요)

## STEP 8. 메모리 유지 — `/init` 과 CLAUDE.md
- **문제**: 세션이 끝나면 대화(맥락)가 **전부 사라진다.** 클로드는 우리 대화를 계속 간직하지 않음.
- **해결**: `/init` 실행 → **CLAUDE.md** 파일 자동 생성. 프로젝트 전반(규칙·했던 것·할 것/하지 말 것)이 정리됨.
- **효과**: 다른 터미널·다른 세션에서 클로드를 켜도 이 파일을 **먼저 참고** → 매번 같은 배경 설명을 반복할 필요가 없어짐. (간단히 둘 수도, 고급스럽게 다듬을 수도 있음)

## STEP 9. 알아두면 편한 단축키 / 기능
- **이전 메시지 다시 불러오기**: 방향키 ↑ / ↓
- **작성 중인 내용 전체 삭제**: ESC 두 번
- **채팅 안에서 줄바꿈**: Shift + Enter
- **파일 참조**: `@` 입력 후 파일 지정 (또는 파일을 드래그해서 끌어오기)
- **이미지 첨부**: 캡처가 클립보드에 있을 때 **Alt + V** 로 붙여넣기 후 요청

## STEP 10. 더 있는 것들 (존재만 소개 — 별도 영상 예고)
- `/agents` : 병렬로 일하는 **서브 에이전트** 생성 (예: UI 담당 / 백엔드 담당).
- `/mcp` : **MCP 서버**로 노션·Gmail·구글 드라이브 등 **외부 서비스 연결** → 워크플로우 확장.
- `/skills` : 반복 작업을 **스킬**로 만들어 호출 → 품질 일관성 확보.
- 👉 마무리 멘트: "에이전트·MCP·스킬은 몰라도 됩니다. 오늘 핵심 노하우만으로 충분히 나만의 무언가를 만들 수 있어요."
