## 매일 자동 실행 (launchd)

**하루 3회(08:00 · 14:00 · 22:00)** 돈다. **`apply` 모드 — 실제로 휴지통으로 보낸다** (30일 복구 가능).

> 맥이 자고 있으면 launchd 가 예약을 버리지 않고 **깨어난 직후 한 번** 실행한다.
> 08:00 만 걸어뒀을 때는 맥이 잠들어 있어 매번 자정 무렵에야 돌았다(2026-08-29 실측).
> 예약 시각에 기록이 없다고 고장이 아니다 — `ls -lT ~/.local/share/mail-triage/logs/` 로 실제 실행 시각 확인.
18계정 전달을 켜고 며칠 관찰한 뒤 실삭제로 바꾸는 게 안전하다.

| 항목 | 위치 |
|---|---|
| 등록 파일 | `~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist` |
| 실행 런타임 | `~/.local/share/mail-triage/` (설치본) |
| 누적 리포트 | `~/.local/share/mail-triage/logs/daily-report.md` |

```bash
# 미리보기로 되돌리기 — plist 의 MODE 를 preview 로 바꾸고 재등록
sed -i '' 's|<string>apply</string>|<string>preview</string>|'   ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist
launchctl unload ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist
launchctl load   ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist

# 즉시 한 번 돌려보기
launchctl kickstart -k gui/$(id -u)/com.yongtimjang.mailtriage

# 자동 실행 끄기
launchctl unload ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist
```

> ⚠️ **규칙(`rules.py`)을 고쳤으면 반드시 `./install.sh` 를 다시 돌려라.**
> 자동 실행은 저장소가 아니라 설치본을 읽는다. macOS TCC 때문에 launchd 로 뜬 프로세스는
> `~/Documents` 안의 파일을 **열 수 없다** (stat 은 되고 open 은 거부돼 `can't open input file` 로 실패).
> 그래서 런타임만 `~/.local/share` 에 복사해 둔 것이다.
>
> ⚠️ 맥이 꺼져 있거나 절전이면 그 시간의 자동화는 건너뛴다(합의된 트레이드오프).

## 폐기 기록 — gws/OAuth 판 (2026-08-27 삭제)

`gws auth` 가 쓰는 `gmail.modify` 와 `drive` 는 Google 이 **"제한된 범위(restricted scope)"** 로 분류한다.
Google 인증 플랫폼 → 데이터 액세스에서 이 둘을 등록하려면
**소유 도메인 + 애플리케이션 홈페이지 · 개인정보처리방침 · 서비스 약관 URL + Search Console 도메인 승인**이
선행돼야 한다. 그게 없으면 "앱의 OAuth 구성이 완료되지 않았습니다" 배너가 안 사라지고
`앱 게시` 버튼이 영구 비활성이라 **Testing 모드 = 토큰 7일 만료**를 벗어날 수 없다.

메일 정리 하나 때문에 도메인·정책 페이지·검증 절차를 치를 이유가 없어 IMAP + 앱 비밀번호로 갈아탔다.
이때 만들었던 코드(`gws_client.py` · `classifier.py`(Claude API 분류) · `email_triage.py` · `state.py` · `triage.py` · `tests/`)는
2026-08-27 에 삭제했다. 필요하면 git 이력에서 복구 가능하고, 설계 문서는
`90-archive/이메일-자동화-gws판-구현계획-2026-08-19.md` 에 남겨 뒀다.

- `ANTHROPIC_API_KEY` 는 이제 이 프로젝트에 필요 없다 (판정이 정규식이라 API 호출 0, 과금 0).
- 구글시트 처리로그(`EMAIL_TRIAGE_SHEET_ID`)도 함께 폐기 — 로그는 `logs/daily-report.md` 로 남는다.
- gws 자체는 캘린더·시트 등 다른 용도로 계속 쓴다 (거긴 수동 재로그인으로 버틸 수 있는 용도).
