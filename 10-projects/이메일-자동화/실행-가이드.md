### OAuth 프로덕션 전환을 폐기한 이유 (2026-08-27)

`gws auth` 가 쓰는 `gmail.modify` 와 `drive` 는 Google 이 **"제한된 범위(restricted scope)"** 로 분류한다.
Google 인증 플랫폼 → 데이터 액세스에서 이 둘을 등록하려 하면 거부되고,
등록하려면 **소유한 도메인 + 애플리케이션 홈페이지 · 개인정보처리방침 · 서비스 약관 URL + Search Console 도메인 승인**이
선행돼야 한다. 그게 없으면 "앱의 OAuth 구성이 완료되지 않았습니다" 배너가 사라지지 않아
`앱 게시` 버튼이 영구 비활성 상태로 남는다. (민감하지 않은/민감한 범위 8개는 정상 등록됨)

메일 정리 하나 때문에 도메인·정책 페이지·검증 절차를 치를 이유가 없어서
**IMAP + 앱 비밀번호**로 갈아탔다. 앱 비밀번호는 만료가 없어 7일 문제가 원천 소멸한다.
gws 는 캘린더·시트 등 나머지 용도로 그대로 둔다(거긴 수동 재로그인으로 버틸 수 있는 용도).

### 매일 자동 실행 (launchd)

매일 **08:00** 에 자동으로 돈다. **현재는 `preview` 모드 — 판정만 하고 아무것도 지우지 않는다.**
사업자 메일 18계정 전달이 켜지고 며칠 관찰한 뒤 실삭제로 바꾸는 게 안전하다.

| 항목 | 위치 |
|---|---|
| 등록 파일 | `~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist` |
| 실행 런타임 | `~/.local/share/mail-triage/` (설치본) |
| 누적 리포트 | `~/.local/share/mail-triage/logs/daily-report.md` |

```bash
# 실삭제로 전환 — plist 의 MODE 를 apply 로 바꾸고 재등록
sed -i '' 's|<string>preview</string>|<string>apply</string>|'   ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist
launchctl unload ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist
launchctl load   ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist

# 즉시 한 번 돌려보기
launchctl kickstart -k gui/$(id -u)/com.yongtimjang.mailtriage

# 자동 실행 끄기
launchctl unload ~/Library/LaunchAgents/com.yongtimjang.mailtriage.plist
```

> ⚠️ **규칙(`rules.py`)을 고쳤으면 반드시 `./install.sh` 를 다시 돌려라.**
> 자동 실행은 저장소가 아니라 설치본을 읽는다. macOS TCC 때문에 launchd 로 뜬 프로세스는
> `~/Documents` 안의 파일을 **열 수 없다** (stat 은 되고 open 은 거부돼서
> `can't open input file` 로 실패한다). 그래서 런타임만 `~/.local/share` 에 복사해 둔 것이다.
