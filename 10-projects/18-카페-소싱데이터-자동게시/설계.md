# 카페 소싱데이터 자동 게시 — 설계

## 1. 무엇을, 왜

용팀장은 한 달에 1~2번, 셀러라이프(셀록홈즈) '카테고리 소싱' 화면의 **전체 카테고리 엑셀 다운로드** 압축파일을 받아 구글 드라이브에 올리고, 네이버 카페 '하우제로'의 **실전반 소통방** 게시판에 드라이브 링크를 글로 올려 수강생에게 준다.

- 손으로 하다 보니 빠진다: 10/5 이후 한 달 넘게 안 올라감.
- 목표: **셀러라이프가 데이터를 새로 낼 때마다(2주마다) 사람 손 없이 카페에 올라간다.** 수강생은 늘 최신 데이터를 받는다.

## 2. 지금 상태(확인한 사실)

- 카페 글 모양(2026-10-05 글 기준): 제목 `2026년 10월 5일 최신화`, 본문은 드라이브 공유 링크 한 줄뿐. 첨부파일 없음.
  - 이전 제목 형식: `2026년 7월 소싱데이터`. 최근(8월~)은 `YYYY년 M월 D일 최신화`.

## 3. 목표 / 비목표 / 실패로 보는 것

- 목표
  - 셀러라이프 업데이트마다 1회: 받기 → 드라이브 업로드·링크 공유 → 카페 글 게시. 무인.
  - "지금 올려" 하면 즉시 1회 실행도 가능.
  - 실패하면 그 회차가 조용히 빠지지 않게 용팀장에게 알림 + 붙여넣을 제목·링크 제공.
- 비목표
  - 파일 가공(카테고리 추리기·필터) 없음. 원본 zip 그대로.
  - 다른 게시판·다른 카페 게시, 댓글 관리 없음.
- 실패로 보는 것(기술적으로 돌아가도)
  - 네이버 약관 위반 방식(브라우저 자동 클릭 매크로)으로 글 쓰기 → 계정 제재 위험.
  - 같은 회차 글이 두 번 올라감(도배).
  - 링크가 '링크 있는 사람 보기'가 아니라 수강생이 못 열음.

## 4. 제약

- 최종 실행 장소: **집에 항상 켜두는 맥북.** 지금은 이 PC(블랙노트북)에서 시험만.
- 카페 게시는 **네이버 공식 카페 API(개발자센터 '카페 글쓰기')** 로만. 매크로 클릭 금지.
- 게시 계정: 용팀장(카페 부매니저) 본인.
- 구글 비밀번호·네이버 비밀번호를 파일에 저장하지 않는다(로그인/허락은 사람이 최초 1회).
- 기존 스킬(`download.py`)은 재작성하지 않고 불러 쓴다.

## 5. 방법 비교(결정됨)

| 방법 | 장점 | 단점 |
|---|---|---|
| **① 네이버 공식 카페 API** ← 선택 | 네이버가 허용한 방식, 화면 바뀌어도 안 깨짐 | 최초 앱 등록·허락 10~15분, 허락 1년쯤마다 재동의 가능성 |
| ② 크롬 자동 클릭 | 등록 없이 빠름 | 약관상 매크로, 보안문자·화면 변경에 깨짐 → 무인에 부적합 |
| ③ 반자동(카페 글만 사람) | 가장 단순 | 완전 자동 아님 |

선택: **①**. ①이 실패한 회차는 ③처럼 알림으로 넘김(대체 경로). 용팀장 결정 2026-11-19.
전제 확인: 착수 전 네이버 개발자센터에서 카페 글쓰기 API가 현재도 제공되는지 확인(대화 시점엔 네이버 사이트 접근이 막혀 미확인).

## 6. 흐름

```
[맥북 스케줄러, 매주 월요일 아침 1회 확인]
  └ 셀러라이프 '기준일'이 지난 게시 회차보다 새로우면 진행, 아니면 종료
      1) download.py 로 전체 카테고리 zip 받기
      2) 드라이브 공유 폴더에 업로드 → '링크 있는 사람 보기' 공유 → 링크 얻기
      3) 카페 API로 실전반 소통방에 글 게시
           제목: YYYY년 M월 D일 최신화   (게시한 날짜)
           본문: 드라이브 링크 한 줄
      4) 게시 기록(기준일·링크·글번호) 남기고, 용팀장에게 완료 알림
  └ 어느 단계든 실패 → 알림(어디서 막혔는지 + 붙여넣을 제목·링크), 다음 주 같은 요일에 다시 시도(급하면 "지금 올려"로 수동 실행)
```

- **주 1회 월요일**(용팀장 결정 2026-11-19): 주간 루틴은 전부 월요일로 통일해야 안 헷갈린다. 셀러라이프는 격주 수요일 업데이트라 게시가 5일쯤 늦지만 용팀장 판단으로 상관없음. 업데이트 없는 주는 확인만 하고 끝난다. 요일은 설정 한 줄로 바꿀 수 있게.
- 기준일이 바뀐 걸 직접 보고 움직이므로, 업데이트가 하루 이틀 밀리거나 맥북이 그날 꺼져 있었어도 다음 주에 따라잡는다.
- **중복 방지**: 게시 기록에 같은 기준일이 있으면 게시하지 않는다.

## 8. 정해 둔 것(클로드 판단 — 용팀장 확인용)

- **공식 카페 API가 없거나 막혀 있으면 → ③ 반자동으로 확정.** ②(자동 클릭)는 쓰지 않는다. 약관 위험을 피한다는 용팀장 우려(2026-11-19 대화)에 따름.
- **게시판은 '실전반 소통방' 하나로 고정.** 6월~10월 글이 기수와 상관없이 같은 게시판에 있음(캡처 확인). 단, 게시판 번호는 설정값으로 둬서 바꾸기 쉽게.
- **중복 판단 기준 = zip 파일 이름의 날짜(예: 20260930).** 화면 기준일은 '받으러 갈 때가 됐나' 확인용으로만 쓰고, 받은 파일 날짜가 지난 게시와 같으면 올리지 않는다.
- **글에는 파일 링크**(폴더 링크 아님) — 기존 글과 같은 방식.
- **지난 회차 zip은 최근 3회차만 남기고 자동 삭제.** 237MB × 2주마다 → 1년 약 6GB라 무료 15GB가 1~2년 안에 참. 지워진 회차의 옛 글 링크는 열리지 않게 됨(최신 글을 보면 됨). 클로드 추천안을 용팀장이 그대로 채택(2026-11-19).
