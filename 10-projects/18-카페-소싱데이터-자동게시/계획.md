# 카페 소싱데이터 자동 게시 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 셀러라이프 '전체 카테고리 엑셀' zip을 매주 월요일 받아, 새 데이터면 구글 드라이브에 올려 공유하고 네이버 카페 실전반 소통방에 링크 글을 자동 게시한다.

**Architecture:** 새 스킬 `.claude/skills/cafe-sourcing-post/` 하나. 받기는 기존 `sellerlife-keyword/scripts/download.py` 를 별도 프로세스로 불러 `###ARTIFACT###` 마커로 경로를 얻는다. 드라이브는 `gws` CLI, 카페는 네이버 공식 카페 API(OAuth). 회차 기록·토큰은 `~/.eroom/` 에 둔다(저장소 밖). 맥북 launchd 가 월요일 09:00 에 `run.py` 실행.

**Tech Stack:** Python 3(워크스페이스 `.venv`), requests, pytest, gws CLI, 네이버 카페 API, macOS launchd.

**Spec:** `10-projects/18-카페-소싱데이터-자동게시/설계.md`

## Global Constraints

- 카페 게시는 **네이버 공식 카페 API로만**. 브라우저 자동 클릭 금지.
- 비밀번호를 파일에 저장하지 않는다. 토큰·시크릿은 `~/.eroom/naver-cafe.json`(저장소 밖).
- 드라이브: 계정 `cy728728@gmail.com`, 폴더 ID `1tHxVObirOwYoxAZAcslA24mV_VctmJXB`, 공유 = 링크 있는 사람 보기.
- 업로드 파일 이름: `SellarSourcingAll_<YYYYMMDD>.zip` (YYYYMMDD = 데이터 날짜).
- 글 제목 `YYYY년 M월 D일 최신화` (게시한 날, 월·일 앞자리 0 없음). 본문 = 드라이브 파일 링크 한 줄.
- 같은 데이터 날짜는 두 번 게시하지 않는다.
- 드라이브에 `SellarSourcingAll_*.zip` 최근 3개만 남기고 나머지는 휴지통으로(영구 삭제 아님).
- 실패 시 메일 알림(받는 사람 = gws 로그인 계정 본인)에 붙여넣을 제목·링크 포함.
- 기존 `download.py` 는 수정하지 않는다.
- 코드: 한국어 주석, 외부 호출은 try-except.

## Review Focus

1. 업로드는 됐는데 카페 게시가 실패한 회차 → 다음 실행에서 **다시 올리지 않고** 기존 링크로 게시만 재시도해야 한다.
2. 셀러라이프 데이터가 아직 안 바뀐 주(격주 중 쉬는 주) → 받기만 하고 조용히 종료, 알림·게시 없음.
3. 네이버 허락(리프레시 토큰) 만료 → 예외로 죽지 않고 "허락 다시 해 줘" + 제목·링크 메일.
4. 셀러라이프 로그인 풀림(download.py 비정상 종료) → "맥북에서 --setup 다시" 안내 메일.
5. 한글 제목·본문 깨짐 → 카페 API 인코딩 규칙대로 보내 테스트로 고정.

### Task 3: 네이버 카페(cafe.py, cafe_setup.py)

**Interfaces — Produces:**
- 설정 파일 `~/.eroom/naver-cafe.json`: `{"client_id","client_secret","refresh_token","access_token","club_id","menu_id"}`
- `refresh_access_token(cfg: dict) -> str` — `POST https://nid.naver.com/oauth2.0/token` `grant_type=refresh_token`; 응답에 `error` 있으면 `CafeAuthError`; 새 토큰을 설정 파일에 저장
