# 키워드 → 상품명 스킬 설계 노트

> 스킬을 직접 만들 사람에게 넘기는 **흐름 정의서**. 코드가 아니라 "무엇을 어떤 순서로, 무엇을 주고받는가"를 적는다.
> 참고 구현: `sellha-itemscout-export/` (1~3단계의 동작하는 코드). 4단계는 `키워드&상품명작성에이전트.md` 가 프롬프트 역할을 한다.

---

## 전체 그림

```
[상품]  →  ①대표키워드  →  ②셀하: 카테고리 조회  →  ③아이템스카우트: 엑셀 다운로드  →  ④키워드·상품명 생성
          (사람/AI)        (로그인+크롤)            (로그인+UI조작+다운로드)          (AI + agents.md 규칙)
```

앞 3단계는 **자동화(브라우저 조작)**, 4단계는 **AI 판단**이다. 성격이 달라 스킬을 2개로 쪼개는 편이 낫다 (아래 §6).

---

## ① 대표 키워드 찾기

| | |
|---|---|
| **입력** | 상품명(타오바오/원문), 썸네일·상세페이지 이미지 |
| **출력** | 대표키워드 1개 (예: `아세아관리기엔진`, `식당케찹디스펜서`) |
| **주체** | 사람 또는 AI |

**정의를 먼저 합의해야 한다.** 대표키워드는 "이 상품이 속한 카테고리를 셀하가 맞히게 만드는 검색어"다. 상품명 그 자체가 아니다.

- 너무 길면(원문 상품명 통째) 셀하가 카테고리를 못 찾는다.
- 너무 짧으면(`디스펜서`) 엉뚱한 대분류로 빠진다.
- 실무적으로는 **명사 2~3개 조합**이 잘 맞는다.

> 자동화 난이도가 가장 애매한 구간. 처음엔 사람이 직접 넣게 하고, 나중에 이미지+상품명을 AI에 물려 뽑는 걸로 승격하는 걸 권한다.

---

## ② 셀하 로그인 → 카테고리 조회

| | |
|---|---|
| **입력** | 대표키워드 |
| **출력** | 네이버 카테고리 경로 `생활/건강 > 공구 > 원예공구 > 농기계` + 확신도 % |
| **상태** | ✅ 검증된 구현 있음 (`scripts/sellha.py`) |

**흐름**
1. `https://sellha.kr/member/login` — `input[name=email]`, `input[name=password]` 채우고 텍스트에 `로그인` 포함된 버튼 클릭
2. 로그인 완료 판정 = URL 이 `/member/login` 을 벗어남
3. `https://sellha.kr/research?keyword=<URL인코딩>&tab=research-result` 로 이동
4. `document.body.innerText` 를 폴링하며 `NN.N% 대분류 > 중분류 > ...` 패턴을 정규식으로 긁음
5. **확신도(%)가 가장 높은 경로 1개** 채택

**주의**
- 셀하는 확장 프로그램 없이 렌더된다 → 일반 Selenium 으로 크롤 가능 (아이템스카우트 키워드 페이지와 다른 점)
- SPA 라 렌더 지연이 있다. 즉시 파싱하면 빈 화면을 읽는다 → **1초 간격 폴링, 최대 ~22초**
- `검색 결과가 없` / `데이터가 없` 텍스트를 보면 즉시 조회실패로 처리 (타임아웃까지 기다리지 말 것)

## ③ 아이템스카우트 아이템발굴 → 엑셀 다운로드

| | |
|---|---|
| **입력** | ②의 카테고리 경로 |
| **출력** | 키워드 엑셀 `.xlsx` (약 500행) |
| **상태** | ⚠️ 부분 구현 — **쇼핑성 필터 미구현, 4차 미대응** |

**흐름**
1. `https://itemscout.io/signin` 로그인 (`input[name=email]` / `input[name=password]`, `이메일 로그인` 버튼)
2. `https://itemscout.io/category` 진입
3. **셀하가 준 카테고리 경로를 차수 순서대로 드롭다운에 그대로 선택**
4. `인기 키워드` 탭 (기본) 선택
5. **🔴 `쇼핑성` 필터 선택 — 여기가 새로 만들어야 하는 부분**
6. `엑셀 다운로드` 버튼 클릭 → `.xlsx` 수신

### 차수 매핑 규칙 (중요)

**두 사이트 모두 네이버 표준 카테고리를 쓴다. 같은 트리로 본다.**

```
셀하:          생활/건강 > 공구 > 원예공구 > 농기계
                  ↓         ↓       ↓          ↓
아이템스카우트:   1차       2차      3차        4차
```

- **차수 개수는 카테고리마다 다르다.** 3차에서 끝나는 카테고리가 있고, 4차까지 있는 카테고리가 있다.
- 따라서 "3차까지만" 같은 고정 상한을 두지 말고, **셀하가 준 경로의 끝까지 그대로 선택을 시도**한다.

### 선택 실패 시: 폴백하지 말고 `확인 필요` 로 보고

셀하 경로의 어떤 차수를 아이템스카우트에서 못 고르면, **임의로 얕은 차수로 물러나지 않는다.** 그 상태로 다운로드하면 엉뚱한 범위의 키워드 엑셀이 나오는데, 받는 쪽에서는 그게 잘못된 줄 모른다.

대신 그 키워드를 **`확인 필요` 로 표시해 사람에게 보고**한다.

```
[확인 필요] 아세아관리기엔진
  셀하 경로   : 생활/건강 > 공구 > 원예공구 > 농기계
  선택 성공   : 생활/건강 > 공구 > 원예공구   (3차까지)
  실패한 차수 : 4차 '농기계'
  가능한 옵션 : ['경운기', '관리기', '트랙터', ...]
```

실패한 차수와 **그 자리에서 실제로 고를 수 있었던 옵션 목록**을 같이 찍어주면, 사람이 바로 판단할 수 있다.

> 1차만 쓰면 그 대분류의 상위 500개(텀블러·비데 같은 초대형 키워드)만 나와 소싱에 쓸모가 없다. 얕은 차수로 자동으로 물러나는 게 위험한 이유가 이것이다.

> **⚠️ 미검증**: 참고 구현(`discover_export.py`)은 `1차/2차/3차 카테고리` 드롭다운 3개만 조작하고, 실패 시 2차→1차로 **자동 폴백한다**. 위 규칙과 어긋난다. 아이템스카우트가 4차 드롭다운을 렌더하는지는 확인해본 적이 없다. **만들 때 실제 화면에서 4차 드롭다운의 라벨을 먼저 확인하고, 폴백 로직을 `확인 필요` 보고로 바꿔야 한다.**

### 드롭다운 조작 요령 (실측 기반)

옵션이 `<select>` 가 아니라 SPAN/DIV leaf 로 렌더된다. `Select` 클래스를 못 쓴다.

- `N차 카테고리` 텍스트를 가진 `button` 을 클릭해 드롭다운을 연다
- **열기 전/후의 "보이는 leaf 텍스트" 를 diff** 해서 옵션 목록을 얻는다
  (`childElementCount === 0 && offsetParent !== null`, 길이 22자 미만)
  → 이렇게 안 하면 하단 키워드 테이블·푸터 텍스트가 옵션으로 섞여 들어온다
- 옵션 클릭은 **정확일치 우선**, 없으면 부분일치까지 허용
  → 단, 부분일치는 엉뚱한 옵션을 집을 수 있다. 실제로 클릭한 텍스트를 되돌려 받아 **셀하 경로와 대조**하고, 다르면 `확인 필요` 로 넘긴다
- 네비게이션 텍스트(`아이템발굴`, `멤버십`, `엑셀 다운로드` 등)는 노이즈 목록으로 빼둔다
- 드롭다운을 열어 얻은 옵션 목록은 **실패 보고에 그대로 실어준다** (사람이 판단할 재료)

### 🔴 쇼핑성 필터 — 미구현 구간

현재 참고 구현에는 **없다.** 두 가지 길이 있다.

| 방식 | 설명 | 평가 |
|---|---|---|
| **A. UI 필터 조작** | 아이템발굴 화면의 필터에서 `쇼핑성` 선택 후 다운로드 | 원하는 대로지만 셀렉터를 직접 찾아야 함 |
| **B. 사후 필터링** | 그냥 다운로드 → 엑셀의 `키워드 분류` 컬럼에서 `쇼핑성` 행만 남김 | 즉시 가능. UI 변경에 안 깨짐 |

> **B 로 시작하는 걸 권한다.** 엑셀에 `키워드 분류` 컬럼이 이미 있어서 openpyxl/pandas 로 한 줄이면 된다. UI 조작은 아이템스카우트가 화면을 바꿀 때마다 깨진다.

### 다운로드 처리

- CDP `Page.setDownloadBehavior` 로 **전용 임시폴더** 지정 (`_dl_tmp/`)
- 신규 파일 감지: 다운로드 전/후 파일목록 diff, `.crdownload` 확장자 제외
- **파일 크기가 2회 연속 같아야** 완료로 본다 (안 그러면 반쯤 받은 파일을 집는다)
- 완료 후 `downloads/` 로 이동·리네임 (`날짜_카테고리_키워드.xlsx`)

### 엑셀 스키마

```
키워드 / 대표 카테고리 / 키워드 분류 / 상품수 / 총 검색량 / 경쟁강도 / ...
```
→ 4단계가 그대로 소비한다.

## ④ 키워드 선별 + 상품명 생성

| | |
|---|---|
| **입력** | ③의 엑셀 + 상품명 + 썸네일/상세페이지 이미지 |
| **출력** | `[01 추천키워드]` 탭, `[02 상품명]` 탭 |
| **주체** | AI (`키워드&상품명작성에이전트.md` 가 시스템 프롬프트) |

**이 단계는 코드가 아니라 프롬프트다.** 이미 작성된 `키워드&상품명작성에이전트.md` 를 그대로 붙이면 된다. 요약하면:

```
엑셀 + 이미지  →  상품수 1만 이하 필터 + 상품 적합성 판단  →  추천키워드 5~6개
               →  핵심 상품명 2개 선정(겹치는 단어 ≤1)  →  최종 상품명 1개 (핵심 2개 분산 배치 + 추가 키워드, term count ≤ 7)
               →  중복어 검수  →  자기검수 체크리스트  →  보고
```

**핵심 제약**
- 상품수 **1만 이하** 기본 / 5개 미만이면 **2만 이하** 확장 (5개 찾아지면 확장 없이 멈춤) / 그래도 부족하면 유사키워드 최대 10개
- 브랜드 키워드 제외 (다이소·락앤락 등 → 구매대행 부적합)
- 원본에서 확인 안 되는 소재/효능/인증 표현 금지
- 최종 상품명 1개 = 핵심 상품명 2개(겹치는 단어 ≤1, 고정 구문·분산 배치) + 나머지 키워드 미사용 단어(추가 키워드), term count 7 이하, 중복 단어 최대 1개·2회까지
- 애매하면 확정하지 말고 `확인 필요`

**자동화 가능한 부분 / 아닌 부분**
- 상품수 필터링, term 분해 초안, 중복어 카운트 → **코드로 가능**
- "이 키워드가 실제 상품과 맞는가" → **AI 판단 필수** (이미지를 봐야 함)

## ⑤ 각 단계 사이의 계약 (인터페이스)

스킬을 나눠 만들 거면 이 형태로 주고받게 하면 된다.

```
① → ②   "아세아관리기엔진"                        (문자열)

② → ③   { "경로": "생활/건강 > 공구 > 원예공구 > 농기계",
           "계층": ["생활/건강","공구","원예공구","농기계"],
           "확신도": "82.4" }

③ → ④   { "xlsx": "/abs/path/260710_생활건강_공구_원예공구_농기계_아세아관리기엔진.xlsx",
           "사용카테고리": "생활/건강 > 공구 > 원예공구 > 농기계",
           "대표키워드": "아세아관리기엔진",
           "상태": "성공" }

③ → 사람  (선택 실패 시 — 엑셀 없이)
         { "대표키워드": "아세아관리기엔진",
           "상태": "확인 필요",
           "셀하경로": "생활/건강 > 공구 > 원예공구 > 농기계",
           "선택성공": "생활/건강 > 공구 > 원예공구",
           "실패차수": "4차 '농기계'",
           "가능옵션": ["경운기", "관리기", "트랙터"] }

④ → 사람  [01 추천키워드] / [02 상품명] 시트 + 보고 요약
```

> `확인 필요` 는 ④로 넘기지 않는다. 사람이 카테고리를 확정한 뒤 ③부터 다시 태운다.

> 스크립트 출력 마지막에 `###XLSX###` 같은 **마커 + 다음 줄에 값** 형태로 찍으면, 스킬 본문(AI)이 stdout 에서 파싱하기 쉽다. 참고 구현이 쓰는 방식.

## ⑥ 스킬 쪼개기 제안

성격이 다르므로 **2개**로 나누는 걸 권한다.

| 스킬 | 범위 | 성격 |
|---|---|---|
| `keyword-category-export` | ① ~ ③ | 브라우저 자동화. 결정적. 실패하면 재시도 |
| `keyword-product-name` | ④ | AI 판단. 이미지 필요. 사람 승인 필요 |

**이유**
- ③까지는 로그인·셀렉터·다운로드라 **깨지면 코드를 고친다**
- ④는 **프롬프트를 고친다**
- 엑셀을 이미 갖고 있는 경우 ④만 단독으로 쓰고 싶어진다 (실제로 자주 그렇다)

## ⑦ 만들기 전에 정해야 할 것

1. **대표키워드를 누가 정하는가** — 사람 입력? AI 추출? (①의 정의 문제)
2. **쇼핑성 필터를 UI 로 걸 것인가, 엑셀에서 걸 것인가** — B 권장
3. **아이템스카우트 4차 드롭다운의 실제 라벨** — 화면에서 직접 확인 (`4차 카테고리`? 다른 이름?)
4. **`확인 필요` 를 어디에 모으는가** — 콘솔 출력? 별도 시트 탭? 배치로 여러 키워드를 돌리면 쌓인다
5. **결과를 어디에 쌓는가** — 구글시트? 로컬 xlsx? (agents.md 는 시트 탭 전제)
6. **이미지를 어떻게 AI 에 넘기는가** — 로컬 파일? URL? (④의 적합성 판단에 필수)

| 아이템스카우트 옵션이 `<select>` 가 아님 | leaf 텍스트 diff 로 옵션 추출 |
| 카테고리마다 차수 개수가 다름 (3차 끝 / 4차 존재) | 고정 상한 두지 말고 **셀하 경로 끝까지 시도** |
| 어떤 차수를 못 고름 | 얕은 차수로 **폴백 금지**. `확인 필요` + 실패차수 + 가능옵션 보고 |
| 반쯤 받은 `.crdownload` 를 집음 | 크기 2회 연속 동일 확인 |
| 2FA/캡차 | `headless` 끄고 창에서 직접 완료 → 스크립트가 이어감 |
| 봇 감지 | `--disable-blink-features=AutomationControlled` + `navigator.webdriver` 언디파인 |
| 1차 카테고리만 선택 | 초대형 키워드만 나옴. 소싱 불가 |
